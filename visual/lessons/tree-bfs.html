Tree BFS (level order)

Visit the tree one floor at a time, top to bottom, using a queue — and freeze the queue's size at the start of each floor so you know where the floor ends.

Time to learn: about 1.5 hours · Prerequisites: Tree traversals, Stack basics (queues)

When to use it — the signal

The problem says level, row, depth by depth, "right side view", "zigzag", "average of each level", "largest value in each row", "minimum depth" or "nearest". Anything about floors of the tree, or the closest node to the root, is BFS.

The idea in plain words

BFS = breadth-first search: go wide before going deep. Instead of diving down one path (that is DFS, the traversals lesson), you visit the root, then all nodes 1 step down, then all nodes 2 steps down, and so on.

The tool is a queue = first in, first out, like a line at a shop. Put the root in. Then repeat: take the node at the front, write it down, and add its children at the back. Because children always join behind everything already waiting, a whole floor leaves the queue before the next floor starts.

The one trick for "per level" problems: at the start of each floor, read size = q.size(). Right then the queue holds exactly the nodes of this floor (say 3). Take exactly 3 nodes out; the children they add are the next floor and wait for the next round.

  • Right side view = the last node of each floor (what you would see standing on the right).
  • Zigzag = same floors, but every second floor is written right-to-left.

Each node goes in and out of the queue once → O(n) time. The queue holds at most one floor plus part of the next → O(width) extra space (up to about n/2 for the bottom floor of a full tree).

Analogy

A building evacuation drill, floor by floor. The guard counts the people on floor 1 ("3 people") and sends exactly those 3 out; each one, as they leave, calls down the people on the floor below to join the end of the line. When the 3 are gone, the guard counts again for the next floor. The count is the size you freeze.

Why it works

"A queue is first-in-first-out, and children are always added behind the nodes already waiting, so nodes leave in order of their distance from the root. When a floor starts, the queue holds exactly that floor, so freezing size tells me where the floor ends. O(n) time, O(width) space."

The template to remember

Queue<TreeNode> q = new ArrayDeque<>();
if (root != null) q.offer(root);
while (!q.isEmpty()) {
    int size = q.size();                // freeze this floor
    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        // per-node work (i == 0 first, i == size - 1 last)
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
    // per-floor work
}
Remember

Level → queue → freeze size. First of floor: i == 0. Last of floor (right view): i == size − 1.

Common mistakes
  • Writing for (int i = 0; i < q.size(); i++) — the size changes while you add children, so floors get mixed. Save it in a variable first.
  • Right side view by following only right children — misses nodes like 7 above that stick out on the left side.
  • Zigzag by reversing the queue or swapping the child order — it breaks the next floor. Change only how the level list is filled.
  • Forgetting the empty tree: q.offer(null) then node.left → NullPointerException.
  • Using Stack or LinkedList.push by mistake — that is LIFO and turns BFS into DFS.

Test yourself

Why must size be read before the inner loop starts?

During the loop you add children to the same queue, so q.size() keeps changing. Reading it once at the start gives the exact number of nodes on the current floor.

What is the extra space of BFS on a perfect binary tree with 15 nodes?

O(width): the bottom floor has 8 nodes, which can all sit in the queue at once — about n/2, so O(n) in the worst case.

How do you get the left side view?

Same BFS, but record the node when i == 0 (the first node of each floor).

Minimum depth: why is BFS often faster than DFS?

BFS goes floor by floor, so it can stop at the first leaf it meets. DFS may explore a very deep branch before finding a shallow leaf elsewhere.
