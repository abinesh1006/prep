Tree BFS (level order)

Visit the tree one floor at a time, top to bottom, using a queue — and freeze the queue's size at the start of each floor so you know where the floor ends.

Time to learn: about 1.5 hours · Prerequisites: Tree traversals, Stack basics (queues)

When to use it — the signal

The problem says level, row, depth by depth, "right side view", "zigzag", "average of each level", "largest value in each row", "minimum depth" or "nearest". Anything about floors of the tree, or the closest node to the root, is BFS.

The idea in plain words

BFS = breadth-first search: go wide before going deep. Instead of diving down one path (that is DFS, the traversals lesson), you visit the root, then all nodes 1 step down, then all nodes 2 steps down, and so on.

The tool is a queue = first in, first out, like a line at a shop. Put the root in. Then repeat: take the node at the front, write it down, and add its children at the back. Because children always join behind everything already waiting, a whole floor leaves the queue before the next floor starts.

The one trick for "per level" problems: at the start of each floor, read size = q.size(). Right then the queue holds exactly the nodes of this floor (say 3). Take exactly 3 nodes out; the children they add are the next floor and wait for the next round.

  • Right side view = the last node of each floor (what you would see standing on the right).
  • Zigzag = same floors, but every second floor is written right-to-left.

Each node goes in and out of the queue once → O(n) time. The queue holds at most one floor plus part of the next → O(width) extra space (up to about n/2 for the bottom floor of a full tree).

Analogy

A building evacuation drill, floor by floor. The guard counts the people on floor 1 ("3 people") and sends exactly those 3 out; each one, as they leave, calls down the people on the floor below to join the end of the line. When the 3 are gone, the guard counts again for the next floor. The count is the size you freeze.

Watch it work

Blue = waiting in the queue, yellow = just taken out, green = written down.

2. Right side view: the last node of each floor

3. Zigzag: flip the direction every floor

The queue part is identical. Only the way we write each floor changes: left-to-right floors add at the back of the level list, right-to-left floors add at the front.

Why it works

"A queue is first-in-first-out, and children are always added behind the nodes already waiting, so nodes leave in order of their distance from the root. When a floor starts, the queue holds exactly that floor, so freezing size tells me where the floor ends. O(n) time, O(width) space."

The template to remember

Queue<TreeNode> q = new ArrayDeque<>();
if (root != null) q.offer(root);
while (!q.isEmpty()) {
    int size = q.size();                // freeze this floor
    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        // per-node work (i == 0 first, i == size - 1 last)
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
    // per-floor work
}
Remember

Level → queue → freeze size. First of floor: i == 0. Last of floor (right view): i == size − 1.

Common mistakes
  • Writing for (int i = 0; i < q.size(); i++) — the size changes while you add children, so floors get mixed. Save it in a variable first.
  • Right side view by following only right children — misses nodes like 7 above that stick out on the left side.
  • Zigzag by reversing the queue or swapping the child order — it breaks the next floor. Change only how the level list is filled.
  • Forgetting the empty tree: q.offer(null) then node.left → NullPointerException.
  • Using Stack or LinkedList.push by mistake — that is LIFO and turns BFS into DFS.

Practice in this order

  • Medium102. Binary Tree Level Order Traversal — animation 1, word for word.
    Show solution

    The idea

    Return the values floor by floor: [3,9,20,null,null,15,7] gives [[3],[9,20],[15,7]]. BFS (breadth-first search) visits nodes with a queue (first in, first out), so it naturally goes floor by floor. The trick: at the start of each floor, the queue's size is exactly how many nodes that floor has.

    Step by step

    1. Empty tree: return [].
    2. Put the root in a queue.
    3. While the queue is not empty, read size = q.size().
    4. Pop exactly size nodes, add their values to this floor's list, and push their children.
    5. Add the floor's list to the answer.

    Java

    class Solution {
    public List<List<Integer>> levelOrder(TreeNode root) {
        List<List<Integer>> out = new ArrayList<>();
        if (root == null) return out;
        Queue<TreeNode> q = new ArrayDeque<>();
        q.offer(root);
        while (!q.isEmpty()) {
            int size = q.size();     // nodes on this floor
            List<Integer> level = new ArrayList<>();
            for (int i = 0; i < size; i++) {
                TreeNode n = q.poll();
                level.add(n.val);
                if (n.left != null) q.offer(n.left);
                if (n.right != null) q.offer(n.right);
            }
            out.add(level);
        }
        return out;
    }
}

    Time O(n) · Space O(w) — each node enters and leaves the queue once; w is the widest floor.

    Dry run

    Queue [3] → floor [3], push 9, 20. Queue [9,20] → floor [9,20], push 15, 7. Queue [15,7] → floor [15,7].

    Watch out

    Read the size before the inner loop; q.size() grows as you push children, so using it in the loop condition mixes floors.

  • Easy637. Average of Levels in Binary Tree — sum each floor, divide by size.
    Show solution

    The idea

    For each floor of the tree, give the average of its values: [3,9,20,null,null,15,7] → [3, 14.5, 11]. Same floor-by-floor BFS as 102, but instead of collecting values, sum them and divide by the floor's size.

    Step by step

    1. Push the root into a queue.
    2. For each floor, read its size and set sum = 0.
    3. Pop that many nodes, adding each value to sum and pushing children.
    4. Append sum / size as a double.

    Java

    class Solution {
    public List<Double> averageOfLevels(TreeNode root) {
        List<Double> out = new ArrayList<>();
        Queue<TreeNode> q = new ArrayDeque<>();
        q.offer(root);
        while (!q.isEmpty()) {
            int size = q.size();
            long sum = 0; // long: big values add up
            for (int i = 0; i < size; i++) {
                TreeNode n = q.poll();
                sum += n.val;
                if (n.left != null) q.offer(n.left);
                if (n.right != null) q.offer(n.right);
            }
            out.add((double) sum / size);
        }
        return out;
    }
}

    Time O(n) · Space O(w) — one visit per node; the queue holds at most one floor plus the next.

    Dry run

    Floor [3] → 3/1 = 3. Floor [9,20] → 29/2 = 14.5. Floor [15,7] → 22/2 = 11.

    Watch out

    Values can be up to 2³¹−1, so two of them overflow an int sum. Use a long sum and divide as a double.

  • Easy111. Minimum Depth of Binary Tree — BFS; the first leaf you meet gives the answer.
    Show solution

    The idea

    Find the number of nodes on the shortest path from the root down to a leaf (a node with no children). [3,9,20,null,null,15,7] → 2 (3 → 9). BFS goes floor by floor, so the very first leaf it pops is the closest one; stop there.

    Brute force first

    A recursive DFS that takes min(left, right) + 1 also works, but it visits the whole tree and must handle one-child nodes carefully.

    Step by step

    1. Empty tree: 0.
    2. BFS with a queue, starting at depth 1.
    3. For each popped node, if it has no children, return the current depth.
    4. Otherwise push its children; after finishing the floor, add 1 to depth.

    Java

    class Solution {
    public int minDepth(TreeNode root) {
        if (root == null) return 0;
        Queue<TreeNode> q = new ArrayDeque<>();
        q.offer(root);
        int depth = 1;
        while (!q.isEmpty()) {
            int size = q.size();
            for (int i = 0; i < size; i++) {
                TreeNode n = q.poll();
                // the first leaf we meet is the shallowest
                if (n.left == null && n.right == null) {
                    return depth;
                }
                if (n.left != null) q.offer(n.left);
                if (n.right != null) q.offer(n.right);
            }
            depth++;                 // go down one floor
        }
        return depth;                // never reached
    }
}

    Time O(n) · Space O(w) — worst case visits every node; often stops early.

    Dry run

    Depth 1: node 3 has children. Depth 2: node 9 has none → return 2.

    Watch out

    A node with only one child is not a leaf. In the recursive version, min(left, right) would wrongly pick the empty side's 0; BFS avoids this because it only stops on real leaves.

  • Medium199. Binary Tree Right Side View — animation 2.
    Show solution

    The idea

    Stand on the right of the tree and list what you see, top to bottom: [1,2,3,null,5,null,4] → [1,3,4]. That is just the last node of every floor in BFS order.

    Step by step

    1. Empty tree: [].
    2. Floor-by-floor BFS as in 102.
    3. While popping the floor's nodes, when i == size - 1 (the last one), record its value.
    4. Push children left then right so the last popped is the rightmost.

    Java

    class Solution {
    public List<Integer> rightSideView(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        if (root == null) return out;
        Queue<TreeNode> q = new ArrayDeque<>();
        q.offer(root);
        while (!q.isEmpty()) {
            int size = q.size();
            for (int i = 0; i < size; i++) {
                TreeNode n = q.poll();
                if (i == size - 1) out.add(n.val); // last one
                if (n.left != null) q.offer(n.left);
                if (n.right != null) q.offer(n.right);
            }
        }
        return out;
    }
}

    Time O(n) · Space O(w) — each node once; the queue holds about one floor.

    Dry run

    Floor [1] → 1. Floor [2,3] → 3. Floor [5,4] → 4. Answer [1,3,4].

    Watch out

    The rightmost node of a floor may come from the left subtree (when the right side is shorter), as in [1,2,3,4] → [1,3,4]. Only looking at .right pointers misses it.

  • Medium103. Binary Tree Zigzag Level Order Traversal — animation 3.
    Show solution

    The idea

    Level order, but every other floor is read right to left: [3,9,20,null,null,15,7] → [[3],[20,9],[15,7]]. Keep the BFS exactly the same; only change where each value is written: at the end of the floor's list or at its front.

    Step by step

    1. Floor-by-floor BFS, with a flag leftToRight = true.
    2. For each floor, make an empty LinkedList.
    3. For each popped node: if the flag is true add the value at the end, else at the front. Push children as usual.
    4. Add the floor list to the answer and flip the flag.

    Java

    class Solution {
    public List<List<Integer>> zigzagLevelOrder(
            TreeNode root) {
        List<List<Integer>> out = new ArrayList<>();
        if (root == null) return out;
        Queue<TreeNode> q = new ArrayDeque<>();
        q.offer(root);
        boolean leftToRight = true;
        while (!q.isEmpty()) {
            int size = q.size();
            LinkedList<Integer> level = new LinkedList<>();
            for (int i = 0; i < size; i++) {
                TreeNode n = q.poll();
                // same BFS order; only where we write flips
                if (leftToRight) level.addLast(n.val);
                else level.addFirst(n.val);
                if (n.left != null) q.offer(n.left);
                if (n.right != null) q.offer(n.right);
            }
            out.add(level);
            leftToRight = !leftToRight;
        }
        return out;
    }
}

    Time O(n) · Space O(w) — adding at either end of a LinkedList is O(1).

    Dry run

    Floor [3] → [3]. Flag flips. Floor pops 9 then 20, each added at the front → [20,9]. Flip. Floor [15,7] → [15,7].

    Watch out

    Do not change the order in which you push children; that mixes up the next floor. Only the write position changes.

  • Medium662. Maximum Width of Binary Tree — queue of (node, position index); width = last − first + 1.
    Show solution

    The idea

    Width of a floor = distance between its leftmost and rightmost nodes, counting the gaps in between as if the tree were full. Number positions like a heap: the root is 0, a node at p has children 2p and 2p+1. Then each floor's width is last − first + 1.

    Step by step

    1. BFS with two queues side by side: nodes and their positions (as long).
    2. At the start of each floor, read the first and last positions; width = last − first + 1; keep the best.
    3. While popping, subtract the floor's first position from p so numbers restart near 0 every floor.
    4. Push the left child with 2p and the right child with 2p + 1.

    Java

    class Solution {
    public int widthOfBinaryTree(TreeNode root) {
        // queue of nodes and, alongside, their positions
        Deque<TreeNode> nodes = new ArrayDeque<>();
        Deque<Long> pos = new ArrayDeque<>();
        nodes.offer(root);
        pos.offer(0L);
        long best = 0;
        while (!nodes.isEmpty()) {
            int size = nodes.size();
            long first = pos.peekFirst();
            long last = pos.peekLast();
            best = Math.max(best, last - first + 1);
            for (int i = 0; i < size; i++) {
                TreeNode n = nodes.poll();
                // shift by first so numbers stay small
                long p = pos.poll() - first;
                if (n.left != null) {
                    nodes.offer(n.left);
                    pos.offer(2 * p);
                }
                if (n.right != null) {
                    nodes.offer(n.right);
                    pos.offer(2 * p + 1);
                }
            }
        }
        return (int) best;
    }
}

    Time O(n) · Space O(w) — each node once.

    Dry run

    [1,3,2,5,3,null,9]: floor 0 → positions {0}, width 1. Floor 1 → {0,1}, width 2. Floor 2 → 5 at 0, 3 at 1, 9 at 3 → width 3 − 0 + 1 = 4.

    Watch out

    Positions double every floor, so on a deep tree they overflow even a long. Subtracting the floor's first position each time keeps them small.

Test yourself

Why must size be read before the inner loop starts?

During the loop you add children to the same queue, so q.size() keeps changing. Reading it once at the start gives the exact number of nodes on the current floor.

What is the extra space of BFS on a perfect binary tree with 15 nodes?

O(width): the bottom floor has 8 nodes, which can all sit in the queue at once — about n/2, so O(n) in the worst case.

How do you get the left side view?

Same BFS, but record the node when i == 0 (the first node of each floor).

Minimum depth: why is BFS often faster than DFS?

BFS goes floor by floor, so it can stop at the first leaf it meets. DFS may explore a very deep branch before finding a shallow leaf elsewhere.
