Pattern 46 · Dynamic programming

0/1 Knapsack

For each item, decide take it or leave it, for every possible bag size — and when you squeeze the table into one row, loop the capacity backwards.

Time to learn: about 3 hours · Prerequisites: DP intro, Coin change

When to use it — the signal

A list of items, each usable at most once, and a limit (weight, budget, target sum): "maximum value within capacity", "can you pick a subset that sums to exactly T", "partition into two equal halves", "number of ways to assign + and − to reach target". If items may be reused, it is coin change (unbounded) instead.

The idea in plain words

A bag holds 4 kg. Items: 1 kg worth 15, 3 kg worth 20, 4 kg worth 30. Greedy by value takes the 4 kg item (30), but 1 kg + 3 kg gives 35.

Let dp[i][c] = the best value using only the first i items with a bag of size c. For item i (weight w, value v) there are only two choices:

  • Leave it: dp[i−1][c] — the best without it, same bag.
  • Take it (only if w ≤ c): v + dp[i−1][c−w] — its value plus the best of the earlier items in the space left over.

Both read from row i−1, the row above. So we only ever need one previous row — and we can even overwrite a single row in place. The catch: dp[c−w] must still hold the old (row i−1) value when we use it. If we loop c upwards, dp[c−w] was already updated for this item, so the item gets used twice. Looping c downwards reads only cells not yet touched in this round.

Partition Equal Subset Sum is the same with true/false: can some subset add up to exactly half of the total?

Analogy

Packing a suitcase for a trip, item by item from a pile: for each item you ask "is my best packing better with this in, or without it?" — and to answer "with it", you look at the best packing of the earlier items in a smaller suitcase. You cannot pack the same jacket twice.

Watch it work

1. The 2D table

Rows = how many items are allowed, columns = bag size. Blue = the cells this one reads; green = the choice that won.

2. One row: why capacity must loop backwards

Keep a single row dp[c] and update it item by item. Watch the first item only (1 kg, $15), which we may take once. First the wrong way (forwards), then the right way (backwards).

3. Partition Equal Subset Sum

[1, 2, 3, 4] adds up to 10. Can we split it into two groups of 5? That is: is there a subset with sum 5? dp[s] = true if some of the numbers seen so far add up to exactly s. Same backwards loop, with OR instead of max.

Why it works

"For each item the best answer either excludes it — the previous row — or includes it once — its value plus the previous row at the reduced capacity. Both only look at the previous row, so one array updated from high capacity to low keeps the previous-row values readable, which enforces 'at most once'."

The template to remember

int[] dp = new int[C + 1];
for (int i = 0; i < n; i++)
    for (int c = C; c >= w[i]; c--)                 // BACKWARDS = each item once
        dp[c] = Math.max(dp[c], v[i] + dp[c - w[i]]);
// subset sum: boolean dp, dp[0] = true, dp[s] |= dp[s - x]
Remember

Take it or leave it. One row → capacity backwards. Forwards = unlimited copies (coin change).

Common mistakes
  • Looping capacity forwards in the 1D version — silently turns 0/1 into unbounded.
  • Partition: forgetting the odd-total check, or using the full total as the target instead of half.
  • Target Sum (+/−): convert to subset sum (sum of the + group = (total + target) / 2) and check that it is a whole, non-negative number.
  • Using the 2D table when only the value is needed — fine, but say you could go to O(C) memory.

Practice in this order

  • Medium416. Partition Equal Subset Sum — the third animation.
    Show solution

    The idea

    Can the array be split into two groups with equal sums? Both groups must sum to total / 2, so the question is: is there a subset that sums to half? [1,5,11,5] → total 22, half 11 = 11 or 1+5+5 → true. Pattern: 0/1 knapsack, subset sum with a 1-D boolean table.

    Brute force first

    Try all 2n subsets: impossible for n = 200.

    Step by step

    1. Sum everything; an odd total means false.
    2. can[0] = true, half = total / 2.
    3. For each number x, for s from half down to x: if can[s-x], set can[s].
    4. Return can[half].

    Java

    class Solution {
    public boolean canPartition(int[] nums) {
        int sum = 0;
        for (int x : nums) sum += x;
        if (sum % 2 == 1) return false; // odd: can't halve
        int half = sum / 2;
        // can[s] = some subset of the items so far sums to s
        boolean[] can = new boolean[half + 1];
        can[0] = true; // the empty subset
        for (int x : nums) {
            // backwards so each item is used at most once
            for (int s = half; s >= x; s--) {
                if (can[s - x]) can[s] = true;
            }
        }
        return can[half];
    }
}

    Time O(n · half) · Space O(half) — each number sweeps the sums once.

    Dry run

    [1,5,11,5], half 11. After 1: {0,1}. After 5: {0,1,5,6}. After 11: adds 11 → true already. (After the last 5 also 10, 11.)

    Watch out

    The inner loop must go backwards. Going up lets the same x be used twice in one pass (1 → 2 → 3…), which turns it into unbounded knapsack.

  • Medium494. Target Sum — count subsets with a given sum.
    Show solution

    The idea

    Put + or − in front of each number so the total equals target; count the ways. Call P the numbers with + and N the ones with −. Then P − N = target and P + N = sum, so P = (sum + target) / 2. The question becomes: how many subsets sum to that P? [1,1,1,1,1], target 3 → P = 4 → choose which 4 ones → 5. Pattern: 0/1 knapsack, count subsets.

    Brute force first

    Try + and − for every number: O(2n), fine for n = 20 but the DP is the expected answer.

    Step by step

    1. t = sum + target. If t < 0 or t is odd, return 0.
    2. P = t / 2. ways[0] = 1.
    3. For each x, for s from P down to x: ways[s] += ways[s-x].
    4. Return ways[P].

    Java

    class Solution {
    public int findTargetSumWays(int[] nums, int target) {
        int sum = 0;
        for (int x : nums) sum += x;
        // P = numbers with +, N = with -.
        // P - N = target and P + N = sum
        // so P = (sum + target) / 2
        int t = sum + target;
        if (t < 0 || t % 2 == 1) return 0;
        int p = t / 2;
        // ways[s] = number of subsets that sum to s
        int[] ways = new int[p + 1];
        ways[0] = 1;
        for (int x : nums) {
            for (int s = p; s >= x; s--) { // 0/1: backwards
                ways[s] += ways[s - x];
            }
        }
        return ways[p];
    }
}

    Time O(n · P) · Space O(P) — a 1-D table of sums.

    Dry run

    [1,2], target −1: sum 3, t = 2, P = 1. ways after 1: [1,1]; after 2: unchanged. Answer 1: the subset {1} gets +, so +1 − 2 = −1.

    Watch out

    Check t < 0 (target can be very negative) and odd t before dividing. Zeros double the count (+0 and −0); the loop s >= x with x = 0 handles that by itself.

  • Medium1049. Last Stone Weight II — closest subset sum to half.
    Show solution

    The idea

    Smashing stones x and y leaves |x − y|. Whatever order you smash in, the result is the same as splitting the stones into two piles and subtracting one pile's sum from the other's. To make that difference small, make one pile as close to sum / 2 as possible. Pattern: 0/1 knapsack, closest subset sum.

    Step by step

    1. sum = total weight, half = sum / 2.
    2. Subset-sum table can[] up to half (backwards loop).
    3. Find the largest s ≤ half with can[s].
    4. Return sum − 2s.

    Java

    class Solution {
    public int lastStoneWeightII(int[] stones) {
        int sum = 0;
        for (int x : stones) sum += x;
        int half = sum / 2;
        // smashing = splitting stones into two piles A, B;
        // what is left is |A - B|. Make A close to sum / 2.
        boolean[] can = new boolean[half + 1];
        can[0] = true;
        for (int x : stones) {
            for (int s = half; s >= x; s--) {
                if (can[s - x]) can[s] = true;
            }
        }
        for (int s = half; s >= 0; s--) {
            if (can[s]) return sum - 2 * s;  // B - A
        }
        return sum;  // not reached: can[0] is true
    }
}

    Time O(n · sum) · Space O(sum) — sum ≤ 30 × 100 = 3000.

    Dry run

    [2,7,4,1,8,1]: sum 23, half 11. Reachable 11 (2+8+1)? yes → 23 − 22 = 1.

    Watch out

    Simulating with a heap (smash the two biggest) is Last Stone Weight I and gives the wrong answer here.

  • Medium474. Ones and Zeroes — two capacities, both loops backwards.
    Show solution

    The idea

    Choose as many binary strings as possible using at most m zeros and n ones in total. Each string is an item with two "weights" (its zeros and ones) and value 1. dp[z][o] = most strings that fit in z zeros and o ones. Pattern: 0/1 knapsack with two capacities.

    Step by step

    1. dp is (m+1)×(n+1), all 0.
    2. For each string, count its zeros and ones.
    3. For z from m down to zeros, for o from n down to ones: dp[z][o] = max(dp[z][o], dp[z-zeros][o-ones] + 1).
    4. Return dp[m][n].

    Java

    class Solution {
    public int findMaxForm(String[] strs, int m, int n) {
        // dp[z][o] = most strings fitting in z zeros, o ones
        int[][] dp = new int[m + 1][n + 1];
        for (String s : strs) {
            int zeros = 0, ones = 0;
            for (char c : s.toCharArray()) {
                if (c == '0') zeros++; else ones++;
            }
            // both capacities backwards: use s at most once
            for (int z = m; z >= zeros; z--) {
                for (int o = n; o >= ones; o--) {
                    dp[z][o] = Math.max(dp[z][o],
                            dp[z - zeros][o - ones] + 1);
                }
            }
        }
        return dp[m][n];
    }
}

    Time O(L · m · n + total length) · Space O(m · n) — L strings, each sweeps the 2-D table once.

    Dry run

    ["10","0","1"], m = 1, n = 1: "10" → dp[1][1] = 1. "0" → dp[1][0] = 1, dp[1][1] stays 1. "1" → dp[1][1] = dp[1][0] + 1 = 2.

    Watch out

    Both loops go backwards so each string is used at most once. Forgetting one of them lets a string count twice.

  • Hard879. Profitable Schemes — knapsack with a count and a cap on profit.
    Show solution

    The idea

    Crimes need group[k] members and earn profit[k]; count crime sets that use at most n members and earn at least minProfit. dp[m][p] = sets using at most m members with profit p, where every profit ≥ minProfit is stored in the single cell p = minProfit (the "cap"). Pattern: 0/1 knapsack counting with a capped dimension.

    Step by step

    1. dp[m][0] = 1 for all m (choose nothing).
    2. For each crime (g, pr), for m from n down to g, for p from minProfit down to 0:
    3. dp[m][p] += dp[m-g][max(0, p-pr)] (mod 109+7).
    4. Return dp[n][minProfit].

    Java

    class Solution {
    public int profitableSchemes(int n, int minProfit,
                                 int[] group, int[] profit) {
        final int MOD = 1_000_000_007;
        // dp[m][p] = schemes using at most m members with
        // profit p, where p is capped at minProfit
        // ("minProfit or more" all share one cell)
        int[][] dp = new int[n + 1][minProfit + 1];
        // empty scheme: profit 0, fits any member count
        for (int m = 0; m <= n; m++) dp[m][0] = 1;
        for (int k = 0; k < group.length; k++) {
            int g = group[k], pr = profit[k];
            for (int m = n; m >= g; m--) {         // 0/1
                for (int p = minProfit; p >= 0; p--) {
                    int from = Math.max(0, p - pr);
                    dp[m][p] = (dp[m][p]
                            + dp[m - g][from]) % MOD;
                }
            }
        }
        return dp[n][minProfit];
    }
}

    Time O(C · n · minProfit) · Space O(n · minProfit) — C crimes, each sweeps the table once.

    Dry run

    n 5, minProfit 3, crimes (2,2), (2,3). Sets: {crime 1} profit 3, {both} profit 5 uses 4 members. {crime 0} alone has 2 < 3. Answer 2.

    Watch out

    max(0, p - pr) is the cap: a crime that alone exceeds what is still needed comes from the profit-0 row. Take the modulo after every addition.

Test yourself

In the 1D version, what goes wrong if c loops upwards?

dp[c − w] may already include the current item, so the item can be counted more than once — you get the unbounded knapsack answer.

[1, 5, 11, 5] — can it be partitioned?

Total 22, target 11: {11} and {1, 5, 5}. Yes.

Why does the 2D version not care about the loop direction?

It reads row i − 1 and writes row i, so reading never sees a value written for the same item.
