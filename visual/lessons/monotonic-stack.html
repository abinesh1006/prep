Monotonic Stack

A stack that is always sorted: when a new number breaks the order, the numbers it pops have just found their "next greater" (or "next smaller") element — in one pass.

Time to learn: about 2–3 hours · Prerequisites: Stacks and queues, Big-O

When to use it — the signal

"Next greater / next smaller element", "how many days until a warmer day", "previous smaller", "stock span", "nearest taller building", "largest rectangle", "sum of minimums of all subarrays". Any time each element wants the nearest element that beats it.

The idea in plain words

Temperatures for 8 days: 73 74 75 71 69 72 76 73. For each day: how many days until a warmer one? The slow way looks forward from every day — about n²/2 checks.

The smart way: walk the days once and keep a stack of days that are still waiting for a warmer day. Because a waiting day would already have been answered by any warmer day after it, the waiting temperatures are always falling from bottom to top. That "always sorted" property is what monotonic means (monotonic = only going one direction).

  • A new day arrives. While it is warmer than the day on top, that top day has found its answer: pop it and write the distance.
  • Then the new day itself starts waiting: push it.

Each day is pushed once and popped at most once, so the whole thing is O(n) even though there is a loop inside a loop.

Flip the comparison for "next smaller". Store indices, not values, so you can compute distances and widths.

Analogy

People stand in a line looking to the right, waiting to see someone taller. A short person standing behind a taller one is hidden, so the people still waiting always get taller as you go back. When a very tall person arrives, everyone shorter in front of them suddenly sees "the next taller person" and leaves the line — tallest-so-far stays.

Watch it work

Largest Rectangle in Histogram

Bars [2, 1, 5, 6, 2, 3], each 1 wide. Biggest rectangle? For every bar ask: how far left and right can it stretch before hitting a shorter bar? Keep a stack of indices with rising heights. When a shorter bar arrives, the popped bar's right wall is the current index and its left wall is the new top.

Why it works

"The stack only holds elements that have not found their next greater element yet, and they are in decreasing order. A new element pops exactly those it beats — it is the first greater element for each of them, because anything earlier would have popped them already. Every index is pushed and popped once, so it is O(n)."

The template to remember

// Next greater element to the right (store indices)
int[] ans = new int[n]; Arrays.fill(ans, -1);
Deque<Integer> st = new ArrayDeque<>();
for (int i = 0; i < n; i++) {
    while (!st.isEmpty() && a[i] > a[st.peek()])
        ans[st.pop()] = a[i];        // i answers everyone it beats
    st.push(i);                      // i waits for its own answer
}
// next SMALLER: flip > to <.  previous greater: the top after pushing
Remember

"Next greater" → decreasing stack, "next smaller" → increasing stack. Pop = that element just found its answer. Store indices, not values.

Common mistakes
  • Storing values instead of indices — then you cannot compute "days until" or rectangle widths.
  • Using if instead of while: one new element can answer many waiting ones.
  • Forgetting the leftovers: elements still on the stack at the end have no answer (0 or −1).
  • Histogram: forgetting the height-0 sentinel at the end, so bars still on the stack are never measured.
  • Width off by one: it is i − left − 1, with left = −1 when the stack is empty.
  • Circular arrays (LC 503): loop to 2n and use i % n.

Test yourself

For "next greater element", are the values on the stack increasing or decreasing from bottom to top?

Decreasing. A bigger value would have popped the smaller ones below it.

There is a while inside a for. Why is it still O(n)?

Each index is pushed once and popped at most once, so the total work of all the while-loops together is at most n pops.

Next greater element of each item in [2, 7, 3, 5, 4, 6, 8]?

[7, 8, 5, 6, 6, 8, −1].

In the histogram, when bar j is popped by index i, why is the new stack top its left wall?

The stack rises, so the element under j is the nearest bar to the left that is shorter than j — j can stretch left until just after it.
