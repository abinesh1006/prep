Quick Sort and Quickselect

Pick one number as the pivot, move everything smaller to its left and everything bigger to its right — the pivot is now in its final place. Repeat on both sides to sort, or on one side only to find the k-th largest.

Time to learn: about 2 hours · Prerequisites: Merge sort, Two pointers

When to use it — the signal

"K-th largest / k-th smallest", "median of an unsorted array", "top k" when the order inside the top k does not matter, "sort in place". Also any "move all X to one side" question (Sort Colors, move zeroes) — that is a partition.

The idea in plain words

Partition is the heart of it. Take [7, 2, 1, 6, 8, 5, 3, 4] and choose the last number, 4, as the pivot (the number we compare everything against).

  • Walk through the other numbers with a reader j. Keep a marker i = "the next slot for a small number".
  • When nums[j] < 4, swap it into slot i and move i one right. Big numbers are simply skipped.
  • At the end, swap the pivot into slot i. Now: [2, 1, 3, 4, 8, 5, 7, 6] — everything left of 4 is smaller, everything right is bigger. 4 is exactly where it belongs in the sorted array.

Quick sort partitions, then sorts the left part and the right part the same way. On average each pivot splits the array roughly in half: O(n log n). If the pivot is always the smallest or largest (e.g. an already sorted array), it degrades to O(n²) — so pick a random pivot.

Quickselect: to find the 2nd largest of 6 numbers, we only need the number that would sit at index 4 after sorting. After a partition we know the pivot's final index p. If p = 4, done. If p < 4, the answer is on the right — ignore the left completely. Only one side is followed, so on average n + n/2 + n/4 + … ≈ 2n work: O(n).

Analogy

A teacher lines up a class by height. She picks one student and says "shorter than Asha to my left, taller to my right." Asha is now standing exactly where she would be in the final line. To find the 3rd tallest, the teacher only needs to keep sorting the group that contains that position — the other group can stay messy.

Why it works

"After a partition the pivot is in its final sorted position, with smaller items left and larger right. Quick sort recurses into both sides (average O(n log n)); quickselect recurses into the one side that contains index n − k, so on average the work is n + n/2 + n/4 … = O(n)."

The template to remember

int partition(int[] a, int lo, int hi) {
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) swap(a, i++, j);
    swap(a, i, hi);
    return i;
}
// sort: recurse both sides. select: follow the side holding target.
Remember

Partition = pivot lands home. Both sides → quick sort O(n log n). One side → quickselect O(n). Random pivot dodges O(n²).

Common mistakes
  • Forgetting the final swap(a, i, hi) — the pivot never moves into place.
  • Using a fixed pivot on sorted input (or a test designed against you) → O(n²). Shuffle or pick a random index and swap it to hi.
  • Kth largest is index n - k, not k - 1.
  • Many equal values make Lomuto slow; a three-way partition (Sort Colors style) fixes that.
  • Quick sort is not stable. If stability matters, use merge sort.

Test yourself

After one partition, what do you know for certain?

The pivot is in its final sorted index; everything left is smaller, everything right is greater or equal. Nothing about the order inside each side.

When is quick sort O(n²)?

When every pivot is the smallest or largest of its range, e.g. last-element pivot on an already sorted array. Each partition then removes only one element.

Quickselect or heap for "k-th largest"?

Quickselect: average O(n), O(1) space, but it rearranges the array. Heap of size k: O(n log k), works on a stream. Mention both.
