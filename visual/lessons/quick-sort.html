Quick Sort and Quickselect

Pick one number as the pivot, move everything smaller to its left and everything bigger to its right — the pivot is now in its final place. Repeat on both sides to sort, or on one side only to find the k-th largest.

Time to learn: about 2 hours · Prerequisites: Merge sort, Two pointers

When to use it — the signal

"K-th largest / k-th smallest", "median of an unsorted array", "top k" when the order inside the top k does not matter, "sort in place". Also any "move all X to one side" question (Sort Colors, move zeroes) — that is a partition.

The idea in plain words

Partition is the heart of it. Take [7, 2, 1, 6, 8, 5, 3, 4] and choose the last number, 4, as the pivot (the number we compare everything against).

  • Walk through the other numbers with a reader j. Keep a marker i = "the next slot for a small number".
  • When nums[j] < 4, swap it into slot i and move i one right. Big numbers are simply skipped.
  • At the end, swap the pivot into slot i. Now: [2, 1, 3, 4, 8, 5, 7, 6] — everything left of 4 is smaller, everything right is bigger. 4 is exactly where it belongs in the sorted array.

Quick sort partitions, then sorts the left part and the right part the same way. On average each pivot splits the array roughly in half: O(n log n). If the pivot is always the smallest or largest (e.g. an already sorted array), it degrades to O(n²) — so pick a random pivot.

Quickselect: to find the 2nd largest of 6 numbers, we only need the number that would sit at index 4 after sorting. After a partition we know the pivot's final index p. If p = 4, done. If p < 4, the answer is on the right — ignore the left completely. Only one side is followed, so on average n + n/2 + n/4 + … ≈ 2n work: O(n).

Analogy

A teacher lines up a class by height. She picks one student and says "shorter than Asha to my left, taller to my right." Asha is now standing exactly where she would be in the final line. To find the 3rd tallest, the teacher only needs to keep sorting the group that contains that position — the other group can stay messy.

Why it works

"After a partition the pivot is in its final sorted position, with smaller items left and larger right. Quick sort recurses into both sides (average O(n log n)); quickselect recurses into the one side that contains index n − k, so on average the work is n + n/2 + n/4 … = O(n)."

The template to remember

int partition(int[] a, int lo, int hi) {
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) swap(a, i++, j);
    swap(a, i, hi);
    return i;
}
// sort: recurse both sides. select: follow the side holding target.
Remember

Partition = pivot lands home. Both sides → quick sort O(n log n). One side → quickselect O(n). Random pivot dodges O(n²).

Common mistakes
  • Forgetting the final swap(a, i, hi) — the pivot never moves into place.
  • Using a fixed pivot on sorted input (or a test designed against you) → O(n²). Shuffle or pick a random index and swap it to hi.
  • Kth largest is index n - k, not k - 1.
  • Many equal values make Lomuto slow; a three-way partition (Sort Colors style) fixes that.
  • Quick sort is not stable. If stability matters, use merge sort.

Practice in this order

  • Easy283. Move Zeroes — a partition with "non-zero" as the test.
    Show solution

    The idea

    Move every 0 to the end while the other numbers keep their order, in place. This is a partition, like the one in quick sort, with the test "is it non-zero?". A slow pointer w marks where the next non-zero should go; a fast pointer scans. Each non-zero is swapped down to w, so the zeros drift to the back.

    Brute force first

    Copy the non-zeros into a new array, then fill the rest with zeros. O(n) time but O(n) extra space, and the problem asks for in place.

    Step by step

    1. Set w = 0.
    2. Scan i from 0 to n − 1.
    3. If nums[i] != 0, swap nums[i] with nums[w] and do w++.
    4. At the end, [0, w) holds the non-zeros in order and the rest are zeros.

    Java

    class Solution {
    public void moveZeroes(int[] nums) {
        int w = 0; // next slot for a non-zero
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != 0) {
                int t = nums[i];
                nums[i] = nums[w];
                nums[w] = t;
                w++;
            }
        }
    }
}

    Time O(n) · Space O(1) — one pass, swaps in place.

    Dry run

    [0,1,0,3,12]
i=1 (1):  swap with w=0 -> [1,0,0,3,12] w=1
i=3 (3):  swap with w=1 -> [1,3,0,0,12] w=2
i=4 (12): swap with w=2 -> [1,3,12,0,0] w=3

    Watch out

    Quick sort's partition is not stable, but this one is, because w only ever points at a zero (or at i itself), so non-zeros are never jumped over each other.

  • Medium75. Sort Colors — three-way partition (0s, 1s, 2s).
    Show solution

    The idea

    Sort an array of 0s, 1s and 2s in one pass and in place. This is the three-way partition (the "Dutch national flag"): keep three zones, 0s on the left, 2s on the right, 1s in the middle, and an unknown zone being scanned. lo is where the next 0 goes, hi is where the next 2 goes, i scans.

    Brute force first

    Count the 0s, 1s and 2s, then write them back. Two passes, O(n); fine, but the follow-up asks for one pass.

    Step by step

    1. lo = 0, i = 0, hi = n - 1.
    2. While i <= hi:
    3. If nums[i] == 0, swap it with nums[lo], then lo++ and i++.
    4. If nums[i] == 1, it is already in the middle zone: i++.
    5. If nums[i] == 2, swap it with nums[hi] and hi--; do not move i, the swapped-in number is still unchecked.

    Java

    class Solution {
    public void sortColors(int[] nums) {
        int lo = 0, i = 0, hi = nums.length - 1;
        while (i <= hi) {
            if (nums[i] == 0) swap(nums, lo++, i++);
            else if (nums[i] == 1) i++;
            else swap(nums, i, hi--); // recheck nums[i]
        }
    }

    private void swap(int[] a, int x, int y) {
        int t = a[x]; a[x] = a[y]; a[y] = t;
    }
}

    Time O(n) · Space O(1) — every step grows a finished zone by one.

    Dry run

    [2,0,2,1,1,0]   lo=0 i=0 hi=5
2 -> swap i,hi  [0,0,2,1,1,2] hi=4
0 -> swap lo,i  lo=1 i=1;  0 -> lo=2 i=2
2 -> swap i,hi  [0,0,1,1,2,2] hi=3
1 -> i=3;  1 -> i=4 > hi, stop

    Watch out

    After swapping with hi, keep i where it is: the number that came from the right has not been looked at yet. Swapping with lo can move i, because everything behind i is already a 0 or 1.

  • Medium912. Sort an Array — quick sort with a random pivot.
    Show solution

    The idea

    Quick sort: pick a pivot, partition the range into "less than pivot", "equal to pivot" and "greater than pivot", then sort the less and greater parts the same way. A random pivot makes the bad O(n²) case (always picking the smallest item) almost impossible, and the three-way split handles arrays full of equal numbers.

    Brute force first

    Insertion sort is O(n²). A quick sort that always uses the first item as pivot is also O(n²) on sorted input and times out.

    Step by step

    1. sort(lo, hi): if the range has fewer than 2 items, return.
    2. Pick a random index in [lo, hi]; its value is the pivot p.
    3. Three-way partition (like Sort Colors): lt = next slot for "< p", gt = next slot for "> p", i scans.
    4. Now [lo, lt) < p, [lt, gt] == p, (gt, hi] > p.
    5. Recurse on [lo, lt - 1] and [gt + 1, hi].

    Java

    class Solution {
    private final Random rnd = new Random();

    public int[] sortArray(int[] nums) {
        sort(nums, 0, nums.length - 1);
        return nums;
    }

    private void sort(int[] a, int lo, int hi) {
        if (lo >= hi) return;
        int p = a[lo + rnd.nextInt(hi - lo + 1)];
        int lt = lo, i = lo, gt = hi;
        while (i <= gt) {
            if (a[i] < p) swap(a, lt++, i++);
            else if (a[i] > p) swap(a, i, gt--);
            else i++; // equal to pivot: stays in the middle
        }
        sort(a, lo, lt - 1);  // the smaller numbers
        sort(a, gt + 1, hi);  // the bigger numbers
    }

    private void swap(int[] a, int x, int y) {
        int t = a[x]; a[x] = a[y]; a[y] = t;
    }
}

    Time O(n log n) expected, O(n²) only with extremely bad luck · Space O(log n) expected for the recursion.

    Dry run

    [5,1,1,2,0,0], pivot = 1 (random)
partition -> [0,0,1,1,2,5]  less=[0,0] equal=[1,1] more=[2,5]
sort less -> [0,0];  sort more -> [2,5]
result [0,0,1,1,2,5]

    Watch out

    A two-way partition with many equal values (e.g. 50,000 copies of 2) still goes quadratic; the three-way split puts all equals in the middle and never touches them again. Merge sort (see that lesson) is the guaranteed O(n log n) choice.

  • Medium215. Kth Largest Element in an Array — the second animation.
    Show solution

    The idea

    The k-th largest is the item that would sit at index n - k if the array were sorted. Quickselect partitions around a random pivot like quick sort, but then only continues into the one side that contains index n - k. On average the range halves each time, so the total work is about n + n/2 + n/4 + ... = 2n.

    Brute force first

    Sort and return nums[n - k]: O(n log n). A min-heap of size k is O(n log k) and is the other common answer.

    Step by step

    1. target = n - k; search the range [lo, hi] = [0, n - 1].
    2. Pick a random pivot and three-way partition the range: [lo, lt) smaller, [lt, gt] equal, (gt, hi] bigger.
    3. If target is inside [lt, gt], the pivot is the answer.
    4. If target < lt, keep only the left part (hi = lt - 1); otherwise keep only the right part (lo = gt + 1).
    5. Repeat.

    Java

    class Solution {
    private final Random rnd = new Random();

    public int findKthLargest(int[] nums, int k) {
        int target = nums.length - k; // index when sorted
        int lo = 0, hi = nums.length - 1;
        while (true) {
            int p = nums[lo + rnd.nextInt(hi - lo + 1)];
            int lt = lo, i = lo, gt = hi;
            while (i <= gt) {
                if (nums[i] < p) swap(nums, lt++, i++);
                else if (nums[i] > p) swap(nums, i, gt--);
                else i++;
            }
            if (target < lt) hi = lt - 1;      // go left
            else if (target > gt) lo = gt + 1; // go right
            else return p; // target sits among the pivots
        }
    }

    private void swap(int[] a, int x, int y) {
        int t = a[x]; a[x] = a[y]; a[y] = t;
    }
}

    Time O(n) average, O(n²) worst · Space O(1) — one side is dropped after each partition.

    Dry run

    nums = [3,2,1,5,6,4], k = 2 -> target index 4
pivot 3: [2,1,3,6,4,5] lt=2 gt=2, 4 > 2 -> lo=3
pivot 5: [..,4,5,6]    lt=4 gt=4, target 4 -> return 5

    Watch out

    Convert "k-th largest" to index n - k; off-by-one here is the usual bug. LeetCode has a test with many equal numbers that makes a two-way quickselect slow; the three-way partition fixes it.

  • Medium973. K Closest Points to Origin — quickselect on distance.
    Show solution

    The idea

    Return any k points closest to (0,0). Distance compares the same as squared distance x² + y², so no square root is needed. Use quickselect on the squared distance: arrange the points so the k closest are in the first k slots (in any order), then copy them out.

    Brute force first

    Sort all points by distance and take the first k: O(n log n). A max-heap of size k is O(n log k).

    Step by step

    1. Search [lo, hi] = [0, n - 1] for the split at index k.
    2. Pick a random pivot point, take its distance pd, and partition: points with distance < pd to the left (Lomuto style), then put the pivot right after them at index p.
    3. If p == k, stop: the first k slots hold the k closest. If p < k, the first p + 1 are settled, so continue on the right (lo = p + 1). If p > k, continue on the left (hi = p - 1).
    4. Return the first k points.

    Java

    class Solution {
    private final Random rnd = new Random();

    public int[][] kClosest(int[][] points, int k) {
        int lo = 0, hi = points.length - 1;
        while (lo < hi) {
            int p = partition(points, lo, hi);
            if (p == k) break;
            if (p < k) lo = p + 1; // need more on the left
            else hi = p - 1;
        }
        return Arrays.copyOfRange(points, 0, k);
    }

    // puts a random pivot at its final place, returns it
    private int partition(int[][] a, int lo, int hi) {
        swap(a, lo + rnd.nextInt(hi - lo + 1), hi);
        int pd = dist(a[hi]), w = lo;
        for (int i = lo; i < hi; i++)
            if (dist(a[i]) < pd) swap(a, i, w++);
        swap(a, w, hi); // pivot goes right after smaller
        return w;
    }

    private int dist(int[] p) {
        return p[0] * p[0] + p[1] * p[1];
    }

    private void swap(int[][] a, int x, int y) {
        int[] t = a[x]; a[x] = a[y]; a[y] = t;
    }
}

    Time O(n) average · Space O(1) besides the output — only one side is kept after each partition.

    Dry run

    points = [[3,3],[5,-1],[-2,4]], k = 2  (dists 18, 26, 20)
pivot [5,-1] (26): 18, 20 go left -> pivot lands at index 2
p = 2 == k -> stop, return [[3,3],[-2,4]]

    Watch out

    When p == k, everything left of index k is no farther than the pivot, so the first k are correct. Coordinates are at most 104, so x² + y² fits in int.

  • Medium324. Wiggle Sort II — find the median by quickselect first.
    Show solution

    The idea

    Reorder so that nums[0] < nums[1] > nums[2] < nums[3].... Split the numbers into a small half and a big half around the median: small ones go to even indexes (valleys), big ones to odd indexes (peaks). Find the median with quickselect, three-way partition around it, then fill both halves in reverse order so that copies of the median land as far apart as possible and never touch.

    Brute force first

    Sort a copy (O(n log n)), then fill even slots from the middle of the copy backwards and odd slots from the end backwards. Same filling as below, just with a full sort instead of quickselect.

    Step by step

    1. Copy the array; quickselect the copy for the median (index (n - 1) / 2).
    2. Three-way partition the copy around the median: smaller, then equal, then bigger. Now the first (n + 1) / 2 items are the small half and the median copies sit at its end and at the start of the big half.
    3. Even slots: nums[0], nums[2], ... take the small half from its last item backwards.
    4. Odd slots: nums[1], nums[3], ... take the big half from the last item backwards.

    Java

    class Solution {
    private final Random rnd = new Random();

    public void wiggleSort(int[] nums) {
        int n = nums.length;
        int[] c = nums.clone();
        int med = select(c, (n - 1) / 2);
        partition3(c, med); // small | median | big
        int s = (n + 1) / 2 - 1; // last of the small half
        int b = n - 1;           // last of the big half
        for (int i = 0; i < n; i++)
            nums[i] = (i % 2 == 0) ? c[s--] : c[b--];
    }

    // quickselect: value at index t if a were sorted
    private int select(int[] a, int t) {
        int lo = 0, hi = a.length - 1;
        while (true) {
            int p = a[lo + rnd.nextInt(hi - lo + 1)];
            int lt = lo, i = lo, gt = hi;
            while (i <= gt) {
                if (a[i] < p) swap(a, lt++, i++);
                else if (a[i] > p) swap(a, i, gt--);
                else i++;
            }
            if (t < lt) hi = lt - 1;
            else if (t > gt) lo = gt + 1;
            else return p;
        }
    }

    // smaller than m, then equal, then bigger
    private void partition3(int[] a, int m) {
        int lt = 0, i = 0, gt = a.length - 1;
        while (i <= gt) {
            if (a[i] < m) swap(a, lt++, i++);
            else if (a[i] > m) swap(a, i, gt--);
            else i++;
        }
    }

    private void swap(int[] a, int x, int y) {
        int t = a[x]; a[x] = a[y]; a[y] = t;
    }
}

    Time O(n) average · Space O(n) for the copy. The follow-up's O(1) space version partitions in place through "virtual indexes" (1 + 2·i) % (n | 1); same idea, harder to get right.

    Dry run

    nums = [1,5,1,1,6,4], n = 6, median (index 2) = 1
partitioned copy: [1,1,1 | 6,5,4]  (big half in any order)
even slots get 1,1,1 ; odd slots take 4,5,6 (from the end)
result [1,4,1,5,1,6], a valid wiggle

    Watch out

    Filling forwards ([1,4,1,5,1,6] style) fails when the median repeats, e.g. [4,5,5,6] gives 4,5,5,6 with two 5s side by side. Reversing both halves gives 5,6,4,5, which is valid.

Test yourself

After one partition, what do you know for certain?

The pivot is in its final sorted index; everything left is smaller, everything right is greater or equal. Nothing about the order inside each side.

When is quick sort O(n²)?

When every pivot is the smallest or largest of its range, e.g. last-element pivot on an already sorted array. Each partition then removes only one element.

Quickselect or heap for "k-th largest"?

Quickselect: average O(n), O(1) space, but it rearranges the array. Heap of size k: O(n log k), works on a stream. Mention both.
