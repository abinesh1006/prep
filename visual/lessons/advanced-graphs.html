Advanced Graphs

Four classic graph questions beyond plain BFS/DFS: can the nodes be split into two teams, which single edge would cut the network, how to use every ticket exactly once, and which groups of nodes can all reach each other.

Time to learn: about 4 hours · Prerequisites: Graph basics, BFS / DFS, Topological sort

When to use it — the signal

"Split into two groups so every edge goes between groups", "possible bipartition", "two colours" → bipartite check. "Critical connection", "edge whose removal disconnects the network", "bridge", "articulation point" → Tarjan. "Use every edge exactly once", "reconstruct itinerary", "valid arrangement of pairs" → Hierholzer (Euler path). "Groups where everyone can reach everyone" in a directed graph → strongly connected components.

The idea in plain words

  • Bipartite = the nodes can be painted with two colours so that every edge joins different colours. Paint the start A, its neighbours B, their neighbours A, and so on (BFS). If an edge ever joins two nodes of the same colour, it is impossible — this happens exactly when the graph has a cycle of odd length.
  • Bridge = an edge that, if removed, splits the graph. Run DFS and give each node a visit time disc. low[u] = the earliest visit time u (or anything below it in the DFS) can reach using one back edge. If a child v has low[v] > disc[u], v's whole subtree has no other way back up, so u–v is a bridge.
  • Euler path = a walk that uses every edge exactly once. Hierholzer: keep walking along unused edges; when you get stuck, the current city is the last unfinished part of the route, so add it to the front of the answer and back up. Stuck cities come out in reverse order.
  • Strongly connected component (SCC) = a largest group of nodes in a directed graph where each can reach every other. Kosaraju: (1) DFS and note the order nodes finish, (2) reverse every edge, (3) DFS again in reverse finish order — each DFS in step 3 paints exactly one SCC.
Analogy

Bipartite: seating guests at two tables so that no two people who dislike each other share a table. Bridge: the single bridge to an island — if it closes, the island is cut off, but a road inside a ring of roads can close and everyone still gets home. Hierholzer: a postman who must walk every street once — when he reaches a dead end, that dead end is where his day finishes.

Watch it work

1. Bipartite check — two colours with BFS

2. Tarjan bridges — Critical Connections (badge = disc / low)

3. Hierholzer — Reconstruct Itinerary

Tickets: JFK→SFO, JFK→ATL, SFO→ATL, ATL→JFK, ATL→SFO. Use every ticket once, start at JFK, and pick the alphabetically smaller city when there is a choice.

4. Strongly connected components — Kosaraju's two passes

Why it works

"BFS paints by distance from the start, so a same-colour edge means two paths of the same parity meet — an odd cycle." "A tree edge u–v is a bridge exactly when nothing in v's subtree has a back edge to u or above, which is low[v] > disc[u]." "Hierholzer: a city where we get stuck has used all its out-tickets, so it must come after everything still on the stack — prepending builds the route backwards correctly." "Kosaraju: the node that finishes last lies in a 'source' component; in the reversed graph that component has no way out, so one DFS paints exactly it."

The template to remember

// Bipartite: color[v] = -color[u]; same colour → false
// Bridges (Tarjan)
disc[u] = low[u] = timer++;
tree edge:  dfs(v); low[u] = min(low[u], low[v]); if (low[v] > disc[u]) bridge;
back edge:  low[u] = min(low[u], disc[v]);
// Euler path (Hierholzer)
while (stack not empty) { top has edge ? push(next) : route.addFirst(pop()); }
// SCC (Kosaraju): finish order → reverse edges → DFS in reverse finish order

Advanced graph algorithms are ordinary DFS or BFS plus one or two int arrays that record a fact per node — a colour, a discovery time, a state.

Remember

Two colours fail only on odd cycles. Bridge: low[child] > disc[parent]. Itinerary: walk until stuck, stuck city goes to the front. SCC: two DFS passes, the second on reversed edges.

Common mistakes
  • Bipartite: only starting BFS from node 0 — the graph may have several separate pieces. Loop over every uncoloured node.
  • Tarjan: skipping the parent by node when there are parallel edges — skip by edge index instead. Also using low[v] instead of disc[v] for a back edge.
  • Itinerary: greedily following the smallest ticket and appending — you can get stuck early with tickets left. Append when stuck, then reverse (or add to front).
  • Kosaraju: running pass 2 on the original graph — then components leak into each other.

Practice in this order

  • Medium785. Is Graph Bipartite? — animation 1.
    Show solution

    The idea

    A graph is bipartite if you can paint every node one of two colours so that every edge joins different colours. Paint any node colour 1. All its neighbours must be the other colour, their neighbours colour 1 again, and so on (a BFS). If an edge ever joins two nodes of the same colour, it is impossible. The graph may have several pieces, so start a BFS from every unpainted node. Pattern: two-colouring with BFS.

    Step by step

    1. color[] = 0 (unpainted) for all nodes.
    2. For each unpainted start node, paint it 1 and push it on the queue.
    3. Pop u. For each neighbour v: if v is unpainted, paint it -color[u] and push it.
    4. If v already has the same colour as u, return false.
    5. If every piece finishes without a clash, return true.

    Java

    class Solution {
    public boolean isBipartite(int[][] graph) {
        int n = graph.length;
        int[] color = new int[n]; // 0 = none, 1 / -1 = sides
        for (int start = 0; start < n; start++) {
            if (color[start] != 0) continue; // done already
            color[start] = 1;
            Deque<Integer> q = new ArrayDeque<>();
            q.offer(start);
            while (!q.isEmpty()) {
                int u = q.poll();
                for (int v : graph[u]) {
                    if (color[v] == 0) {
                        color[v] = -color[u]; // other side
                        q.offer(v);
                    } else if (color[v] == color[u]) {
                        return false; // same side: clash
                    }
                }
            }
        }
        return true;
    }
}

    Time O(V + E) · Space O(V) — each node and edge is looked at once (twice for undirected edges).

    Dry run

    [[1,3],[0,2],[1,3],[0,2]], a square 0-1-2-3. 0 = A, so 1 and 3 = B, so 2 = A. Every edge joins A and B, so the answer is true. In example 1, 0, 1 and 2 form a triangle: 0 = A, 1 = B, 2 = B, and the edge 1–2 clashes, so the answer is false.

    Watch out

    Do not BFS only from node 0. Unconnected pieces (like node 0 with no edges) would never be checked.

  • Medium886. Possible Bipartition — build the "dislike" graph, then two colours.
    Show solution

    The idea

    Split n people into two groups so that no two people who dislike each other end up together. Make each dislike pair an edge. Then the question is "is this graph bipartite?", the same two-colouring as problem 785. Pattern: build the graph + two-colouring.

    Step by step

    1. Build an adjacency list for nodes 1..n, adding each dislike in both directions.
    2. color[] = 0 for everyone.
    3. For each uncoloured person, BFS: give each neighbour the opposite colour.
    4. If a neighbour already has your colour, return false.
    5. Otherwise return true.

    Java

    class Solution {
    public boolean possibleBipartition(int n, int[][] dislikes) {
        List<List<Integer>> g = new ArrayList<>();
        for (int i = 0; i <= n; i++) g.add(new ArrayList<>());
        for (int[] d : dislikes) { // dislike goes both ways
            g.get(d[0]).add(d[1]);
            g.get(d[1]).add(d[0]);
        }
        int[] color = new int[n + 1];
        for (int start = 1; start <= n; start++) {
            if (color[start] != 0) continue;
            color[start] = 1;
            Deque<Integer> q = new ArrayDeque<>();
            q.offer(start);
            while (!q.isEmpty()) {
                int u = q.poll();
                for (int v : g.get(u)) {
                    if (color[v] == 0) {
                        color[v] = -color[u];
                        q.offer(v);
                    } else if (color[v] == color[u]) {
                        return false;
                    }
                }
            }
        }
        return true;
    }
}

    Time O(n + E) · Space O(n + E) — the adjacency list plus one BFS pass.

    Dry run

    n = 3, dislikes 1–2, 1–3, 2–3. 1 = A, so 2 = B and 3 = B, but 2 and 3 dislike each other and have the same colour. The answer is false.

    Watch out

    People are numbered from 1, so size the arrays n + 1. Dislikes are undirected, so add both directions.

  • Hard1192. Critical Connections in a Network — animation 2.
    Show solution

    The idea

    A bridge (a critical connection) is an edge whose removal splits the graph. Use Tarjan's DFS. disc[u] is the time a node is first reached, and low[u] is the earliest discovery time that u's subtree can reach using one back edge (an edge to an already-visited node that is not the parent). Edge u–v is a bridge exactly when low[v] > disc[u]: v's side has no way back to u or above. Pattern: Tarjan bridges.

    Brute force first

    Remove each edge and test whether the graph is still connected: O(E · (V + E)).

    Step by step

    1. Build the adjacency list. disc = −1 everywhere.
    2. dfs(u, parent): set disc[u] = low[u] = time++.
    3. For each neighbour v ≠ parent. If v is unvisited: dfs(v, u), then low[u] = min(low[u], low[v]), and if low[v] > disc[u], record [u, v].
    4. If v is already visited (a back edge): low[u] = min(low[u], disc[v]).

    Java

    class Solution {
    private List<List<Integer>> g;
    private int[] disc, low; // discovery time, lowest reach
    private int time = 0;
    private List<List<Integer>> bridges;

    public List<List<Integer>> criticalConnections(
            int n, List<List<Integer>> connections) {
        g = new ArrayList<>();
        for (int i = 0; i < n; i++) g.add(new ArrayList<>());
        for (List<Integer> c : connections) {
            g.get(c.get(0)).add(c.get(1));
            g.get(c.get(1)).add(c.get(0));
        }
        disc = new int[n];
        low = new int[n];
        Arrays.fill(disc, -1);
        bridges = new ArrayList<>();
        for (int i = 0; i < n; i++)
            if (disc[i] == -1) dfs(i, -1);
        return bridges;
    }

    private void dfs(int u, int parent) {
        disc[u] = low[u] = time++;
        for (int v : g.get(u)) {
            if (v == parent) continue; // don't go straight back
            if (disc[v] == -1) {
                dfs(v, u);
                low[u] = Math.min(low[u], low[v]);
                // v's subtree can't climb above v: bridge
                if (low[v] > disc[u]) bridges.add(List.of(u, v));
            } else {
                low[u] = Math.min(low[u], disc[v]); // back edge
            }
        }
    }
}

    Time O(V + E) · Space O(V + E) — one DFS.

    Dry run

    Edges 0-1, 1-2, 2-0, 1-3. DFS 0(0) → 1(1) → 2(2). 2 sees 0, so low[2] = 0, and low[1] = 0. Then 3(3) has no way back, so low[3] = 3 > disc[1] = 1, and [1,3] is a bridge.

    Watch out

    Skip only the edge straight back to the parent, not every visited node. The recursion can be 10⁵ deep. That passes on LeetCode, but on your own machine you may need a bigger stack or an iterative DFS.

  • Hard332. Reconstruct Itinerary — animation 3.
    Show solution

    The idea

    Use every ticket exactly once, starting at JFK, and if several routes work, return the alphabetically smallest. Using every edge once is an Euler path. Hierholzer's algorithm: from an airport, keep flying the smallest unused ticket. When you are stuck (no tickets left from here), put this airport at the front of the answer. A dead end that is reached too early gets placed at the end of the route, which fixes the order automatically.

    Brute force first

    Backtracking: try destinations in sorted order and undo when stuck. That works for 300 tickets, but Hierholzer is linear.

    Step by step

    1. Build a map from each airport to a min-heap of destinations.
    2. visit(a): while a has tickets, poll the smallest destination and visit it.
    3. After the loop, route.addFirst(a).
    4. Call visit("JFK") and return the route.

    Java

    class Solution {
    private final Map<String, PriorityQueue<String>> g =
        new HashMap<>();
    private final LinkedList<String> route = new LinkedList<>();

    public List<String> findItinerary(List<List<String>> tickets) {
        for (List<String> t : tickets) {
            g.computeIfAbsent(t.get(0), x -> new PriorityQueue<>())
             .offer(t.get(1)); // min-heap = smallest name first
        }
        visit("JFK");
        return route;
    }

    // Hierholzer: use up every ticket, add airport at the end
    private void visit(String airport) {
        PriorityQueue<String> next = g.get(airport);
        while (next != null && !next.isEmpty()) {
            visit(next.poll()); // each ticket used once
        }
        route.addFirst(airport); // stuck here: prepend
    }
}

    Time O(E log E) · Space O(E) — each ticket is pushed and polled from a heap once.

    Dry run

    JFK→KUL, JFK→NRT, NRT→JFK. visit JFK: the smallest is KUL, and KUL is stuck, so the route is [KUL]. Back at JFK the next is NRT, then NRT→JFK, and JFK is now stuck: [JFK, KUL]. Then NRT: [NRT, JFK, KUL]. Then the first JFK: [JFK, NRT, JFK, KUL].

    Watch out

    Greedily following the smallest name without the "add at the end" step fails on this example (JFK→KUL is a dead end). Poll the ticket, so that each one is used once.

  • Hard2097. Valid Arrangement of Pairs — Euler path; start where out − in = 1.
    Show solution

    The idea

    Order the pairs [a, b] so that each pair's end equals the next pair's start. Each pair is a directed edge a → b, and you need a path that uses every edge once: an Euler path. It must start at the node where out-degree − in-degree = 1. If there is no such node, every node is balanced and any node works. Then run Hierholzer's algorithm. Pattern: Euler path (Hierholzer).

    Step by step

    1. Build adjacency lists and degree[x] = out − in.
    2. start = the node with degree 1, or else pairs[0][0].
    3. Iterative Hierholzer: push start. While the stack is not empty, look at the top u. If u has an unused edge, take it and push its end. Otherwise pop u into the path.
    4. Reverse the path, so that the nodes are in travel order.
    5. Turn consecutive nodes into pairs.

    Java

    class Solution {
    public int[][] validArrangement(int[][] pairs) {
        Map<Integer, Deque<Integer>> g = new HashMap<>();
        Map<Integer, Integer> degree = new HashMap<>(); // out - in
        for (int[] p : pairs) {
            g.computeIfAbsent(p[0], x -> new ArrayDeque<>())
             .push(p[1]);
            degree.merge(p[0], 1, Integer::sum);
            degree.merge(p[1], -1, Integer::sum);
        }
        // start where out - in = 1, else anywhere
        int start = pairs[0][0];
        for (var e : degree.entrySet()) {
            if (e.getValue() == 1) {
                start = e.getKey();
                break;
            }
        }
        // iterative Hierholzer (recursion could be too deep)
        List<Integer> path = new ArrayList<>();
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(start);
        while (!stack.isEmpty()) {
            int u = stack.peek();
            Deque<Integer> out = g.get(u);
            if (out != null && !out.isEmpty()) {
                stack.push(out.pop()); // walk an unused edge
            } else {
                path.add(stack.pop()); // dead end: record it
            }
        }
        Collections.reverse(path); // nodes in travel order
        int[][] res = new int[pairs.length][];
        for (int i = 0; i + 1 < path.size(); i++) {
            res[i] = new int[]{path.get(i), path.get(i + 1)};
        }
        return res;
    }
}

    Time O(E) · Space O(E) — each edge is pushed and popped once.

    Dry run

    [[5,1],[4,5],[11,9],[9,4]]. Degrees: 11 has +1, so start there. Walk 11→9→4→5→1. The answer is [[11,9],[9,4],[4,5],[5,1]].

    Watch out

    n is up to 10⁵, so a recursive DFS can overflow the stack. The explicit stack avoids that. Starting at the wrong node strands some edges.

  • Hard753. Cracking the Safe — Euler circuit on a de Bruijn graph.
    Show solution

    The idea

    The safe checks the last n digits you type. Find the shortest string that contains every n-digit password (digits 0..k−1). Think of each (n−1)-digit string as a node. Typing digit d moves from node "x…" to "…d", and the edge you walk is one password. Covering every password once means using every edge once: an Euler circuit on this de Bruijn graph, giving length kⁿ + n − 1. A simple way to walk it: start with n zeros and always append the largest digit that makes a new password. A known result (the "prefer largest" rule) guarantees that this never gets stuck early. A Hierholzer DFS also works but recurses kⁿ deep.

    Brute force first

    Backtracking over all strings of length kⁿ + n − 1 until one covers every password. It works for small inputs but can be exponential.

    Step by step

    1. total = kⁿ. Start with sb = n zeros and add "00…0" to seen.
    2. While seen has fewer than total passwords: tail = the last n − 1 digits.
    3. Try d from k − 1 down to 0. The first tail + d not seen yet is added to seen, and d is appended.
    4. Return sb.

    Java

    class Solution {
    public String crackSafe(int n, int k) {
        int total = (int) Math.pow(k, n); // passwords to cover
        // start with n zeros: the password 00..0
        StringBuilder sb = new StringBuilder("0".repeat(n));
        Set<String> seen = new HashSet<>();
        seen.add(sb.toString());
        while (seen.size() < total) {
            // last n-1 digits = the node we stand on
            String tail = sb.substring(sb.length() - n + 1);
            // walk the unused edge with the largest digit
            for (int d = k - 1; d >= 0; d--) {
                String code = tail + d;
                if (seen.add(code)) {
                    sb.append(d);
                    break;
                }
            }
        }
        return sb.toString();
    }
}

    Time O(kⁿ · k · n) · Space O(kⁿ · n) — kⁿ ≤ 4096 passwords, each step tries up to k digits and builds n-length strings.

    Dry run

    n = 2, k = 2. Start "00". Tail "0": try 1, "01" is new, so "001". Tail "1": "11" is new, so "0011". Tail "1": "11" is seen, "10" is new, so "00110". All 4 passwords are in, length 5 = 2² + 1.

    Watch out

    n = 1 is the edge case: the tail is empty, and the answer is all k digits once (e.g. "0987654321"). The length must be exactly kⁿ + n − 1.

  • Medium802. Find Eventual Safe States — nodes not on any cycle (related to SCC thinking).
    Show solution

    The idea

    A node is safe if every path from it ends at a terminal node (a node with no outgoing edges). It is unsafe exactly when some path from it reaches a cycle. Use DFS with three colours: 0 = unvisited, 1 = on the current path (in progress), 2 = known safe. Meeting a 1 again means a cycle. Any node that reaches a cycle stays 1 forever, which marks it unsafe. Pattern: cycle detection with three-colour DFS. (Alternative: reverse the edges and run Kahn's topological sort from the terminal nodes.)

    Step by step

    1. state[] = 0 for all nodes.
    2. isSafe(u): if state[u] is not 0, return state[u] == 2.
    3. Set state[u] = 1, then check every neighbour. If any is not safe, return false and leave u at 1.
    4. If all neighbours are safe, set state[u] = 2 and return true.
    5. Collect, in order, every node i where isSafe(i) is true.

    Java

    class Solution {
    public List<Integer> eventualSafeNodes(int[][] graph) {
        int n = graph.length;
        // 0 = unvisited, 1 = on current path, 2 = safe
        int[] state = new int[n];
        List<Integer> res = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            if (isSafe(graph, i, state)) res.add(i);
        }
        return res;
    }

    private boolean isSafe(int[][] g, int u, int[] state) {
        if (state[u] != 0) return state[u] == 2;
        state[u] = 1; // on the path: seeing it again = cycle
        for (int v : g[u]) {
            if (!isSafe(g, v, state)) return false; // stays 1
        }
        state[u] = 2;
        return true;
    }
}

    Time O(V + E) · Space O(V) — each node's state is settled once.

    Dry run

    [[1,2],[2,3],[5],[0],[5],[],[]]. 0→1→3→0 is a cycle, so 0, 1 and 3 stay at 1 (unsafe). 2→5 is terminal, so 2 is safe, and so are 4, 5 and 6. The answer is [2,4,5,6].

    Watch out

    Do not reset state to 0 after a node fails. Leaving it at 1 is what remembers "unsafe" and keeps the run linear.

Test yourself

Is a tree always bipartite?

Yes — a tree has no cycles at all, so no odd cycles. Colour by depth: even depth A, odd depth B.

Why is an edge inside a cycle never a bridge?

If you remove it, the rest of the cycle still connects its two ends.

When does a directed graph have an Euler path?

All edges are in one connected piece, and every node has out-degree = in-degree, except at most one start (out − in = 1) and one end (in − out = 1).

How many SCCs does a DAG with n nodes have?

n — with no cycles, every node is its own component.
