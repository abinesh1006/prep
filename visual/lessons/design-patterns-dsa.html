Data-Structure Design

"Design a class with these methods, each in O(1) (or O(log n))" — solved by gluing two simple structures together so each covers the other's weak spot.

Time to learn: about 3 hours · Prerequisites: Arrays and hashing, Stack basics, LRU cache, Binary search

When to use it — the signal

The question starts with "Design a ..." or "Implement the class ..." and lists methods with a required speed: "getMin in O(1)", "insert, delete and getRandom in average O(1)", "get the value at a timestamp", "number of hits in the past 5 minutes", "evict the least frequently used".

The idea in plain words

Write down each method and the speed it needs. Then ask: which single structure makes each method fast?

  • Hash map: find / insert / delete by key in O(1) — but no order and no "random element".
  • Array list: random index in O(1), add/remove at the end in O(1) — but finding a value is O(n).
  • Stack / queue / deque: O(1) at the ends; great when old items expire in order (time windows).
  • Sorted list + binary search: "the last value at or before time t" in O(log n).
  • Doubly linked list: move or remove a known node in O(1) (LRU, LFU).

When no single structure covers all methods, combine two and keep them in sync in every method. Example: RandomizedSet = array (for random) + map from value to index (for finding). Removing from the middle of an array is slow, so move the last element into the hole and remove the end instead.

Analogy

A library: books stand on shelves in a row (the array — easy to grab "a random book"), and the catalogue says which shelf slot each book is in (the map — easy to find a specific one). When a book leaves, the librarian moves the last book into the empty slot and fixes one catalogue card, instead of shifting the whole shelf.

Watch it work

1. Min Stack (recap) — a second stack of "minimum so far"

2. Insert Delete GetRandom O(1) — array + map

3. Time-Based Key-Value Store — binary search on timestamps

Calls set("foo", v, t) arrive with increasing t, so each key's timestamps are already sorted. get("foo", t) = the value with the largest timestamp ≤ t.

4. Design Hit Counter — a queue of timestamps

Count hits in the past 300 seconds (5 minutes): a hit at time h counts at time t when h > t − 300.

LFU cache — the idea

LFU (Least Frequently Used) evicts the key that was used the fewest times; ties go to the least recently used among them. Both get and put must be O(1).

  • vals: key → value, and freq: key → how many times it was used.
  • buckets: frequency → a LinkedHashSet of keys with that frequency, in the order they were last used (oldest first). This is a small LRU list per frequency.
  • minFreq: the smallest frequency that has any keys.
  • On every use of a key with frequency f: move it from bucket f to bucket f + 1. If bucket f became empty and f was minFreq, then minFreq = f + 1.
  • On put of a new key when full: evict the first key of buckets[minFreq], then insert the new key with frequency 1 and set minFreq = 1.
void touch(int key) {                 // called by get and put
    int f = freq.get(key);
    freq.put(key, f + 1);
    buckets.get(f).remove(key);
    if (f == minFreq && buckets.get(f).isEmpty()) minFreq++;
    buckets.computeIfAbsent(f + 1, k -> new LinkedHashSet<>()).add(key);
}
// evict: int old = buckets.get(minFreq).iterator().next(); remove it everywhere

Why it works

"Each method's speed comes from one structure: the map answers 'where is x', the array answers 'give me a random one', the queue drops expired items from the front, the sorted list answers 'latest before t' by binary search. Every method updates both structures, so they never disagree."

The template to remember

// 1. List each method + required speed
// 2. Pick one structure per method:
//    find by key → HashMap      random → ArrayList
//    expire oldest → Deque      latest before t → sorted list + binary search
//    move/remove known item → doubly linked list (LinkedHashMap / LinkedHashSet)
// 3. Glue them; every method updates ALL of them
// Remove from the middle of an array in O(1):
list.set(i, last); pos.put(last, i); list.remove(list.size() - 1);
Remember

One structure per method, glued together and always updated together. Array + map for random; queue for time windows; binary search for "at time t"; buckets of LRU lists for LFU.

Common mistakes
  • RandomizedSet: forgetting to update the moved element's index in the map — or removing x from the map before reading its index. Also the case where x is the last element (the code above still works: it moves x onto itself, then removes it).
  • Min Stack with a single min variable — after popping the minimum you no longer know the next one.
  • Time map: binary searching for "== t" instead of "last ≤ t".
  • Hit counter: using < t − 300 instead of <= t − 300 — a hit exactly 300 seconds ago is out of the window.
  • LFU: forgetting to reset minFreq = 1 when a new key is inserted.

  • Medium155. Min Stack — animation 1.
    Show solution

    The idea

    A stack that also answers "what is the smallest value inside?" in O(1). Trick: with every value you push, store the minimum at that moment (the smaller of the new value and the min below it). Popping removes both, so the min underneath is still correct. Pattern: augment each entry with a running summary.

    Brute force first

    Scan the whole stack in getMin: O(n) per call.

    Step by step

    1. Each stack entry is the pair {value, minSoFar}.
    2. push(v): minSoFar = v if the stack is empty, otherwise min(v, top.minSoFar).
    3. pop(): remove the top pair.
    4. top() returns top.value, and getMin() returns top.minSoFar.

    Java

    class MinStack {
    // each entry: {value, smallest value at or below it}
    private final Deque<int[]> stack = new ArrayDeque<>();

    public void push(int val) {
        int min = stack.isEmpty() ? val
                : Math.min(val, stack.peek()[1]);
        stack.push(new int[]{val, min});
    }

    public void pop() {
        stack.pop();
    }

    public int top() {
        return stack.peek()[0];
    }

    public int getMin() {
        return stack.peek()[1];
    }
}

    Time O(1) for every operation · Space O(n) — one extra number per entry.

    Dry run

    push −2 {−2,−2}, push 0 {0,−2}, push −3 {−3,−3}. getMin = −3. pop. top = 0, getMin = −2.

    Watch out

    Keeping only one "current min" variable breaks after you pop the min, because you no longer know the previous one. That is why every entry stores its own.

  • Medium380. Insert Delete GetRandom O(1) — animation 2.
    Show solution

    The idea

    Insert, remove and pick a random element, all in average O(1). A list gives O(1) random picks by index, and a map gives O(1) lookup of where a value sits. Removing from the middle of a list is slow, so move the last element into the hole and remove the last slot instead. Pattern: array + hash map of indices.

    Brute force first

    Use a HashSet alone: insert and remove are O(1), but a random pick needs O(n) iteration.

    Step by step

    1. insert(v): if v is in the map, return false. Otherwise map v → list.size() and append v.
    2. remove(v): find its index i. Put the last value into slot i and update that value's index in the map.
    3. Remove the last slot of the list and remove v from the map.
    4. getRandom(): list.get(random index).

    Java

    class RandomizedSet {
    private final List<Integer> list = new ArrayList<>();
    private final Map<Integer, Integer> index = new HashMap<>();
    private final Random rnd = new Random();

    public boolean insert(int val) {
        if (index.containsKey(val)) return false;
        index.put(val, list.size());
        list.add(val);
        return true;
    }

    public boolean remove(int val) {
        Integer i = index.get(val);
        if (i == null) return false;
        // move the last value into the hole, drop the last
        int last = list.get(list.size() - 1);
        list.set(i, last);
        index.put(last, i);
        list.remove(list.size() - 1);
        index.remove(val);
        return true;
    }

    public int getRandom() {
        return list.get(rnd.nextInt(list.size()));
    }
}

    Time O(1) average per operation · Space O(n) — one list slot and one map entry per value.

    Dry run

    insert 1 and 2: list [1,2], map {1:0, 2:1}. remove 1: the last value 2 moves into slot 0, map {2:0}, list [2]. getRandom always returns 2.

    Watch out

    Update the moved value's index before removing val from the map. If val is itself the last element, the order matters.

  • Medium981. Time Based Key-Value Store — animation 3.
    Show solution

    The idea

    Store values with timestamps, and get(key, t) returns the value set at the latest time ≤ t. The problem promises that timestamps for set only increase, so each key's list is already sorted. Then get is a binary search for the last time ≤ t. Pattern: hash map + binary search on a sorted list.

    Brute force first

    Scan the key's whole list backwards: O(n) per get.

    Step by step

    1. set: append the timestamp to times[key] and the value to values[key].
    2. get: if the key is unknown, return "".
    3. Binary search: when ts[mid] ≤ t, remember mid and go right. Otherwise go left.
    4. Return values[found], or "" if no time was ≤ t.

    Java

    class TimeMap {
    // key -> timestamps in increasing order (given by problem)
    private final Map<String, List<Integer>> times =
        new HashMap<>();
    private final Map<String, List<String>> values =
        new HashMap<>();

    public void set(String key, String value, int timestamp) {
        times.computeIfAbsent(key, k -> new ArrayList<>())
             .add(timestamp);
        values.computeIfAbsent(key, k -> new ArrayList<>())
              .add(value);
    }

    public String get(String key, int timestamp) {
        List<Integer> ts = times.get(key);
        if (ts == null) return "";
        // last index with ts[i] <= timestamp
        int lo = 0, hi = ts.size() - 1, found = -1;
        while (lo <= hi) {
            int mid = (lo + hi) >>> 1;
            if (ts.get(mid) <= timestamp) {
                found = mid;
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return found == -1 ? "" : values.get(key).get(found);
    }
}

    Time O(1) set, O(log n) get · Space O(n) — every set is stored once.

    Dry run

    set(foo, bar, 1), set(foo, bar2, 4). get(foo, 3): the times are [1,4], and the last one ≤ 3 is 1, so "bar". get(foo, 5) gives "bar2". get(foo, 0) gives "".

    Watch out

    You want the last time ≤ t, not an exact match. A TreeMap.floorEntry per key also works in O(log n).

  • Medium362. Design Hit Counter — animation 4 (premium).
    Show solution

    The idea

    Count the hits in the past 5 minutes (300 seconds). Keep a ring of 300 slots, where second s goes to slot s % 300. Each slot remembers which second it holds and how many hits it got then. If a hit lands in a slot that holds an old second, reset that slot first. To count, add up the slots whose second is within the last 300. Pattern: circular buffer. A queue of timestamps is the simpler alternative, but its memory grows with the number of hits.

    Step by step

    1. Make two arrays of size 300: time[] and hits[].
    2. hit(t): i = t % 300. If time[i] ≠ t, set time[i] = t and hits[i] = 0. Then hits[i]++.
    3. getHits(t): add up hits[i] for every slot where t − time[i] < 300.
    4. Return the total.

    Java

    class HitCounter {
    // ring of 300 slots, one per second of the window
    private final int[] time = new int[300];
    private final int[] hits = new int[300];

    public void hit(int timestamp) {
        int i = timestamp % 300;
        if (time[i] != timestamp) { // old second: reuse slot
            time[i] = timestamp;
            hits[i] = 0;
        }
        hits[i]++;
    }

    public int getHits(int timestamp) {
        int total = 0;
        for (int i = 0; i < 300; i++) {
            // count only the last 300 seconds
            if (timestamp - time[i] < 300) total += hits[i];
        }
        return total;
    }
}

    Time O(1) hit, O(300) = O(1) getHits · Space O(300) — fixed, no matter how many hits arrive.

    Dry run

    Hits at 1, 2, 3 and 300. getHits(300) = 4. getHits(301): second 1 is 300 seconds old, so it no longer counts. The answer is 3.

    Watch out

    Use < 300, not ≤. A hit at second 1 is outside the window at second 301. Many hits in the same second share one slot.

  • Medium146. LRU Cache — map + doubly linked list.
    Show solution

    The idea

    Cache with a capacity. When it is full, evict the least recently used key. Both get and put must be O(1). A hash map finds a key's node in O(1). A doubly linked list (each node knows its previous and next node) keeps usage order: newest at the front, oldest at the back. A node can be moved in O(1) because it knows its neighbours. Pattern: hash map + doubly linked list.

    Brute force first

    Store a "last used" time per key and scan for the smallest when evicting: O(n) per eviction.

    Step by step

    1. Two dummy nodes, head and tail, so that there are no null checks at the ends.
    2. get(k): if k is missing, return −1. Otherwise unlink its node, add it at the front, and return its value.
    3. put(k, v) for an existing key: update the value and move the node to the front.
    4. put for a new key: if the cache is full, remove tail.prev (the oldest) from both the list and the map. Then add the new node at the front.

    Java

    class LRUCache {
    private static class Node {
        int key, val;
        Node prev, next;
        Node(int k, int v) { key = k; val = v; }
    }

    private final int capacity;
    private final Map<Integer, Node> map = new HashMap<>();
    // dummy ends: head.next = newest, tail.prev = oldest
    private final Node head = new Node(0, 0);
    private final Node tail = new Node(0, 0);

    public LRUCache(int capacity) {
        this.capacity = capacity;
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        Node node = map.get(key);
        if (node == null) return -1;
        unlink(node);
        addFront(node); // just used: now newest
        return node.val;
    }

    public void put(int key, int value) {
        Node node = map.get(key);
        if (node != null) {
            node.val = value;
            unlink(node);
            addFront(node);
            return;
        }
        if (map.size() == capacity) {
            Node old = tail.prev; // least recently used
            unlink(old);
            map.remove(old.key);
        }
        node = new Node(key, value);
        map.put(key, node);
        addFront(node);
    }

    private void unlink(Node n) {
        n.prev.next = n.next;
        n.next.prev = n.prev;
    }

    private void addFront(Node n) {
        n.next = head.next;
        n.prev = head;
        head.next.prev = n;
        head.next = n;
    }
}

    Time O(1) per get and put · Space O(capacity) — one map entry and one node per key.

    Dry run

    Capacity 2. put 1, put 2, get 1 (order: 1, 2). put 3 evicts 2. get 2 = −1. put 4 evicts 1. get 1 = −1, get 3 = 3, get 4 = 4.

    Watch out

    The node must store its key, so that on eviction you can remove it from the map too. Updating an existing key must also count as a use.

  • Medium355. Design Twitter — map of lists + a heap to merge feeds.
    Show solution

    The idea

    Users post tweets and follow each other. A news feed is the 10 newest tweets from you and the people you follow. Give each tweet a global time number. Each user's tweets are already in time order, so the feed is a merge of k sorted lists: put each user's newest tweet in a max-heap, pop the newest, and push that user's next older tweet. Stop after 10. Pattern: k-way merge with a heap.

    Brute force first

    Collect every tweet of every followed user, sort them all and take 10: O(T log T) per feed.

    Step by step

    1. postTweet: append {clock++, tweetId} to that user's list.
    2. follow and unfollow: add to or remove from a set of followees.
    3. getNewsFeed: users = followees + yourself. Push each user's last tweet as {time, id, user, index}.
    4. Pop up to 10 times. After each pop, push the same user's tweet at index − 1 if it exists.

    Java

    class Twitter {
    private int clock = 0; // bigger = newer
    // userId -> list of {time, tweetId}, oldest first
    private final Map<Integer, List<int[]>> tweets =
        new HashMap<>();
    private final Map<Integer, Set<Integer>> follows =
        new HashMap<>();

    public void postTweet(int userId, int tweetId) {
        tweets.computeIfAbsent(userId, k -> new ArrayList<>())
              .add(new int[]{clock++, tweetId});
    }

    public List<Integer> getNewsFeed(int userId) {
        Set<Integer> users = new HashSet<>(
            follows.getOrDefault(userId, Set.of()));
        users.add(userId); // see your own tweets too
        // max-heap of {time, tweetId, user, index in list}
        PriorityQueue<int[]> pq =
            new PriorityQueue<>((x, y) -> y[0] - x[0]);
        for (int u : users) {
            List<int[]> list = tweets.get(u);
            if (list == null || list.isEmpty()) continue;
            int i = list.size() - 1; // newest of this user
            pq.offer(new int[]{list.get(i)[0], list.get(i)[1], u, i});
        }
        List<Integer> feed = new ArrayList<>();
        while (!pq.isEmpty() && feed.size() < 10) {
            int[] top = pq.poll();
            feed.add(top[1]);
            int i = top[3] - 1; // that user's next older tweet
            if (i >= 0) {
                int[] t = tweets.get(top[2]).get(i);
                pq.offer(new int[]{t[0], t[1], top[2], i});
            }
        }
        return feed;
    }

    public void follow(int followerId, int followeeId) {
        follows.computeIfAbsent(followerId, k -> new HashSet<>())
               .add(followeeId);
    }

    public void unfollow(int followerId, int followeeId) {
        Set<Integer> s = follows.get(followerId);
        if (s != null) s.remove(followeeId);
    }
}

    Time O(f + 10 log f) per feed, f = number of followees · Space O(f) for the heap — only 10 pops, each O(log f).

    Dry run

    User 1 posts 5. Feed = [5]. Follow 2. User 2 posts 6. Feed = [6, 5] (6 is newer). Unfollow 2. Feed = [5].

    Watch out

    Include the user's own tweets, and do not show them twice if they "follow" themselves. A set handles that. Unfollowing someone you do not follow must not crash.

  • Hard381. GetRandom O(1) — Duplicates Allowed — value → set of indices.
    Show solution

    The idea

    The same as 380, but duplicates are allowed, and getRandom must favour values with more copies. The list still holds every copy. The map now goes from each value to a set of indices where it sits. Removing still moves the last element into the hole. Pattern: array + map of index sets.

    Brute force first

    A list alone: remove needs an O(n) search.

    Step by step

    1. insert(v): add the index list.size() to v's set and append v. Return true if the set now has size 1.
    2. remove(v): take any index hole from v's set and remove it.
    3. Move the last value into the hole: list[hole] = last. In last's set, add hole and remove lastIdx.
    4. Drop the last slot of the list.
    5. getRandom: a random index of the list. Copies are picked in proportion to their count.

    Java

    class RandomizedCollection {
    private final List<Integer> list = new ArrayList<>();
    // value -> every index where it sits in list
    private final Map<Integer, Set<Integer>> idx = new HashMap<>();
    private final Random rnd = new Random();

    public boolean insert(int val) {
        Set<Integer> s = idx.computeIfAbsent(val,
            k -> new HashSet<>());
        s.add(list.size());
        list.add(val);
        return s.size() == 1; // true if it was not there
    }

    public boolean remove(int val) {
        Set<Integer> s = idx.get(val);
        if (s == null || s.isEmpty()) return false;
        int hole = s.iterator().next(); // any copy of val
        s.remove(hole);
        int lastIdx = list.size() - 1;
        int last = list.get(lastIdx);
        // move the last value into the hole
        list.set(hole, last);
        Set<Integer> ls = idx.get(last);
        ls.add(hole);
        ls.remove(lastIdx); // safe even if hole == lastIdx
        list.remove(lastIdx);
        return true;
    }

    public int getRandom() {
        return list.get(rnd.nextInt(list.size()));
    }
}

    Time O(1) average per operation · Space O(n) — each copy has one list slot and one set entry.

    Dry run

    insert 1, 1, 2: list [1,1,2], 1 → {0,1}, 2 → {2}. remove 1 (hole 0): the last value 2 moves into 0, so 2 → {0}, and the list is [2,1].

    Watch out

    When the removed element is the last one (hole == lastIdx), add hole first and remove lastIdx second. Doing it in the other order leaves a stale index.

  • Hard460. LFU Cache — buckets of LRU lists + minFreq.
    Show solution

    The idea

    When full, evict the key used the fewest times. Among keys with the same count, evict the least recently used one. Keep a bucket for each use count, where each bucket is an LRU-ordered set of keys (a LinkedHashSet keeps insertion order, oldest first). Also keep minFreq, the smallest count that has keys. Every get or put moves a key from bucket f to bucket f + 1. Pattern: buckets of LRU lists + minFreq.

    Brute force first

    Scan all keys for the smallest (count, last used) on every eviction: O(n).

    Step by step

    1. Maps: key → value, key → freq, freq → LinkedHashSet of keys.
    2. touch(key): remove it from bucket f and add it to bucket f + 1. If bucket f was the minFreq bucket and is now empty, do minFreq++.
    3. get: if the key is missing, return −1. Otherwise touch it and return the value.
    4. put for an existing key: update the value and touch it. For a new key: if full, evict the first key in buckets[minFreq]. Then insert it with freq 1 and set minFreq = 1.

    Java

    class LFUCache {
    private final int capacity;
    private int minFreq = 0;
    private final Map<Integer, Integer> vals = new HashMap<>();
    private final Map<Integer, Integer> freq = new HashMap<>();
    // freq -> keys with that freq, oldest first (LRU order)
    private final Map<Integer, LinkedHashSet<Integer>> buckets =
        new HashMap<>();

    public LFUCache(int capacity) {
        this.capacity = capacity;
    }

    public int get(int key) {
        if (!vals.containsKey(key)) return -1;
        touch(key);
        return vals.get(key);
    }

    public void put(int key, int value) {
        if (capacity == 0) return;
        if (vals.containsKey(key)) {
            vals.put(key, value);
            touch(key);
            return;
        }
        if (vals.size() == capacity) {
            // evict the oldest key of the lowest freq
            LinkedHashSet<Integer> b = buckets.get(minFreq);
            int victim = b.iterator().next();
            b.remove(victim);
            vals.remove(victim);
            freq.remove(victim);
        }
        vals.put(key, value);
        freq.put(key, 1);
        buckets.computeIfAbsent(1, k -> new LinkedHashSet<>())
               .add(key);
        minFreq = 1; // a new key always has freq 1
    }

    // move key from bucket f to bucket f + 1
    private void touch(int key) {
        int f = freq.get(key);
        LinkedHashSet<Integer> b = buckets.get(f);
        b.remove(key);
        if (f == minFreq && b.isEmpty()) minFreq++;
        freq.put(key, f + 1);
        buckets.computeIfAbsent(f + 1, k -> new LinkedHashSet<>())
               .add(key); // newest at the end
    }
}

    Time O(1) average per operation · Space O(capacity) — a constant number of map entries per key.

    Dry run

    Capacity 2. put 1, put 2, get 1 (1 now has freq 2). put 3 evicts 2 (freq 1). get 2 = −1, get 3 = 3 (freq 2). put 4: 1 and 3 both have freq 2, and 1 is older, so evict 1. get 1 = −1, get 3 = 3, get 4 = 4.

    Watch out

    Capacity 0 must ignore every put. After inserting a new key, minFreq is always 1. Forgetting that reset makes later evictions read the wrong bucket.

Test yourself

Why can RandomizedSet not use only a HashSet?

A HashSet cannot return a random element in O(1) — there is no index to pick. The array provides the index.

In the time map, why does appending keep the list sorted?

The problem guarantees set calls come with increasing timestamps, so every new time is the largest so far.

What does the Min Stack's mins stack hold after push 4, push 6, push 1?

[4, 4, 1] — the minimum of everything at or below each level.

In LFU, when does minFreq change?

It becomes f + 1 when the last key with frequency f = minFreq is used again, and it resets to 1 whenever a new key is inserted.
