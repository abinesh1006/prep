Sliding Window

Keep a stretch of neighbouring elements (a "window") and slide it along the array, updating its sum or contents by what enters and what leaves — instead of recomputing every stretch from scratch.

Time to learn: about 2.5 hours · Prerequisites: Two pointers, Arrays and hashing

When to use it — the signal

The question is about a contiguous piece — "subarray" or "substring" — and asks for the longest, shortest, maximum sum of size k, "at most k distinct", "without repeating", "contains all characters of t". If the elements are all non-negative (or the condition only gets worse as the window grows), a window works.

The idea in plain words

A subarray is a run of neighbours: in [2, 1, 5, 1, 3], [1, 5, 1] is one, [2, 5] is not. An array of 10,000 numbers has about 50 million subarrays — checking each is O(n²) or worse.

A window is a subarray marked by two indices, l (left edge) and r (right edge). When it moves one step right, only one number enters and one leaves. So the new sum is old sum + entering − leaving: one step, not k steps.

  • Fixed window (size k given): move both edges together.
  • Variable window: grow the right edge every step; when the window breaks the rule (a repeat, too big a sum), shrink from the left until it is valid again. Record the best valid window.

Each index enters the window once and leaves once, so the whole thing is O(n) even with the inner "shrink" loop.

Analogy

A train window showing 3 houses at a time. As the train moves, one house appears on the right and one disappears on the left — you do not re-look at the middle house. For the variable window, think of a caterpillar: the head stretches forward, and when the body is too long (breaks a rule), the tail pulls in.

Watch it work

Fixed window: the largest sum of any k = 3 neighbours in [2, 1, 5, 1, 3, 2, 6, 1].

Variable window: Longest Substring Without Repeating Characters in "abcabcbb". The set holds the letters inside the window.

The Minimum Window Substring idea: smallest piece of s = "AXBYCAB" containing all of t = "ABC". Grow until the window is valid (nothing missing), then shrink while it stays valid, recording the smallest.

Why it works (the one sentence to say in an interview)

"If a window breaks the rule, every bigger window with the same left edge also breaks it, so the left edge can move forward for good; since l and r each move right at most n times, the total work is O(n)."

The template to remember

// Variable window: longest / shortest valid subarray
int l = 0, best = 0;
for (int r = 0; r < n; r++) {
    add(a[r]);                     // grow the head
    while (!valid()) remove(a[l++]); // pull in the tail
    best = Math.max(best, r - l + 1);   // longest
}
// Shortest: while (valid()) { best = min(...); remove(a[l++]); }
// Fixed k:  sum += a[r] - a[r - k];
Remember

Contiguous + longest/shortest → window. Right edge always grows; left edge shrinks only when the rule breaks. "Longest" updates after shrinking; "shortest" updates while shrinking.

Common mistakes
  • Using a window when numbers can be negative and the question is about a sum. Adding a number may make the sum smaller, so "shrink when too big" is wrong — use prefix sums + a map instead.
  • Using if instead of while to shrink — one step may not be enough.
  • Off-by-one in the length: it is r − l + 1.
  • For the "shortest" variant, recording the answer after the loop instead of inside the shrink loop.
  • Rebuilding the window's sum or set from scratch each step — that is O(n·k) again.

Test yourself

The inner while loop can run many times. Why is the whole algorithm still O(n)?

l only moves right and never past r, so across the whole run the inner loop executes at most n times in total.

"Longest subarray with sum exactly k", numbers can be negative. Window?

No. Negative numbers break the "growing makes it bigger" rule. Use prefix sums with a map of first positions.

In the fixed window, why does sum += a[r] − a[r − k] work?

Moving right by one adds exactly the new element a[r] and removes exactly the element that fell off, a[r − k]. Everything in the middle is unchanged.
