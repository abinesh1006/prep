Sliding Window

Keep a stretch of neighbouring elements (a "window") and slide it along the array, updating its sum or contents by what enters and what leaves — instead of recomputing every stretch from scratch.

Time to learn: about 2.5 hours · Prerequisites: Two pointers, Arrays and hashing

When to use it — the signal

The question is about a contiguous piece — "subarray" or "substring" — and asks for the longest, shortest, maximum sum of size k, "at most k distinct", "without repeating", "contains all characters of t". If the elements are all non-negative (or the condition only gets worse as the window grows), a window works.

The idea in plain words

A subarray is a run of neighbours: in [2, 1, 5, 1, 3], [1, 5, 1] is one, [2, 5] is not. An array of 10,000 numbers has about 50 million subarrays — checking each is O(n²) or worse.

A window is a subarray marked by two indices, l (left edge) and r (right edge). When it moves one step right, only one number enters and one leaves. So the new sum is old sum + entering − leaving: one step, not k steps.

  • Fixed window (size k given): move both edges together.
  • Variable window: grow the right edge every step; when the window breaks the rule (a repeat, too big a sum), shrink from the left until it is valid again. Record the best valid window.

Each index enters the window once and leaves once, so the whole thing is O(n) even with the inner "shrink" loop.

Analogy

A train window showing 3 houses at a time. As the train moves, one house appears on the right and one disappears on the left — you do not re-look at the middle house. For the variable window, think of a caterpillar: the head stretches forward, and when the body is too long (breaks a rule), the tail pulls in.

Watch it work

Fixed window: the largest sum of any k = 3 neighbours in [2, 1, 5, 1, 3, 2, 6, 1].

Variable window: Longest Substring Without Repeating Characters in "abcabcbb". The set holds the letters inside the window.

The Minimum Window Substring idea: smallest piece of s = "AXBYCAB" containing all of t = "ABC". Grow until the window is valid (nothing missing), then shrink while it stays valid, recording the smallest.

Why it works (the one sentence to say in an interview)

"If a window breaks the rule, every bigger window with the same left edge also breaks it, so the left edge can move forward for good; since l and r each move right at most n times, the total work is O(n)."

The template to remember

// Variable window: longest / shortest valid subarray
int l = 0, best = 0;
for (int r = 0; r < n; r++) {
    add(a[r]);                     // grow the head
    while (!valid()) remove(a[l++]); // pull in the tail
    best = Math.max(best, r - l + 1);   // longest
}
// Shortest: while (valid()) { best = min(...); remove(a[l++]); }
// Fixed k:  sum += a[r] - a[r - k];
Remember

Contiguous + longest/shortest → window. Right edge always grows; left edge shrinks only when the rule breaks. "Longest" updates after shrinking; "shortest" updates while shrinking.

Common mistakes
  • Using a window when numbers can be negative and the question is about a sum. Adding a number may make the sum smaller, so "shrink when too big" is wrong — use prefix sums + a map instead.
  • Using if instead of while to shrink — one step may not be enough.
  • Off-by-one in the length: it is r − l + 1.
  • For the "shortest" variant, recording the answer after the loop instead of inside the shrink loop.
  • Rebuilding the window's sum or set from scratch each step — that is O(n·k) again.

Practice in this order

  • Easy643. Maximum Average Subarray I — the fixed window above, divide by k.
    Show solution

    The idea

    Among all runs of exactly k neighbours, find the biggest average. [1,12,-5,-6,50,3], k = 4 → 12.75 (12−5−6+50 = 51, /4). The insight: the biggest average is the biggest sum divided by k. Slide a fixed window: add the number entering on the right, subtract the one leaving on the left.

    Brute force first

    Re-add k numbers for every start: O(n · k). Sliding makes each move O(1).

    Step by step

    1. Sum the first k numbers: that is the first window.
    2. For i from k to n − 1: sum += nums[i] - nums[i - k] (one in, one out).
    3. Keep the largest sum.
    4. Return best / (double) k.

    Java

    class Solution {
    public double findMaxAverage(int[] nums, int k) {
        int sum = 0;
        for (int i = 0; i < k; i++) sum += nums[i];
        int best = sum;
        for (int i = k; i < nums.length; i++) {
            sum += nums[i] - nums[i - k]; // in, out
            best = Math.max(best, sum);
        }
        return best / (double) k;
    }
}

    Time O(n) · Space O(1) — each number enters and leaves the window once.

    Dry run

    [1,12,-5,-6,50,3], k=4
first window 1+12-5-6 = 2   best 2
i=4: +50 -1  -> 51          best 51
i=5: +3  -12 -> 42          best 51
51 / 4 = 12.75

    Watch out

    Start best at the first window sum, not 0: all numbers can be negative. Divide as double, or integer division drops the .75.

  • Easy121. Best Time to Buy and Sell Stock — l is the cheapest day so far.
    Show solution

    The idea

    Buy on one day, sell on a later day, maximise profit (or 0). [7,1,5,3,6,4] → 5 (buy at 1, sell at 6). The insight: as you walk right, the best buy day so far is simply the cheapest price so far (the window's left end l). Each day, check "sell today" against it.

    Brute force first

    Every buy/sell pair: O(n²). Too slow for 105 days.

    Step by step

    1. Keep minPrice = cheapest price seen so far (start with the first day).
    2. For each day: profit if sold today = price - minPrice; keep the best.
    3. If today is cheaper than minPrice, today becomes the new buy day.
    4. Return the best profit (0 if prices only fall).

    Java

    class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = prices[0], best = 0;
        for (int p : prices) {
            best = Math.max(best, p - minPrice); // sell today
            minPrice = Math.min(minPrice, p);    // cheaper buy
        }
        return best;
    }
}

    Time O(n) · Space O(1) — one pass, two variables.

    Dry run

    [7,1,5,3,6,4]: min 7 → 1 at day 2; day 3 profit 4; day 5 profit 5 (best); day 6 profit 3. Answer 5.

    Watch out

    You must buy before you sell, so never subtract a later minimum from an earlier price. If prices only go down, the answer is 0, not negative.

  • Medium3. Longest Substring Without Repeating Characters — the animation above.
    Show solution

    The idea

    Longest stretch of a string with no repeated character. "abcabcbb" → 3 ("abc"). The insight: grow a variable window with the right pointer; when the new character is already inside, jump the left pointer just past its previous position. Remember each character's last index.

    Brute force first

    Check every substring for repeats: O(n³), or O(n²) with a set per start.

    Step by step

    1. Make last, an array of 128 ints filled with −1 (last index of each ASCII character).
    2. Walk r from left to right. Let c = s.charAt(r).
    3. If c was seen at or after l, move l = last[c] + 1.
    4. Record last[c] = r; window length is r - l + 1; keep the max.

    Java

    class Solution {
    public int lengthOfLongestSubstring(String s) {
        int[] last = new int[128];
        Arrays.fill(last, -1);
        int l = 0, best = 0;
        for (int r = 0; r < s.length(); r++) {
            char c = s.charAt(r);
            // c repeats inside the window: jump past it
            if (last[c] >= l) l = last[c] + 1;
            last[c] = r;
            best = Math.max(best, r - l + 1);
        }
        return best;
    }
}

    Time O(n) · Space O(1) — r moves once across, l only jumps forward, the table is a fixed 128.

    Dry run

    "abba"
r=0 a: l=0 len 1
r=1 b: l=0 len 2
r=2 b: last[b]=1 >= 0 -> l=2, len 1
r=3 a: last[a]=0 <  2 -> keep l=2, len 2

    Watch out

    The last[c] >= l check matters: in "abba", the old a at index 0 is already outside the window, so l must not move back. Spaces and digits are characters too, hence 128 slots.

  • Medium209. Minimum Size Subarray Sum — shortest window with sum ≥ target.
    Show solution

    The idea

    Shortest run of neighbours whose sum is at least target (all numbers positive); 0 if none. target 7, [2,3,1,2,4,3] → 2 ([4,3]). The insight: grow the window on the right until the sum is big enough, then shrink from the left as long as it stays big enough, recording the length each time.

    Brute force first

    Every start, extend until the sum reaches target: O(n²).

    Step by step

    1. l = 0, sum = 0, best = infinity.
    2. For each r: add nums[r] to sum.
    3. While sum >= target: record r - l + 1, then remove nums[l] and l++.
    4. Return best, or 0 if it never changed.

    Java

    class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int l = 0, sum = 0, best = Integer.MAX_VALUE;
        for (int r = 0; r < nums.length; r++) {
            sum += nums[r];
            while (sum >= target) {   // valid: try smaller
                best = Math.min(best, r - l + 1);
                sum -= nums[l++];
            }
        }
        return best == Integer.MAX_VALUE ? 0 : best;
    }
}

    Time O(n) · Space O(1) — each index is added once and removed once.

    Dry run

    target 7, [2,3,1,2,4,3]
r=3 sum 8 >= 7: len 4, drop 2 -> 6
r=4 sum 10: len 4, drop 3 -> 7: len 3, drop 1 -> 6
r=5 sum 9: len 3, drop 2 -> 7: len 2, drop 4 -> 3
best = 2

    Watch out

    This works only because all numbers are positive (adding makes the sum bigger, removing makes it smaller). Return 0, not MAX_VALUE, when no window reaches the target.

  • Medium424. Longest Repeating Character Replacement — valid while length − maxCount ≤ k.
    Show solution

    The idea

    You may change up to k letters. What is the longest stretch that can become one repeated letter? "AABABBA", k = 1 → 4. The insight: a window is fixable if length - (count of its most common letter) ≤ k (the rest are the letters you change). Grow on the right; when it breaks, slide the left by one.

    Brute force first

    Every substring, count its letters: O(26 · n²).

    Step by step

    1. Keep count[26] for the window and maxCount, the highest count seen.
    2. For each r: add s[r], update maxCount.
    3. If (r - l + 1) - maxCount > k, remove s[l] and l++ (the window slides, never shrinks).
    4. Answer is the final largest window size r - l + 1; track the max.

    Java

    class Solution {
    public int characterReplacement(String s, int k) {
        int[] count = new int[26];
        int l = 0, maxCount = 0, best = 0;
        for (int r = 0; r < s.length(); r++) {
            int c = s.charAt(r) - 'A';
            maxCount = Math.max(maxCount, ++count[c]);
            // too many letters to change: slide left
            if (r - l + 1 - maxCount > k) {
                count[s.charAt(l) - 'A']--;
                l++;
            }
            best = Math.max(best, r - l + 1);
        }
        return best;
    }
}

    Time O(n) · Space O(1) — one pass, a 26-slot table.

    Dry run

    "AABABBA", k=1
r=0..3 "AABA": len 4, maxCount 3, 4-3=1 ok  best 4
r=4 "AABAB": 5-3=2 > 1 -> drop A, window "ABAB"
r=5 "ABABB": maxCount 3 (B), 5-3=2 -> drop A
r=6 "BABBA": 5-3=2 -> drop B. best stays 4

    Watch out

    It is fine that maxCount is never decreased: the answer only grows when a letter really reaches a new higher count. Letters are uppercase, so subtract 'A'.

  • Medium567. Permutation in String — fixed window of size |s1| with letter counts.
    Show solution

    The idea

    Does s2 contain some rearrangement of s1 as a block? s1 = "ab", s2 = "eidbaooo" → true ("ba"). The insight: a rearrangement has the same letter counts, so slide a fixed window of length |s1| over s2 and compare its 26 counts with s1's.

    Brute force first

    Generate every permutation of s1 and search for it: O(n!), hopeless. Or count letters fresh for every window: O(26 · n · |s1|).

    Step by step

    1. If s1 is longer than s2, return false.
    2. Count s1's letters in need[26], and the first |s1| letters of s2 in win[26].
    3. If the arrays are equal, return true.
    4. Slide: add s2[i], remove s2[i - m], compare again.
    5. If no window matches, return false.

    Java

    class Solution {
    public boolean checkInclusion(String s1, String s2) {
        int m = s1.length(), n = s2.length();
        if (m > n) return false;
        int[] need = new int[26], win = new int[26];
        for (int i = 0; i < m; i++) {
            need[s1.charAt(i) - 'a']++;
            win[s2.charAt(i) - 'a']++;
        }
        if (Arrays.equals(need, win)) return true;
        for (int i = m; i < n; i++) {
            win[s2.charAt(i) - 'a']++;     // enters
            win[s2.charAt(i - m) - 'a']--; // leaves
            if (Arrays.equals(need, win)) return true;
        }
        return false;
    }
}

    Time O(26 · n) = O(n) · Space O(1) — each slide is O(1) plus a 26-slot compare.

    Dry run

    s1 "ab": need a1 b1. s2 "eidbaooo", windows: ei, id, db, ba → a1 b1 matches → true.

    Watch out

    Check the very first window before sliding (the match may start at index 0). A faster version keeps a "matches" counter of equal slots instead of comparing all 26 each time.

  • Hard76. Minimum Window Substring — need counts + missing, as above.
    Show solution

    The idea

    Smallest block of s containing every character of t (with repeats). s = "ADOBECODEBANC", t = "ABC" → "BANC". The insight: need[c] = how many more c the window still needs, and missing = total characters still needed. Grow right until missing == 0, then shrink left as far as possible and record. Pattern: variable window with need counts.

    Brute force first

    Check every substring of s for containing t: O(n²) substrings × counting each.

    Step by step

    1. Fill need[c] from t; missing = t.length().
    2. Move r: if need[s[r]] > 0, this char was really needed, so missing--. Then need[s[r]]-- (can go negative = extra copies).
    3. While missing == 0: record the window if smaller; then give back s[l]: need[s[l]]++, and if it became > 0 the window lacks it now, so missing++. l++.
    4. Return the best window, or "".

    Java

    class Solution {
    public String minWindow(String s, String t) {
        int[] need = new int[128];
        for (char c : t.toCharArray()) need[c]++;
        int missing = t.length();
        int l = 0, bestL = 0, bestLen = Integer.MAX_VALUE;
        for (int r = 0; r < s.length(); r++) {
            char c = s.charAt(r);
            if (need[c] > 0) missing--; // a needed char
            need[c]--;
            while (missing == 0) {       // window is valid
                if (r - l + 1 < bestLen) {
                    bestLen = r - l + 1;
                    bestL = l;
                }
                char d = s.charAt(l++);
                need[d]++;
                if (need[d] > 0) missing++; // lost one
            }
        }
        return bestLen == Integer.MAX_VALUE ? ""
                : s.substring(bestL, bestL + bestLen);
    }
}

    Time O(|s| + |t|) · Space O(1) — l and r each cross s once; the table has 128 slots.

    Dry run

    s="ADOBECODEBANC" t="ABC"
r=5 "ADOBEC" missing 0 -> best 6, drop A -> missing 1
r=10 "DOBECODEBA" valid -> shrink to "CODEBA"(6), drop C
r=12 "ODEBANC" valid -> shrink to "BANC"(4)
answer "BANC"

    Watch out

    Decrement missing only when need[c] > 0 before the decrement; extra copies must not count. Duplicates in t ("aa") are why we count, not just use a set.

  • Hard239. Sliding Window Maximum — fixed window plus a monotonic deque.
    Show solution

    The idea

    For every window of size k, report its maximum. [1,3,-1,-3,5,3,6,7], k = 3 → [3,3,5,5,6,7]. The insight: keep a monotonic deque (double-ended queue) of indexes whose values are decreasing from front to back. The front is always the window max. A new number kicks out smaller ones from the back: they can never be a max again.

    Brute force first

    Scan each window for its max: O(n · k). A max-heap with lazy removal gives O(n log n).

    Step by step

    1. Deque stores indexes, values decreasing front to back.
    2. For each i: if the front index is i - k or older, it left the window: pollFirst.
    3. While the back value is ≤ nums[i], pollLast (useless now). Then add i at the back.
    4. Once i >= k - 1, the front is the window max: record nums[front].

    Java

    class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        int n = nums.length;
        int[] ans = new int[n - k + 1];
        Deque<Integer> dq = new ArrayDeque<>(); // indexes
        for (int i = 0; i < n; i++) {
            // front fell out of the window
            if (!dq.isEmpty() && dq.peekFirst() <= i - k) {
                dq.pollFirst();
            }
            // smaller values behind i are never a max
            while (!dq.isEmpty()
                    && nums[dq.peekLast()] <= nums[i]) {
                dq.pollLast();
            }
            dq.offerLast(i);
            if (i >= k - 1) ans[i - k + 1] = nums[dq.peekFirst()];
        }
        return ans;
    }
}

    Time O(n) · Space O(k) — each index is pushed once and popped at most once.

    Dry run

    [1,3,-1,-3,5,3,6,7], k=3  (deque shows values)
i=1: 3 kicks 1   -> [3]
i=2: [3,-1]      -> max 3
i=3: [3,-1,-3]   -> max 3
i=4: 3 leaves; 5 kicks -1,-3 -> [5]  max 5
i=5: [5,3] max 5; i=6: [6] max 6; i=7: [7] max 7

    Watch out

    Store indexes, not values, so you can tell when the front has left the window. The answer array has n - k + 1 slots.

Test yourself

The inner while loop can run many times. Why is the whole algorithm still O(n)?

l only moves right and never past r, so across the whole run the inner loop executes at most n times in total.

"Longest subarray with sum exactly k", numbers can be negative. Window?

No. Negative numbers break the "growing makes it bigger" rule. Use prefix sums with a map of first positions.

In the fixed window, why does sum += a[r] − a[r − k] work?

Moving right by one adds exactly the new element a[r] and removes exactly the element that fell off, a[r − k]. Everything in the middle is unchanged.
