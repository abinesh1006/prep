Merge Sorted Lists

Build the answer behind a dummy node: keep taking the smaller front node and hooking it onto the tail. For k lists, let a min-heap tell you which front is smallest.

Time to learn: about 1.5 hours · Prerequisites: Reverse a linked list, Merge sort, Heap

When to use it — the signal

"Merge two / k sorted lists (or arrays)", "combine sorted streams", "sort a linked list", "k-th smallest across k sorted rows", "smallest range covering k lists". Sorted inputs + one sorted output = merge.

The idea in plain words

Two lists: 1 → 2 → 4 and 1 → 3 → 4. The smallest node of the answer is one of the two fronts. Take it, hook it to the answer, and the next front of that list moves up. Repeat. When one list runs out, hook the rest of the other list on in one go — it is already sorted.

The dummy node is a fake first node (value doesn't matter). Without it, the very first hook is a special case ("the answer is empty, so this node becomes the head"). With it, every hook is the same: tail.next = node; tail = node;. At the end the real answer is dummy.next.

K lists: comparing k fronts each time costs k per node. Instead, put the k fronts into a min-heap (a structure that hands you its smallest item in O(log k)). Pop the smallest, hook it on, push that node's follower. Total O(N log k) for N nodes.

Analogy

Several checkout queues where everyone is sorted by ticket number, merging into one exit door. A guard looks only at the person at the front of each queue and waves through the lowest ticket. With many queues, the guard keeps a little sorted notepad of just the front tickets (the heap) so he never has to scan all queues.

Why it works

"Every list is sorted, so the smallest remaining node overall is always one of the current fronts. Taking it never blocks a smaller node later. Two lists: compare the two fronts, O(m + n). K lists: a min-heap of the k fronts gives the smallest in O(log k), so O(N log k)."

The template to remember

ListNode dummy = new ListNode(0), tail = dummy;
while (a != null && b != null) {
    if (a.val <= b.val) { tail.next = a; a = a.next; }
    else { tail.next = b; b = b.next; }
    tail = tail.next;
}
tail.next = (a != null) ? a : b;
return dummy.next;
// k lists: heap of fronts; poll, hook, push poll.next

Merging two sorted sources needs only pointers; merging k of them needs one more thing, the cheapest "who is smallest" answer, which is a min-heap of size k.

Remember

Dummy + tail, smaller front wins, hook the leftovers. K lists: heap of fronts → O(N log k).

Common mistakes
  • Forgetting tail = tail.next — every node overwrites the same link.
  • Looping over the leftovers one by one — just one assignment tail.next = rest.
  • Comparator a.val - b.val can overflow for big negative/positive values; use Integer.compare.
  • Pushing null heads into the heap (empty lists) → NullPointerException.
  • Merging k lists one after another into a growing result: O(N·k). Use a heap or pair them up (divide and conquer).

Practice in this order

  • Easy21. Merge Two Sorted Lists — first animation.
    Show solution

    The idea

    Join two sorted lists into one sorted list: 1→2→4 and 1→3→4 give 1→1→2→3→4→4. Compare the two fronts, take the smaller, move that list forward. A dummy head means you never special-case the first node. Pattern: two-pointer merge.

    Step by step

    1. Create dummy and a tail pointer at it.
    2. While both lists have nodes: attach the smaller front to tail.next, advance that list and tail.
    3. One list is empty now: attach whatever is left of the other.
    4. Return dummy.next.

    Java

    class Solution {
    public ListNode mergeTwoLists(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(), tail = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) {      // take from a
                tail.next = a;
                a = a.next;
            } else {                   // take from b
                tail.next = b;
                b = b.next;
            }
            tail = tail.next;
        }
        tail.next = (a != null) ? a : b; // leftovers
        return dummy.next;
    }
}

    Time O(n + m) · Space O(1) — each node is attached once; nodes are reused, not copied.

    Dry run

    a=1-2-4  b=1-3-4
take a1   take b1   take a2   take b3   take a4   take b4
result: 1 1 2 3 4 4

    Watch out

    Do not forget the leftover tail after the loop. Using <= takes from a on ties, which keeps the merge stable.

  • Easy88. Merge Sorted Array — same idea on arrays, fill from the back.
    Show solution

    The idea

    nums1 has m real numbers followed by n empty slots; merge nums2 into it, sorted. Filling from the front would overwrite numbers you still need, so fill from the back: compare the largest remaining of each array and write it into the last free slot. Pattern: two pointers from the end.

    Brute force first

    Copy nums2 into the empty slots and call Arrays.sort. O((m+n) log(m+n)).

    Step by step

    1. i = m-1 (end of nums1's numbers), j = n-1 (end of nums2), k = m+n-1 (last slot).
    2. While j >= 0: if i >= 0 and nums1[i] > nums2[j], write nums1[i] and move i; else write nums2[j] and move j.
    3. Move k down each time.
    4. When j runs out, nums1's remaining numbers are already in place.

    Java

    class Solution {
    public void merge(int[] nums1, int m,
                      int[] nums2, int n) {
        int i = m - 1, j = n - 1, k = m + n - 1;
        while (j >= 0) {         // nums2 left to place
            if (i >= 0 && nums1[i] > nums2[j]) {
                nums1[k--] = nums1[i--];
            } else {
                nums1[k--] = nums2[j--];
            }
        }
    }
}

    Time O(m + n) · Space O(1) — each slot is written once, in place.

    Dry run

    [1,2,3,_,_,_]  nums2=[2,5,6]
6 > 3 -> slot5=6    5 > 3 -> slot4=5
2 < 3 -> slot3=3    2 = 2 -> slot2=2 (from nums2)
done: [1,2,2,3,5,6]

    Watch out

    Loop on j >= 0, not on i: leftover nums2 values must still be copied, while leftover nums1 values are already where they belong. Guard i >= 0 when m = 0.

  • Medium148. Sort List — split at the middle, sort halves, merge two lists.
    Show solution

    The idea

    Sort a linked list in O(n log n). Arrays use quicksort, but lists are best with merge sort: split at the middle (fast/slow pointers), sort each half recursively, then merge the two sorted halves (problem 21). Merging lists needs no extra array.

    Brute force first

    Copy values into an array, sort, write back. O(n log n) time but O(n) space.

    Step by step

    1. Base case: 0 or 1 node is already sorted.
    2. Find the end of the first half with slow/fast (start fast at head.next so slow stops before the middle).
    3. Cut: right = slow.next, slow.next = null.
    4. Sort both halves recursively and return merge(left, right).

    Java

    class Solution {
    public ListNode sortList(ListNode head) {
        if (head == null || head.next == null) return head;
        // slow stops at the end of the left half
        ListNode slow = head, fast = head.next;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        ListNode right = slow.next;
        slow.next = null;                    // cut
        return merge(sortList(head), sortList(right));
    }

    private ListNode merge(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(), t = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) { t.next = a; a = a.next; }
            else { t.next = b; b = b.next; }
            t = t.next;
        }
        t.next = (a != null) ? a : b;
        return dummy.next;
    }
}

    Time O(n log n) · Space O(log n) — log n levels of splitting, O(n) merge work per level; the recursion stack is log n deep.

    Dry run

    4-2-1-3
split   4-2 | 1-3
split   4 | 2    1 | 3
merge   2-4      1-3
merge   1-2-3-4

    Watch out

    If fast starts at head instead of head.next, a 2-node list never splits and recursion runs forever. Always cut with slow.next = null.

  • Medium378. Kth Smallest Element in a Sorted Matrix — heap of row fronts, poll k times.
    Show solution

    The idea

    Each row and each column of an n×n matrix is sorted; find the k-th smallest value. Each row is a sorted list, so this is "merge n sorted lists, but stop after k items". Keep a min-heap (a structure that always gives back its smallest item fast) holding the front of each row; poll the smallest k times, and each time push the next number from that row.

    Brute force first

    Put all n² numbers in an array, sort, take index k-1. O(n² log n).

    Step by step

    1. Push (value, row, col=0) for each row into a min-heap ordered by value.
    2. Repeat k-1 times: poll the smallest; if its row has a next column, push that cell.
    3. The heap's top is now the k-th smallest; return it.

    Java

    class Solution {
    public int kthSmallest(int[][] matrix, int k) {
        int n = matrix.length;
        // each entry: {value, row, col}
        PriorityQueue<int[]> heap =
            new PriorityQueue<>((x, y) -> x[0] - y[0]);
        for (int r = 0; r < n; r++) {
            heap.offer(new int[]{matrix[r][0], r, 0});
        }
        for (int i = 0; i < k - 1; i++) {
            int[] top = heap.poll();
            int r = top[1], c = top[2];
            if (c + 1 < n) {                // next in row
                heap.offer(new int[]{
                    matrix[r][c + 1], r, c + 1});
            }
        }
        return heap.peek()[0];
    }
}

    Time O(k log n) · Space O(n) — k heap operations on a heap of at most n entries.

    Dry run

    rows: [1,5,9] [10,11,13] [12,13,15], k=8
heap {1,10,12}
poll 1 push 5 | poll 5 push 9 | poll 9
poll 10 push 11 | poll 11 push 13 | poll 12 push 13
poll one 13      (7 polls)  -> top = 13

    Watch out

    Comparator x[0] - y[0] is fine here because values fit in a narrow range; for any ints use Integer.compare. The other well-known approach is binary search on the value with a staircase count, O(n log(max−min)).

  • Hard23. Merge K Sorted Lists — second animation.
    Show solution

    The idea

    Merge k sorted lists into one. At every moment the next output node is the smallest among the k current fronts. A min-heap of those fronts gives the smallest in O(log k): poll it, attach it, push its next. Pattern: k-way merge with a heap.

    Brute force first

    Merge the lists one after another into a growing result: O(k·N) where N is the total node count. Or collect all values and sort: O(N log N).

    Step by step

    1. Push every non-null head into a min-heap ordered by val.
    2. dummy and tail as in problem 21.
    3. While the heap is not empty: poll the smallest node, attach it to tail, and push its next if not null.
    4. Return dummy.next.

    Java

    class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        PriorityQueue<ListNode> heap = new PriorityQueue<>(
            (a, b) -> Integer.compare(a.val, b.val));
        for (ListNode head : lists) {
            if (head != null) heap.offer(head);
        }
        ListNode dummy = new ListNode(), tail = dummy;
        while (!heap.isEmpty()) {
            ListNode node = heap.poll();   // smallest front
            tail.next = node;
            tail = node;
            if (node.next != null) heap.offer(node.next);
        }
        return dummy.next;
    }
}

    Time O(N log k) · Space O(k) — every one of the N nodes goes through a heap of at most k nodes.

    Dry run

    heap {1a,1b,2}
poll 1a push 4a  -> 1
poll 1b push 3b  -> 1 1
poll 2  push 6   -> 1 1 2
poll 3b push 4b  -> ... 3   and so on: 1 1 2 3 4 4 5 6

    Watch out

    Skip null lists when building the heap, or the comparator throws. Divide and conquer (merge pairs of lists, then pairs of results) also gives O(N log k) with O(1) extra space besides recursion.

  • Hard632. Smallest Range Covering Elements from K Lists — heap of fronts plus a running max.
    Show solution

    The idea

    Pick one number from each of k sorted lists so that max − min is as small as possible; return [min, max]. Keep exactly one pointer per list. The current range is [smallest front, largest front]. To shrink it, the only useful move is to advance the list holding the minimum. So use a min-heap of fronts plus a running max, and stop when some list runs out.

    Brute force first

    Try every combination of one number per list: exponential. Or put all numbers (tagged with their list) in one sorted array and use a sliding window that covers all k lists: O(N log N), also valid.

    Step by step

    1. Push the first element of each list into a min-heap as (value, list, index); track max of them.
    2. Poll the min. If max - min beats the best range, save [min, max].
    3. If that list has no next element, stop (you can no longer cover every list).
    4. Otherwise push its next element and update max; repeat.

    Java

    class Solution {
    public int[] smallestRange(List<List<Integer>> nums) {
        // entry: {value, listIndex, positionInList}
        PriorityQueue<int[]> heap = new PriorityQueue<>(
            (a, b) -> Integer.compare(a[0], b[0]));
        int max = Integer.MIN_VALUE;
        for (int i = 0; i < nums.size(); i++) {
            int v = nums.get(i).get(0);
            heap.offer(new int[]{v, i, 0});
            max = Math.max(max, v);
        }
        int[] best = {-100000, 100000};
        while (true) {
            int[] top = heap.poll();
            int min = top[0], li = top[1], pos = top[2];
            if (max - min < best[1] - best[0]) {
                best = new int[]{min, max};
            }
            List<Integer> list = nums.get(li);
            if (pos + 1 == list.size()) break; // list done
            int next = list.get(pos + 1);
            heap.offer(new int[]{next, li, pos + 1});
            max = Math.max(max, next);
        }
        return best;
    }
}

    Time O(N log k) · Space O(k) — each of the N numbers is pushed and polled once in a heap of size k.

    Dry run

    fronts 4,0,5  max 5   range [0,5]
pop 0 push 9  max 9   [4,9]
pop 4 push 10 max 10  [5,10]
... later fronts 20,24,22 -> [20,24] (size 4, best)
pop 20: list 2 is done -> stop

    Watch out

    Use strictly smaller (<) when comparing sizes so ties keep the earlier range, which has the smaller start. Stop as soon as the list you just polled is exhausted; continuing would leave that list uncovered.

Test yourself

What does the dummy node save you from?

The special case of the first node: without it you must check "is the answer still empty?" before every hook. With it, tail always exists.

Why is the heap size never more than k?

It holds at most one node per list — the current front. Each poll is followed by at most one push from the same list.

Without a heap, how else can you merge k lists in O(N log k)?

Divide and conquer: merge lists in pairs (1+2, 3+4, …), then pairs of results, for log k rounds, each round O(N).
