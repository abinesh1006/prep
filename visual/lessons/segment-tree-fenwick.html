Segment Tree and Fenwick Tree

When an array keeps changing and you keep asking "what is the sum of positions l to r?", store sums of ranges in a tree so both the change and the question cost O(log n).

Time to learn: about 3 hours · Prerequisites: Prefix sum, Recursion, Bit tricks

When to use it — the signal

Many operations mixed together: "update index i" and "sum / min / max of range [l, r]". A prefix-sum array answers ranges in O(1) but each update costs O(n) to rebuild. Also: "count of smaller numbers after self", "count inversions", "range frequency" — process numbers in order and count with a Fenwick tree.

The idea in plain words

A segment tree is a binary tree over the array. The root stores the sum of the whole array [0..5]. Its left child stores [0..2], its right child [3..5], and so on until each leaf holds one number. 6 numbers → 11 nodes. We keep it in an array: node k has children 2k and 2k + 1 (size 4n is always enough).

  • Query [1..4]: start at the root. If a node's range is completely inside [1..4], use its sum and stop. If it is completely outside, it adds 0. Otherwise ask both children. Only about 2 nodes per level are touched → O(log n).
  • Update index 2: walk down to the leaf for index 2, change it, then fix the sums on the way back up — one node per level → O(log n).

A Fenwick tree (also called a Binary Indexed Tree, BIT) does prefix sums with a single array and two tiny loops. lowbit(i) = i & −i is the value of the lowest 1-bit of i (6 = 110₂ → 2). bit[i] stores the sum of the last lowbit(i) numbers ending at i. To get the sum of a[1..7], jump 7 → 6 → 4 → 0 by subtracting lowbit. To add to a[3], jump 3 → 4 → 8 by adding lowbit.

Analogy

A company's sales report: each shop knows its own total, each region manager knows the total of their shops, the country manager knows the regions. "Sales of shops 2 to 9?" — ask a few managers whose regions fit completely, not every shop. When one shop's number changes, only its chain of managers updates their totals.

Watch it work

1. Build a segment tree (bottom-up through recursion)

2. Query sum [1..4], then update a[2] = 10

3. Fenwick tree — lowbit jumps

1-indexed array a[1..8] = [3, 2, −1, 6, 5, 4, −3, 3] (slot 0 unused). First see what each bit[i] covers, then a prefix query and an update.

When to use which

NeedBest tool
Array never changes, many range sumsPrefix-sum array — O(1) per query
Point updates + range sums (or counts)Fenwick tree — shortest code, O(log n)
Point updates + range min / max / gcdSegment tree (Fenwick cannot "subtract" a min)
Range updates ("add 5 to all of [l, r]") + range queriesSegment tree with lazy propagation
Count smaller elements / inversionsFenwick over values (compress values to 1..n first)

Why it works

"A segment tree splits every query range into at most O(log n) whole nodes, and an update only touches the log n nodes on one root-to-leaf path." "In a Fenwick tree, subtracting the lowest bit jumps to the block just before the current one, so the blocks tile [1..i] exactly; adding the lowest bit jumps to the next block that also contains i."

The template to remember

// Segment tree: node k → children 2k, 2k+1, size 4n
if (outside) return 0;
if (inside)  return tree[k];
return query(left) + query(right);
// Fenwick: lowbit = i & -i
for (; i > 0;  i -= i & -i) s += bit[i];       // prefix
for (; i <= n; i += i & -i) bit[i] += delta;  // update

A Fenwick array is enough for sums with point updates; reach for a real segment tree once you need range updates or max/min.

Remember

Segment tree: outside → 0, inside → take it, partly → split. Fenwick: query subtracts lowbit, update adds lowbit.

Common mistakes
  • Fenwick with index 0 — 0 & −0 = 0, so the loop never moves. Shift everything to 1-based.
  • Segment tree array of size 2n — too small for n that is not a power of two. Use 4n.
  • Fenwick "set a[i] = v": it only supports adding, so add v − a[i] and keep a copy of a.
  • Forgetting to recompute the parent after updating a child in the segment tree.

Practice in this order

  • Medium307. Range Sum Query - Mutable — write both trees for it.
    Show solution

    The idea

    You need two operations that both stay fast: change one number, and get the sum of a range. A plain prefix-sum array makes updates O(n). A Fenwick tree (also called a binary indexed tree) stores partial sums in "boxes". Box i covers the last i & -i positions up to i, where i & -i is the lowest set bit of i. Both operations touch only O(log n) boxes. A segment tree also solves this (point update, range sum), with more code but the same O(log n).

    Brute force first

    Keep the array and sum the range in a loop: O(1) update but O(n) query.

    Step by step

    1. Keep nums (current values) and tree (size n + 1, 1-based).
    2. update(i, val): delta = val − nums[i]. Then, starting at j = i + 1, add delta to tree[j] and do j += j & -j until j > n.
    3. prefix(count): add up tree[j] for j = count, doing j -= j & -j until j reaches 0.
    4. sumRange(l, r) = prefix(r+1) − prefix(l).
    5. Build by calling update for each starting value.

    Java

    class NumArray {
    private final int n;
    private final int[] nums; // current values
    private final int[] tree; // Fenwick tree, 1-based

    public NumArray(int[] nums) {
        n = nums.length;
        this.nums = new int[n];
        tree = new int[n + 1];
        for (int i = 0; i < n; i++) update(i, nums[i]);
    }

    public void update(int index, int val) {
        int delta = val - nums[index];
        nums[index] = val;
        // walk up: add delta to every box that covers index
        for (int i = index + 1; i <= n; i += i & -i)
            tree[i] += delta;
    }

    // sum of nums[0 .. count-1]
    private int prefix(int count) {
        int s = 0;
        for (int i = count; i > 0; i -= i & -i) s += tree[i];
        return s;
    }

    public int sumRange(int left, int right) {
        return prefix(right + 1) - prefix(left);
    }
}

    Time O(log n) per update and query (build O(n log n)) · Space O(n) — each loop moves one bit per step.

    Dry run

    [1,3,5]. tree[1] = 1, tree[2] = 1 + 3 = 4, tree[3] = 5. sumRange(0,2) = prefix(3) = tree[3] + tree[2] = 9. update(1, 2) gives delta −1, so tree[2] = 3. The sum is now 8.

    Watch out

    Fenwick indices start at 1. Index 0 never changes in i += i & -i, so the loop would never end. Store the old value so that you can turn "set" into "add delta".

  • Medium308. Range Sum Query 2D - Mutable — a 2D Fenwick (premium).
    Show solution

    The idea

    The same as 307 but on a grid: update one cell, and get the sum of a rectangle. A 2D Fenwick tree nests the 1D loops, an outer loop over rows and an inner loop over columns. A rectangle sum then comes from four prefix rectangles by inclusion-exclusion (add the big one, subtract two strips, add back the corner subtracted twice).

    Brute force first

    A plain grid gives O(1) updates but O(m · n) per rectangle. Row prefix sums give O(n) per update and O(m) per rectangle. Neither is good when both operations are frequent.

    Step by step

    1. Keep vals and tree[rows+1][cols+1].
    2. update: delta = new − old. For i from row+1 up by i & -i, and j from col+1 up by j & -j, do tree[i][j] += delta.
    3. prefix(r, c): the same nested loops going down, adding tree[i][j]. This is the sum of rows [0, r) and columns [0, c).
    4. sumRegion = P(r2+1, c2+1) − P(r1, c2+1) − P(r2+1, c1) + P(r1, c1).

    Java

    class NumMatrix {
    private final int rows, cols;
    private final int[][] vals; // current values
    private final int[][] tree; // 2D Fenwick, 1-based

    public NumMatrix(int[][] matrix) {
        rows = matrix.length;
        cols = matrix[0].length;
        vals = new int[rows][cols];
        tree = new int[rows + 1][cols + 1];
        for (int r = 0; r < rows; r++)
            for (int c = 0; c < cols; c++)
                update(r, c, matrix[r][c]);
    }

    public void update(int row, int col, int val) {
        int delta = val - vals[row][col];
        vals[row][col] = val;
        for (int i = row + 1; i <= rows; i += i & -i)
            for (int j = col + 1; j <= cols; j += j & -j)
                tree[i][j] += delta;
    }

    // sum of the rectangle rows [0, r), cols [0, c)
    private int prefix(int r, int c) {
        int s = 0;
        for (int i = r; i > 0; i -= i & -i)
            for (int j = c; j > 0; j -= j & -j)
                s += tree[i][j];
        return s;
    }

    public int sumRegion(int row1, int col1,
                         int row2, int col2) {
        // inclusion-exclusion on four prefix rectangles
        return prefix(row2 + 1, col2 + 1)
             - prefix(row1, col2 + 1)
             - prefix(row2 + 1, col1)
             + prefix(row1, col1);
    }
}

    Time O(log m · log n) per operation · Space O(m · n) — nested log loops.

    Dry run

    In the example, region (2,1)–(4,3) sums to 8. update(3,2,2) changes 0 to 2, so delta = +2 and the region becomes 10.

    Watch out

    The +1 shifts on each side are easy to mix up. The four-corner formula takes prefix(row1, …) without +1, because prefix is exclusive.

  • Hard315. Count of Smaller Numbers After Self — scan from the right, Fenwick over values.
    Show solution

    The idea

    For each number, count how many numbers to its right are smaller. Walk from right to left and keep a Fenwick tree over the values seen so far (tree[v] = how many times value v was seen). For nums[i], the answer is the prefix count of values below it. Then add nums[i]. Values lie in [−10⁴, 10⁴], so shift them by 10001 to make every index ≥ 1. Pattern: Fenwick over values.

    Brute force first

    For each i, scan everything to its right: O(n²). Merge sort counting is the other O(n log n) answer.

    Step by step

    1. Make a Fenwick tree of size 20002. index = value + 10001.
    2. For i from n−1 down to 0: res[i] = prefix sum up to index − 1 (values strictly smaller).
    3. Then add 1 at index, so that this value counts for the numbers to its left.
    4. Return res as a list.

    Java

    class Solution {
    public List<Integer> countSmaller(int[] nums) {
        final int OFFSET = 10001; // -10^4 becomes index 1
        int size = 20002;
        int[] tree = new int[size + 1];
        Integer[] res = new Integer[nums.length];
        for (int i = nums.length - 1; i >= 0; i--) {
            int idx = nums[i] + OFFSET;
            // how many seen values are <= idx - 1
            int count = 0;
            for (int j = idx - 1; j > 0; j -= j & -j)
                count += tree[j];
            res[i] = count;
            // now mark this value as seen
            for (int j = idx; j <= size; j += j & -j)
                tree[j]++;
        }
        return Arrays.asList(res);
    }
}

    Time O(n log V) · Space O(V) — V ≈ 20001 possible values, and each step is a log V walk.

    Dry run

    [5,2,6,1], from the right. 1: nothing seen, so 0. 6: 1 is smaller, so 1. 2: 1 is smaller, so 1. 5: 2 and 1 are smaller, so 2. Result [2,1,1,0].

    Watch out

    Query idx − 1, not idx, or equal values count as "smaller" (try [−1,−1], whose answer is [0,0]).

  • Hard493. Reverse Pairs — Fenwick with compressed values.
    Show solution

    The idea

    Count pairs i < j with nums[i] > 2 · nums[j]. Walk left to right. For each x, count the earlier values bigger than 2x, then add x. Values go up to 2³¹, so compress them: sort the distinct values and use the rank (position) as the Fenwick index. "Earlier values > 2x" = seen − (earlier values ≤ 2x), and a binary search turns 2x into a rank. Pattern: Fenwick with coordinate compression.

    Brute force first

    Check all pairs: O(n²). Merge-sort counting is the other standard O(n log n) answer.

    Step by step

    1. Copy the values into a long array, sort it and remove duplicates. That gives m distinct values.
    2. For each x: pos = number of distinct values ≤ 2x (binary search). notBigger = prefix(pos).
    3. pairs += seen − notBigger.
    4. Add 1 at x's rank (number of values ≤ x, which is 1-based), then seen++.

    Java

    class Solution {
    public int reversePairs(int[] nums) {
        int n = nums.length;
        // sorted distinct values, for compression
        long[] sorted = new long[n];
        for (int i = 0; i < n; i++) sorted[i] = nums[i];
        Arrays.sort(sorted);
        int m = 0;
        for (int i = 0; i < n; i++)
            if (m == 0 || sorted[i] != sorted[m - 1])
                sorted[m++] = sorted[i];
        int[] tree = new int[m + 1];
        int pairs = 0, seen = 0;
        for (int x : nums) {
            // count earlier values > 2x = seen - (values <= 2x)
            int pos = upperBound(sorted, m, 2L * x); // # <= 2x
            int notBigger = 0;
            for (int j = pos; j > 0; j -= j & -j)
                notBigger += tree[j];
            pairs += seen - notBigger;
            // add x at its compressed index (1-based)
            int idx = upperBound(sorted, m, x);
            for (int j = idx; j <= m; j += j & -j) tree[j]++;
            seen++;
        }
        return pairs;
    }

    // number of values in sorted[0..m) that are <= key
    private int upperBound(long[] a, int m, long key) {
        int lo = 0, hi = m;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] <= key) lo = mid + 1;
            else hi = mid;
        }
        return lo;
    }
}

    Time O(n log n) · Space O(n) — a sort plus two binary searches and two Fenwick walks per element.

    Dry run

    [1,3,2,3,1]. At the last 1, 2x = 2 and the earlier values are 1,3,2,3. The ones bigger than 2 are the two 3s, which adds 2. No other position adds anything, so the total is 2.

    Watch out

    2 * x overflows int when x is near 2³¹. Use 2L * x and a long array.

  • Hard327. Count of Range Sum — prefix sums + Fenwick.
    Show solution

    The idea

    Count the blocks whose sum is in [lower, upper]. With prefix sums, block (i, j] has sum pre[j] − pre[i]. So for each j, count the earlier i with pre[j] − upper ≤ pre[i] ≤ pre[j] − lower. That is a range count over earlier values, done with a Fenwick tree over compressed prefix values. Pattern: prefix sums + Fenwick.

    Brute force first

    Try every (i, j): O(n²). Merge sort on the prefix array is the other O(n log n) answer.

    Step by step

    1. Build pre (n + 1 longs, pre[0] = 0).
    2. Sort and remove duplicates to get the rank table.
    3. For each p in pre, in order: hi = count of ranks ≤ p − lower, lo = count of ranks ≤ p − upper − 1.
    4. count += prefix(hi) − prefix(lo), which counts the earlier prefixes inside the window.
    5. Insert p at its rank.

    Java

    class Solution {
    public int countRangeSum(int[] nums, int lower, int upper) {
        int n = nums.length;
        long[] pre = new long[n + 1];
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];
        // compress the prefix values
        long[] sorted = pre.clone();
        Arrays.sort(sorted);
        int m = 0;
        for (int i = 0; i <= n; i++)
            if (m == 0 || sorted[i] != sorted[m - 1])
                sorted[m++] = sorted[i];
        int[] tree = new int[m + 1];
        int count = 0;
        for (long p : pre) {
            // earlier q with p - upper <= q <= p - lower
            int hi = countLE(sorted, m, p - lower);
            int lo = countLE(sorted, m, p - upper - 1);
            count += query(tree, hi) - query(tree, lo);
            add(tree, countLE(sorted, m, p), m); // insert p
        }
        return count;
    }

    private int query(int[] tree, int i) {
        int s = 0;
        for (; i > 0; i -= i & -i) s += tree[i];
        return s;
    }

    private void add(int[] tree, int i, int m) {
        for (; i <= m; i += i & -i) tree[i]++;
    }

    // number of values in a[0..m) that are <= key
    private int countLE(long[] a, int m, long key) {
        int lo = 0, hi = m;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] <= key) lo = mid + 1;
            else hi = mid;
        }
        return lo;
    }
}

    Time O(n log n) · Space O(n) — compression plus log-time queries.

    Dry run

    [−2,5,−1], range [−2,2]. pre = 0, −2, 3, 2. At −2: −2 − 0 = −2 is in range, so +1. At 3: 3 − 0 = 3 and 3 − (−2) = 5 are both out, so +0. At 2: 2 − 0 = 2 and 2 − 3 = −1 are in, 2 − (−2) = 4 is out, so +2. Total 3.

    Watch out

    Insert p after querying, otherwise the empty block (i = j) is counted. Use long, because sums of ±2³¹ overflow int.

  • Hard732. My Calendar III — segment tree with range add + max.
    Show solution

    The idea

    After each booking [start, end), report the largest number of bookings that overlap at any moment. Think of a timeline where each booking adds +1 to every time in [start, end − 1], and the answer is the max over the timeline. That is range add + global max: a segment tree with lazy propagation (a pending "+x" stored on a node and handed down to its children only when needed). Times go up to 10⁹, so create nodes only when they are first visited (a dynamic segment tree). A sweep with a TreeMap of +1/−1 events is the simpler O(n²) alternative.

    Step by step

    1. Each node stores max (the most overlaps in its range) and lazy (an add not yet pushed down).
    2. book: add +1 over [start, end−1] starting at the root range [0, 10⁹].
    3. If a node's range is fully inside, do max++ and lazy++, then stop.
    4. Otherwise create the children, push the lazy value down, recurse into both halves, and set max = the larger child max.
    5. Return root.max.

    Java

    class MyCalendarThree {
    // a segment tree node, made only when needed
    private static class Node {
        int max;  // most overlaps anywhere in this range
        int lazy; // +lazy still to push to both children
        Node left, right;
    }

    private final Node root = new Node();

    public int book(int startTime, int endTime) {
        // the booking covers times startTime .. endTime-1
        add(root, 0, 1_000_000_000, startTime, endTime - 1);
        return root.max;
    }

    private void add(Node node, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return; // no overlap
        if (l <= lo && hi <= r) {     // fully covered
            node.max++;
            node.lazy++;
            return;
        }
        int mid = lo + (hi - lo) / 2;
        if (node.left == null) node.left = new Node();
        if (node.right == null) node.right = new Node();
        push(node);
        add(node.left, lo, mid, l, r);
        add(node.right, mid + 1, hi, l, r);
        node.max = Math.max(node.left.max, node.right.max);
    }

    // hand a pending +lazy down to the children
    private void push(Node node) {
        if (node.lazy == 0) return;
        node.left.max += node.lazy;
        node.left.lazy += node.lazy;
        node.right.max += node.lazy;
        node.right.lazy += node.lazy;
        node.lazy = 0;
    }
}

    Time O(log C) per booking, C = 10⁹ · Space O(n log C) nodes — each booking touches about 4 log C nodes.

    Dry run

    book(10,20) gives 1, book(50,60) gives 1, book(10,40) overlaps [10,20) for 2, book(5,15) makes [10,15) 3 deep. The next two bookings never go above 3.

    Watch out

    Bookings are half-open, so update end − 1. Without that, [5,10) and [10,40) would wrongly overlap at 10. Push the lazy value before recursing, or the children read stale counts.

Test yourself

What is lowbit(12)?

12 = 1100₂, the lowest 1-bit is 100₂ = 4.

Which cells change when you add to a[5] in a Fenwick tree of size 8?

5 → 6 → 8 (5 + 1 = 6, 6 + 2 = 8).

Why can a Fenwick tree not answer range minimum in general?

Range answers come from prefix(r) − prefix(l − 1). There is no "subtract" for min, so you cannot remove the part before l.

In the segment tree query, what are the three cases?

Node range outside the query → 0; completely inside → its stored value; partly inside → combine the answers of both children.
