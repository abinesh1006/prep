Segment Tree and Fenwick Tree

When an array keeps changing and you keep asking "what is the sum of positions l to r?", store sums of ranges in a tree so both the change and the question cost O(log n).

Time to learn: about 3 hours · Prerequisites: Prefix sum, Recursion, Bit tricks

When to use it — the signal

Many operations mixed together: "update index i" and "sum / min / max of range [l, r]". A prefix-sum array answers ranges in O(1) but each update costs O(n) to rebuild. Also: "count of smaller numbers after self", "count inversions", "range frequency" — process numbers in order and count with a Fenwick tree.

The idea in plain words

A segment tree is a binary tree over the array. The root stores the sum of the whole array [0..5]. Its left child stores [0..2], its right child [3..5], and so on until each leaf holds one number. 6 numbers → 11 nodes. We keep it in an array: node k has children 2k and 2k + 1 (size 4n is always enough).

  • Query [1..4]: start at the root. If a node's range is completely inside [1..4], use its sum and stop. If it is completely outside, it adds 0. Otherwise ask both children. Only about 2 nodes per level are touched → O(log n).
  • Update index 2: walk down to the leaf for index 2, change it, then fix the sums on the way back up — one node per level → O(log n).

A Fenwick tree (also called a Binary Indexed Tree, BIT) does prefix sums with a single array and two tiny loops. lowbit(i) = i & −i is the value of the lowest 1-bit of i (6 = 110₂ → 2). bit[i] stores the sum of the last lowbit(i) numbers ending at i. To get the sum of a[1..7], jump 7 → 6 → 4 → 0 by subtracting lowbit. To add to a[3], jump 3 → 4 → 8 by adding lowbit.

Analogy

A company's sales report: each shop knows its own total, each region manager knows the total of their shops, the country manager knows the regions. "Sales of shops 2 to 9?" — ask a few managers whose regions fit completely, not every shop. When one shop's number changes, only its chain of managers updates their totals.

When to use which

NeedBest tool
Array never changes, many range sumsPrefix-sum array — O(1) per query
Point updates + range sums (or counts)Fenwick tree — shortest code, O(log n)
Point updates + range min / max / gcdSegment tree (Fenwick cannot "subtract" a min)
Range updates ("add 5 to all of [l, r]") + range queriesSegment tree with lazy propagation
Count smaller elements / inversionsFenwick over values (compress values to 1..n first)

Why it works

"A segment tree splits every query range into at most O(log n) whole nodes, and an update only touches the log n nodes on one root-to-leaf path." "In a Fenwick tree, subtracting the lowest bit jumps to the block just before the current one, so the blocks tile [1..i] exactly; adding the lowest bit jumps to the next block that also contains i."

The template to remember

// Segment tree: node k → children 2k, 2k+1, size 4n
if (outside) return 0;
if (inside)  return tree[k];
return query(left) + query(right);
// Fenwick: lowbit = i & -i
for (; i > 0;  i -= i & -i) s += bit[i];       // prefix
for (; i <= n; i += i & -i) bit[i] += delta;  // update
Remember

Segment tree: outside → 0, inside → take it, partly → split. Fenwick: query subtracts lowbit, update adds lowbit.

Common mistakes
  • Fenwick with index 0 — 0 & −0 = 0, so the loop never moves. Shift everything to 1-based.
  • Segment tree array of size 2n — too small for n that is not a power of two. Use 4n.
  • Fenwick "set a[i] = v": it only supports adding, so add v − a[i] and keep a copy of a.
  • Forgetting to recompute the parent after updating a child in the segment tree.

Test yourself

What is lowbit(12)?

12 = 1100₂, the lowest 1-bit is 100₂ = 4.

Which cells change when you add to a[5] in a Fenwick tree of size 8?

5 → 6 → 8 (5 + 1 = 6, 6 + 2 = 8).

Why can a Fenwick tree not answer range minimum in general?

Range answers come from prefix(r) − prefix(l − 1). There is no "subtract" for min, so you cannot remove the part before l.

In the segment tree query, what are the three cases?

Node range outside the query → 0; completely inside → its stored value; partly inside → combine the answers of both children.
