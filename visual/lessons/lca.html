Lowest Common Ancestor

The lowest node that has both p and q below it (or is one of them) — the point where the two paths from the root split apart.

Time to learn: about 1.5 hours · Prerequisites: Tree recursion, Binary search trees

When to use it — the signal

"Lowest common ancestor", "first shared manager of two employees", "distance between two nodes" (= depth(p) + depth(q) − 2 × depth(LCA)), "smallest subtree containing both", "where do the paths to p and q meet".

The idea in plain words

An ancestor of a node = its parent, its parent's parent, and so on up to the root (we also count the node itself). A common ancestor of p and q is an ancestor of both — the root always is one. The lowest common ancestor (LCA) is the deepest one: walk down from the root along the path to p and the path to q; the LCA is the last node the two paths share.

In a BST the values tell you where p and q are. At each node: if both are smaller, both are in the left subtree → go left. If both are bigger → go right. Otherwise they are on different sides (or one of them is this node) → this is the split point, the LCA. One path down: O(h).

In a plain binary tree there is no order, so ask each subtree a question by recursion: "did you find p or q down there?" Each call returns the p or q it found (or the LCA if it found both), else null.

  • If the node is p or q → return it (no need to look below).
  • If the left side found something and the right side found something → p and q are on different sides → I am the LCA.
  • Otherwise pass up whatever one side found (or null).

That visits each node at most once: O(n) time, O(h) stack.

Analogy

A family tree: the lowest common ancestor of you and your cousin is your shared grandparent — not your great-grandparent (also shared, but higher). In a company, it is the first manager both employees report up to. Ask each department "is either of the two people in your team?" — the manager whose two different teams both say "yes" is the one.

Why it works

"In a BST, if p and q are both smaller than the node they are both on the left, so the LCA is too; when they fall on different sides, this node is the deepest one above both. In a binary tree, each call returns p, q or the LCA if it is in that subtree; the first node that hears 'found' from both sides is the split point. BST version O(h), general version O(n)."

The template to remember

// BST: walk to the split point
while (true) {
    if (p < node.val && q < node.val) node = node.left;
    else if (p > node.val && q > node.val) node = node.right;
    else return node;
}
// Binary tree: who found what?
if (node == null || node == p || node == q) return node;
l = lca(left); r = lca(right);
return l != null && r != null ? node : (l != null ? l : r);
Remember

BST: both smaller → left, both bigger → right, else here. Binary tree: found on both sides → me; else pass up the side that found something.

Common mistakes
  • Forgetting that a node is its own ancestor: LCA(2, 4) is 2 if 4 is below 2.
  • Using the BST shortcut on a tree that is not a BST — the values say nothing about where nodes are.
  • Comparing values instead of nodes in the general version when values can repeat. Compare references: node == p.
  • If p or q might be missing from the tree, the basic version returns the one it found. Count how many were really found (LC 1644).

  • Medium235. LCA of a Binary Search Tree — animation 1.
    Show solution

    The idea

    The LCA (lowest common ancestor) of p and q is the deepest node that has both of them in its subtree (a node counts as its own ancestor). In a BST you can steer: if both values are smaller than the current node, the LCA is on the left; if both are bigger, on the right; otherwise they split here (or one of them is here), so this is the LCA.

    Step by step

    1. Start at the root.
    2. If p and q are both smaller, move left.
    3. If both are bigger, move right.
    4. Otherwise return the current node.

    Java

    class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root,
            TreeNode p, TreeNode q) {
        TreeNode cur = root;
        while (cur != null) {
            if (p.val < cur.val && q.val < cur.val) {
                cur = cur.left;       // both on the left
            } else if (p.val > cur.val && q.val > cur.val) {
                cur = cur.right;      // both on the right
            } else {
                return cur;           // they split here
            }
        }
        return null;                  // never reached
    }
}

    Time O(h) · Space O(1) — one path down, no recursion.

    Dry run

    [6,2,8,0,4,7,9,null,null,3,5], p = 2, q = 4: at 6 both smaller → left; at 2, 2 is not smaller than 2 → split → return 2.

    Watch out

    Use strict comparisons: when p or q equals the current node, that node is the answer.

  • Medium236. LCA of a Binary Tree — animation 2.
    Show solution

    The idea

    Same question, but in a plain binary tree, so values do not tell you where to go. Ask each subtree: "did you find p or q?" If p is found on one side and q on the other, I am the LCA. If only one side found something, pass that up. A node that is p or q reports itself.

    Step by step

    1. If the node is null, p, or q, return it.
    2. Ask the left subtree and the right subtree.
    3. If both answers are non-null, p and q are on different sides: return this node.
    4. Otherwise return whichever answer is non-null (or null).

    Java

    class Solution {
    public TreeNode lowestCommonAncestor(TreeNode root,
            TreeNode p, TreeNode q) {
        // empty, or I am one of the two: report myself
        if (root == null || root == p || root == q) {
            return root;
        }
        TreeNode left = lowestCommonAncestor(root.left, p, q);
        TreeNode right =
            lowestCommonAncestor(root.right, p, q);
        if (left != null && right != null) {
            return root;     // one found on each side: me
        }
        return left != null ? left : right; // pass it up
    }
}

    Time O(n) · Space O(h) — each node visited at most once.

    Dry run

    [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4: the left call reaches 5 and returns 5 at once; the right call (subtree 1) finds nothing → null. At 3: only left is non-null → answer 5 (5 is an ancestor of 4).

    Watch out

    Returning early when the node is p is correct even if q is below it: then p is the LCA. That is why the problem promises both nodes exist.

  • Medium1123. LCA of Deepest Leaves — return (depth, lca) from each side; equal depths → me.
    Show solution

    The idea

    Find the smallest subtree that contains all the deepest leaves. Each call returns two things: the depth of its subtree and the LCA of its deepest leaves. If the left side is deeper, the answer lives there; if the right is deeper, there; if equal, the deepest leaves are on both sides, so I am the answer.

    Step by step

    1. Null node: depth 0, no node.
    2. Get the left and right results.
    3. Left deeper: return (left depth + 1, left's node).
    4. Right deeper: return (right depth + 1, right's node).
    5. Equal: return (depth + 1, me).

    Java

    class Solution {
    // what each subtree reports to its parent
    record Result(int depth, TreeNode lca) {}

    public TreeNode lcaDeepestLeaves(TreeNode root) {
        return dfs(root).lca();
    }

    private Result dfs(TreeNode n) {
        if (n == null) return new Result(0, null);
        Result l = dfs(n.left);
        Result r = dfs(n.right);
        if (l.depth() > r.depth()) { // deeper on left
            return new Result(l.depth() + 1, l.lca());
        }
        if (r.depth() > l.depth()) { // deeper on right
            return new Result(r.depth() + 1, r.lca());
        }
        return new Result(l.depth() + 1, n); // tie: me
    }
}

    Time O(n) · Space O(h) — one visit per node. A Java record is a short way to return two values.

    Dry run

    [3,5,1,6,2,0,8,null,null,7,4]: at 2, children 7 and 4 both depth 1 → (2, node 2). At 5: left 6 is depth 1, right is depth 2 → (3, node 2). At 1: (2, node 1). At 3: left 3 > right 2 → node 2.

    Watch out

    A single deepest leaf is its own answer: if one leaf is deepest, the result is that leaf, not its parent.

  • Medium2096. Step-By-Step Directions From a Binary Tree Node to Another — find both root paths, drop the shared prefix.
    Show solution

    The idea

    Give directions from node startValue to node destValue: "U" goes to the parent, "L"/"R" to a child. Every route goes up from the start to their LCA and then down to the destination. Find the path from the root to each node as a string of L/R; the shared beginning of the two strings is the way to the LCA. Drop it: each remaining start step becomes a "U", and the remaining dest steps stay.

    Step by step

    1. find searches for a value and, on the way back up, appends 'L' or 'R'; this builds the path backwards, so reverse it.
    2. Get both root paths.
    3. Count how many first letters they share.
    4. Answer = "U" repeated (start path length − shared) + the rest of the dest path.

    Java

    class Solution {
    public String getDirections(TreeNode root,
            int startValue, int destValue) {
        StringBuilder s = new StringBuilder();
        StringBuilder d = new StringBuilder();
        find(root, startValue, s);    // root -> start
        find(root, destValue, d);     // root -> dest
        // find() writes the path bottom-up; flip it
        s.reverse();
        d.reverse();
        int i = 0;                    // skip shared prefix
        while (i < s.length() && i < d.length()
                && s.charAt(i) == d.charAt(i)) {
            i++;
        }
        // climb from start to the split, then walk down
        return "U".repeat(s.length() - i) + d.substring(i);
    }

    // true if val is under n; appends moves on the way back
    private boolean find(TreeNode n, int val,
                         StringBuilder path) {
        if (n == null) return false;
        if (n.val == val) return true;
        if (find(n.left, val, path)) {
            path.append('L');
            return true;
        }
        if (find(n.right, val, path)) {
            path.append('R');
            return true;
        }
        return false;
    }
}

    Time O(n) · Space O(n) — two searches over the tree and paths up to n long.

    Dry run

    [5,1,2,3,null,6,4], start 3, dest 6: root → 3 is "LL", root → 6 is "RL". Shared prefix 0. Answer "UU" + "RL" = "UURL".

    Watch out

    Build paths with a StringBuilder, not string concatenation inside recursion. On a 100,000-node chain the recursion is very deep; an iterative search avoids stack overflow if it appears.

  • Medium863. All Nodes Distance K in Binary Tree — add parent links, then BFS from the target.
    Show solution

    The idea

    List every node exactly k edges away from target. Distances can go up through parents, but tree nodes only point down. So first record each node's parent in a map; then the tree is just a graph, and a BFS from target, ring by ring, finds the nodes at distance k.

    Step by step

    1. DFS once to fill parent for every node.
    2. Start a BFS from target with a seen set.
    3. Repeat k times: expand the current ring to left child, right child and parent, skipping null and seen nodes.
    4. What is left in the queue is the ring at distance k; return its values.

    Java

    class Solution {
    private Map<TreeNode, TreeNode> parent = new HashMap<>();

    public List<Integer> distanceK(TreeNode root,
            TreeNode target, int k) {
        link(root, null);        // 1. remember every parent
        // 2. BFS outward from target: left, right and up
        Queue<TreeNode> q = new ArrayDeque<>();
        Set<TreeNode> seen = new HashSet<>();
        q.offer(target);
        seen.add(target);
        for (int dist = 0; dist < k && !q.isEmpty(); dist++) {
            int size = q.size();
            for (int i = 0; i < size; i++) {
                TreeNode n = q.poll();
                for (TreeNode nb : new TreeNode[]{
                        n.left, n.right, parent.get(n)}) {
                    if (nb != null && seen.add(nb)) {
                        q.offer(nb);
                    }
                }
            }
        }
        List<Integer> out = new ArrayList<>(); // ring k
        for (TreeNode n : q) out.add(n.val);
        return out;
    }

    private void link(TreeNode n, TreeNode p) {
        if (n == null) return;
        parent.put(n, p);
        link(n.left, n);
        link(n.right, n);
    }
}

    Time O(n) · Space O(n) — the parent map, the seen set and the queue each hold up to n nodes.

    Dry run

    Target 5, k = 2. Ring 1: 6, 2, 3. Ring 2: from 6 nothing; from 2 → 7, 4; from 3 → 1. Answer [7,4,1].

    Watch out

    Without the seen set the BFS walks back down to where it came from and counts nodes twice. k = 0 must return just the target.

Test yourself

In the BST above (root 6), what is LCA(0, 3)?

2: at 6 both are smaller → left to 2; at 2, 0 < 2 < 3, so they split at 2.

Why does the general version return as soon as node == p, without searching below?

If q is below p, p is the LCA. If q is elsewhere, some higher node will hear "found" from both sides. Either way nothing below p changes the answer.

How do you get the distance between p and q using the LCA?

depth(p) + depth(q) − 2 × depth(LCA): go up from p to the LCA, then down to q.

What is the time of each version on a balanced tree with n nodes?

BST version O(log n) (one path). General version O(n) (it may need to look at every node).
