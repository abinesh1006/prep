Grid BFS and DFS

A 2D grid is a graph in disguise: every cell is a node and its up/down/left/right cells are its neighbours, so islands are found with a DFS "flood fill" and shortest routes with a BFS.

Time to learn: about 2.5 hours · Prerequisites: Graph basics, Recursion

When to use it — the signal

The input is a matrix / board / map of 0s and 1s (or letters), and the question says "island", "region", "connected cells", "flood / paint", "enclosed", or "shortest path from the top-left to the bottom-right".

The idea in plain words

Look at a 4 × 5 grid of land (1) and water (0). You never build an adjacency list: the neighbours of cell (r, c) are simply (r+1, c), (r−1, c), (r, c+1), (r, c−1) — as long as they are inside the grid. Some problems also allow the 4 diagonals (8 neighbours).

  • Counting islands (groups of touching land): scan the grid row by row. The first time you step on land you have never seen, that is a new island — add 1 to the count, then "flood" it: visit every land cell you can reach from there and mark it, so the scan will not count it again.
  • Shortest path: start a BFS from the start cell. Write 1 in it, then 2 in every free neighbour, then 3 in their free neighbours... The number that lands on the target is the length of the shortest route.

Marking can be done in place (without a separate visited array): overwrite a visited land cell with 0 so it looks like water. A grid of R rows and C columns is visited in O(R × C).

Analogy

Counting islands is like spilling paint: you find an unpainted island, pour a bucket on one square, and the paint runs into every connected land square. Count the buckets you used. Shortest path is like dropping a stone in a pond — the ripple reaches nearby squares first, and the ring number when it hits the corner is the distance.

Watch it work

1. Number of Islands (DFS flood fill). Land is "1", water is shown dark. Each island gets a letter as it is flooded. The panel under the grid is the recursion stack — the cells whose calls are still open.

2. Shortest Path in Binary Matrix (BFS). 0 = free, ■ = blocked. Move in 8 directions (diagonals allowed) from the top-left to the bottom-right. BFS writes the distance (counted in cells, start = 1) into each cell it reaches.

Why it works

"Each scan that lands on unvisited land must be a new island, because flood fill already marked every cell connected to earlier islands — so the count equals the number of flood fills. For shortest path, BFS on an unweighted grid visits cells in increasing distance, so the first time it reaches the target is via the fewest moves."

The template to remember

int[][] DIRS = {{1,0},{-1,0},{0,1},{0,-1}};
// count regions: scan + flood
for (r...) for (c...) if (isTarget(r, c)) { count++; dfs(r, c); }
void dfs(int r, int c) {
    if (outside || !isTarget(r, c)) return;
    mark(r, c);                         // BEFORE recursing
    for (int[] d : DIRS) dfs(r + d[0], c + d[1]);
}
// shortest path: BFS, dist[start] = 1, dist[next] = dist[cur] + 1
Remember

Grid = graph with 4 (or 8) neighbours. Count groups → scan + DFS flood. Fewest moves → BFS with distances.

Common mistakes
  • Marking a cell after the recursive calls — neighbours come back to it and you loop forever.
  • Checking bounds after reading g[r][c] — ArrayIndexOutOfBounds. Bounds first.
  • Using DFS for shortest path — it finds a path, not the shortest.
  • Forgetting the start (or end) cell may itself be blocked in LC 1091.

Practice in this order

  • Easy733. Flood Fill — the flood without the scan.
    Show solution

    The idea

    Like the paint-bucket tool: starting at pixel (sr, sc), repaint it and every pixel of the same old colour connected to it up, down, left or right. Key insight: a grid is a graph where each cell's neighbours are its 4 sides. Painting a cell also marks it visited, because a painted cell no longer has the old colour. Pattern: grid DFS / flood fill.

    Step by step

    1. Remember old = image[sr][sc]. If it already equals the new colour, return the image unchanged.
    2. Call fill(sr, sc).
    3. In fill: stop if the cell is off the grid or its colour is not old.
    4. Otherwise paint it, then call fill on its 4 neighbours.

    Java

    class Solution {
    public int[][] floodFill(int[][] image, int sr, int sc,
                             int color) {
        int old = image[sr][sc];
        if (old == color) return image; // nothing to change
        fill(image, sr, sc, old, color);
        return image;
    }

    private void fill(int[][] img, int r, int c,
                      int old, int color) {
        if (r < 0 || c < 0 || r >= img.length
                || c >= img[0].length) return; // off the grid
        if (img[r][c] != old) return;   // other colour or done
        img[r][c] = color;              // paint = mark visited
        fill(img, r + 1, c, old, color);
        fill(img, r - 1, c, old, color);
        fill(img, r, c + 1, old, color);
        fill(img, r, c - 1, old, color);
    }
}

    Time O(m·n) · Space O(m·n) — each cell is painted at most once; the recursion can be as deep as the region.

    Dry run

    [[1,1,1],[1,1,0],[1,0,1]], start (1,1), colour 2. old = 1. Paint (1,1), spread to (0,1), (0,0), (0,2), (1,0), (2,0). (1,2) is 0 and (2,1) is 0, so they stop the fill, and (2,2) is never reached. Result [[2,2,2],[2,2,0],[2,0,1]].

    Watch out

    If the new colour equals the old one, the "has old colour" check never fails, and the recursion runs forever (stack overflow). The early return fixes that.

  • Medium200. Number of Islands — exactly animation 1.
    Show solution

    The idea

    In a grid of '1' (land) and '0' (water), count islands: groups of land joined up, down, left or right. Key insight: scan every cell; each time you hit land you have not visited, that is a new island, so count it and immediately "sink" the whole island with DFS so it is never counted again. Pattern: scan + flood fill (count connected components).

    Step by step

    1. Loop over every cell.
    2. When a cell is '1', add 1 to the count and call sink on it.
    3. sink stops on off-grid or non-'1' cells; otherwise it sets the cell to '0' and recurses on the 4 neighbours.
    4. Return the count after the scan.

    Java

    class Solution {
    public int numIslands(char[][] grid) {
        int islands = 0;
        for (int r = 0; r < grid.length; r++) {
            for (int c = 0; c < grid[0].length; c++) {
                if (grid[r][c] == '1') { // land not seen yet
                    islands++;
                    sink(grid, r, c);    // erase this island
                }
            }
        }
        return islands;
    }

    private void sink(char[][] g, int r, int c) {
        if (r < 0 || c < 0 || r >= g.length
                || c >= g[0].length || g[r][c] != '1') {
            return;
        }
        g[r][c] = '0';                   // mark visited
        sink(g, r + 1, c);
        sink(g, r - 1, c);
        sink(g, r, c + 1);
        sink(g, r, c - 1);
    }
}

    Time O(m·n) · Space O(m·n) — every cell is visited a constant number of times; worst-case recursion depth is the whole grid.

    Dry run

    (0,0) is land → count 1, sink the 2×2 block. (2,2) → count 2, sink it. (3,3) → count 3, sink (3,3) and (3,4). Answer 3.

    Watch out

    Diagonal cells do not count as touching; use only 4 directions. If you must not change the input, use a separate boolean[][] seen instead of writing '0'. BFS or Union-Find also work.

  • Medium695. Max Area of Island — dfs returns 1 + sum of the four calls.
    Show solution

    The idea

    Same grid of 1s and 0s, but now return the size of the biggest island. Key insight: let the DFS return a number. The area of an island from a cell = 1 (this cell) + the areas found from its 4 neighbours, and water or visited cells give 0. Pattern: flood fill that returns a count.

    Step by step

    1. For every cell, call area(r, c) and keep the maximum.
    2. In area: return 0 if off-grid or not land.
    3. Set the cell to 0 so it is never counted twice.
    4. Return 1 + the four recursive calls added together.

    Java

    class Solution {
    public int maxAreaOfIsland(int[][] grid) {
        int best = 0;
        for (int r = 0; r < grid.length; r++) {
            for (int c = 0; c < grid[0].length; c++) {
                best = Math.max(best, area(grid, r, c));
            }
        }
        return best;
    }

    // size of the island touching (r, c); 0 for water
    private int area(int[][] g, int r, int c) {
        if (r < 0 || c < 0 || r >= g.length
                || c >= g[0].length || g[r][c] != 1) {
            return 0;
        }
        g[r][c] = 0;                     // mark visited
        return 1 + area(g, r + 1, c) + area(g, r - 1, c)
                 + area(g, r, c + 1) + area(g, r, c - 1);
    }
}

    Time O(m·n) · Space O(m·n) — each land cell is counted once; recursion depth up to the island size.

    Dry run

    Grid [[1,1],[0,1]]. area(0,0): mark it, 1 + area(1,0)=0 + area(0,1). area(0,1): mark it, 1 + area(1,1)=1 + others 0 = 2. So area(0,0) = 1 + 2 = 3. Other cells now give 0. Max 3.

    Watch out

    Mark the cell before recursing into neighbours, or two neighbours can count each other again and again. An all-water grid must return 0, which the starting value best = 0 covers.

  • Medium1091. Shortest Path in Binary Matrix — exactly animation 2.
    Show solution

    The idea

    In an n×n grid of 0 (open) and 1 (blocked), find the shortest path from top-left to bottom-right, moving in 8 directions (diagonals too). The length counts cells, so a 1×1 grid answers 1. Key insight: every move costs the same, so BFS finds the shortest path: it explores all cells 1 step away, then 2 steps, and so on, so the first time it reaches the end is the shortest.

    Step by step

    1. If the start or the end cell is 1, return −1.
    2. Queue (0,0), mark it visited (set it to 1), and set length = 1.
    3. Process the queue one level at a time: everything in it now is length cells from the start.
    4. For each cell, return length if it is the end; otherwise queue all 8 open, unvisited neighbours and mark them.
    5. After each level add 1 to length. If the queue empties, return −1.

    Java

    class Solution {
    public int shortestPathBinaryMatrix(int[][] grid) {
        int n = grid.length;
        if (grid[0][0] == 1 || grid[n - 1][n - 1] == 1) {
            return -1;                   // start or end blocked
        }
        Deque<int[]> queue = new ArrayDeque<>();
        queue.add(new int[]{0, 0});
        grid[0][0] = 1;                  // mark visited
        int length = 1;                  // cells on the path
        while (!queue.isEmpty()) {
            // everything in the queue now is `length` away
            for (int size = queue.size(); size > 0; size--) {
                int[] cell = queue.poll();
                int r = cell[0], c = cell[1];
                if (r == n - 1 && c == n - 1) return length;
                for (int dr = -1; dr <= 1; dr++) {
                    for (int dc = -1; dc <= 1; dc++) {
                        int nr = r + dr, nc = c + dc;
                        if (nr >= 0 && nc >= 0 && nr < n
                                && nc < n && grid[nr][nc] == 0) {
                            grid[nr][nc] = 1;
                            queue.add(new int[]{nr, nc});
                        }
                    }
                }
            }
            length++;
        }
        return -1;
    }
}

    Time O(n²) · Space O(n²) — each cell enters the queue at most once and checks 8 neighbours.

    Dry run

    [[0,0,0],[1,1,0],[1,1,0]]. Level 1: (0,0). Level 2: (0,1). Level 3: (0,2), (1,2) (diagonal). Level 4: (2,2) is the end → return 4.

    Watch out

    Mark a cell visited when you queue it, not when you pop it, or a cell is queued many times. Do not forget the 4 diagonal moves, or the start-cell-blocked check (a blocked start returns −1 even on a 1×1 grid). DFS does not give shortest paths here.

  • Medium130. Surrounded Regions — flood from the border first, flip the rest.
    Show solution

    The idea

    Flip every 'O' region that is fully surrounded by 'X' into 'X'. A region that touches the border can never be surrounded. Key insight: instead of checking each region, start from the border: flood every 'O' that is connected to an edge and mark it safe. Every 'O' left afterwards must be surrounded. Pattern: reverse thinking + flood fill from the border.

    Step by step

    1. For every cell on the four edges, run mark: it turns connected 'O' cells into a temporary 'S' (safe).
    2. Scan the whole board.
    3. Any 'O' still there was not reached from the border, so make it 'X'.
    4. Any 'S' goes back to 'O'.

    Java

    class Solution {
    public void solve(char[][] board) {
        int m = board.length, n = board[0].length;
        // 1. every O joined to the border is safe: mark it S
        for (int r = 0; r < m; r++) {
            mark(board, r, 0);
            mark(board, r, n - 1);
        }
        for (int c = 0; c < n; c++) {
            mark(board, 0, c);
            mark(board, m - 1, c);
        }
        // 2. leftover O is surrounded -> X;  S -> back to O
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (board[r][c] == 'O') board[r][c] = 'X';
                else if (board[r][c] == 'S') board[r][c] = 'O';
            }
        }
    }

    private void mark(char[][] b, int r, int c) {
        if (r < 0 || c < 0 || r >= b.length
                || c >= b[0].length || b[r][c] != 'O') {
            return;
        }
        b[r][c] = 'S';
        mark(b, r + 1, c);
        mark(b, r - 1, c);
        mark(b, r, c + 1);
        mark(b, r, c - 1);
    }
}

    Time O(m·n) · Space O(m·n) — each cell is marked at most once; recursion depth up to the board size.

    Dry run

    XXXX     XXXX
XOOX  →  XXXX
XXOX     XXXX
XOXX     XOXX

    Only (3,1) is an edge 'O', so it becomes 'S'. The middle group is never reached and turns into 'X'; then (3,1) goes back to 'O'.

    Watch out

    Do not flip cells while you are still exploring a region; that is why the temporary 'S' marker exists. Running DFS from every inner 'O' to "check if it escapes" works but is slower and easy to get wrong.

  • Medium417. Pacific Atlantic Water Flow — two floods uphill from each ocean, intersect.
    Show solution

    The idea

    Rain flows from a cell to a neighbour with height ≤ its own. The Pacific touches the top and left edges, the Atlantic the bottom and right. Find cells whose water can reach both oceans. Key insight: run it backwards. From each ocean's edge, walk uphill (to neighbours with height ≥ the current one). Every cell you reach can drain into that ocean. Do it for both oceans and keep the cells in both sets. Pattern: multi-start flood fill from the borders.

    Brute force first

    From every cell, run a DFS downhill and check whether it reaches both oceans: O((m·n)²), far too slow for 200×200.

    Step by step

    1. Make two boolean grids, pac and atl.
    2. Run climb into pac from every top-row and left-column cell, and into atl from every bottom-row and right-column cell.
    3. climb marks the cell, then moves to each in-grid neighbour that is not marked and is at least as high.
    4. Collect every cell where both grids are true.

    Java

    class Solution {
    private static final int[][] DIRS =
            {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public List<List<Integer>> pacificAtlantic(
            int[][] heights) {
        int m = heights.length, n = heights[0].length;
        boolean[][] pac = new boolean[m][n];
        boolean[][] atl = new boolean[m][n];
        for (int r = 0; r < m; r++) {
            climb(heights, pac, r, 0);       // left edge
            climb(heights, atl, r, n - 1);   // right edge
        }
        for (int c = 0; c < n; c++) {
            climb(heights, pac, 0, c);       // top edge
            climb(heights, atl, m - 1, c);   // bottom edge
        }
        List<List<Integer>> result = new ArrayList<>();
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (pac[r][c] && atl[r][c]) {
                    result.add(List.of(r, c));
                }
            }
        }
        return result;
    }

    // from an ocean cell, walk to equal-or-higher cells
    private void climb(int[][] h, boolean[][] ok,
                       int r, int c) {
        if (ok[r][c]) return;
        ok[r][c] = true;
        for (int[] d : DIRS) {
            int nr = r + d[0], nc = c + d[1];
            if (nr >= 0 && nc >= 0 && nr < h.length
                    && nc < h[0].length
                    && h[nr][nc] >= h[r][c]) {
                climb(h, ok, nr, nc);
            }
        }
    }
}

    Time O(m·n) · Space O(m·n) — each flood visits every cell at most once.

    Dry run

    Grid [[1,2],[2,1]]. Pacific starts at (0,0), (0,1), (1,0), so everything except (1,1) is in pac; from (0,0)=1 it climbs to (0,1)=2 and (1,0)=2, but (1,1)=1 is lower than both and never reached. Atlantic starts at (1,1), (0,1), (1,0), all but (0,0). Both: (0,1), (1,0).

    Watch out

    The direction flips: walking back from the ocean you go to neighbours that are higher or equal (>=), not lower. Equal heights let water flow, so > drops correct cells.

Test yourself

Why does Number of Islands not need a separate visited array?

We overwrite each visited land cell with '0', so it looks like water and is never flooded or counted again. (Ask the interviewer whether modifying the input is allowed.)

What is the time and space of Number of Islands on an R × C grid?

Time O(R × C) — every cell is scanned once and sunk at most once. Space O(R × C) in the worst case for the recursion depth (a grid full of land).

In the BFS, why mark a cell (give it a distance) when it is added, not when it is polled?

Otherwise two different cells can add the same neighbour before it is polled, so it enters the queue twice and the work blows up.
