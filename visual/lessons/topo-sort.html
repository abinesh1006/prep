Topological Sort (Kahn's algorithm)

Put tasks in an order where every task comes after the tasks it depends on, by repeatedly taking a task that has no unfinished prerequisites — and if you get stuck, there is a cycle.

Time to learn: about 2 hours · Prerequisites: Graph basics, BFS with a queue

When to use it — the signal

"Prerequisites", "must come before", "depends on", "build order", "task scheduling", "is it possible to finish all courses", "order the letters of an alien alphabet". Directed edges, and the question is about a valid order or a cycle.

The idea in plain words

You have 6 courses. Course 1 needs 0, course 3 needs 1 and 2, and so on. Draw an arrow from the prerequisite to the course: 0 → 1 means "do 0 before 1". A valid study plan is called a topological order.

For every course count its in-degree = how many arrows point into it = how many prerequisites are still not done. A course with in-degree 0 can be taken right now.

  • Put every in-degree-0 course in a queue.
  • Take one out, add it to the plan, and "cross it off" for its followers: every arrow out of it lowers the follower's in-degree by 1.
  • When a follower's in-degree reaches 0, all its prerequisites are done — put it in the queue.

If the plan ends with all 6 courses, it is possible. If some courses are left over, they all wait on each other in a loop (a cycle: 1 needs 3, 3 needs 2, 2 needs 1) and no order exists. Time O(V + E).

Analogy

Getting dressed: socks before shoes, underwear before trousers, trousers before shoes and belt. At any moment you put on something whose "must be on first" items are already on. If shoes needed a belt and a belt needed shoes, you could never get dressed — that is a cycle.

Watch it work

1. Course Schedule with 6 courses. Arrows go prerequisite → course. The badge on each course is its current in-degree (prerequisites not yet done).

2. Cycle detection. Courses 1 → 2 → 3 → 1 wait on each other in a loop. Kahn's algorithm simply gets stuck, and the nodes left over are exactly the ones on (or behind) the cycle.

Why it works

"A node enters the queue only when all its prerequisites have been output, so the output order respects every edge. In a cycle, every node waits on another node of the same cycle, so none of them ever reaches in-degree 0 — fewer than n nodes come out exactly when there is a cycle."

The template to remember

int[] indeg = new int[n];
for (edge a -> b) { adj[a].add(b); indeg[b]++; }
for (int i = 0; i < n; i++) if (indeg[i] == 0) q.add(i);
while (!q.isEmpty()) {
    int u = q.poll(); order.add(u);
    for (int v : adj[u]) if (--indeg[v] == 0) q.add(v);
}
return order.size() == n ? order : /* cycle */ empty;
Remember

Count arrows in. Start with the zeros. Removing a node frees its followers. Fewer than n out = cycle.

Common mistakes
  • Drawing the arrow the wrong way: LC 207 gives [course, prereq], so the edge is prereq → course.
  • Forgetting courses that appear in no pair — they have in-degree 0 and must start in the queue too.
  • Returning the order without checking its length — with a cycle it is incomplete.
  • Using a plain visited set for cycle detection in a directed DFS — you need three states (unvisited, in progress, done).

Practice in this order

  • Medium207. Course Schedule — exactly the animations: compare taken with n.
    Show solution

    The idea

    [a, b] means "take b before a". Can you finish all courses? Only if the prerequisites have no cycle (a cycle like A needs B, B needs A can never start). Key insight, Kahn's algorithm (topological sort with a queue): keep taking courses that have no unmet prerequisites. Each one you take unlocks others. If you manage to take all n, there is no cycle.

    Step by step

    1. Build edges b → a and count indeg[a] = number of unmet prerequisites of a.
    2. Queue every course with indegree 0 (nothing to wait for).
    3. Pop a course and add 1 to taken.
    4. For each course after it, lower its indegree; when it hits 0, queue it.
    5. Return taken == numCourses. Courses on a cycle never reach 0, so they are never taken.

    Java

    class Solution {
    public boolean canFinish(int numCourses,
                             int[][] prerequisites) {
        List<List<Integer>> next = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) {
            next.add(new ArrayList<>());
        }
        int[] indeg = new int[numCourses]; // unmet prereqs
        for (int[] p : prerequisites) {
            next.get(p[1]).add(p[0]);   // p[1] comes before p[0]
            indeg[p[0]]++;
        }
        Deque<Integer> queue = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (indeg[i] == 0) queue.add(i); // free to take
        }
        int taken = 0;
        while (!queue.isEmpty()) {
            int course = queue.poll();
            taken++;
            for (int after : next.get(course)) {
                if (--indeg[after] == 0) queue.add(after);
            }
        }
        return taken == numCourses;     // fewer = a cycle
    }
}

    Time O(V + E) · Space O(V + E) — each course and prerequisite is handled once.

    Dry run

    n = 2, [[1,0],[0,1]]. indeg = [1, 1]. No course has indegree 0, queue is empty, taken = 0 ≠ 2 → false. With only [[1,0]]: take 0, then 1 drops to 0, take 1 → 2 == 2 → true.

    Watch out

    The edge direction: [a, b] means b → a, not a → b. Getting it backwards still detects cycles here, but in 210 it gives the order reversed. DFS with three colours (unvisited / in progress / done) is the other common way to find a cycle.

  • Medium210. Course Schedule II — return the order itself.
    Show solution

    The idea

    Same as 207, but return one valid order to take all courses, or an empty array if impossible. Key insight: the order in which Kahn's algorithm pops courses is already a valid order, because a course is only popped after every prerequisite was popped. Just write them down.

    Step by step

    1. Build b → a edges and indegrees exactly as in 207.
    2. Queue all courses with indegree 0.
    3. Pop a course and write it at order[taken++].
    4. Lower the indegree of each course after it; queue it at 0.
    5. If taken == numCourses return order, otherwise return an empty array (cycle).

    Java

    class Solution {
    public int[] findOrder(int numCourses,
                           int[][] prerequisites) {
        List<List<Integer>> next = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) {
            next.add(new ArrayList<>());
        }
        int[] indeg = new int[numCourses];
        for (int[] p : prerequisites) {
            next.get(p[1]).add(p[0]);
            indeg[p[0]]++;
        }
        Deque<Integer> queue = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++) {
            if (indeg[i] == 0) queue.add(i);
        }
        int[] order = new int[numCourses];
        int taken = 0;
        while (!queue.isEmpty()) {
            int course = queue.poll();
            order[taken++] = course;    // write it down
            for (int after : next.get(course)) {
                if (--indeg[after] == 0) queue.add(after);
            }
        }
        // a cycle left some courses out
        return taken == numCourses ? order : new int[0];
    }
}

    Time O(V + E) · Space O(V + E) — same work as 207 plus the output array.

    Dry run

    n = 4, [[1,0],[2,0],[3,1],[3,2]]. indeg = [0,1,1,2]. Pop 0 → 1 and 2 drop to 0. Pop 1 → 3 drops to 1. Pop 2 → 3 drops to 0. Pop 3. Order [0,1,2,3].

    Watch out

    On a cycle you must return new int[0], not a half-filled array. Many orders can be valid; any of them is accepted.

  • Medium802. Find Eventual Safe States — Kahn on the reversed graph.
    Show solution

    The idea

    A node is safe if every path from it ends at a terminal node (a node with no outgoing edges), so it can never get stuck in a cycle. Return all safe nodes in increasing order. Key insight: terminal nodes are safe; a node becomes safe once all its outgoing edges lead to safe nodes. That is Kahn's algorithm on the reversed graph, where "out-degree" plays the role of indegree.

    Step by step

    1. Reverse every edge: for u → v, store u in before[v]. Set out[u] = number of u's edges.
    2. Queue every node with out == 0 (terminal).
    3. Pop v and mark it safe. For each u in before[v], lower out[u]; at 0, all of u's exits are safe, so queue u.
    4. Loop 0..n−1 and collect the safe nodes, which keeps them sorted.

    Java

    class Solution {
    public List<Integer> eventualSafeNodes(int[][] graph) {
        int n = graph.length;
        // reversed edges: before.get(v) = nodes that point to v
        List<List<Integer>> before = new ArrayList<>();
        for (int i = 0; i < n; i++) before.add(new ArrayList<>());
        int[] out = new int[n];         // edges still unsafe
        for (int u = 0; u < n; u++) {
            out[u] = graph[u].length;
            for (int v : graph[u]) before.get(v).add(u);
        }
        Deque<Integer> queue = new ArrayDeque<>();
        for (int u = 0; u < n; u++) {
            if (out[u] == 0) queue.add(u); // terminal = safe
        }
        boolean[] safe = new boolean[n];
        while (!queue.isEmpty()) {
            int v = queue.poll();
            safe[v] = true;
            for (int u : before.get(v)) {
                // one more of u's exits is known to be safe
                if (--out[u] == 0) queue.add(u);
            }
        }
        List<Integer> result = new ArrayList<>();
        for (int u = 0; u < n; u++) {
            if (safe[u]) result.add(u);  // ascending order
        }
        return result;
    }
}

    Time O(V + E) · Space O(V + E) — the reversed graph stores each edge once.

    Dry run

    graph = [[1,2],[2,3],[5],[0],[5],[],[]]. Terminals 5, 6. Pop 5: out[2] → 0 and out[4] → 0, queue both. Pop 6. Pop 2: out[0] → 1, out[1] → 1. Pop 4. Nodes 0, 1, 3 are in the cycle 0→1→3→0 and never reach 0. Safe: [2,4,5,6].

    Watch out

    Do not run Kahn on the original graph: it removes nodes with no incoming edges, which says nothing about safety. A DFS with colours (cycle = unsafe) also works.

  • Medium2115. Find All Possible Recipes — ingredients are prerequisites; supplies start in the queue.
    Show solution

    The idea

    You have some supplies. A recipe can be made once all its ingredients are available, and a recipe you made can be an ingredient of another. Return every recipe you can make. Key insight: ingredients are prerequisites. Draw an edge ingredient → recipe and count missing ingredients per recipe (its indegree). Supplies are ready from the start, so they begin in the queue. Pattern: Kahn's algorithm on strings.

    Step by step

    1. For each recipe, store missing = number of ingredients and add it to usedBy[ingredient] for each ingredient.
    2. Queue all supplies.
    3. Pop an item. For each recipe that uses it, lower its missing count.
    4. When a recipe reaches 0, add it to the answer and queue it, since it can now feed other recipes.

    Java

    class Solution {
    public List<String> findAllRecipes(String[] recipes,
            List<List<String>> ingredients, String[] supplies) {
        // ingredient -> recipes that need it
        Map<String, List<String>> usedBy = new HashMap<>();
        // recipe -> how many ingredients still missing
        Map<String, Integer> missing = new HashMap<>();
        for (int i = 0; i < recipes.length; i++) {
            missing.put(recipes[i], ingredients.get(i).size());
            for (String ing : ingredients.get(i)) {
                usedBy.computeIfAbsent(ing,
                        k -> new ArrayList<>()).add(recipes[i]);
            }
        }
        Deque<String> queue =
                new ArrayDeque<>(Arrays.asList(supplies));
        List<String> made = new ArrayList<>();
        while (!queue.isEmpty()) {
            String item = queue.poll();
            for (String r : usedBy.getOrDefault(item,
                                                List.of())) {
                if (missing.merge(r, -1, Integer::sum) == 0) {
                    made.add(r);        // all ingredients ready
                    queue.add(r);       // it can feed others
                }
            }
        }
        return made;
    }
}

    Time O(R + I + S) · Space O(R + I) — R recipes, I total ingredient entries, S supplies; each entry is handled once.

    Dry run

    recipes bread [yeast, flour], sandwich [bread, meat]; supplies yeast, flour, meat. missing: bread 2, sandwich 2. Pop yeast → bread 1. Pop flour → bread 0, made, queued. Pop meat → sandwich 1. Pop bread → sandwich 0, made. Answer [bread, sandwich].

    Watch out

    An ingredient that is neither a supply nor a recipe simply never shows up in the queue, so its recipes stay above 0, which is correct. Recipes that need each other in a cycle also never reach 0.

  • Hard2050. Parallel Courses III — Kahn plus "finish time = max of prerequisites + own time".
    Show solution

    The idea

    Courses 1..n take time[i−1] months; any number can run in parallel, but a course starts only after all its prerequisites finish. Find the minimum total months. Key insight: a course's earliest finish = its own time + the latest finish among its prerequisites. Process courses in topological order (Kahn), so all prerequisites are known before the course. The answer is the largest finish time. Pattern: topological sort + DP (longest path in a DAG).

    Step by step

    1. Build edges and indegrees from relations.
    2. start[c] = earliest start of c, all 0 at first. Queue courses with indegree 0.
    3. Pop c: finish = start[c] + time[c−1]; update the answer with it.
    4. For each next course d: start[d] = max(start[d], finish); lower its indegree and queue it at 0.
    5. Return the largest finish seen.

    Java

    class Solution {
    public int minimumTime(int n, int[][] relations,
                           int[] time) {
        List<List<Integer>> next = new ArrayList<>();
        for (int i = 0; i <= n; i++) next.add(new ArrayList<>());
        int[] indeg = new int[n + 1];   // courses are 1..n
        for (int[] r : relations) {
            next.get(r[0]).add(r[1]);
            indeg[r[1]]++;
        }
        int[] start = new int[n + 1];   // earliest start time
        Deque<Integer> queue = new ArrayDeque<>();
        for (int i = 1; i <= n; i++) {
            if (indeg[i] == 0) queue.add(i);
        }
        int answer = 0;
        while (!queue.isEmpty()) {
            int c = queue.poll();
            int finish = start[c] + time[c - 1];
            answer = Math.max(answer, finish);
            for (int d : next.get(c)) {
                // d must wait for its slowest prerequisite
                start[d] = Math.max(start[d], finish);
                if (--indeg[d] == 0) queue.add(d);
            }
        }
        return answer;
    }
}

    Time O(n + E) · Space O(n + E) — one Kahn pass with constant work per edge.

    Dry run

    n = 3, relations [[1,3],[2,3]], time [3,2,5]. Pop 1: finish 3, start[3] = 3. Pop 2: finish 2, start[3] stays 3, indegree 0 → queue. Pop 3: finish 3 + 5 = 8. Answer 8.

    Watch out

    Take the max over prerequisites, not the sum: parallel courses overlap. Courses are 1-indexed while time is 0-indexed, so use time[c − 1]. The answer is the max over all courses, not the finish of the last one popped.

  • Hard269. Alien Dictionary — compare neighbouring words to get letter edges, then topo sort.
    Show solution

    The idea

    Words are sorted in an unknown alphabet; find any valid letter order, or "" if impossible. Key insight: only neighbouring words give information, and only at their first different letter: in "wrt" before "wrf", t comes before f. Each such pair is an edge, every letter seen is a node, and a topological sort of the letters is the alphabet. A cycle means "".

    Step by step

    1. Add every letter of every word as a node with indegree 0.
    2. For each pair of neighbouring words: if the first is longer and the second is its prefix ("abc" before "ab"), return "".
    3. Otherwise find the first position where they differ, add edge x → y (only once), raise y's indegree, and stop comparing that pair.
    4. Run Kahn: queue letters with indegree 0, pop, append to the answer, lower neighbours.
    5. If the answer has every letter, return it; otherwise there was a cycle, return "".

    Java

    class Solution {
    public String alienOrder(String[] words) {
        Map<Character, Set<Character>> next = new HashMap<>();
        Map<Character, Integer> indeg = new HashMap<>();
        for (String w : words) {        // every letter is a node
            for (char ch : w.toCharArray()) {
                next.putIfAbsent(ch, new HashSet<>());
                indeg.putIfAbsent(ch, 0);
            }
        }
        for (int i = 0; i + 1 < words.length; i++) {
            String a = words[i], b = words[i + 1];
            // "abc" listed before "ab" is impossible
            if (a.length() > b.length() && a.startsWith(b)) {
                return "";
            }
            int len = Math.min(a.length(), b.length());
            for (int j = 0; j < len; j++) {
                char x = a.charAt(j), y = b.charAt(j);
                if (x != y) {           // first difference: x < y
                    if (next.get(x).add(y)) { // new edge only
                        indeg.merge(y, 1, Integer::sum);
                    }
                    break;              // later letters tell nothing
                }
            }
        }
        Deque<Character> queue = new ArrayDeque<>();
        for (char ch : indeg.keySet()) {
            if (indeg.get(ch) == 0) queue.add(ch);
        }
        StringBuilder order = new StringBuilder();
        while (!queue.isEmpty()) {
            char ch = queue.poll();
            order.append(ch);
            for (char nx : next.get(ch)) {
                if (indeg.merge(nx, -1, Integer::sum) == 0) {
                    queue.add(nx);
                }
            }
        }
        // letters left out = a cycle
        return order.length() == indeg.size()
                ? order.toString() : "";
    }
}

    Time O(C) · Space O(1) — C = total characters in all words; there are at most 26 letters and 26² edges.

    Dry run

    ["wrt","wrf","er","ett","rftt"] gives t→f, w→e, r→t, e→r. Indegree 0: w. Pop w → e free. Pop e → r. Pop r → t. Pop t → f. Answer "wertf".

    Watch out

    Two classic bugs: comparing letters after the first difference (they tell nothing), and missing the prefix case, which must return "". Also add an edge only once (a Set), or the indegree is counted twice and the letter never becomes free.

Test yourself

Is a topological order unique?

No. Whenever two nodes are in the queue at the same time, either can come first. In the animation, 1 and 2 could swap.

Can an undirected graph be topologically sorted?

No — the idea only makes sense with directions. Topological order exists exactly for DAGs (directed acyclic graphs).

What is the time complexity of Kahn's algorithm?

O(V + E): every node is enqueued once and every edge decrements an in-degree once.
