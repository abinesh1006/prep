Topological Sort (Kahn's algorithm)

Put tasks in an order where every task comes after the tasks it depends on, by repeatedly taking a task that has no unfinished prerequisites — and if you get stuck, there is a cycle.

Time to learn: about 2 hours · Prerequisites: Graph basics, BFS with a queue

When to use it — the signal

"Prerequisites", "must come before", "depends on", "build order", "task scheduling", "is it possible to finish all courses", "order the letters of an alien alphabet". Directed edges, and the question is about a valid order or a cycle.

The idea in plain words

You have 6 courses. Course 1 needs 0, course 3 needs 1 and 2, and so on. Draw an arrow from the prerequisite to the course: 0 → 1 means "do 0 before 1". A valid study plan is called a topological order.

For every course count its in-degree = how many arrows point into it = how many prerequisites are still not done. A course with in-degree 0 can be taken right now.

  • Put every in-degree-0 course in a queue.
  • Take one out, add it to the plan, and "cross it off" for its followers: every arrow out of it lowers the follower's in-degree by 1.
  • When a follower's in-degree reaches 0, all its prerequisites are done — put it in the queue.

If the plan ends with all 6 courses, it is possible. If some courses are left over, they all wait on each other in a loop (a cycle: 1 needs 3, 3 needs 2, 2 needs 1) and no order exists. Time O(V + E).

Analogy

Getting dressed: socks before shoes, underwear before trousers, trousers before shoes and belt. At any moment you put on something whose "must be on first" items are already on. If shoes needed a belt and a belt needed shoes, you could never get dressed — that is a cycle.

Watch it work

1. Course Schedule with 6 courses. Arrows go prerequisite → course. The badge on each course is its current in-degree (prerequisites not yet done).

2. Cycle detection. Courses 1 → 2 → 3 → 1 wait on each other in a loop. Kahn's algorithm simply gets stuck, and the nodes left over are exactly the ones on (or behind) the cycle.

Why it works

"A node enters the queue only when all its prerequisites have been output, so the output order respects every edge. In a cycle, every node waits on another node of the same cycle, so none of them ever reaches in-degree 0 — fewer than n nodes come out exactly when there is a cycle."

The template to remember

int[] indeg = new int[n];
for (edge a -> b) { adj[a].add(b); indeg[b]++; }
for (int i = 0; i < n; i++) if (indeg[i] == 0) q.add(i);
while (!q.isEmpty()) {
    int u = q.poll(); order.add(u);
    for (int v : adj[u]) if (--indeg[v] == 0) q.add(v);
}
return order.size() == n ? order : /* cycle */ empty;
Remember

Count arrows in. Start with the zeros. Removing a node frees its followers. Fewer than n out = cycle.

Common mistakes
  • Drawing the arrow the wrong way: LC 207 gives [course, prereq], so the edge is prereq → course.
  • Forgetting courses that appear in no pair — they have in-degree 0 and must start in the queue too.
  • Returning the order without checking its length — with a cycle it is incomplete.
  • Using a plain visited set for cycle detection in a directed DFS — you need three states (unvisited, in progress, done).

Test yourself

Is a topological order unique?

No. Whenever two nodes are in the queue at the same time, either can come first. In the animation, 1 and 2 could swap.

Can an undirected graph be topologically sorted?

No — the idea only makes sense with directions. Topological order exists exactly for DAGs (directed acyclic graphs).

What is the time complexity of Kahn's algorithm?

O(V + E): every node is enqueued once and every edge decrements an in-degree once.
