Arrays and Hashing

An array finds a slot by its number in one step; a hash map finds a value by its name in one step. Together they turn most "search again and again" solutions from O(n²) into O(n).

Time to learn: about 2.5 hours · Prerequisites: Big-O

When to use it — the signal

"Have I seen this before?", "count how many times", "find the pair / complement" in an unsorted array, "group things that are the same in some way", "duplicate", "first unique", "in O(n) time". Any time your first idea has an inner loop that searches for something, a hash map can usually replace that loop.

The idea in plain words

Array: the numbers sit side by side in memory, each taking the same space (an int is 4 bytes). If the array starts at address 1000, then nums[3] is at 1000 + 3 × 4 = 1012. The computer does that one sum and jumps straight there — O(1), no matter how long the array is.

The price: inserting at the front means every number must shift one place right — O(n). And finding a value (not an index) means looking at every cell — also O(n).

Hash map (in Java HashMap; a HashSet is the same thing with keys only): an array of "buckets". To store a key, a hash function turns the key into a number, and that number (mod the bucket count) picks the bucket. To find the key later, compute the same number and look only in that one bucket. On average that is O(1).

Two different keys can land in the same bucket — a collision. The bucket then holds a short list and we check each entry. With a good hash function and enough buckets, the lists stay tiny.

The trade: a hash map spends O(n) extra memory to buy O(1) lookups.

Analogy

An array is a row of numbered lockers: "locker 37" — walk straight to it. A hash map is a coat check: you hand over your coat, the attendant puts it on the hook for your ticket's colour-and-number. When you come back, they do not search every hook; your ticket tells them exactly where to look. Two coats on the same hook (a collision) just means a quick glance at two coats instead of one.

Watch it work

Array in memory. Reading by index is one sum; inserting at the front shifts everything.

Inside a hash set. 5 buckets. The (toy) hash of a word is the sum of its letter codes; the bucket is that sum mod 5. Watch the collision in bucket 3.

Java's real HashMap works the same way, with a better hash (key.hashCode()), 16 buckets to start, and it doubles the buckets when they get crowded so lists stay short.

Two Sum (unsorted). For each number, ask the map: "have I already seen the number that completes it?"

Group Anagrams. Anagrams have the same letters, so sorting the letters gives the same key. Use that key in a map.

Longest Consecutive Sequence. Put every number in a set. Only start counting from a number whose left neighbour (x − 1) is missing — that number is the start of a run.

Why it works (the one sentence to say in an interview)

"An inner loop that searches for a value is O(n); a hash map answers the same question in O(1) on average, so trading O(n) memory for the map turns the O(n²) brute force into a single O(n) pass."

The template to remember

// "Have I seen the thing that completes me?"
Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < n; i++) {
    int need = f(nums[i]);           // what would pair with me
    if (seen.containsKey(need)) ...  // found it in O(1)
    seen.put(nums[i], i);            // remember me for later
}
// Counting: map.merge(x, 1, Integer::sum);
// Grouping: map.computeIfAbsent(key, k -> new ArrayList<>()).add(x);
Remember

Searching inside a loop? Replace the search with a map. Seen → set. How many → map of counts. Which group → map of key → list. The key is the trick: complement, sorted letters, count signature.

Common mistakes
  • Two Sum: putting the number in the map before checking — then 3 + 3 = 6 "finds" the same element twice. Check first, then put.
  • Using == to compare Integer values from a map. It works for −128..127 only; use .equals() or unbox to int.
  • Calling map.get(k) on a missing key and unboxing null → NullPointerException. Use getOrDefault(k, 0).
  • Longest Consecutive: counting from every number (not just run starts) — that is O(n²) again.
  • Saying a hash map is O(1) "always". It is O(1) on average; with many collisions it degrades.

Test yourself

Why is reading nums[i] O(1) but finding the value 42 in an array O(n)?

The index gives the address directly (start + i × size). A value has no address formula, so you must look at cells one by one.

What is a collision, and does it break the hash map?

Two keys landing in the same bucket. It does not break anything: the bucket holds both and a lookup compares with equals(). It only slows things down if a bucket gets long.

Two Sum: why check the map before putting the current number in?

Otherwise a number could pair with itself (target 6, number 3 at one index).

What key would you use to group strings that are rotations or shifts of each other ("abc", "bcd")?

The differences between neighbouring letters (mod 26), e.g. "1,1". Any key that is equal exactly when the items belong together works.
