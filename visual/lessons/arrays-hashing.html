Arrays and Hashing

An array finds a slot by its number in one step; a hash map finds a value by its name in one step. Together they turn most "search again and again" solutions from O(n²) into O(n).

Time to learn: about 2.5 hours · Prerequisites: Big-O

When to use it — the signal

"Have I seen this before?", "count how many times", "find the pair / complement" in an unsorted array, "group things that are the same in some way", "duplicate", "first unique", "in O(n) time". Any time your first idea has an inner loop that searches for something, a hash map can usually replace that loop.

The idea in plain words

Array: the numbers sit side by side in memory, each taking the same space (an int is 4 bytes). If the array starts at address 1000, then nums[3] is at 1000 + 3 × 4 = 1012. The computer does that one sum and jumps straight there — O(1), no matter how long the array is.

The price: inserting at the front means every number must shift one place right — O(n). And finding a value (not an index) means looking at every cell — also O(n).

Hash map (in Java HashMap; a HashSet is the same thing with keys only): an array of "buckets". To store a key, a hash function turns the key into a number, and that number (mod the bucket count) picks the bucket. To find the key later, compute the same number and look only in that one bucket. On average that is O(1).

Two different keys can land in the same bucket — a collision. The bucket then holds a short list and we check each entry. With a good hash function and enough buckets, the lists stay tiny.

The trade: a hash map spends O(n) extra memory to buy O(1) lookups.

Analogy

An array is a row of numbered lockers: "locker 37" — walk straight to it. A hash map is a coat check: you hand over your coat, the attendant puts it on the hook for your ticket's colour-and-number. When you come back, they do not search every hook; your ticket tells them exactly where to look. Two coats on the same hook (a collision) just means a quick glance at two coats instead of one.

Watch it work

Array in memory. Reading by index is one sum; inserting at the front shifts everything.

Inside a hash set. 5 buckets. The (toy) hash of a word is the sum of its letter codes; the bucket is that sum mod 5. Watch the collision in bucket 3.

Java's real HashMap works the same way, with a better hash (key.hashCode()), 16 buckets to start, and it doubles the buckets when they get crowded so lists stay short.

Two Sum (unsorted). For each number, ask the map: "have I already seen the number that completes it?"

Group Anagrams. Anagrams have the same letters, so sorting the letters gives the same key. Use that key in a map.

Longest Consecutive Sequence. Put every number in a set. Only start counting from a number whose left neighbour (x − 1) is missing — that number is the start of a run.

Why it works (the one sentence to say in an interview)

"An inner loop that searches for a value is O(n); a hash map answers the same question in O(1) on average, so trading O(n) memory for the map turns the O(n²) brute force into a single O(n) pass."

The template to remember

// "Have I seen the thing that completes me?"
Map<Integer, Integer> seen = new HashMap<>();
for (int i = 0; i < n; i++) {
    int need = f(nums[i]);           // what would pair with me
    if (seen.containsKey(need)) ...  // found it in O(1)
    seen.put(nums[i], i);            // remember me for later
}
// Counting: map.merge(x, 1, Integer::sum);
// Grouping: map.computeIfAbsent(key, k -> new ArrayList<>()).add(x);

Almost every problem here asks "have I met the thing that completes me?" or "how many of each?" Those are exactly the two questions a hash map (or a small counting array when keys are tiny) answers in O(1).

Remember

Searching inside a loop? Replace the search with a map. Seen → set. How many → map of counts. Which group → map of key → list. The key is the trick: complement, sorted letters, count signature.

Common mistakes
  • Two Sum: putting the number in the map before checking — then 3 + 3 = 6 "finds" the same element twice. Check first, then put.
  • Using == to compare Integer values from a map. It works for −128..127 only; use .equals() or unbox to int.
  • Calling map.get(k) on a missing key and unboxing null → NullPointerException. Use getOrDefault(k, 0).
  • Longest Consecutive: counting from every number (not just run starts) — that is O(n²) again.
  • Saying a hash map is O(1) "always". It is O(1) on average; with many collisions it degrades.

Practice in this order

  • Easy217. Contains Duplicate — a set; return true the moment add() fails.
    Show solution

    The idea

    Given numbers, say whether any value appears twice. [1,2,3,1] → true because 1 shows up twice. The insight: instead of comparing every pair, remember what you have already seen in a hash set (a bag that answers "have I seen this?" in O(1)). Pattern: hashing to replace a nested loop.

    Brute force first

    Compare every pair i < j: O(n²) time. Too slow for n = 105.

    Step by step

    1. Make an empty HashSet.
    2. Walk the array one number at a time.
    3. set.add(x) returns false if x was already inside: that is a duplicate, return true.
    4. If the loop ends, no number repeated: return false.

    Java

    class Solution {
    public boolean containsDuplicate(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) {
            // add() is false when x was already there
            if (!seen.add(x)) return true;
        }
        return false;
    }
}

    Time O(n) · Space O(n) — each number is added once, and the set may hold all n.

    Dry run

    [1,2,3,1]: add 1 → {1}; add 2 → {1,2}; add 3 → {1,2,3}; add 1 fails → return true.

    Watch out

    Sorting first and checking neighbours also works in O(n log n) time with O(1) extra space; mention it if the interviewer asks for less memory. A single-element array has no duplicate.

  • Easy242. Valid Anagram — count letters in an int[26].
    Show solution

    The idea

    Two words are anagrams if they use exactly the same letters the same number of times: "anagram" and "nagaram" → true. The insight: only 26 lowercase letters exist, so count them in an int[26]: +1 for each letter of s, −1 for each letter of t. All zero at the end means anagram. Pattern: counting array as a tiny hash map.

    Brute force first

    Sort both strings and compare: O(n log n). Fine, but counting is O(n).

    Step by step

    1. If the lengths differ, return false at once.
    2. Make int[] count = new int[26].
    3. For each position i: count[s.charAt(i) - 'a']++ and count[t.charAt(i) - 'a']--.
    4. If every count is 0, return true; otherwise false.

    Java

    class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;
        int[] count = new int[26];
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++; // letter from s
            count[t.charAt(i) - 'a']--; // letter from t
        }
        for (int c : count) {
            if (c != 0) return false;
        }
        return true;
    }
}

    Time O(n) · Space O(1) — one pass, and the array is always 26 slots.

    Dry run

    "rat" vs "car": r+1 c−1, a+1 a−1, t+1 r−1 → r=0, a=0, c=−1, t=+1. Not all zero → false.

    Watch out

    Check the lengths first, or t.charAt(i) can run past the end. For Unicode input (the follow-up) use a HashMap<Character,Integer> instead of int[26].

  • Easy1. Two Sum — exactly the animation above.
    Show solution

    The idea

    Find the two indexes whose values add up to target. [2,7,11,15], target 9 → [0,1]. The insight: when you stand on x, the partner you need is target - x; a hash map from value to index tells you in O(1) if you already passed it. Pattern: hash map lookup of the complement.

    Brute force first

    Try every pair i < j and check the sum: O(n²) time, O(1) space.

    Step by step

    1. Make an empty map: value → index.
    2. For each index i, compute need = target - nums[i].
    3. If need is in the map, return [map.get(need), i].
    4. Otherwise put nums[i] → i into the map and continue.

    Java

    class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            if (seen.containsKey(need)) {
                return new int[]{seen.get(need), i};
            }
            seen.put(nums[i], i); // store after checking
        }
        return new int[0]; // problem says never happens
    }
}

    Time O(n) · Space O(n) — one pass, each lookup O(1), the map can hold n values.

    Dry run

    [3,2,4], target 6: i=0 need 3, map empty, store 3→0. i=1 need 4, not there, store 2→1. i=2 need 2, found at 1 → return [1,2].

    Watch out

    Check the map before putting the current number in, otherwise [3,2,4], target 6 would pair index 0 with itself. Duplicates like [3,3] work because the first 3 is stored before the second is checked.

  • Medium49. Group Anagrams — sorted letters as the key.
    Show solution

    The idea

    Put words that are anagrams of each other into the same group: ["eat","tea","tan","ate","nat","bat"] → [["eat","tea","ate"],["tan","nat"],["bat"]]. The insight: anagrams become the same string when you sort their letters ("eat", "tea" → "aet"). Use that sorted string as a hash map key. Pattern: group by a canonical key.

    Brute force first

    Compare every word with every other word using an anagram check: O(n² · k). Too slow for 104 words.

    Step by step

    1. Make a map: key (sorted letters) → list of words.
    2. For each word, turn it into a char array, sort it, and make a string from it: that is the key.
    3. computeIfAbsent(key, ...) gets the list for that key (creating it if new); add the word.
    4. Return all the lists in the map.

    Java

    class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String w : strs) {
            char[] c = w.toCharArray();
            Arrays.sort(c);
            String key = new String(c); // "eat" -> "aet"
            groups.computeIfAbsent(key, k -> new ArrayList<>())
                  .add(w);
        }
        return new ArrayList<>(groups.values());
    }
}

    Time O(n · k log k) · Space O(n · k) — n words of length up to k, each sorted once; the map stores every word.

    Dry run

    "eat"→key aet {aet:[eat]}; "tea"→aet {aet:[eat,tea]}; "tan"→ant new group; "ate"→aet; "nat"→ant; "bat"→abt new group.

    Watch out

    c.toString() on a char array gives a memory address, not the letters; use new String(c). The empty string is a valid word and forms its own group. A faster key is the 26 letter counts joined with # (O(k) instead of O(k log k)).

  • Medium347. Top K Frequent Elements — count with a map, then bucket by count.
    Show solution

    The idea

    Return the k numbers that appear most often: [1,1,1,2,2,3], k = 2 → [1,2]. The insight: count with a hash map, then bucket by count: bucket[c] holds every number that appears exactly c times. A count can never exceed n, so walk the buckets from n down and take k numbers. Pattern: counting + bucket sort, O(n).

    Brute force first

    Count, then sort the distinct numbers by count: O(n log n). A min-heap of size k gives O(n log k); both pass, but buckets are O(n).

    Step by step

    1. Count each number in a HashMap.
    2. Make bucket, an array of n + 1 lists. Put each number into bucket[its count].
    3. Walk i from n down to 1; copy numbers from bucket[i] into the answer.
    4. Stop as soon as you have k numbers.

    Java

    class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> count = new HashMap<>();
        for (int x : nums) count.merge(x, 1, Integer::sum);

        // bucket[c] = numbers that appear exactly c times
        List<Integer>[] bucket = new List[nums.length + 1];
        for (var e : count.entrySet()) {
            int c = e.getValue();
            if (bucket[c] == null) bucket[c] = new ArrayList<>();
            bucket[c].add(e.getKey());
        }

        int[] ans = new int[k];
        int idx = 0;
        for (int c = nums.length; c > 0 && idx < k; c--) {
            if (bucket[c] == null) continue;
            for (int x : bucket[c]) {
                if (idx == k) break;
                ans[idx++] = x;
            }
        }
        return ans;
    }
}

    Time O(n) · Space O(n) — one pass to count, one to bucket, one walk over n + 1 buckets.

    Dry run

    [1,1,1,2,2,3]: counts {1:3, 2:2, 3:1} → bucket[3]=[1], bucket[2]=[2], bucket[1]=[3]. Walk 6,5,4 empty; 3 → take 1; 2 → take 2; have k = 2 → [1,2].

    Watch out

    The bucket array needs size n + 1 because a number can appear n times. Java warns about the generic array new List[...]; that warning is harmless here.

  • Medium128. Longest Consecutive Sequence — only count from run starts.
    Show solution

    The idea

    Find the length of the longest run of consecutive values, in any order: [100,4,200,1,3,2] → 4 (1,2,3,4). Must be O(n), so no sorting. The insight: put everything in a hash set, and only start counting from a number x whose x - 1 is missing (a run start). Each number is then counted by exactly one run.

    Brute force first

    Sort and scan for runs: O(n log n). Or, for every number, count upward with a set without the run-start check: that can be O(n²).

    Step by step

    1. Put all numbers in a HashSet (this also removes duplicates).
    2. For each x in the set: if x - 1 is in the set, skip it (it is not a start).
    3. Otherwise count up: x + 1, x + 2, ... while they are in the set.
    4. Keep the longest length seen.

    Java

    class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) set.add(x);
        int best = 0;
        for (int x : set) {
            if (set.contains(x - 1)) continue; // not a start
            int len = 1;
            while (set.contains(x + len)) len++;
            best = Math.max(best, len);
        }
        return best;
    }
}

    Time O(n) · Space O(n) — the inner while only runs from run starts, so each number is visited at most twice in total.

    Dry run

    Set {100,4,200,1,3,2}. 100: 99 missing, start; 101 missing → len 1. 4: 3 present, skip. 200: len 1. 1: 0 missing, start; 2,3,4 present, 5 missing → len 4. 3, 2: skip. Answer 4.

    Watch out

    Loop over the set, not the array: with many duplicates of a run start, looping the array repeats the long count and can become O(n²). Empty input returns 0.

  • Medium36. Valid Sudoku — one set per row, column and box.
    Show solution

    The idea

    Check a partly filled 9×9 board: no digit may repeat in any row, column or 3×3 box (empty cells are '.'). You do not need to solve it. The insight: keep one set per row, per column and per box; box number is (r / 3) * 3 + c / 3. Pattern: hash sets for "seen before" checks.

    Step by step

    1. Make 9 sets for rows, 9 for columns, 9 for boxes.
    2. Visit every cell; skip '.'.
    3. Work out the box index b = (r / 3) * 3 + c / 3.
    4. Try to add the digit to rows[r], cols[c] and boxes[b]; if any add fails, the digit repeats: return false.
    5. If all cells pass, return true.

    Java

    class Solution {
    public boolean isValidSudoku(char[][] board) {
        Set<Character>[] rows = new HashSet[9];
        Set<Character>[] cols = new HashSet[9];
        Set<Character>[] boxes = new HashSet[9];
        for (int i = 0; i < 9; i++) {
            rows[i] = new HashSet<>();
            cols[i] = new HashSet<>();
            boxes[i] = new HashSet<>();
        }
        for (int r = 0; r < 9; r++) {
            for (int c = 0; c < 9; c++) {
                char d = board[r][c];
                if (d == '.') continue;
                int b = (r / 3) * 3 + c / 3; // box 0..8
                if (!rows[r].add(d) || !cols[c].add(d)
                        || !boxes[b].add(d)) {
                    return false;
                }
            }
        }
        return true;
    }
}

    Time O(81) = O(1) · Space O(81) = O(1) — the board is always 9×9.

    Dry run

    Cell (0,0) = 5: rows[0]={5}, cols[0]={5}, boxes[0]={5}. Change (0,0) to 8 and later reach (3,0) = 8: cols[0].add('8') fails → false.

    Watch out

    Box index: (r / 3) * 3 + c / 3, using integer division. Forgetting to skip '.' makes every board look invalid. Only check the filled cells; a valid board need not be solvable.

Test yourself

Why is reading nums[i] O(1) but finding the value 42 in an array O(n)?

The index gives the address directly (start + i × size). A value has no address formula, so you must look at cells one by one.

What is a collision, and does it break the hash map?

Two keys landing in the same bucket. It does not break anything: the bucket holds both and a lookup compares with equals(). It only slows things down if a bucket gets long.

Two Sum: why check the map before putting the current number in?

Otherwise a number could pair with itself (target 6, number 3 at one index).

What key would you use to group strings that are rotations or shifts of each other ("abc", "bcd")?

The differences between neighbouring letters (mod 26), e.g. "1,1". Any key that is equal exactly when the items belong together works.
