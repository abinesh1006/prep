LRU Cache

A HashMap finds any item in O(1); a doubly linked list keeps items in "most recently used" order and can move or drop any item in O(1). Together they make every get and put O(1).

Time to learn: about 2 hours · Prerequisites: Arrays and hashing, Reverse a linked list, Merge sorted lists (dummy nodes)

When to use it — the signal

"Design a cache", "least recently used", "evict the oldest", "O(1) get and put", "move to front on access", "keep the last k distinct items". Whenever you need both fast lookup by key and a changing order, pair a map with a linked list.

The idea in plain words

A cache with capacity 2 can remember two key → value pairs. When a third arrives, it must forget one: the least recently used (LRU) — the one nobody has read or written for the longest time.

  • We need an order from most recent to least recent. Every get or put of a key moves it to the front. Eviction removes from the back.
  • An array would need shifting (O(n)) to move an item to the front. A doubly linked list — each node has a next arrow and a prev arrow — can unhook any node and re-hook it at the front by changing 6 arrows: O(1).
  • But finding the node for key 7 in a list means walking it (O(n)). So a HashMap stores key → node, and jumps straight to it.
  • Two fake nodes, head (H) and tail (T), sit at both ends forever. The real front is head.next, the LRU is tail.prev, and no operation ever has to check for null.
Analogy

A desk with room for only a few files, stacked with the one you touched last on top. When you use a file you pull it out and put it on top. When a new file arrives and the desk is full, the bottom file goes back to the archive. Your index cards (the HashMap) tell you exactly where each file is in the stack, so you never search.

Watch it work

First, the pointer surgery for one get(1): order is 3, 2, 1 (1 is least recent). Node 1 is unhooked and re-hooked right after H. Each arrow is one line of code. Upper arrows are next, lower arrows are prev; the small chip is the stored value.

Now a full sequence with capacity 2: put(1,A), put(2,B), get(1), put(3,C), get(2), put(4,D), get(3), get(4).

Why it works

"The HashMap turns 'find the node for this key' into O(1). The doubly linked list keeps usage order, and because each node knows its prev and next, unhooking it or adding it after the head is a constant number of pointer changes. Sentinel head and tail remove every null check. So get and put are both O(1)."

The template to remember

class Node { int key, val; Node prev, next; }
// head <-> ... most recent ... least recent ... <-> tail
remove(n):   n.prev.next = n.next; n.next.prev = n.prev;
addFront(n): n.prev = head; n.next = head.next;
             head.next.prev = n; head.next = n;
get: miss → -1; hit → remove, addFront, return val
put: exists → remove; full → evict tail.prev (and map key); add new at front

Data structures used — and why

StructureWhat we need from itCostWhy not the alternative
Node[] buckets + chains706: index = key % 1009; collisions chain on next.O(1) average A plain int[1000001] works for this range but wastes memory; chaining is what interviewers want to see.

HashMap<String, Bucket> + HashSet432: key → its count bucket; each bucket holds a set of keys, buckets are a doubly linked list by count.O(1) for every operation A heap gives max or min in O(log n), but not both, and updates are slow.

The hash map answers "where is it?" and the doubly linked list answers "what is oldest?"; neither does both alone, which is why every design here pairs them. Java's LinkedHashMap is exactly this pair, built in.

Remember

Map for "where", list for "when". Use → move to front. Full → drop tail.prev. Sentinels H and T, and store the key in the node so eviction can delete it from the map.

Common mistakes
  • Not storing the key inside the node — when evicting tail.prev you cannot remove it from the map.
  • Forgetting that get also counts as "use" and must move the node to the front.
  • On put of an existing key, evicting anyway (the size did not grow) or forgetting to update the value.
  • Wrong order inside addFront: set head.next = n last, or you lose the old front.
  • In Java you may mention LinkedHashMap(cap, 0.75f, true) with removeEldestEntry, but interviewers want the hand-built version.

Practice in this order

  • Easy706. Design HashMap — warm-up: buckets of linked lists.
    Show solution

    The idea

    Build put, get and remove for int keys without Java's HashMap. A hash map is an array of buckets: the hash function (key % size) picks a bucket, and keys that land in the same bucket (a collision) are kept in a small linked list there. Pattern: separate chaining.

    Brute force first

    Keys are at most 106, so an int[1000001] filled with -1 works in O(1) per call, but it wastes memory and is not what the question is testing.

    Step by step

    1. Make an array of, say, 1009 buckets (a prime spreads keys better). Each bucket is a linked list of (key, value) nodes.
    2. put: walk the bucket; if the key exists, overwrite the value, else add a new node at the front.
    3. get: walk the bucket; return the value or -1.
    4. remove: walk the bucket keeping the previous node, and unlink the match.

    Java

    class MyHashMap {
    private static class Node {
        int key, val;
        Node next;
        Node(int k, int v, Node n) {
            key = k; val = v; next = n;
        }
    }
    private static final int SIZE = 1009;  // prime
    private final Node[] buckets = new Node[SIZE];

    private int idx(int key) { return key % SIZE; }

    public void put(int key, int value) {
        int i = idx(key);
        for (Node n = buckets[i]; n != null; n = n.next) {
            if (n.key == key) { n.val = value; return; }
        }
        buckets[i] = new Node(key, value, buckets[i]);
    }

    public int get(int key) {
        for (Node n = buckets[idx(key)]; n != null;
                n = n.next) {
            if (n.key == key) return n.val;
        }
        return -1;
    }

    public void remove(int key) {
        int i = idx(key);
        Node dummy = new Node(0, 0, buckets[i]), p = dummy;
        while (p.next != null) {
            if (p.next.key == key) {
                p.next = p.next.next;   // unlink
                break;
            }
            p = p.next;
        }
        buckets[i] = dummy.next;
    }
}

    Time O(n / buckets) average per call · Space O(n + buckets) — buckets stay short when keys spread evenly.

    Dry run

    put(1,1)   bucket1: (1,1)
put(2,2)   bucket2: (2,2)
put(2,1)   bucket2: (2,1)   overwrite, no new node
remove(2)  bucket2: empty  -> get(2) = -1

    Watch out

    put on an existing key must overwrite, not add a second node. In remove, deleting the bucket's first node is the special case; the dummy node avoids it.

  • Medium707. Design Linked List — practise sentinels and pointer updates.
    Show solution

    The idea

    Build a linked list with get(index), addAtHead, addAtTail, addAtIndex and deleteAtIndex. Two sentinels (fake nodes that are always there) at the front and back of a doubly linked list mean every insert and delete looks the same: there is always a real node before and after. Keep a size to check indexes.

    Step by step

    1. head and tail sentinels linked to each other; size = 0.
    2. node(i): walk from head.next i steps (walk from the tail side when i is in the back half to halve the work).
    3. addAtIndex(i, v): if i > size do nothing; else insert before node(i) (when i = size that is the tail sentinel).
    4. Head and tail adds are addAtIndex(0, v) and addAtIndex(size, v).
    5. deleteAtIndex(i): if valid, link its neighbours to each other.

    Java

    class MyLinkedList {
    private static class Node {
        int val;
        Node prev, next;
        Node(int v) { val = v; }
    }
    private final Node head = new Node(0); // sentinel
    private final Node tail = new Node(0); // sentinel
    private int size = 0;

    public MyLinkedList() {
        head.next = tail;
        tail.prev = head;
    }

    // node at index i, 0 <= i <= size (size = tail)
    private Node node(int i) {
        if (i < size / 2) {
            Node n = head.next;
            while (i-- > 0) n = n.next;
            return n;
        }
        Node n = tail;
        for (int k = size; k > i; k--) n = n.prev;
        return n;
    }

    public int get(int index) {
        if (index < 0 || index >= size) return -1;
        return node(index).val;
    }

    public void addAtHead(int val) { addAtIndex(0, val); }

    public void addAtTail(int val) {
        addAtIndex(size, val);
    }

    public void addAtIndex(int index, int val) {
        if (index < 0 || index > size) return;
        Node after = node(index), before = after.prev;
        Node n = new Node(val);
        n.prev = before;
        n.next = after;
        before.next = n;
        after.prev = n;
        size++;
    }

    public void deleteAtIndex(int index) {
        if (index < 0 || index >= size) return;
        Node n = node(index);
        n.prev.next = n.next;   // skip over n
        n.next.prev = n.prev;
        size--;
    }
}

    Time O(n) for index operations, O(1) at head/tail · Space O(n) — reaching an index means walking to it.

    Dry run

    addAtHead(1)     H-1-T
addAtTail(3)     H-1-3-T
addAtIndex(1,2)  H-1-2-3-T   get(1)=2
deleteAtIndex(1) H-1-3-T     get(1)=3

    Watch out

    addAtIndex with index == size is allowed (append), but index > size is ignored. get and delete need index < size. Remember to update size.

  • Medium146. LRU Cache — the animations above.
    Show solution

    The idea

    A cache of fixed capacity: get and put in O(1), and when full, throw out the least recently used key. A HashMap finds a key's node in O(1); a doubly linked list keeps nodes in use order (most recent at the front) and can unlink any node in O(1). Together they give O(1) for everything.

    Brute force first

    Store a timestamp with each key and scan for the oldest when evicting: O(capacity) per eviction.

    Step by step

    1. Map key → node; list with head/tail sentinels, front = most recent.
    2. get: if missing, -1. Else move the node to the front and return its value.
    3. put on an existing key: update the value and move to the front.
    4. put on a new key: add a node at the front and to the map; if size exceeds capacity, remove tail.prev from both list and map.

    Java

    class LRUCache {
    private static class Node {
        int key, val;
        Node prev, next;
        Node(int k, int v) { key = k; val = v; }
    }
    private final int cap;
    private final Map<Integer, Node> map = new HashMap<>();
    private final Node head = new Node(0, 0); // newest side
    private final Node tail = new Node(0, 0); // oldest side

    public LRUCache(int capacity) {
        cap = capacity;
        head.next = tail;
        tail.prev = head;
    }

    private void unlink(Node n) {
        n.prev.next = n.next;
        n.next.prev = n.prev;
    }

    private void addFront(Node n) {
        n.next = head.next;
        n.prev = head;
        head.next.prev = n;
        head.next = n;
    }

    public int get(int key) {
        Node n = map.get(key);
        if (n == null) return -1;
        unlink(n);            // mark as just used
        addFront(n);
        return n.val;
    }

    public void put(int key, int value) {
        Node n = map.get(key);
        if (n != null) {
            n.val = value;
            unlink(n);
            addFront(n);
            return;
        }
        n = new Node(key, value);
        map.put(key, n);
        addFront(n);
        if (map.size() > cap) {
            Node old = tail.prev;   // least recently used
            unlink(old);
            map.remove(old.key);
        }
    }
}

    Time O(1) per call · Space O(capacity) — map lookup plus a fixed number of pointer changes.

    Dry run

    cap 2      list (newest first)
put 1      1
put 2      2 1
get 1      1 2
put 3      3 1      (2 evicted)
put 4      4 3      (1 evicted)

    Watch out

    Store the key inside the node: on eviction you only have the node and must remove it from the map too. Updating an existing key must not evict anything.

  • Medium1472. Design Browser History — doubly linked list of pages.
    Show solution

    The idea

    Browser history: visit(url) clears all forward pages, back(steps) and forward(steps) move but stop at the ends. A doubly linked list of pages with a curr pointer models it directly: visiting attaches a new node after curr, which cuts off the old forward chain.

    Step by step

    1. Start with one node for the homepage; curr points to it.
    2. visit: new node, curr.next = node, node.prev = curr, move curr to it (the old forward part is dropped).
    3. back(k): step to prev while k > 0 and prev exists; return curr's url.
    4. forward(k): same with next.

    Java

    class BrowserHistory {
    private static class Page {
        String url;
        Page prev, next;
        Page(String u) { url = u; }
    }
    private Page curr;

    public BrowserHistory(String homepage) {
        curr = new Page(homepage);
    }

    public void visit(String url) {
        Page p = new Page(url);
        curr.next = p;        // forward history is gone
        p.prev = curr;
        curr = p;
    }

    public String back(int steps) {
        while (steps-- > 0 && curr.prev != null) {
            curr = curr.prev;
        }
        return curr.url;
    }

    public String forward(int steps) {
        while (steps-- > 0 && curr.next != null) {
            curr = curr.next;
        }
        return curr.url;
    }
}

    Time O(steps) for back/forward, O(1) for visit · Space O(pages visited) — one node per visit.

    Dry run

    leet - google - facebook - youtube*     back(1) -> facebook
back(1) -> google*      forward(1) -> facebook*
visit linkedin: leet - google - facebook - linkedin*  (youtube gone)
forward(2) stays linkedin;  back(2) -> google;  back(7) -> leet

    Watch out

    Stop at the ends instead of walking off into null. An array list plus a curr index and a last index is the other common answer and makes back/forward O(1) with a single Math.max/Math.min.

  • Hard432. All O`one Data Structure — map + doubly linked list of count buckets.
    Show solution

    The idea

    Keep string counts with inc, dec, getMaxKey and getMinKey, all O(1). Group keys into count buckets (one node per count, holding the set of keys with that count) in a doubly linked list sorted by count. A key's count only moves by one, so it moves to the neighbouring bucket, which is O(1). The minimum is the first bucket, the maximum the last. A map key → bucket finds a key's bucket.

    Step by step

    1. List of buckets between head and tail sentinels, increasing count; map key → bucket.
    2. inc: current bucket b (head if new). If b.next does not have count+1, insert a new bucket after b. Move the key there; if b becomes empty (and is not head), unlink it.
    3. dec: bucket b. If count is 1, just drop the key from the map. Else make sure b.prev has count−1 (insert one before b if not) and move the key there. Remove b if empty.
    4. getMaxKey: any key of tail.prev; getMinKey: any key of head.next; "" if empty.

    Java

    class AllOne {
    private static class Bucket {
        int count;
        Set<String> keys = new HashSet<>();
        Bucket prev, next;
        Bucket(int c) { count = c; }
    }
    private final Bucket head = new Bucket(0);
    private final Bucket tail = new Bucket(0);
    private final Map<String, Bucket> where =
        new HashMap<>();

    public AllOne() {
        head.next = tail;
        tail.prev = head;
    }

    private Bucket insertAfter(Bucket b, int count) {
        Bucket n = new Bucket(count);
        n.prev = b;
        n.next = b.next;
        b.next.prev = n;
        b.next = n;
        return n;
    }

    private void removeIfEmpty(Bucket b) {
        if (b != head && b.keys.isEmpty()) {
            b.prev.next = b.next;
            b.next.prev = b.prev;
        }
    }

    public void inc(String key) {
        Bucket b = where.getOrDefault(key, head);
        Bucket up = b.next;
        if (up == tail || up.count != b.count + 1) {
            up = insertAfter(b, b.count + 1);
        }
        up.keys.add(key);
        where.put(key, up);
        b.keys.remove(key);
        removeIfEmpty(b);
    }

    public void dec(String key) {
        Bucket b = where.get(key);
        if (b == null) return;
        if (b.count == 1) {
            where.remove(key);
        } else {
            Bucket down = b.prev;
            if (down == head || down.count != b.count - 1) {
                down = insertAfter(b.prev, b.count - 1);
            }
            down.keys.add(key);
            where.put(key, down);
        }
        b.keys.remove(key);
        removeIfEmpty(b);
    }

    public String getMaxKey() {
        return tail.prev == head ? ""
            : tail.prev.keys.iterator().next();
    }

    public String getMinKey() {
        return head.next == tail ? ""
            : head.next.keys.iterator().next();
    }
}

    Time O(1) per call · Space O(number of keys) — each call touches the key’s bucket and one neighbour only.

    Dry run

    inc hello   [1:{hello}]
inc hello   [2:{hello}]          (bucket 1 empty, removed)
inc leet    [1:{leet}] [2:{hello}]
max = last bucket = hello, min = first bucket = leet

    Watch out

    Never unlink the head sentinel (a new key's "old bucket" is head). When the needed neighbour bucket does not exist, insert it right next to the current one so the list stays sorted.

  • Hard460. LFU Cache — one LRU list per frequency, plus a min-frequency pointer.
    Show solution

    The idea

    Like LRU, but evict the key used the fewest times; break ties by least recently used. Keep each key's count, and for every count an LRU-ordered list of its keys (LinkedHashSet keeps insertion order and removes in O(1)). Track minFreq, the smallest count in use: evict the oldest key in lists[minFreq].

    Step by step

    1. Maps: key → value, key → count, count → LinkedHashSet of keys; integer minFreq.
    2. touch(key): move the key from list c to list c+1; if list c was minFreq and is now empty, minFreq++.
    3. get: missing → -1; else touch and return the value.
    4. put existing: update value, touch. New key: if full, remove the first key of lists[minFreq] from everything; then add with count 1 and set minFreq = 1.

    Java

    class LFUCache {
    private final int cap;
    private final Map<Integer, Integer> vals =
        new HashMap<>();
    private final Map<Integer, Integer> freq =
        new HashMap<>();
    // count -> keys with that count, oldest first
    private final Map<Integer, LinkedHashSet<Integer>>
        lists = new HashMap<>();
    private int minFreq = 0;

    public LFUCache(int capacity) { cap = capacity; }

    private void touch(int key) {
        int c = freq.get(key);
        freq.put(key, c + 1);
        lists.get(c).remove(key);
        if (c == minFreq && lists.get(c).isEmpty()) {
            minFreq++;
        }
        lists.computeIfAbsent(c + 1,
            x -> new LinkedHashSet<>()).add(key);
    }

    public int get(int key) {
        if (!vals.containsKey(key)) return -1;
        touch(key);
        return vals.get(key);
    }

    public void put(int key, int value) {
        if (cap == 0) return;
        if (vals.containsKey(key)) {
            vals.put(key, value);
            touch(key);
            return;
        }
        if (vals.size() == cap) {
            // oldest key among the least used
            int old = lists.get(minFreq).iterator().next();
            lists.get(minFreq).remove(old);
            vals.remove(old);
            freq.remove(old);
        }
        vals.put(key, value);
        freq.put(key, 1);
        lists.computeIfAbsent(1, x -> new LinkedHashSet<>())
             .add(key);
        minFreq = 1;
    }
}

    Time O(1) per call · Space O(capacity) — hash map and linked-hash-set operations only.

    Dry run

    put1 put2       f1:[1,2]          min 1
get1            f1:[2] f2:[1]     min 1
put3 (full)     evict 2 -> f1:[3] f2:[1]
get3            f2:[1,3]          min 2
put4 (full)     evict 1 (oldest in f2) -> f1:[4] f2:[3], min 1

    Watch out

    minFreq only grows inside touch, and resets to 1 whenever a new key goes in. Capacity 0 must store nothing. On eviction remove the key from all three maps.

Test yourself

Why a doubly linked list and not a singly linked one?

To unhook a node you must change its previous node's next. A singly linked list cannot reach the previous node in O(1); prev gives it directly.

What do the sentinel head and tail buy you?

Every real node always has a non-null prev and next, so remove and addFront need no "is this the first/last node?" checks, even on an empty cache.

Capacity 2: put(1), put(2), get(1), put(3). Which key is evicted?

Key 2. get(1) made 1 the most recent, so 2 was the least recently used when 3 arrived.
