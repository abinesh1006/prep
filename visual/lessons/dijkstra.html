Dijkstra's Shortest Path

For roads with travel times, always settle the closest unsettled place next (a min-heap gives it to you), and use it to shorten the routes to its neighbours.

Time to learn: about 2.5 hours · Prerequisites: Graph basics, Heap

When to use it — the signal

Weighted edges (time, cost, distance, effort), all weights ≥ 0, and "minimum time / cost from a source". If all weights are equal, plain BFS is enough; if some are negative, Dijkstra is the wrong tool.

The idea in plain words

A signal starts at node 1 and travels along one-way cables; each cable takes some milliseconds. When does the last node hear it? We need the shortest time from 1 to every node.

Keep a table dist[]: the best time found so far to each node. Start with dist[1] = 0 and everything else = ∞ (not reached).

  • Take the node with the smallest dist that is not settled yet — a min-heap (priority queue) hands it over in O(log n).
  • Its dist is now final: any other route would go through a node that is already farther away, and weights cannot be negative, so it cannot get cheaper.
  • Relax its outgoing edges: for edge u → v with weight w, if dist[u] + w < dist[v], we found a shorter way to v — update it and push (new dist, v) into the heap.

An old, larger entry for v may still be in the heap; when it pops later we see it is bigger than dist[v] and skip it (a "stale" entry). Total time O((V + E) log V).

Analogy

Water poured at the start of a network of pipes of different lengths. The water reaches the nearest junction first, then flows on from there. A junction is "wet" at the earliest possible moment, and once wet it stays wet — no later water can arrive earlier. Dijkstra simulates that order with a heap instead of a stopwatch.

Watch it work

1. Network Delay Time. Source = node 1. The badge on a node is its current best distance. Settled nodes turn green; the edge being relaxed is highlighted; the shortest-path tree grows in green.

2. Why negative weights break it. Edge C → B costs −3. Classic Dijkstra settles B too early and never takes it back.

Why it works

"When a node is popped with the smallest tentative distance, every other path to it must leave the settled set through a node that is at least as far, and with non-negative weights the rest of that path cannot make it shorter — so the popped distance is final. With a negative edge, a later path can get cheaper, so Dijkstra fails; use Bellman-Ford instead."

The template to remember

int[] dist = ∞; dist[src] = 0;
PriorityQueue<int[]> pq = /* min by a[0] */;
pq.add(new int[]{0, src});
while (!pq.isEmpty()) {
    int[] t = pq.poll(); int d = t[0], u = t[1];
    if (d > dist[u]) continue;               // stale
    for (edge u -> v, w)
        if (d + w < dist[v]) { dist[v] = d + w; pq.add(new int[]{dist[v], v}); }
}

Dijkstra is BFS with the queue swapped for a heap: once edges have different weights, "next in line" must mean "closest so far", and the heap gives that in O(log n).

Remember

Pop the smallest, skip if stale, relax the neighbours. Weights ≥ 0 only. Unweighted → BFS; negative → Bellman-Ford.

Common mistakes
  • Forgetting the stale check if (d > dist[u]) continue; — still correct, but it re-relaxes and can be much slower.
  • Comparator a[0] - b[0] can overflow with huge distances — use Integer.compare or long.
  • Adding dist[u] + w when dist[u] is MAX_VALUE — overflow to a negative number.
  • Using Dijkstra when there is a limit on the number of edges (Cheapest Flights Within K Stops) — the state needs the stop count too, or use Bellman-Ford rounds.

Practice in this order

  • Medium743. Network Delay Time — exactly animation 1.
    Show solution

    The idea

    A signal leaves node k and travels along directed, weighted edges [u, v, time]. How long until every node has received it, or −1 if some never does? Key insight: each node hears the signal at its shortest-path distance from k, so the answer is the largest of those distances. Weights are non-negative, so use Dijkstra: always settle the closest unsettled node next, using a min-heap (a priority queue that hands back the smallest item first).

    Brute force first

    Bellman-Ford (relax every edge n − 1 times) also works: O(n·E).

    Step by step

    1. Build the adjacency list. dist = ∞ everywhere except dist[k] = 0.
    2. Push {k, 0} into the min-heap.
    3. Pop the smallest {u, d}. If d > dist[u] it is an outdated entry: skip it.
    4. For each edge u → v: if d + w < dist[v], update dist[v] and push {v, new distance}.
    5. At the end, if any distance is still ∞ return −1, else return the maximum.

    Java

    class Solution {
    public int networkDelayTime(int[][] times, int n, int k) {
        List<List<int[]>> graph = new ArrayList<>();
        for (int i = 0; i <= n; i++) graph.add(new ArrayList<>());
        for (int[] t : times) {        // t = {from, to, time}
            graph.get(t[0]).add(new int[]{t[1], t[2]});
        }
        int[] dist = new int[n + 1];   // nodes are 1..n
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[k] = 0;
        // heap of {node, distance}: smallest distance first
        PriorityQueue<int[]> heap = new PriorityQueue<>(
                Comparator.comparingInt(x -> x[1]));
        heap.add(new int[]{k, 0});
        while (!heap.isEmpty()) {
            int[] top = heap.poll();
            int u = top[0], d = top[1];
            if (d > dist[u]) continue; // old, outdated entry
            for (int[] e : graph.get(u)) {
                int v = e[0], nd = d + e[1];
                if (nd < dist[v]) {    // found a faster way
                    dist[v] = nd;
                    heap.add(new int[]{v, nd});
                }
            }
        }
        int worst = 0;                 // last node to hear it
        for (int i = 1; i <= n; i++) {
            if (dist[i] == Integer.MAX_VALUE) return -1;
            worst = Math.max(worst, dist[i]);
        }
        return worst;
    }
}

    Time O(E log E) · Space O(n + E) — each edge can push one heap entry, and each push or pop costs log of the heap size.

    Dry run

    times [[2,1,1],[2,3,1],[3,4,1]], k = 2. Pop {2,0}: dist[1] = 1, dist[3] = 1. Pop {1,1}: no edges. Pop {3,1}: dist[4] = 2. Pop {4,2}. Max of 1, 0, 1, 2 = 2.

    Watch out

    Skip stale heap entries (d > dist[u]), or the same node is expanded many times. Nodes are 1..n, so loop from 1, not 0. Dijkstra fails with negative weights.

  • Medium1514. Path with Maximum Probability — max-heap, multiply instead of add.
    Show solution

    The idea

    Each undirected edge has a success probability; find the most likely path from start to end (the probability of a path is the product of its edges). Key insight: probabilities are ≤ 1, so multiplying can only make a path less likely, just as adding a non-negative weight only makes a path longer. That makes Dijkstra valid with two changes: a max-heap and multiply instead of add.

    Step by step

    1. Build the adjacency list with each edge both ways. best[start] = 1, everything else 0.
    2. Push {start, 1.0} into a max-heap (largest probability first).
    3. Pop {u, p}. If u is the end, return p: nothing popped later can be larger.
    4. If p < best[u], skip (outdated). Otherwise for each edge, np = p · prob; if it beats best[v], update and push.
    5. If the heap empties, return 0.

    Java

    class Solution {
    public double maxProbability(int n, int[][] edges,
            double[] succProb, int start_node, int end_node) {
        List<List<double[]>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
        for (int i = 0; i < edges.length; i++) {
            int a = edges[i][0], b = edges[i][1];
            graph.get(a).add(new double[]{b, succProb[i]});
            graph.get(b).add(new double[]{a, succProb[i]});
        }
        double[] best = new double[n]; // 0.0 = not reached
        best[start_node] = 1.0;
        // max-heap of {node, probability}: biggest first
        PriorityQueue<double[]> heap = new PriorityQueue<>(
                (x, y) -> Double.compare(y[1], x[1]));
        heap.add(new double[]{start_node, 1.0});
        while (!heap.isEmpty()) {
            double[] top = heap.poll();
            int u = (int) top[0];
            double p = top[1];
            if (u == end_node) return p; // can only get worse
            if (p < best[u]) continue;   // outdated entry
            for (double[] e : graph.get(u)) {
                int v = (int) e[0];
                double np = p * e[1];    // multiply, not add
                if (np > best[v]) {
                    best[v] = np;
                    heap.add(new double[]{v, np});
                }
            }
        }
        return 0.0;                      // end not reachable
    }
}

    Time O(E log E) · Space O(n + E) — the same as standard Dijkstra.

    Dry run

    Edges 0–1 (0.5), 1–2 (0.5), 0–2 (0.2), start 0, end 2. Pop {0,1}: best[1] = 0.5, best[2] = 0.2. Pop {1,0.5}: 0.5 · 0.5 = 0.25 > 0.2, so best[2] = 0.25. Pop {2,0.25} → return 0.25.

    Watch out

    The comparator must sort descending (Double.compare(y[1], x[1])). Return 0 (not −1) when the end is unreachable. Store the node id in a double array, so cast it back with (int).

  • Medium1631. Path With Minimum Effort — grid Dijkstra, path cost = max step instead of sum.
    Show solution

    The idea

    Walk from the top-left to the bottom-right of a height grid. A path's effort is its biggest single step (the largest height difference between two neighbouring cells on it). Find the smallest possible effort. Key insight: Dijkstra still works when the path cost is max(cost so far, step) instead of a sum, because extending a path never makes its cost smaller. Pattern: grid Dijkstra with a max-cost path.

    Brute force first

    Binary search on the effort and check with BFS whether the end is reachable using only steps ≤ that effort: O(m·n·log H), also accepted.

    Step by step

    1. effort grid = ∞, except 0 at the start. Push {0, 0, 0} into a min-heap.
    2. Pop the smallest {e, r, c}. If it is the bottom-right cell, return e.
    3. Skip it if e > effort[r][c].
    4. For each in-grid neighbour, ne = max(e, |height difference|); if smaller than its effort, update and push.

    Java

    class Solution {
    public int minimumEffortPath(int[][] heights) {
        int m = heights.length, n = heights[0].length;
        int[][] effort = new int[m][n];
        for (int[] row : effort) {
            Arrays.fill(row, Integer.MAX_VALUE);
        }
        effort[0][0] = 0;
        // heap of {effort, row, col}: smallest effort first
        PriorityQueue<int[]> heap = new PriorityQueue<>(
                Comparator.comparingInt(x -> x[0]));
        heap.add(new int[]{0, 0, 0});
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        while (!heap.isEmpty()) {
            int[] top = heap.poll();
            int e = top[0], r = top[1], c = top[2];
            if (r == m - 1 && c == n - 1) return e;
            if (e > effort[r][c]) continue; // outdated
            for (int[] d : dirs) {
                int nr = r + d[0], nc = c + d[1];
                if (nr < 0 || nc < 0 || nr >= m || nc >= n) {
                    continue;
                }
                int step = Math.abs(heights[nr][nc]
                                    - heights[r][c]);
                int ne = Math.max(e, step); // worst step so far
                if (ne < effort[nr][nc]) {
                    effort[nr][nc] = ne;
                    heap.add(new int[]{ne, nr, nc});
                }
            }
        }
        return 0;
    }
}

    Time O(m·n·log(m·n)) · Space O(m·n) — every cell has 4 edges, each pushing at most one heap entry.

    Dry run

    [[1,2,2],[3,8,2],[5,3,5]]. The route 1 → 3 → 5 → 3 → 5 (down the left, then along the bottom) has steps 2, 2, 2, 2, so its effort is 2. Any route through 8 has a step of at least 5. Dijkstra settles the cells reachable with effort ≤ 2 first and pops the corner at 2.

    Watch out

    Use max, not +, when extending a path. A 1×1 grid answers 0 (the start is the end). Return when the target is popped, not when it is first pushed.

  • Medium787. Cheapest Flights Within K Stops — the stop limit changes the state; Bellman-Ford with k + 1 rounds.
    Show solution

    The idea

    Find the cheapest flight route from src to dst using at most k stops (so at most k + 1 flights), or −1. Key insight: the stop limit means the cheapest route overall may be too long, so plain Dijkstra on price alone is wrong. Bellman-Ford fits perfectly: after round i, cost holds the cheapest price using at most i flights. Run exactly k + 1 rounds.

    Step by step

    1. cost = ∞ except cost[src] = 0.
    2. Repeat k + 1 times:
    3. Copy cost into next. For every flight from → to: if cost[from] is known and cost[from] + price < next[to], update next[to].
    4. Set cost = next.
    5. Return cost[dst], or −1 if it is still ∞.

    Java

    class Solution {
    public int findCheapestPrice(int n, int[][] flights,
                                 int src, int dst, int k) {
        final int INF = Integer.MAX_VALUE;
        int[] cost = new int[n];       // cheapest so far
        Arrays.fill(cost, INF);
        cost[src] = 0;
        // k stops = at most k + 1 flights = k + 1 rounds
        for (int round = 0; round <= k; round++) {
            int[] next = cost.clone(); // read old, write new
            for (int[] f : flights) {
                int from = f[0], to = f[1], price = f[2];
                if (cost[from] != INF
                        && cost[from] + price < next[to]) {
                    next[to] = cost[from] + price;
                }
            }
            cost = next;
        }
        return cost[dst] == INF ? -1 : cost[dst];
    }
}

    Time O(k·E) · Space O(n) — k + 1 passes over all flights, two arrays of size n.

    Dry run

    Flights 0→1 (100), 1→2 (100), 0→2 (500), k = 1. Round 1: cost[1] = 100, cost[2] = 500. Round 2: via 1, 100 + 100 = 200 < 500, cost[2] = 200. Answer 200. With k = 0, only round 1 runs → 500.

    Watch out

    Read from the old array and write into the copy. Updating in place lets one round chain several flights and break the stop limit (0→1→2 with k = 0 would wrongly be allowed). Dijkstra with state (node, stops used) also works.

  • Hard778. Swim in Rising Water — Dijkstra where the cost of a path is its highest cell.
    Show solution

    The idea

    At time t, water depth is t everywhere, and you can swim into a cell only if its height ≤ t. Find the earliest time to go from top-left to bottom-right. Key insight: a path is usable once the water covers its highest cell, so the cost of a path is its maximum height. Find the path with the smallest maximum: Dijkstra where cost = max, just like Minimum Effort.

    Brute force first

    Binary search on t and BFS through cells with height ≤ t: O(n² log n²). Union-Find adding cells in height order also works.

    Step by step

    1. Push {grid[0][0], 0, 0} into a min-heap and mark (0,0) seen.
    2. Pop the smallest {t, r, c}. If it is the bottom-right cell, return t.
    3. For each unseen in-grid neighbour, mark it seen and push {max(t, its height), nr, nc}.

    Java

    class Solution {
    public int swimInWater(int[][] grid) {
        int n = grid.length;
        boolean[][] seen = new boolean[n][n];
        // heap of {time, row, col}: lowest time first
        PriorityQueue<int[]> heap = new PriorityQueue<>(
                Comparator.comparingInt(x -> x[0]));
        heap.add(new int[]{grid[0][0], 0, 0});
        seen[0][0] = true;
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        while (!heap.isEmpty()) {
            int[] top = heap.poll();
            int t = top[0], r = top[1], c = top[2];
            if (r == n - 1 && c == n - 1) return t;
            for (int[] d : dirs) {
                int nr = r + d[0], nc = c + d[1];
                if (nr < 0 || nc < 0 || nr >= n || nc >= n
                        || seen[nr][nc]) {
                    continue;
                }
                seen[nr][nc] = true;
                // must wait until the water covers the
                // highest cell on the path
                int nt = Math.max(t, grid[nr][nc]);
                heap.add(new int[]{nt, nr, nc});
            }
        }
        return -1;
    }
}

    Time O(n² log n) · Space O(n²) — each cell is pushed once; log n² = 2 log n.

    Dry run

    [[0,2],[1,3]]. Push {0,(0,0)}. Pop it: push {2,(0,1)} and {1,(1,0)}. Pop {1,(1,0)}: push {max(1,3)=3,(1,1)}. Pop {2,(0,1)}: (1,1) already seen. Pop {3,(1,1)} → return 3.

    Watch out

    The start cell's own height counts: begin with grid[0][0], not 0. Marking a cell seen when pushed is safe here because the heap always pops the lowest time first, so the first push into a cell is never beaten.

Test yourself

All edges have weight 1. Do you need Dijkstra?

No — BFS gives the same answer in O(V + E) without a heap.

Why can the same node appear in the heap more than once?

Java's PriorityQueue cannot lower a key in place, so each improvement pushes a new entry. The older, larger entries are skipped as stale when popped.

What is the time complexity of Dijkstra with a binary heap?

O((V + E) log V): every edge can push one heap entry, and each push or pop costs O(log V).
