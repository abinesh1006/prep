Dijkstra's Shortest Path

For roads with travel times, always settle the closest unsettled place next (a min-heap gives it to you), and use it to shorten the routes to its neighbours.

Time to learn: about 2.5 hours · Prerequisites: Graph basics, Heap

When to use it — the signal

Weighted edges (time, cost, distance, effort), all weights ≥ 0, and "minimum time / cost from a source". If all weights are equal, plain BFS is enough; if some are negative, Dijkstra is the wrong tool.

The idea in plain words

A signal starts at node 1 and travels along one-way cables; each cable takes some milliseconds. When does the last node hear it? We need the shortest time from 1 to every node.

Keep a table dist[]: the best time found so far to each node. Start with dist[1] = 0 and everything else = ∞ (not reached).

  • Take the node with the smallest dist that is not settled yet — a min-heap (priority queue) hands it over in O(log n).
  • Its dist is now final: any other route would go through a node that is already farther away, and weights cannot be negative, so it cannot get cheaper.
  • Relax its outgoing edges: for edge u → v with weight w, if dist[u] + w < dist[v], we found a shorter way to v — update it and push (new dist, v) into the heap.

An old, larger entry for v may still be in the heap; when it pops later we see it is bigger than dist[v] and skip it (a "stale" entry). Total time O((V + E) log V).

Analogy

Water poured at the start of a network of pipes of different lengths. The water reaches the nearest junction first, then flows on from there. A junction is "wet" at the earliest possible moment, and once wet it stays wet — no later water can arrive earlier. Dijkstra simulates that order with a heap instead of a stopwatch.

Why it works

"When a node is popped with the smallest tentative distance, every other path to it must leave the settled set through a node that is at least as far, and with non-negative weights the rest of that path cannot make it shorter — so the popped distance is final. With a negative edge, a later path can get cheaper, so Dijkstra fails; use Bellman-Ford instead."

The template to remember

int[] dist = ∞; dist[src] = 0;
PriorityQueue<int[]> pq = /* min by a[0] */;
pq.add(new int[]{0, src});
while (!pq.isEmpty()) {
    int[] t = pq.poll(); int d = t[0], u = t[1];
    if (d > dist[u]) continue;               // stale
    for (edge u -> v, w)
        if (d + w < dist[v]) { dist[v] = d + w; pq.add(new int[]{dist[v], v}); }
}
Remember

Pop the smallest, skip if stale, relax the neighbours. Weights ≥ 0 only. Unweighted → BFS; negative → Bellman-Ford.

Common mistakes
  • Forgetting the stale check if (d > dist[u]) continue; — still correct, but it re-relaxes and can be much slower.
  • Comparator a[0] - b[0] can overflow with huge distances — use Integer.compare or long.
  • Adding dist[u] + w when dist[u] is MAX_VALUE — overflow to a negative number.
  • Using Dijkstra when there is a limit on the number of edges (Cheapest Flights Within K Stops) — the state needs the stop count too, or use Bellman-Ford rounds.

Test yourself

All edges have weight 1. Do you need Dijkstra?

No — BFS gives the same answer in O(V + E) without a heap.

Why can the same node appear in the heap more than once?

Java's PriorityQueue cannot lower a key in place, so each improvement pushes a new entry. The older, larger entries are skipped as stale when popped.

What is the time complexity of Dijkstra with a binary heap?

O((V + E) log V): every edge can push one heap entry, and each push or pop costs O(log V).
