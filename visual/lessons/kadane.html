Kadane's Algorithm

Walk the array once, and at every number decide: keep adding to the run I have, or throw it away and start fresh here. The best run you ever had is the answer.

Time to learn: about 1.5 hours · Prerequisites: Prefix sum, Big-O

When to use it — the signal

"Maximum sum subarray", "largest contiguous sum", "maximum product subarray", "best profit from one buy and one sell", "maximum circular subarray" — one best stretch of neighbours, numbers can be negative, and you want O(n) time with O(1) memory.

The idea in plain words

In [−2, 1, −3, 4, −1, 2, 1, −5, 4] the best stretch is [4, −1, 2, 1] with sum 6. There are 45 stretches; we do not want to try them all.

Walk left to right keeping cur = the best sum of a stretch that ends right here. At the next number x there are only two choices:

  • Keep: extend the previous stretch → cur + x.
  • Restart: start a new stretch at x → x.

Pick the bigger. In plain words: if the run so far is negative, it only drags you down — drop it. Keep best = the largest cur ever seen.

For products, a negative number flips the biggest product into the smallest and the smallest into the biggest (−6 × −4 = 24). So keep both the largest (hi) and the smallest (lo) product ending here.

Analogy

A gambler walking past a row of tables, each paying a win or a loss. He carries his running winnings. If at some table his pocket is below zero, he leaves that debt behind and starts again with an empty pocket — a debt can never help a future streak. He writes down his best pocket total ever.

Why it works (the one sentence to say in an interview)

"The best subarray ending at i either extends the best one ending at i − 1 or starts fresh at i — a negative prefix can only lower the sum — so one pass tracking 'best ending here' and 'best overall' finds the maximum in O(n). For products I track both max and min because a negative number swaps them."

The template to remember

int cur = a[0], best = a[0];
for (int i = 1; i < n; i++) {
    cur  = Math.max(a[i], cur + a[i]);   // restart or keep
    best = Math.max(best, cur);
}
// Product: track hi and lo; candidates are a[i], hi*a[i], lo*a[i]

Data structures used — and why

Kadane is a DP whose table collapses to a few variables: each step only needs the answer for the previous index, so no array beyond the input is kept.

Remember

Keep or restart: cur = max(x, cur + x). A negative run is dead weight. Products: carry both hi and lo — a minus sign swaps them.

Common mistakes
  • Starting with best = 0: if every number is negative (e.g. [−3, −1]) the answer is −1, not 0.
  • Product: updating hi first and then using the new hi to compute lo. Save hi·x and lo·x before updating either.
  • Forgetting that 0 resets a product run — the "x alone" candidate handles it.
  • Circular version: the answer is max(normal Kadane, total − minimum subarray), except when all numbers are negative.

Practice in this order

  • Easy121. Best Time to Buy and Sell Stock — Kadane on daily price differences, or track the minimum price.
    Show solution

    The idea

    Buy one day, sell a later day, maximise profit (or 0). [7,1,5,3,6,4] → 5. The insight: as you walk, the best buy is the cheapest price so far; selling today earns price - minPrice. (Same answer as Kadane on the daily differences [-6,4,-2,3,-2]: best run 4−2+3 = 5.)

    Brute force first

    Every buy/sell pair: O(n²).

    Step by step

    1. minPrice = first price, best = 0.
    2. For each price: best = max(best, price - minPrice).
    3. Then minPrice = min(minPrice, price).
    4. Return best.

    Java

    class Solution {
    public int maxProfit(int[] prices) {
        int minPrice = prices[0], best = 0;
        for (int p : prices) {
            best = Math.max(best, p - minPrice); // sell
            minPrice = Math.min(minPrice, p);    // buy
        }
        return best;
    }
}

    Time O(n) · Space O(1) — one pass, two variables.

    Dry run

    [7,1,5,3,6,4]: min 7, then 1; profits 4 (sell at 5), 2, 5 (sell at 6), 3. Best 5.

    Watch out

    Update best before minPrice so you never buy and sell on the same moment (it would only give 0 anyway, but the order shows the idea). Falling prices give 0.

  • Medium53. Maximum Subarray — the first animation.
    Show solution

    The idea

    Find the run of neighbours with the largest sum. [-2,1,-3,4,-1,2,1,-5,4] → 6 ([4,-1,2,1]). The insight (Kadane): at each number, either extend the run ending at the previous number, or start fresh here. If the run so far is negative, it only hurts, so start fresh.

    Brute force first

    Every start and end with a running sum: O(n²).

    Step by step

    1. cur = best sum of a run ending here; best = best seen. Both start at nums[0].
    2. For each next x: cur = max(x, cur + x) (start fresh or extend).
    3. best = max(best, cur).
    4. Return best.

    Java

    class Solution {
    public int maxSubArray(int[] nums) {
        int cur = nums[0], best = nums[0];
        for (int i = 1; i < nums.length; i++) {
            // extend the run, or start again at nums[i]
            cur = Math.max(nums[i], cur + nums[i]);
            best = Math.max(best, cur);
        }
        return best;
    }
}

    Time O(n) · Space O(1) — one pass, two variables.

    Dry run

    x:    -2  1 -3  4 -1  2  1 -5  4
cur:  -2  1 -2  4  3  5  6  1  5
best: -2  1  1  4  4  5  6  6  6

    Watch out

    Start with nums[0], not 0: if every number is negative the answer is the largest single number (−1 for [-3,-1,-2]), not 0.

  • Medium152. Maximum Product Subarray — the second animation.
    Show solution

    The idea

    Largest product of a run of neighbours. [2,3,-2,4] → 6. The twist: a negative number turns the smallest product into the largest. So track both the max and the min product of a run ending here; when x is negative they swap roles. Pattern: Kadane with max and min.

    Brute force first

    Every run with a running product: O(n²).

    Step by step

    1. hi = lo = best = nums[0].
    2. For each next x: if x < 0, swap hi and lo (negative flips big and small).
    3. hi = max(x, hi * x), lo = min(x, lo * x): extend or start fresh.
    4. best = max(best, hi).

    Java

    class Solution {
    public int maxProduct(int[] nums) {
        int hi = nums[0], lo = nums[0], best = nums[0];
        for (int i = 1; i < nums.length; i++) {
            int x = nums[i];
            if (x < 0) { // negative swaps biggest/smallest
                int t = hi; hi = lo; lo = t;
            }
            hi = Math.max(x, hi * x);
            lo = Math.min(x, lo * x);
            best = Math.max(best, hi);
        }
        return best;
    }
}

    Time O(n) · Space O(1) — one pass, three variables.

    Dry run

    [-2,3,-4]
start hi=-2 lo=-2 best=-2
x=3:  hi=max(3,-6)=3   lo=min(3,-6)=-6  best 3
x=-4: swap -> hi=-6 lo=3
      hi=max(-4,24)=24 lo=min(-4,-12)=-12 best 24

    Watch out

    Zero resets both (start fresh after it) and is handled by the max(x, ...). Do the swap before multiplying, or compute both new values from the old ones at the same time.

  • Medium918. Maximum Sum Circular Subarray — total minus the minimum subarray.
    Show solution

    The idea

    Like Maximum Subarray, but the run may wrap from the end back to the start. [5,-3,5] → 10 (5 + 5 wrapping). The insight: a wrapping run is everything except a middle run; to make it largest, remove the smallest middle run. So answer = max(maxSubarray, total - minSubarray).

    Brute force first

    Try every start and every length up to n, wrapping with % n: O(n²).

    Step by step

    1. Run Kadane for the max run (curMax, bestMax) and, in the same loop, for the min run (curMin, bestMin). Also add up total.
    2. If bestMax < 0, every number is negative: return bestMax.
    3. Otherwise return max(bestMax, total - bestMin).

    Java

    class Solution {
    public int maxSubarraySumCircular(int[] nums) {
        int curMax = 0, bestMax = nums[0];
        int curMin = 0, bestMin = nums[0], total = 0;
        for (int x : nums) {
            curMax = Math.max(x, curMax + x);
            bestMax = Math.max(bestMax, curMax);
            curMin = Math.min(x, curMin + x);
            bestMin = Math.min(bestMin, curMin);
            total += x;
        }
        // all negative: total - bestMin would be empty
        if (bestMax < 0) return bestMax;
        return Math.max(bestMax, total - bestMin);
    }
}

    Time O(n) · Space O(1) — one pass running both Kadanes.

    Dry run

    [5,-3,5]: bestMax = 7 (5−3+5), bestMin = −3, total = 7. Wrap = 7 − (−3) = 10. Answer max(7, 10) = 10.

    Watch out

    All-negative input: the min run is the whole array, so total - bestMin = 0 would mean picking nothing, which is not allowed. That is why we return bestMax when it is negative.

  • Medium1749. Maximum Absolute Sum of Any Subarray — run Kadane for max and for min.
    Show solution

    The idea

    Largest |sum| of any run (the empty run counts as 0). [2,-5,1,-4,3,-2] → 8 (−5+1−4 = −8). The insight: the biggest absolute value is either the biggest sum or the most negative sum, so run Kadane twice (max and min) in one loop and take the larger magnitude.

    Brute force first

    Every run with a running sum: O(n²). (Alternative O(n): answer = max prefix − min prefix.)

    Step by step

    1. curMax = curMin = 0, best = 0.
    2. For each x: curMax = max(0, curMax + x), curMin = min(0, curMin + x) (0 = restart with an empty run).
    3. best = max(best, curMax, -curMin).
    4. Return best.

    Java

    class Solution {
    public int maxAbsoluteSum(int[] nums) {
        int curMax = 0, curMin = 0, best = 0;
        for (int x : nums) {
            curMax = Math.max(0, curMax + x); // biggest sum
            curMin = Math.min(0, curMin + x); // most negative
            best = Math.max(best, Math.max(curMax, -curMin));
        }
        return best;
    }
}

    Time O(n) · Space O(1) — one pass, three variables.

    Dry run

    [1,-3,2,3,-4]
x:      1 -3  2  3 -4
curMax: 1  0  2  5  1
curMin: 0 -3 -1  0 -4
best:   1  3  3  5  5

    Watch out

    Here restarting at 0 is allowed because the empty run (sum 0) counts. |x| fits in int: n ≤ 105 and |x| ≤ 104 gives at most 109.

Test yourself

All numbers are negative: [−5, −2, −7]. What does Kadane return, and why must best not start at 0?

−2. A subarray must contain at least one number; starting best at 0 would wrongly return the empty subarray's sum.

When exactly do we "restart"?

When cur + x < x, i.e. when cur < 0. A negative run can only make the next stretch smaller.

Why track the minimum in the product version?

A very negative product times a negative number becomes a very large positive product — today's minimum can be tomorrow's maximum.
