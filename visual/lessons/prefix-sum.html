Prefix Sum

Add up the array once from the left into a "running total" array; after that, the sum of any stretch is one subtraction.

Time to learn: about 2 hours · Prerequisites: Arrays and hashing, Big-O

When to use it — the signal

"Sum of a range l..r", many range queries on an array that does not change, "number of subarrays with sum = k", "subarray sum divisible by k", "equal number of 0s and 1s", "pivot index" — especially when the numbers can be negative (where a sliding window fails).

The idea in plain words

Take nums = [3, 1, 4, 1, 5, 9, 2]. Build pre where pre[i] = sum of the first i numbers: pre = [0, 3, 4, 8, 9, 14, 23, 25]. It has one extra slot at the start, pre[0] = 0 (the sum of nothing).

The sum of nums[2..4] (4 + 1 + 5 = 10) is "everything up to index 4" minus "everything before index 2": pre[5] − pre[2] = 14 − 4 = 10. One subtraction, no loop.

Building pre costs O(n) once. Each query afterwards is O(1). With 10,000 queries on 10,000 numbers that is 20,000 steps instead of up to 100 million.

The deeper trick: a subarray sums to k exactly when two prefix sums differ by k. So while walking, ask a hash map "how many earlier prefix sums equal current − k?" That counts subarrays in one pass — even with negative numbers.

Analogy

A car's odometer. To know how far you drove between the 2nd and 5th petrol station, you do not re-drive the road — you read the odometer at both stations and subtract. The prefix array is the odometer reading at every station.

Why it works (the one sentence to say in an interview)

"The sum of nums[l..r] is pre[r+1] − pre[l], so a subarray ending at j sums to k exactly when some earlier prefix equals pre[j+1] − k; counting earlier prefixes in a hash map gives every such subarray in one O(n) pass."

The template to remember

// Range queries
int[] pre = new int[n + 1];
for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
sum(l..r) = pre[r + 1] - pre[l];

// Count subarrays with sum k
count.put(0, 1);
for (int x : a) {
    sum += x;
    ans += count.getOrDefault(sum - k, 0);   // look back first
    count.merge(sum, 1, Integer::sum);      // then record
}

A prefix array turns "sum of a range" into one subtraction; pairing it with a hash map turns "how many ranges have sum k" into one lookup per index.

Remember

Range sum = pre[r+1] − pre[l]. Subarray = difference of two prefixes. Seed the map with {0 : 1}; look back first, then record.

Common mistakes
  • Forgetting count.put(0, 1) — subarrays that start at index 0 are never counted.
  • Recording the current sum before looking up sum − k: with k = 0 every position counts itself.
  • Off-by-one: with the n + 1 array it is pre[r + 1] − pre[l], not pre[r] − pre[l].
  • Overflow: sums of 105 numbers up to 109 need long.
  • Reaching for a sliding window when numbers can be negative — prefix sums + map is the right tool.

Practice in this order

  • Easy1480. Running Sum of 1d Array — just build the prefix array.
    Show solution

    The idea

    Return an array where position i holds nums[0] + ... + nums[i]. [1,2,3,4] → [1,3,6,10]. This is the prefix array: each entry is the previous entry plus one number.

    Brute force first

    For each i, loop from 0 to i and add up. That is 1 + 2 + ... + n additions = O(n²) time.

    Step by step

    1. Start at index 1 (index 0 is already its own running sum).
    2. Set nums[i] += nums[i - 1]: the previous cell already holds the sum of everything before.
    3. Keep going to the end and return nums.

    Java

    class Solution {
    public int[] runningSum(int[] nums) {
        for (int i = 1; i < nums.length; i++) {
            // nums[i-1] already holds the sum so far
            nums[i] += nums[i - 1];
        }
        return nums;
    }
}

    Time O(n) · Space O(1) — one pass, and we reuse the input array for the answer.

    Dry run

    [1,2,3,4]: i=1 → 2+1=3; i=2 → 3+3=6; i=3 → 4+6=10 → [1,3,6,10].

    Watch out

    Start the loop at 1, not 0, or you read nums[-1]. If you must not change the input, copy it into a new array first (then space is O(n)).

  • Easy303. Range Sum Query – Immutable — the second animation.
    Show solution

    The idea

    Many questions "sum of nums[left..right]?" on an array that never changes. The insight: build pre[i] = sum of the first i numbers once; then any range sum is pre[right + 1] - pre[left] in O(1). Pattern: prefix sums.

    Brute force first

    Loop from left to right for each query: O(n) per query, O(n · q) total.

    Step by step

    1. Make pre of size n + 1 with pre[0] = 0.
    2. pre[i + 1] = pre[i] + nums[i].
    3. For a query, return pre[right + 1] - pre[left]: everything up to right, minus everything before left.

    Java

    class NumArray {
    private final int[] pre; // pre[i] = sum of first i

    public NumArray(int[] nums) {
        pre = new int[nums.length + 1];
        for (int i = 0; i < nums.length; i++) {
            pre[i + 1] = pre[i] + nums[i];
        }
    }

    public int sumRange(int left, int right) {
        return pre[right + 1] - pre[left];
    }
}

    Time O(n) to build, O(1) per query · Space O(n) — one extra array.

    Dry run

    nums = [-2, 0, 3,-5, 2,-1]
pre  = [0,-2,-2, 1,-4,-2,-3]
sumRange(2,5) = pre[6] - pre[2] = -3 - (-2) = -1

    Watch out

    The extra leading 0 (size n + 1) removes the special case for left = 0. Off-by-one: it is pre[right + 1], not pre[right].

  • Easy724. Find Pivot Index — left sum = total − left − nums[i].
    Show solution

    The idea

    Find the leftmost index where the sum of numbers to its left equals the sum to its right. [1,7,3,6,5,6] → 3 (1+7+3 = 11 = 5+6). The insight: once you know the total, the right sum is total - left - nums[i], so one running left sum is enough.

    Brute force first

    For each index, add up its left and its right side: O(n²).

    Step by step

    1. Compute total, the sum of all numbers.
    2. Walk i with left = 0 (sum of everything before i).
    3. If left == total - left - nums[i], return i.
    4. Otherwise left += nums[i] and continue. Return −1 if none.

    Java

    class Solution {
    public int pivotIndex(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;
        int left = 0;
        for (int i = 0; i < nums.length; i++) {
            int right = total - left - nums[i];
            if (left == right) return i;
            left += nums[i];
        }
        return -1;
    }
}

    Time O(n) · Space O(1) — two passes, two variables.

    Dry run

    [1,7,3,6,5,6], total 28: i=0 left 0 right 27; i=1 left 1 right 20; i=2 left 8 right 17; i=3 left 11 right 28−11−6 = 11 → return 3.

    Watch out

    Check before adding nums[i] to left: the pivot itself belongs to neither side. Index 0 can be the pivot (left sum is 0), as in [2,1,-1].

  • Medium560. Subarray Sum Equals K — the third animation.
    Show solution

    The idea

    Count the runs of neighbours that add up to exactly k (numbers can be negative). [1,1,1], k = 2 → 2. The insight: a run ending at i sums to k exactly when some earlier prefix equals prefix - k. Keep a hash map from prefix sum to how many times it has appeared. Pattern: prefix sum + hash map.

    Brute force first

    Every start, extend to every end, keep a running sum: O(n²). Sliding window fails because of negative numbers.

    Step by step

    1. Map count with {0: 1}: the empty prefix, so runs starting at index 0 are counted.
    2. Walk the array keeping a running sum.
    3. Add count.get(sum - k) to the answer: each such earlier prefix starts one valid run.
    4. Then record the current sum: count[sum]++.

    Java

    class Solution {
    public int subarraySum(int[] nums, int k) {
        Map<Integer, Integer> count = new HashMap<>();
        count.put(0, 1); // empty prefix
        int sum = 0, ans = 0;
        for (int x : nums) {
            sum += x;
            ans += count.getOrDefault(sum - k, 0);
            count.merge(sum, 1, Integer::sum);
        }
        return ans;
    }
}

    Time O(n) · Space O(n) — one pass; the map can hold n prefix sums.

    Dry run

    [1,2,3], k=3      map starts {0:1}
x=1 sum 1: need -2 -> 0   map {0:1,1:1}
x=2 sum 3: need  0 -> +1  map {..,3:1}   ([1,2])
x=3 sum 6: need  3 -> +1  ([3])          ans 2

    Watch out

    Forgetting count.put(0, 1) misses every run that starts at index 0. Look up sum - k before adding the current sum, or k = 0 counts empty runs.

  • Medium523. Continuous Subarray Sum — store prefix mod k → first index.
    Show solution

    The idea

    Is there a run of at least 2 neighbours whose sum is a multiple of k? [23,2,4,6,7], k = 6 → true (2+4 = 6). The insight: if two prefix sums leave the same remainder mod k, the numbers between them sum to a multiple of k. Store each remainder's first index and check the gap is ≥ 2.

    Brute force first

    All runs of length ≥ 2 with a running sum: O(n²). n can be 105.

    Step by step

    1. Map first remainder → earliest index, starting with {0: -1} (empty prefix before index 0).
    2. Walk i, keep mod = (mod + nums[i]) % k.
    3. If mod was seen at index j and i - j >= 2, return true.
    4. If it was never seen, store first[mod] = i (keep the earliest; never overwrite).
    5. Return false at the end.

    Java

    class Solution {
    public boolean checkSubarraySum(int[] nums, int k) {
        Map<Integer, Integer> first = new HashMap<>();
        first.put(0, -1); // empty prefix
        int mod = 0;
        for (int i = 0; i < nums.length; i++) {
            mod = (mod + nums[i]) % k;
            Integer j = first.get(mod);
            if (j == null) first.put(mod, i);
            else if (i - j >= 2) return true;
        }
        return false;
    }
}

    Time O(n) · Space O(min(n, k)) — one pass; at most k different remainders.

    Dry run

    [23,2,4,6,7], k=6   first {0:-1}
i=0 mod 23%6=5   new   {5:0}
i=1 mod 25%6=1   new   {1:1}
i=2 mod 29%6=5   seen at 0, gap 2 -> true

    Watch out

    Keep the first index of each remainder, never update it, or the length check fails. {0: -1} makes a run starting at index 0 count. A single 0 is not enough: length must be ≥ 2.

  • Medium525. Contiguous Array — treat 0 as −1, find equal prefix sums.
    Show solution

    The idea

    In a 0/1 array, find the longest run with as many 0s as 1s. [0,1,0] → 2. The insight: count 0 as −1. Then "equal 0s and 1s" means "sums to 0", and a run sums to 0 when two prefix sums are equal. Store each prefix sum's first index.

    Brute force first

    Every run, count zeros and ones: O(n²).

    Step by step

    1. Map first: prefix sum → earliest index, starting {0: -1}.
    2. Walk i: sum += nums[i] == 1 ? 1 : -1.
    3. If this sum was seen at j, the run j+1..i is balanced: length i - j; keep the max.
    4. If not seen, store first[sum] = i.

    Java

    class Solution {
    public int findMaxLength(int[] nums) {
        Map<Integer, Integer> first = new HashMap<>();
        first.put(0, -1);
        int sum = 0, best = 0;
        for (int i = 0; i < nums.length; i++) {
            sum += nums[i] == 1 ? 1 : -1; // 0 counts as -1
            Integer j = first.get(sum);
            if (j != null) best = Math.max(best, i - j);
            else first.put(sum, i);
        }
        return best;
    }
}

    Time O(n) · Space O(n) — one pass; up to n different sums.

    Dry run

    [0,1,0]: i=0 sum −1 new; i=1 sum 0, seen at −1 → length 2; i=2 sum −1, seen at 0 → length 2. Answer 2.

    Watch out

    Store only the first index of each sum (that gives the longest run). Without {0: -1} you miss runs that start at index 0, like [0,1].

  • Medium304. Range Sum Query 2D — prefix sums on a grid.
    Show solution

    The idea

    Many questions "sum of the rectangle from (r1,c1) to (r2,c2)?" on a fixed grid. The insight: pre[i][j] = sum of the rectangle from (0,0) to (i−1, j−1). Any rectangle is then big box minus top strip minus left strip plus the corner that was removed twice. Pattern: 2D prefix sums.

    Brute force first

    Add every cell inside the rectangle for each query: O(rows × cols) per query.

    Step by step

    1. Make pre of size (m + 1) × (n + 1), all 0.
    2. Fill pre[i+1][j+1] = matrix[i][j] + pre[i][j+1] + pre[i+1][j] - pre[i][j] (cell + above + left − overlap).
    3. Query: pre[r2+1][c2+1] - pre[r1][c2+1] - pre[r2+1][c1] + pre[r1][c1].

    Java

    class NumMatrix {
    private final int[][] pre;

    public NumMatrix(int[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        pre = new int[m + 1][n + 1];
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                // cell + above + left - counted twice
                pre[i + 1][j + 1] = matrix[i][j]
                    + pre[i][j + 1] + pre[i + 1][j]
                    - pre[i][j];
            }
        }
    }

    public int sumRegion(int r1, int c1, int r2, int c2) {
        return pre[r2 + 1][c2 + 1] - pre[r1][c2 + 1]
             - pre[r2 + 1][c1] + pre[r1][c1];
    }
}

    Time O(m·n) to build, O(1) per query · Space O(m·n) — one extra grid.

    Dry run

    grid [[1,2],     pre [[0,0,0],
      [3,4]]          [0,1,3],
                      [0,4,10]]
sumRegion(1,1,1,1) = 10 - 3 - 4 + 1 = 4

    Watch out

    The extra row and column of zeros remove edge cases for r1 = 0 or c1 = 0. Remember to add back the corner pre[r1][c1]: it was subtracted twice.

Test yourself

Why does pre have n + 1 slots instead of n?

pre[0] = 0 stands for "sum of nothing", so a range that starts at index 0 is pre[r+1] − pre[0] with no special case.

Why do we seed the map with {0 : 1}?

A subarray from index 0 to j has sum pre[j+1] − 0. The 0 must already be "seen" for it to be counted.

The array has negative numbers and you need the count of subarrays with sum k. Window or prefix sum?

Prefix sum + hash map. Negatives mean growing a window can shrink its sum, so the window logic breaks.
