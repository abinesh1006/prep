Tree Traversals

Visiting every node of a tree exactly once — and the only difference between pre-order, in-order and post-order is when you write the node down.

Time to learn: about 2 hours · Prerequisites: Recursion, Stack basics

When to use it — the signal

"Return the nodes in pre-order / in-order / post-order", "print the tree", "copy / serialize the tree", "sorted order of a BST", or any problem that must look at every node — that is every tree problem. Level by level is a different walk: see Tree BFS.

The idea in plain words

First, the words (each one is used in every tree problem):

  • Node = one box holding a value plus links to its children. In a binary tree each node has at most two children: left and right.
  • Root = the top node (no parent). Leaf = a node with no children. null = an empty spot where a child could be.
  • Subtree = a node together with everything below it. The left child is the root of the left subtree.
  • Depth of a node = how many steps down from the root (root = 0). Height of the tree = the number of levels (here we count nodes on the longest root-to-leaf path).

A tree is recursive by nature: a tree is "a root, plus a left tree, plus a right tree". So a walk over it is three jobs: handle me, walk my left subtree, walk my right subtree. The three famous orders just put "me" in a different place:

  • Pre-order = me, left, right. ("pre" = me before my children.) Good for copying a tree.
  • In-order = left, me, right. (me in between.) In a binary search tree this gives the values sorted.
  • Post-order = left, right, me. (me after my children.) Good when a node needs its children's answers first — heights, sizes, deleting a tree.

Every walk visits each of the n nodes once → O(n) time. The call stack holds one path from the root down → O(h) extra space, where h = height (about log n for a balanced tree, n for a tree that is one long line).

Analogy

A family tree and a manager asking for a report. Pre-order: the manager writes their own name, then asks the left team, then the right team. Post-order: the manager waits until both teams have reported, then writes the summary — like adding up the budgets of a company. In-order: read the left team's names, then the manager, then the right team's — like reading a book's index left to right.

3. Post-order: left, right, me

A node is written only after both children are finished, so the root comes out last.

4. In-order without recursion: an explicit stack

Interviewers often ask for the loop version. The recursion's call stack becomes our own Deque: slide left as far as possible, saving each node on the stack; then pop one, write it, and go to its right child.

Why it works

"A tree is a root plus a left tree plus a right tree, so one recursive function that handles the root and trusts itself on both subtrees visits every node exactly once. The three orders differ only in where the line that handles the root sits. Time O(n), space O(h) for the call stack."

The template to remember

void dfs(TreeNode node) {
    if (node == null) return;   // base case: empty spot
    // PRE-order work here  (me before children)
    dfs(node.left);
    // IN-order work here   (me between children)
    dfs(node.right);
    // POST-order work here (me after children)
}

A traversal is a walk that must remember where to come back to; recursion hides that memory in the call stack, and the iterative versions show it as an explicit ArrayDeque.

Remember

Pre = me first. In = me in the middle. Post = me last. In-order of a BST is sorted. Post-order when you need the children's answers first.

Common mistakes
  • Forgetting if (node == null) return; → NullPointerException on the first leaf.
  • Creating a new list inside the recursive function — pass one list down (or use a field) so all calls add to the same list.
  • Iterative in-order: writing the loop as while (!st.isEmpty()) only — at the start the stack is empty, and after popping the root the right side is forgotten. Use cur != null || !st.isEmpty().
  • Saying the space is O(log n) for any tree. It is O(h): a tree shaped like a line has h = n.

Practice in this order

  • Easy144. Binary Tree Preorder Traversal — animation 1; then do it with a stack (push right before left).
    Show solution

    The idea

    Preorder means: visit me, then my whole left subtree, then my whole right subtree. For root 1 with right child 2 whose left child is 3, the answer is [1,2,3]. The recursive version is three lines; the interview follow-up is doing it with an explicit stack (last in, first out), which copies what the call stack does.

    Step by step

    1. If the tree is empty, return an empty list.
    2. Push the root onto a stack.
    3. Pop a node and record its value (me first).
    4. Push its right child, then its left child, so the left one is popped next.
    5. Repeat until the stack is empty.

    Java

    class Solution {
    public List<Integer> preorderTraversal(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        if (root == null) return out;
        Deque<TreeNode> stack = new ArrayDeque<>();
        stack.push(root);
        while (!stack.isEmpty()) {
            TreeNode n = stack.pop();
            out.add(n.val);                  // me first
            // right goes in first so left comes out first
            if (n.right != null) stack.push(n.right);
            if (n.left != null) stack.push(n.left);
        }
        return out;
    }
}

    Time O(n) · Space O(h) — every node is pushed and popped once; the stack holds about one path plus siblings (h = height).

    Dry run

    Tree 1 → (right) 2 → (left) 3. Stack [1] → pop 1, push 2 → pop 2, push 3 → pop 3. Output [1,2,3].

    Watch out

    Pushing left before right gives "me, right, left", the wrong order. Push right first. Never push null children.

  • Easy94. Binary Tree Inorder Traversal — animations 2 and 4.
    Show solution

    The idea

    Inorder means: left subtree, then me, then right subtree. For 1 → (right) 2 → (left) 3 the answer is [1,3,2]. Iteratively: slide as far left as possible pushing nodes on a stack; the top of the stack is then the next node to print; after printing it, go into its right subtree and repeat.

    Step by step

    1. Start with cur = root and an empty stack.
    2. While cur is not null, push it and move to cur.left.
    3. Pop a node: this is the leftmost unprinted node. Record it.
    4. Set cur to its right child and go back to step 2.
    5. Stop when cur is null and the stack is empty.

    Java

    class Solution {
    public List<Integer> inorderTraversal(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode cur = root;
        while (cur != null || !stack.isEmpty()) {
            while (cur != null) { // slide all the way left
                stack.push(cur);
                cur = cur.left;
            }
            cur = stack.pop(); // leftmost not yet printed
            out.add(cur.val);
            cur = cur.right; // then its right subtree
        }
        return out;
    }
}

    Time O(n) · Space O(h) — each node is pushed and popped once; the stack holds at most one root-to-leaf path.

    Dry run

    1 → R 2 → L 3. Push 1, left is null → pop 1, print 1, cur = 2. Push 2, push 3 → pop 3, print → cur = null → pop 2, print. Output [1,3,2].

    Watch out

    The outer loop condition needs both parts: cur != null || !stack.isEmpty(). With only the stack check you stop before visiting a right subtree.

  • Easy145. Binary Tree Postorder Traversal — iterative: reverse of (me, right, left).
    Show solution

    The idea

    Postorder means: left subtree, right subtree, then me. For 1 → R 2 → L 3 the answer is [3,2,1]. Trick: "me, right, left" is easy with a stack (it is preorder with the children swapped), and its reverse is exactly "left, right, me". Adding each value at the front of the list does the reversing for free.

    Step by step

    1. Push the root on a stack.
    2. Pop a node and add its value at the front of the result.
    3. Push its left child, then its right child (so right is processed first).
    4. Repeat until the stack is empty; the list is already in postorder.

    Java

    class Solution {
    public List<Integer> postorderTraversal(TreeNode root) {
        LinkedList<Integer> out = new LinkedList<>();
        if (root == null) return out;
        Deque<TreeNode> stack = new ArrayDeque<>();
        stack.push(root);
        while (!stack.isEmpty()) {
            TreeNode n = stack.pop();
            // build (me, right, left) backwards by adding
            // at the front: the list ends up left, right, me
            out.addFirst(n.val);
            if (n.left != null) stack.push(n.left);
            if (n.right != null) stack.push(n.right);
        }
        return out;
    }
}

    Time O(n) · Space O(n) — each node handled once; the output list itself is n long.

    Dry run

    Stack [1] → pop 1, list [1], push 2 → pop 2, list [2,1], push 3 → pop 3, list [3,2,1].

    Watch out

    Use a LinkedList (or reverse at the end); ArrayList.add(0, x) is O(n) each time and makes the whole thing O(n²).

  • Easy100. Same Tree — walk both trees at once, compare node by node.
    Show solution

    The idea

    Two trees are the same if they have the same shape and the same values everywhere. Walk both trees at once: the roots must match, and then the left subtrees must be the same and the right subtrees must be the same. This is tree recursion: trust the call on the children.

    Step by step

    1. Both nodes null: same (true).
    2. Exactly one null: different shape (false).
    3. Values differ: false.
    4. Otherwise return same(left, left) and same(right, right).

    Java

    class Solution {
    public boolean isSameTree(TreeNode p, TreeNode q) {
        if (p == null && q == null) return true; // both empty
        if (p == null || q == null) return false; // one empty
        if (p.val != q.val) return false;
        // same value here: both subtrees must match too
        return isSameTree(p.left, q.left)
            && isSameTree(p.right, q.right);
    }
}

    Time O(n) · Space O(h) — each pair of nodes is compared once; recursion goes as deep as the tree.

    Dry run

    [1,2] vs [1,null,2]: roots 1 = 1. Left: 2 vs null → one is null → false. Answer false.

    Watch out

    Check the null cases before reading .val, or you get a NullPointerException.

  • Medium105. Construct Tree from Preorder and Inorder — preorder[0] is the root; find it in inorder to split left and right.
    Show solution

    The idea

    Rebuild a tree from its preorder (me, left, right) and inorder (left, me, right) lists. preorder[0] is the root; finding that value in inorder splits it into the left subtree (everything before it) and the right subtree (everything after). Then recurse. A map from value to inorder position makes each lookup O(1).

    Brute force first

    Search inorder with a loop each time and copy sub-arrays: O(n²) in the worst case.

    Step by step

    1. Store each value's index in inorder in a HashMap (values are unique).
    2. Keep a pointer next into preorder; the next unused preorder value is always the root of the range you are building.
    3. build(lo, hi) builds the tree whose inorder is inorder[lo..hi]; an empty range gives null.
    4. Take the root value, find its index mid, build the left range lo..mid-1 first, then the right range mid+1..hi.

    Java

    class Solution {
    private Map<Integer, Integer> pos = new HashMap<>();
    private int next = 0;  // next preorder index to use

    public TreeNode buildTree(int[] preorder, int[] inorder) {
        // where each value sits in inorder (values unique)
        for (int i = 0; i < inorder.length; i++) {
            pos.put(inorder[i], i);
        }
        return build(preorder, 0, inorder.length - 1);
    }

    // build the tree whose inorder is inorder[lo..hi]
    private TreeNode build(int[] pre, int lo, int hi) {
        if (lo > hi) return null;          // empty range
        int val = pre[next++];             // root of range
        TreeNode root = new TreeNode(val);
        int mid = pos.get(val);            // split point
        root.left = build(pre, lo, mid - 1);  // left first!
        root.right = build(pre, mid + 1, hi);
        return root;
    }
}

    Time O(n) · Space O(n) — every node is created once with O(1) lookup; the map holds n entries.

    Dry run

    pre [3,9,20,15,7], in [9,3,15,20,7]. Root 3 at in-index 1 → left range [9], right [15,20,7]. Next pre is 9 → leaf. Next is 20 at in-index 3 → left 15, right 7. Tree [3,9,20,null,null,15,7].

    Watch out

    Build the left subtree before the right one: preorder lists all of the left subtree before any of the right, so the shared next pointer only works in that order.

  • Hard297. Serialize and Deserialize Binary Tree — pre-order with "#" for null.
    Show solution

    The idea

    Turn a tree into a string and back again. Write it in preorder (me, left, right) and write "#" for every missing child; the markers make the shape unambiguous, so reading the tokens in the same order rebuilds exactly the same tree.

    Step by step

    1. serialize: recursive preorder; for null append "#,", else append the value and a comma, then do left, then right.
    2. deserialize: split on commas into a queue of tokens.
    3. read: take the next token; "#" means null; otherwise make a node with that value.
    4. Read its left subtree, then its right subtree, from the same queue, and return the node.

    Java

    class Codec {
    // preorder, "#" for an empty child, commas between
    public String serialize(TreeNode root) {
        StringBuilder sb = new StringBuilder();
        write(root, sb);
        return sb.toString();
    }

    private void write(TreeNode n, StringBuilder sb) {
        if (n == null) {
            sb.append("#,");
            return;
        }
        sb.append(n.val).append(',');
        write(n.left, sb);
        write(n.right, sb);
    }

    public TreeNode deserialize(String data) {
        Deque<String> tokens =
            new ArrayDeque<>(Arrays.asList(data.split(",")));
        return read(tokens);
    }

    // read tokens in the same order they were written
    private TreeNode read(Deque<String> tokens) {
        String t = tokens.poll();
        if (t.equals("#")) return null;
        TreeNode n = new TreeNode(Integer.parseInt(t));
        n.left = read(tokens);
        n.right = read(tokens);
        return n;
    }
}

    Time O(n) · Space O(n) — each node and each null marker is written and read once.

    Dry run

    Tree [1,2,3,null,null,4,5] → "1,2,#,#,3,4,#,#,5,#,#,". Reading: 1, its left is 2 (children #,#), its right is 3 with left 4 and right 5.

    Watch out

    Use a separator, because values can be negative or have several digits ("-10"). An empty tree becomes "#," and must read back as null. split(",") drops the trailing empty token, which is what we want.

Test yourself

Tree: root 1, left child 2, right child 3. Write the pre-, in- and post-order.

Pre: 1, 2, 3. In: 2, 1, 3. Post: 2, 3, 1.

Which order would you use to compute the height of every node, and why?

Post-order: a node's height is 1 + max(left height, right height), so both children must be finished first.

What is the extra space of a recursive traversal on a tree with 1,000 nodes all in one line?

O(n): the height is 1,000, so 1,000 frames sit on the call stack at the deepest point.

In the iterative in-order, why push the node before going left?

Because we must come back to write it after its whole left side is done — the stack remembers it, just like a paused recursive call would.
