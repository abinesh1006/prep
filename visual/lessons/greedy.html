Pattern 24 · Greedy & intervals

Greedy

Make the choice that looks best right now, never go back — and be able to say why that choice can never hurt the final answer.

Time to learn: about 2–3 hours · Prerequisites: Arrays and hashing, Intervals

When to use it — the signal

"Can you reach the end", "minimum number of jumps / arrows / coins (for normal coins) / platforms", "maximum number of meetings", "partition into as many parts as possible", "where should you start". One pass with one running number (farthest reach, fuel in tank, last position) seems to decide everything.

The idea in plain words

A greedy algorithm walks through the input once and at every step makes the locally best choice — "jump as far as allowed", "take the meeting that ends first" — without ever undoing it.

That is only correct when a locally best choice can never block a better overall answer. The usual way to convince yourself (and the interviewer) is an exchange argument: "take any best answer; if it does not use my greedy choice, swap my choice in — it is no worse". If you can't find such an argument, try a small counter-example, and if it breaks, use dynamic programming instead.

  • Jump Game: keep the farthest index you can reach. Walking left to right, if you ever stand on an index beyond that reach, you are stuck.
  • Gas Station: if your tank goes negative between start and station i, no station from start to i can be the start — jump the start to i + 1.
  • Partition Labels: a part must stretch to the last appearance of every letter inside it. Cut when the scan reaches that farthest last appearance.

Greedy is usually O(n) (or O(n log n) with a sort) and O(1) extra space — that is why it is worth recognising.

Analogy

Crossing a river on stepping stones where each stone says how far you may jump from it. You don't plan every route — you just remember "the farthest stone I could get to so far" and keep walking. If you ever reach a stone that is past that mark, you know the river can't be crossed.

Why it works (how to know greedy is safe)

Jump Game: "reach is the farthest index any path can get to; if i is beyond it, no path touches i." Gas Station: "if the tank goes negative at i starting from s, every start between s and i arrives at i with no more fuel, so they all fail too; and a non-negative total guarantees the remaining start succeeds." Partition Labels: "a cut is legal only after the last appearance of every letter seen so far, and cutting at the first legal spot leaves the most room for further cuts."

The general test: can you argue that swapping your greedy choice into any optimal answer keeps it optimal? If yes, greedy is safe. If a tiny example breaks it (coins 1, 3, 4 and amount 6: greedy takes 4+1+1, best is 3+3), use DP.

The template to remember

// one pass, one running quantity, decide on the spot
int best = start;
for (int i = 0; i < n; i++) {
    if (impossible(i, best)) return fail;   // e.g. i > reach
    best = improve(best, i);                // e.g. max(reach, i + a[i])
    if (canCommit(i, best)) commit();        // e.g. i == end → cut
}
// with intervals: sort by end first, then the same loop
Remember

Greedy = one pass + one running number + a reason it never hurts. No reason? Find a counter-example, then switch to DP.

Common mistakes
  • Using greedy without a proof — coin change with odd coin sets and 0/1 knapsack are the classic traps.
  • Jump Game: returning false as soon as you see a 0. A 0 is fine if an earlier jump carries you past it.
  • Gas Station: trying every start (O(n²)). The reset trick makes it O(n); check total < 0 for −1.
  • Partition Labels: cutting when you see a letter for the last time instead of when i == end of the whole part.
  • Jump Game II (minimum jumps): count a jump when i reaches the end of the current jump's range, not at every improvement.

Practice in this order

  • Easy455. Assign Cookies — sort both, give the smallest cookie that satisfies.
    Show solution

    The idea

    Child i is happy with a cookie of size at least g[i]; each child gets at most one cookie. Maximize happy children. Greedy: sort both lists and give each cookie, smallest first, to the least greedy child still waiting if it is big enough. A small cookie that cannot please the least greedy child cannot please anyone, so skip it.

    Brute force first

    Try every way to match cookies to children. Exponential.

    Step by step

    1. Sort g (greed) and s (cookie sizes).
    2. child = 0; walk the cookies from smallest to largest.
    3. If the cookie is big enough for g[child], that child is happy: child++.
    4. Either way, the cookie is used or useless; move on.
    5. Return child, the number of happy children.

    Java

    class Solution {
    public int findContentChildren(int[] g, int[] s) {
        Arrays.sort(g);
        Arrays.sort(s);
        int child = 0;
        int n = g.length;
        for (int i = 0; i < s.length && child < n; i++) {
            // fits the least greedy child left?
            if (s[i] >= g[child]) child++;
        }
        return child;
    }
}

    Time O(n log n + m log m) · Space O(log n) for the sorts — one walk after sorting.

    Dry run

    g = [1,2], s = [1,2,3]
cookie 1 >= 1 -> child 1 happy (child=1)
cookie 2 >= 2 -> child 2 happy (child=2), all children done
answer 2

    Watch out

    Stop when all children are served (child < g.length), or g[child] goes out of bounds. Empty cookie list returns 0.

  • Easy122. Best Time to Buy and Sell Stock II — take every rising day.
    Show solution

    The idea

    You may buy and sell as often as you like (holding at most one share). Any rising stretch, like 1 → 5, can be split into daily steps 1→2→3→4→5 with the same total. So the best profit is simply the sum of every daily rise: take each day where the price goes up, skip each day where it goes down.

    Brute force first

    Try every set of buy and sell days with recursion. Exponential. A small DP (holding / not holding) is O(n) too, but greedy is shorter.

    Step by step

    1. profit = 0.
    2. For each day i from 1 on, compare with the day before.
    3. If prices[i] > prices[i - 1], add the difference.
    4. Return profit.

    Java

    class Solution {
    public int maxProfit(int[] prices) {
        int profit = 0;
        for (int i = 1; i < prices.length; i++) {
            // take every rise from yesterday to today
            if (prices[i] > prices[i - 1])
                profit += prices[i] - prices[i - 1];
        }
        return profit;
    }
}

    Time O(n) · Space O(1) — one pass.

    Dry run

    prices = [7,1,5,3,6,4]
1->5: +4,  3->6: +3,  others fall
answer 7

    Watch out

    This only works because there is no limit on the number of trades and no fee. With "at most k trades" or a fee, it becomes a DP problem.

  • Medium55. Jump Game — the first animation.
    Show solution

    The idea

    From index i you can jump up to nums[i] steps. Can you reach the last index? Walk left to right and keep far, the farthest index reachable so far. If you ever stand on an index beyond far, you are stuck. Greedy reach: we never need to know which jumps, only how far we can get.

    Brute force first

    Recursion that tries every jump length from every index. Exponential; with memo it is O(n²).

    Step by step

    1. far = 0.
    2. For each index i: if i > far, return false (we cannot even get here).
    3. Update far = max(far, i + nums[i]).
    4. If far >= n - 1, return true early.
    5. After the loop, return true.

    Java

    class Solution {
    public boolean canJump(int[] nums) {
        int far = 0; // farthest index we can reach
        for (int i = 0; i < nums.length; i++) {
            if (i > far) return false; // stuck before i
            far = Math.max(far, i + nums[i]);
            if (far >= nums.length - 1) return true;
        }
        return true;
    }
}

    Time O(n) · Space O(1) — one pass with one number.

    Dry run

    [3,2,1,0,4]
i=0 far=3, i=1 far=3, i=2 far=3, i=3 far=3
i=4: 4 > 3 -> false
[2,3,1,1,4]: i=0 far=2, i=1 far=4 >= 4 -> true

    Watch out

    A single item [0] is already at the end, so it is true. Zeros are the only way to get stuck; the check i > far catches them.

  • Medium45. Jump Game II — BFS by ranges: jumps++ when i passes the current range end.
    Show solution

    The idea

    Now reaching the end is guaranteed; find the fewest jumps. Think in layers, like BFS by ranges: with 0 jumps you can stand on index 0; with 1 jump on everything up to nums[0]; with 2 jumps on everything the previous layer can reach, and so on. Walk left to right, track the farthest reach of the current layer, and add a jump each time i passes the end of the current layer.

    Brute force first

    DP: jumps[j] = min(jumps[i] + 1) over every i that can reach j. O(n²).

    Step by step

    1. jumps = 0, end = 0 (last index reachable with jumps jumps), far = 0.
    2. For i from 0 to n - 2 (we never jump from the last index): far = max(far, i + nums[i]).
    3. If i == end, the current layer is used up: take a jump (jumps++) and set end = far.
    4. Return jumps.

    Java

    class Solution {
    public int jump(int[] nums) {
        int jumps = 0, end = 0, far = 0;
        // stop before the last index: no jump from there
        for (int i = 0; i < nums.length - 1; i++) {
            far = Math.max(far, i + nums[i]);
            if (i == end) {   // layer finished
                jumps++;
                end = far;    // next layer reaches here
            }
        }
        return jumps;
    }
}

    Time O(n) · Space O(1) — each index is seen once.

    Dry run

    [2,3,1,1,4]
i=0: far=2, i==end(0) -> jumps=1, end=2
i=1: far=4
i=2: far=4, i==end(2) -> jumps=2, end=4
i=3: far=4  (loop stops before index 4) -> answer 2

    Watch out

    Loop to n - 2, not n - 1: if you process the last index too, i == end can add one extra jump (for [0] you would get 1 instead of 0).

  • Medium134. Gas Station — the second animation.
    Show solution

    The idea

    Station i gives gas[i], and driving to the next costs cost[i]. Find the start that lets you drive the full circle. Two facts: if total gas < total cost, no start works. And if you start at s and run dry at station i, no station between s and i works either (each would arrive with even less fuel), so restart at i + 1.

    Brute force first

    Try every start and simulate the full loop. O(n²).

    Step by step

    1. Keep total (sum of gas - cost over all stations), tank (fuel since the current start), and start = 0.
    2. For each station, add gas[i] - cost[i] to both.
    3. If tank < 0, we cannot get past station i: set start = i + 1 and tank = 0.
    4. At the end, return start if total >= 0, else -1.

    Java

    class Solution {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int total = 0, tank = 0, start = 0;
        for (int i = 0; i < gas.length; i++) {
            int diff = gas[i] - cost[i];
            total += diff;
            tank += diff;
            if (tank < 0) {     // ran dry leaving station i
                start = i + 1;  // nothing in [start..i] works
                tank = 0;
            }
        }
        return total >= 0 ? start : -1;
    }
}

    Time O(n) · Space O(1) — one pass around the circle.

    Dry run

    gas = [1,2,3,4,5], cost = [3,4,5,1,2] -> diff [-2,-2,-2,3,3]
i=0 tank=-2 -> start=1; i=1 -2 -> start=2; i=2 -2 -> start=3
i=3 tank=3, i=4 tank=6; total = 0 >= 0 -> answer 3

    Watch out

    We never check the wrap-around part from the start back to it. The total check covers it: if the total is not negative, the deficit before start is paid by the surplus after it.

  • Medium763. Partition Labels — the third animation.
    Show solution

    The idea

    Cut the string into as many pieces as possible so each letter appears in only one piece; return the piece sizes. First record the last position of every letter. Walk the string and keep end = the farthest last position of any letter seen in the current piece. When i reaches end, no letter of this piece appears later: cut here.

    Brute force first

    For each possible cut point, check whether the letters on the left appear on the right. O(n²) or worse.

    Step by step

    1. Fill last[c] = the last index of letter c.
    2. start = 0, end = 0.
    3. For each i: end = max(end, last[s[i]]).
    4. If i == end, the piece [start, i] is closed: add i - start + 1 and set start = i + 1.

    Java

    class Solution {
    public List<Integer> partitionLabels(String s) {
        int[] last = new int[26];
        for (int i = 0; i < s.length(); i++)
            last[s.charAt(i) - 'a'] = i;
        List<Integer> res = new ArrayList<>();
        int start = 0, end = 0;
        for (int i = 0; i < s.length(); i++) {
            // this piece must reach the letter's last copy
            end = Math.max(end, last[s.charAt(i) - 'a']);
            if (i == end) {              // safe to cut here
                res.add(i - start + 1);
                start = i + 1;
            }
        }
        return res;
    }
}

    Time O(n) · Space O(1) — two passes and an array of 26.

    Dry run

    s = "ababcbacadefegdehijhklij"
last: a=8, b=5, c=7 ... end grows to 8 at i=8 -> cut, size 9
next piece "defegde" ends at 15 -> size 7
"hijhklij" -> size 8;  answer [9,7,8]

    Watch out

    Update end before checking i == end, otherwise a letter at position i that appears later is missed.

  • Medium846. Hand of Straights — always start a run from the smallest card left.
    Show solution

    The idea

    Can the cards be split into groups of groupSize consecutive numbers? The smallest card left must start a group (nothing smaller exists to put it in), so the group smallest, smallest+1, ... is forced. Greedy: repeatedly take the smallest card, remove one of each of the next groupSize values, and fail if one is missing. A TreeMap (a sorted map) keeps the counts in order.

    Brute force first

    Try all ways to split into groups with backtracking. Exponential.

    Step by step

    1. If n % groupSize != 0, return false.
    2. Count each card in a TreeMap.
    3. While the map is not empty, take the smallest key x.
    4. For x, x+1, ..., x+groupSize-1: if a value is missing, return false; otherwise lower its count by one and remove it when it hits 0.
    5. If the map empties, return true.

    Java

    class Solution {
    public boolean isNStraightHand(int[] hand, int groupSize) {
        if (hand.length % groupSize != 0) return false;
        TreeMap<Integer, Integer> cnt = new TreeMap<>();
        for (int c : hand) cnt.merge(c, 1, Integer::sum);
        while (!cnt.isEmpty()) {
            // the smallest card must start a group
            int x = cnt.firstKey();
            for (int v = x; v < x + groupSize; v++) {
                Integer c = cnt.get(v);
                if (c == null) return false; // gap in the run
                if (c == 1) cnt.remove(v);
                else cnt.put(v, c - 1);
            }
        }
        return true;
    }
}

    Time O(n log n) · Space O(n) — each card is removed once from a sorted map.

    Dry run

    hand = [1,2,3,6,2,3,4,7,8], groupSize = 3
counts {1:1, 2:2, 3:2, 4:1, 6:1, 7:1, 8:1}
take 1: use 1,2,3 -> {2:1, 3:1, 4:1, 6,7,8}
take 2: use 2,3,4 -> {6,7,8};  take 6: use 6,7,8 -> empty -> true

    Watch out

    Check n % groupSize first; it is a quick false. Starting a group from any card other than the smallest can fail even when an answer exists.

  • Hard135. Candy — one pass left to right, one right to left, take the max.
    Show solution

    The idea

    Every child gets at least one candy, and a child with a higher rating than a neighbour must get more than that neighbour. Handle the two sides separately: a left-to-right pass fixes "more than the left neighbour", a right-to-left pass fixes "more than the right neighbour". Each child takes the max of the two, which satisfies both with the fewest candies.

    Brute force first

    Give everyone 1 and keep sweeping, fixing any broken pair, until nothing changes. O(n²).

    Step by step

    1. Give everyone 1 candy.
    2. Left to right: if ratings[i] > ratings[i - 1], set candy[i] = candy[i - 1] + 1.
    3. Right to left: if ratings[i] > ratings[i + 1], set candy[i] = max(candy[i], candy[i + 1] + 1).
    4. Return the sum.

    Java

    class Solution {
    public int candy(int[] ratings) {
        int n = ratings.length;
        int[] c = new int[n];
        Arrays.fill(c, 1);
        // more than the left neighbour
        for (int i = 1; i < n; i++)
            if (ratings[i] > ratings[i - 1])
                c[i] = c[i - 1] + 1;
        // more than the right neighbour, keep the left rule
        for (int i = n - 2; i >= 0; i--)
            if (ratings[i] > ratings[i + 1])
                c[i] = Math.max(c[i], c[i + 1] + 1);
        int sum = 0;
        for (int x : c) sum += x;
        return sum;
    }
}

    Time O(n) · Space O(n) — two passes and one array.

    Dry run

    ratings = [1,0,2]
start      [1,1,1]
left pass  [1,1,2]   (2 > 0)
right pass [2,1,2]   (1 > 0)
sum 5

    Watch out

    Use max in the second pass: overwriting with c[i + 1] + 1 can break the rule the first pass set up (a peak needs to beat both sides). Equal neighbours have no rule between them, so [1,2,2] gives 1+2+1 = 4.

Test yourself

Is [2, 0, 0] a true or false Jump Game?

True. From index 0 the reach is 2, which is the last index.

In Gas Station, why can we skip every start between the old start and i when the tank goes negative?

Each of them was reached with a tank ≥ 0 from the old start, so starting there with 0 fuel can only be worse — they also run dry before i + 1.

Coins {1, 3, 4}, amount 6. Does "take the biggest coin first" give the fewest coins?

No: greedy gives 4 + 1 + 1 (3 coins) but 3 + 3 is 2 coins. That counter-example means coin change needs DP.

Partition Labels for "abab"?

[4] — 'a' last appears at 2 and 'b' at 3, so the first part must reach the end.
