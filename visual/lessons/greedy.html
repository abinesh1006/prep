Greedy

Make the choice that looks best right now, never go back — and be able to say why that choice can never hurt the final answer.

Time to learn: about 2–3 hours · Prerequisites: Arrays and hashing, Intervals

When to use it — the signal

"Can you reach the end", "minimum number of jumps / arrows / coins (for normal coins) / platforms", "maximum number of meetings", "partition into as many parts as possible", "where should you start". One pass with one running number (farthest reach, fuel in tank, last position) seems to decide everything.

The idea in plain words

A greedy algorithm walks through the input once and at every step makes the locally best choice — "jump as far as allowed", "take the meeting that ends first" — without ever undoing it.

That is only correct when a locally best choice can never block a better overall answer. The usual way to convince yourself (and the interviewer) is an exchange argument: "take any best answer; if it does not use my greedy choice, swap my choice in — it is no worse". If you can't find such an argument, try a small counter-example, and if it breaks, use dynamic programming instead.

  • Jump Game: keep the farthest index you can reach. Walking left to right, if you ever stand on an index beyond that reach, you are stuck.
  • Gas Station: if your tank goes negative between start and station i, no station from start to i can be the start — jump the start to i + 1.
  • Partition Labels: a part must stretch to the last appearance of every letter inside it. Cut when the scan reaches that farthest last appearance.

Greedy is usually O(n) (or O(n log n) with a sort) and O(1) extra space — that is why it is worth recognising.

Analogy

Crossing a river on stepping stones where each stone says how far you may jump from it. You don't plan every route — you just remember "the farthest stone I could get to so far" and keep walking. If you ever reach a stone that is past that mark, you know the river can't be crossed.

Why it works (how to know greedy is safe)

Jump Game: "reach is the farthest index any path can get to; if i is beyond it, no path touches i." Gas Station: "if the tank goes negative at i starting from s, every start between s and i arrives at i with no more fuel, so they all fail too; and a non-negative total guarantees the remaining start succeeds." Partition Labels: "a cut is legal only after the last appearance of every letter seen so far, and cutting at the first legal spot leaves the most room for further cuts."

The general test: can you argue that swapping your greedy choice into any optimal answer keeps it optimal? If yes, greedy is safe. If a tiny example breaks it (coins 1, 3, 4 and amount 6: greedy takes 4+1+1, best is 3+3), use DP.

The template to remember

// one pass, one running quantity, decide on the spot
int best = start;
for (int i = 0; i < n; i++) {
    if (impossible(i, best)) return fail;   // e.g. i > reach
    best = improve(best, i);                // e.g. max(reach, i + a[i])
    if (canCommit(i, best)) commit();        // e.g. i == end → cut
}
// with intervals: sort by end first, then the same loop
Remember

Greedy = one pass + one running number + a reason it never hurts. No reason? Find a counter-example, then switch to DP.

Common mistakes
  • Using greedy without a proof — coin change with odd coin sets and 0/1 knapsack are the classic traps.
  • Jump Game: returning false as soon as you see a 0. A 0 is fine if an earlier jump carries you past it.
  • Gas Station: trying every start (O(n²)). The reset trick makes it O(n); check total < 0 for −1.
  • Partition Labels: cutting when you see a letter for the last time instead of when i == end of the whole part.
  • Jump Game II (minimum jumps): count a jump when i reaches the end of the current jump's range, not at every improvement.

Test yourself

Is [2, 0, 0] a true or false Jump Game?

True. From index 0 the reach is 2, which is the last index.

In Gas Station, why can we skip every start between the old start and i when the tank goes negative?

Each of them was reached with a tank ≥ 0 from the old start, so starting there with 0 fuel can only be worse — they also run dry before i + 1.

Coins {1, 3, 4}, amount 6. Does "take the biggest coin first" give the fewest coins?

No: greedy gives 4 + 1 + 1 (3 coins) but 3 + 3 is 2 coins. That counter-example means coin change needs DP.

Partition Labels for "abab"?

[4] — 'a' last appears at 2 and 'b' at 3, so the first part must reach the end.
