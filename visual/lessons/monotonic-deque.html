Monotonic Deque

A double-ended queue that keeps its values in falling (or rising) order, so the best value of a moving window is always waiting at the front.

Time to learn: about 2 hours · Prerequisites: Sliding window, Monotonic stack, Prefix sum

When to use it — the signal

"Maximum (or minimum) of every window of size k", "max minus min in a window ≤ limit", "shortest subarray with sum at least K" when numbers can be negative, or a DP where dp[i] depends on the best dp[j] for j in the last k positions.

The idea in plain words

A deque (say "deck", double-ended queue) lets you add and remove at both ends in O(1). In Java: ArrayDeque with offerLast, pollLast, peekFirst, pollFirst.

For the window maximum, we store indices in the deque, with their values falling from front to back. When a new number arrives, every smaller number at the back is useless: the new number is bigger and stays in the window longer, so those smaller ones can never be the maximum again. Pop them.

The front is the biggest number still in the window. If its index has slid out of the window (index ≤ i − k), pop it from the front.

Each index is pushed once and popped at most once, so the whole scan is O(n) — compared with O(n·k) for scanning every window, or O(n log k) with a heap.

Analogy

A queue of job applicants where a stronger, younger applicant arrives: everyone weaker and older standing behind in line just goes home — they will never be picked while the newcomer is around. The person at the front is the best one, until they retire (leave the window).

Watch it work

1. Sliding Window Maximum (k = 3)

2. Shortest Subarray with Sum at Least K (negatives allowed)

Plain sliding window breaks when numbers can be negative (growing the window can make the sum smaller). Instead use prefix sums P: the sum of nums[i..j−1] is P[j] − P[i]. We want the closest i before j with P[j] − P[i] ≥ K. Keep start indices in a deque with rising P values. Here nums = [2, −1, 2, 3], K = 4.

Why it works

"An element that is smaller than a newer element can never be the window maximum again, because the newer one is bigger and leaves later — so dropping it loses nothing. Every index is pushed and popped at most once, which gives O(n)." For the K problem: "a later start with a smaller-or-equal prefix sum is better in every way, and once a start has produced an answer, later ends can only make it longer."

The template to remember

Deque<Integer> dq = new ArrayDeque<>();   // indices
for (int i = 0; i < n; i++) {
    if (!dq.isEmpty() && dq.peekFirst() <= i - k) dq.pollFirst(); // expired
    while (!dq.isEmpty() && worse(dq.peekLast(), i)) dq.pollLast(); // useless
    dq.offerLast(i);
    if (i >= k - 1) use(dq.peekFirst());    // front = best
}
Remember

Front = best, and leaves when too old. Back = newest; it kicks out everyone worse before it joins. Store indices, not values.

Common mistakes
  • Storing values instead of indices — then you cannot tell when the front has left the window.
  • Using < instead of <= when popping the back: duplicates pile up (still correct, but slower to reason about).
  • Using a plain sliding window for "sum ≥ K" with negative numbers — it gives wrong answers; use prefix sums + deque.
  • Using Stack or LinkedList — ArrayDeque is the fast, standard choice.

  • Hard239. Sliding Window Maximum — animation 1.
    Show solution

    The idea

    For every window of k numbers, report its largest value. Keep a deque (a list you can add to or remove from at both ends) of indices whose values go down from front to back. A new number knocks out every smaller number at the back, because those can never be the max while it is in the window. The front is always the current max. Pattern: monotonic deque.

    Brute force first

    Scan each window for its max: O(n · k), too slow when k is large.

    Step by step

    1. For each i: if the front index is ≤ i − k, it has left the window, so pop it from the front.
    2. While the back value is ≤ nums[i], pop it from the back.
    3. Push i at the back.
    4. Once i ≥ k − 1, the answer for this window is nums[front].

    Java

    class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        int n = nums.length;
        int[] res = new int[n - k + 1];
        // indices; their values decrease from front to back
        Deque<Integer> dq = new ArrayDeque<>();
        for (int i = 0; i < n; i++) {
            // front index fell out of the window
            if (!dq.isEmpty() && dq.peekFirst() <= i - k)
                dq.pollFirst();
            // smaller values can never be a max again
            while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i])
                dq.pollLast();
            dq.offerLast(i);
            if (i >= k - 1) res[i - k + 1] = nums[dq.peekFirst()];
        }
        return res;
    }
}

    Time O(n) · Space O(k) — each index is pushed once and popped at most once.

    Dry run

    nums = 1 3 -1 -3 5 3 6 7, k = 3   (deque shows values)
i=2  [3,-1]      max 3
i=3  [3,-1,-3]   max 3
i=4  [5]         max 5   (5 knocks out all)
i=5  [5,3]       max 5
i=6  [6]         max 6
i=7  [7]         max 7

    Watch out

    Store indices, not values. You need the index to know when the front has left the window.

  • Medium1438. Longest Subarray with Abs Diff ≤ Limit — two deques: one max, one min.
    Show solution

    The idea

    Find the longest block where max − min ≤ limit. Use a sliding window (left, right). To know the window's max and min at all times, keep two monotonic deques: one decreasing (front = max) and one increasing (front = min). When max − min is too big, move left forward. Pattern: sliding window + two monotonic deques.

    Brute force first

    Check every subarray and track its max and min: O(n²).

    Step by step

    1. Add nums[right] to both deques, first popping the back of maxQ while it is smaller and the back of minQ while it is bigger.
    2. While maxQ.front − minQ.front > limit: the value at left is leaving. If it equals a deque's front, pop that front. Then do left++.
    3. Update best = max(best, right − left + 1).
    4. Return best.

    Java

    class Solution {
    public int longestSubarray(int[] nums, int limit) {
        Deque<Integer> maxQ = new ArrayDeque<>(); // decreasing
        Deque<Integer> minQ = new ArrayDeque<>(); // increasing
        int left = 0, best = 0;
        for (int right = 0; right < nums.length; right++) {
            int x = nums[right];
            while (!maxQ.isEmpty() && maxQ.peekLast() < x)
                maxQ.pollLast();
            maxQ.offerLast(x);
            while (!minQ.isEmpty() && minQ.peekLast() > x)
                minQ.pollLast();
            minQ.offerLast(x);
            // shrink until max - min fits the limit
            while (maxQ.peekFirst() - minQ.peekFirst() > limit) {
                int out = nums[left++];
                if (maxQ.peekFirst() == out) maxQ.pollFirst();
                if (minQ.peekFirst() == out) minQ.pollFirst();
            }
            best = Math.max(best, right - left + 1);
        }
        return best;
    }
}

    Time O(n) · Space O(n) — every value enters and leaves each deque once.

    Dry run

    [8,2,4,7], limit 4. right=1: max 8, min 2, so the gap 6 is too big; drop 8 and the window is [2]. right=2: [2,4] gap 2, length 2. right=3: [2,4,7] gap 5 is too big; drop 2 and the window is [4,7], gap 3. The best is 2.

    Watch out

    The deques keep equal values (pop only strictly smaller or bigger ones). Otherwise, when a duplicate leaves, you could pop a copy that is still inside the window.

  • Medium1696. Jump Game VI — DP, best of the last k values from a deque.
    Show solution

    The idea

    You start on index 0 and jump 1 to k steps forward each time, adding the values you land on. Maximise the total at the last index. dp[i] = nums[i] + max(dp[i-k .. i-1]). The "max of the last k dp values" is a sliding window maximum, so keep a decreasing deque of dp indices. Pattern: DP + monotonic deque.

    Brute force first

    For each i, scan the previous k dp values: O(n · k), too slow for n = k = 10⁵.

    Step by step

    1. dp[0] = nums[0]. Put index 0 in the deque.
    2. For each i ≥ 1: if the front index is < i − k, it is out of reach, so pop it.
    3. dp[i] = nums[i] + dp[front].
    4. Pop from the back while the back dp is ≤ dp[i], then push i.
    5. Return dp[n−1].

    Java

    class Solution {
    public int maxResult(int[] nums, int k) {
        int n = nums.length;
        int[] dp = new int[n]; // dp[i] = best score landing on i
        dp[0] = nums[0];
        Deque<Integer> dq = new ArrayDeque<>(); // dp decreasing
        dq.offerLast(0);
        for (int i = 1; i < n; i++) {
            if (dq.peekFirst() < i - k) dq.pollFirst(); // too far
            dp[i] = nums[i] + dp[dq.peekFirst()];
            while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i])
                dq.pollLast();
            dq.offerLast(i);
        }
        return dp[n - 1];
    }
}

    Time O(n) · Space O(n) — one push and at most one pop per index.

    Dry run

    [1,−1,−2,4,−7,3], k = 2. dp = 1, 0, −1, 4, −3, 7. For example dp[5] = 3 + max(dp[3], dp[4]) = 3 + 4 = 7. The answer is 7.

    Watch out

    Here you must land on every chosen index, including negative ones. Do not take max(0, …) as in 1425: you cannot skip to "nothing".

  • Hard1425. Constrained Subsequence Sum — same DP + deque idea.
    Show solution

    The idea

    Pick a non-empty subsequence with the biggest sum, where two picked neighbours are at most k indices apart. dp[i] = best sum of such a subsequence that ends at i = nums[i] + max(0, best dp in the last k). The 0 means "start fresh here" when the earlier sums are negative. The best of the last k uses a decreasing deque. Pattern: DP + monotonic deque.

    Brute force first

    O(n · k), checking each of the last k dp values for every i.

    Step by step

    1. For each i, pop the front if it is < i − k.
    2. prev = max(0, dp[front]) (0 if the deque is empty), and dp[i] = nums[i] + prev.
    3. Track the overall best dp value. The answer can end anywhere.
    4. Keep the deque decreasing: pop the back while its dp ≤ dp[i], then push i.

    Java

    class Solution {
    public int constrainedSubsetSum(int[] nums, int k) {
        int n = nums.length;
        // dp[i] = best sum of a valid subsequence ending at i
        int[] dp = new int[n];
        Deque<Integer> dq = new ArrayDeque<>(); // dp decreasing
        int best = Integer.MIN_VALUE;
        for (int i = 0; i < n; i++) {
            if (!dq.isEmpty() && dq.peekFirst() < i - k)
                dq.pollFirst();
            // take the best earlier sum only if it helps
            int prev = dq.isEmpty() ? 0
                    : Math.max(0, dp[dq.peekFirst()]);
            dp[i] = nums[i] + prev;
            best = Math.max(best, dp[i]);
            while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i])
                dq.pollLast();
            dq.offerLast(i);
        }
        return best;
    }
}

    Time O(n) · Space O(n) — each index enters and leaves the deque once.

    Dry run

    [10,2,−10,5,20], k = 2. dp = 10, 12, 2, 17, 37. dp[4] = 20 + max(dp[2], dp[3]) = 20 + 17 = 37. The best is 37.

    Watch out

    Start best at Integer.MIN_VALUE, not 0. If every number is negative (e.g. [−1,−2,−3]), the answer is the largest one, −1.

  • Hard862. Shortest Subarray with Sum at Least K — animation 2.
    Show solution

    The idea

    Find the shortest block with sum ≥ k, where numbers can be negative. With prefix sums, block (i, j] has sum pre[j] − pre[i]. For each end j you want the latest start i with pre[i] ≤ pre[j] − k. Keep a deque of start indices with increasing prefix values. Pattern: prefix sums + monotonic deque.

    Brute force first

    Try every pair i < j: O(n²). A plain sliding window fails because negative numbers break the rule that "growing the window grows the sum".

    Step by step

    1. Build pre of length n + 1 with long values.
    2. For each j from 0 to n: while pre[j] − pre[front] ≥ k, record j − front and pop the front. A later j could only be longer with that start.
    3. While pre[back] ≥ pre[j], pop the back. j is a later and smaller start, so it is always at least as good.
    4. Push j. At the end return best, or −1 if nothing was found.

    Java

    class Solution {
    public int shortestSubarray(int[] nums, int k) {
        int n = nums.length;
        long[] pre = new long[n + 1]; // pre[i] = sum of first i
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];
        int best = n + 1;
        Deque<Integer> dq = new ArrayDeque<>(); // pre increasing
        for (int j = 0; j <= n; j++) {
            // front start works: record it, it can't do better
            while (!dq.isEmpty() && pre[j] - pre[dq.peekFirst()] >= k)
                best = Math.min(best, j - dq.pollFirst());
            // a later, smaller-or-equal prefix is a better start
            while (!dq.isEmpty() && pre[dq.peekLast()] >= pre[j])
                dq.pollLast();
            dq.offerLast(j);
        }
        return best == n + 1 ? -1 : best;
    }
}

    Time O(n) · Space O(n) — each index is pushed and popped once.

    Dry run

    nums [2,−1,2], k = 3, so pre = 0,2,1,3. j=1: deque [0,1]. j=2: pre 1 < 2, so pop 1; deque [0,2]. j=3: pre[3] − pre[0] = 3 ≥ 3, so record length 3. The answer is 3.

    Watch out

    Use long for the prefix sums (values up to 10⁵ × 10⁵ can overflow int), and start the loop at j = 0 so that index 0 can act as a start.

  • Hard1499. Max Value of Equation — deque of best y − x within distance k.
    Show solution

    The idea

    The points are sorted by x. Maximise yi + yj + |xi − xj| where xj − xi ≤ k. With i before j this becomes (yi − xi) + (yj + xj). So for each j you need the biggest y − x among the earlier points within distance k: a sliding window maximum. Pattern: rewrite the formula + monotonic deque.

    Brute force first

    Check every pair within distance k: O(n²) in the worst case.

    Step by step

    1. Keep a deque of (x, y − x) with y − x decreasing.
    2. For each point (x, y): pop from the front while x − front.x > k.
    3. If the deque is not empty, try front.key + y + x as an answer.
    4. Push (x, y − x) after popping back entries whose key ≤ y − x.

    Java

    class Solution {
    public int findMaxValueOfEquation(int[][] points, int k) {
        // yi + yj + |xi - xj| = (yi - xi) + (yj + xj), xi < xj
        // deque of [x, y - x], with y - x decreasing
        Deque<int[]> dq = new ArrayDeque<>();
        int best = Integer.MIN_VALUE;
        for (int[] p : points) {
            int x = p[0], y = p[1];
            // drop points more than k to the left
            while (!dq.isEmpty() && x - dq.peekFirst()[0] > k)
                dq.pollFirst();
            if (!dq.isEmpty())
                best = Math.max(best, dq.peekFirst()[1] + y + x);
            int key = y - x;
            while (!dq.isEmpty() && dq.peekLast()[1] <= key)
                dq.pollLast();
            dq.offerLast(new int[]{x, key});
        }
        return best;
    }
}

    Time O(n) · Space O(n) — each point enters and leaves once.

    Dry run

    [[1,3],[2,0],[5,10],[6,−10]], k = 1. At (2,0) the front is (1, key 2), giving 2 + 0 + 2 = 4. At (5,10) everything is too far. At (6,−10) the front is (5, key 5), giving 5 − 10 + 6 = 1. The best is 4.

    Watch out

    Query the deque before pushing the current point, because i and j must be different points.

Test yourself

Why is the sliding window maximum O(n) even though there is a while loop inside the for loop?

Each index is pushed exactly once and popped at most once, so across the whole run the while loop does at most n pops in total.

For the window minimum, what changes?

Keep values rising from front to back: pop the back while it is ≥ the new value.

Why can we pop the front in the "sum ≥ K" problem after recording it?

That start already gave its shortest possible answer with the current end j; any later end would make the subarray longer, so it is no longer useful.
