Reverse a Linked List

Walk the list once with three pointers — prev, curr, next — and turn every arrow around as you pass it.

Time to learn: about 2 hours · Prerequisites: Big-O, Two pointers

When to use it — the signal

"Reverse the list", "reverse between positions m and n", "reverse in groups of k", "is the list a palindrome", "reorder the list", "add numbers stored backwards" — anything that wants to read or rebuild a list from the back, with O(1) extra space.

The idea in plain words

What is a linked list? An array keeps its numbers side by side in memory, so you can jump to item 7 instantly. A linked list keeps each number in its own little box called a node, scattered anywhere in memory. Each node holds two things: its value and a pointer called next — the address of the following node, like an arrow. The last node's next is null (nothing). We only keep the address of the first node, the head.

So to reach the 4th node you must start at the head and follow 3 arrows. In return, adding or removing a node is just changing one or two arrows — no shifting of other items.

Reversing 1 → 2 → 3 → 4 → 5 means making it 5 → 4 → 3 → 2 → 1. We do not move any values; we just turn every arrow to point backwards. The catch: the moment you turn node 1's arrow away from 2, you have lost your only way to reach 2. So before turning an arrow, save where it pointed. Three pointers:

  • curr — the node whose arrow we are turning now.
  • prev — the node behind it (where its arrow should point; starts as null).
  • next — a bookmark to the rest of the list, saved before the turn.

Save next, turn curr's arrow to prev, step prev and curr forward. Repeat until curr falls off the end. prev is then the new head. Each node is visited once: O(n) time, O(1) extra space.

Analogy

A line of people, each pointing at the person in front of them. To reverse the line without anyone moving, you walk down it and ask each person to turn around and point at the person behind. Before you ask someone to turn, you note who they were pointing at — otherwise you would not know whom to visit next.

Watch it work

Now the iterative reversal of 1 → 2 → 3 → 4 → 5. The nodes stay where they are; watch the arrows flip one by one.

Reverse a sublist (Reverse Linked List II): reverse only positions 2..4 of 1 → 2 → 3 → 4 → 5. A dummy node in front means "the node before the part" always exists. Then we repeatedly take the node after cur and move it to the front of the part. Here the boxes are redrawn in list order, so you can see nodes move.

Why it works

"At every step, prev is the head of the already-reversed part and curr is the head of the untouched part. Saving next before turning curr's arrow means we never lose the rest of the list. When curr is null, the reversed part is the whole list, and prev is its head."

The template to remember

ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;   // save
    curr.next = prev;            // flip
    prev = curr;                 // step
    curr = next;                 // step
}
return prev;
Remember

Save, flip, step, step. prev starts null, the answer is prev. Sublist: dummy + pre + "move the next node to the front".

Common mistakes
  • Flipping before saving next — the rest of the list is lost.
  • Returning head or curr instead of prev (head is now the tail; curr is null).
  • Forgetting that the old head must end with next = null — starting prev at null does this for you.
  • In sublist problems, no dummy node: when left = 1 there is no "node before", and the code needs a special case.

Practice in this order

  • Easy206. Reverse Linked List — the second animation; then write the recursive version.
    Show solution

    The idea

    Turn 1→2→3→null into 3→2→1→null. A node only knows its next, so walk the list once and flip each arrow to point backwards. Keep three pointers: prev (the already-reversed part), curr (the node being flipped) and next (saved so the rest of the list is not lost). Pattern: in-place linked list reversal.

    Brute force first

    Copy every value into an array, then write them back in reverse order. It works but uses O(n) extra space; interviewers want the pointer flip.

    Step by step

    1. Start with prev = null and curr = head.
    2. Save next = curr.next before you break the link.
    3. Flip: curr.next = prev.
    4. Move both one step: prev = curr, curr = next.
    5. When curr is null, prev is the new head.

    Java

    class Solution {
    public ListNode reverseList(ListNode head) {
        ListNode prev = null, curr = head;
        while (curr != null) {
            ListNode next = curr.next; // save the rest
            curr.next = prev;          // flip the arrow
            prev = curr;               // step forward
            curr = next;
        }
        return prev;                   // new head
    }

    // Recursive version: reverse the rest, then hook
    // this node onto the end of it.
    public ListNode reverseRec(ListNode head) {
        if (head == null || head.next == null) return head;
        ListNode newHead = reverseRec(head.next);
        head.next.next = head; // node after me points back
        head.next = null;      // I become the tail
        return newHead;
    }
}

    Time O(n) · Space O(1) — one pass, three pointers (the recursive version uses O(n) call stack).

    Dry run

    list 1-2-3      prev   curr  after flip
step 1          null   1     1-null
step 2          1      2     2-1-null
step 3          2      3     3-2-1-null
curr = null  -> return prev = 3

    Watch out

    Save next before flipping, otherwise you lose the rest of the list. Return prev, not curr (which is null at the end). Empty list and single node must return as they are.

  • Easy234. Palindrome Linked List — find middle, reverse the second half, compare.
    Show solution

    The idea

    Is 1→2→2→1 the same forwards and backwards? A singly linked list cannot walk backwards, so find the middle with fast/slow pointers, reverse the second half, then walk both halves together comparing values. Patterns: fast/slow pointers + reversal.

    Brute force first

    Copy values into an array and check it with two pointers from both ends. O(n) time but O(n) extra space.

    Step by step

    1. Move slow one step and fast two steps until fast reaches the end; slow is now at the middle.
    2. Reverse the list starting at slow.
    3. Walk a from head and b from the reversed half; if any values differ, return false.
    4. Stop when b runs out; return true.

    Java

    class Solution {
    public boolean isPalindrome(ListNode head) {
        // 1. find the middle
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        // 2. reverse the second half
        ListNode prev = null;
        while (slow != null) {
            ListNode next = slow.next;
            slow.next = prev;
            prev = slow;
            slow = next;
        }
        // 3. compare the two halves
        ListNode a = head, b = prev;
        while (b != null) {
            if (a.val != b.val) return false;
            a = a.next;
            b = b.next;
        }
        return true;
    }
}

    Time O(n) · Space O(1) — three linear walks, only pointers kept.

    Dry run

    1→2→2→1: slow stops at the second 2. Reverse that half: 1→2. Compare 1=1, 2=2, b runs out → true.

    Watch out

    Loop the comparison on the reversed half (b), which is never longer than the first half; for odd lengths the middle node is shared and compares with itself. This changes the input list; reverse the half back if the interviewer asks you to leave it intact.

  • Medium92. Reverse Linked List II — the third animation.
    Show solution

    The idea

    Reverse only positions left..right (1-based): 1→2→3→4→5, left=2, right=4 gives 1→4→3→2→5. Walk to the node just before left, then repeatedly take the node after the current one and move it to the front of the section. A dummy node handles left = 1 without a special case.

    Step by step

    1. Make dummy → head and move before forward left - 1 steps.
    2. curr = before.next; this node will end up as the section's tail.
    3. Repeat right - left times: cut move = curr.next out and insert it right after before.
    4. Return dummy.next.

    Java

    class Solution {
    public ListNode reverseBetween(ListNode head,
                                   int left, int right) {
        ListNode dummy = new ListNode(0, head);
        ListNode before = dummy;
        for (int i = 1; i < left; i++) before = before.next;

        ListNode curr = before.next; // becomes the tail
        for (int i = 0; i < right - left; i++) {
            ListNode move = curr.next;   // node to move
            curr.next = move.next;       // cut it out
            move.next = before.next;     // put it in front
            before.next = move;
        }
        return dummy.next;
    }
}

    Time O(n) · Space O(1) — one walk to the start, one pass over the section.

    Dry run

    before=1, curr=2      1-2-3-4-5
move 3 to front       1-3-2-4-5
move 4 to front       1-4-3-2-5   done (right-left = 2 moves)

    Watch out

    Without the dummy node, left = 1 needs its own branch because the head changes. Do exactly right - left moves, not right - left + 1.

  • Medium24. Swap Nodes in Pairs — reversal in groups of 2.
    Show solution

    The idea

    Swap every two adjacent nodes: 1→2→3→4 becomes 2→1→4→3, by relinking nodes, not swapping values. It is reversal in groups of 2. Use a dummy node and a prev pointer that sits just before each pair.

    Step by step

    1. dummy → head, prev = dummy.
    2. While two nodes a = prev.next and b = a.next exist:
    3. Relink: a.next = b.next, b.next = a, prev.next = b.
    4. Move prev = a (a is now second in the pair).
    5. Return dummy.next.

    Java

    class Solution {
    public ListNode swapPairs(ListNode head) {
        ListNode dummy = new ListNode(0, head);
        ListNode prev = dummy;
        while (prev.next != null
                && prev.next.next != null) {
            ListNode a = prev.next, b = a.next;
            a.next = b.next;   // a points past the pair
            b.next = a;        // b points back to a
            prev.next = b;     // previous part points to b
            prev = a;          // a is now the pair's tail
        }
        return dummy.next;
    }
}

    Time O(n) · Space O(1) — each node is relinked once.

    Dry run

    prev=d  a=1 b=2   d-2-1-3-4   prev=1
prev=1  a=3 b=4   d-2-1-4-3   prev=3
no pair left -> return 2-1-4-3

    Watch out

    Do the three assignments in that order; setting b.next = a first loses b.next. An odd last node stays where it is.

  • Medium143. Reorder List — middle + reverse + weave.
    Show solution

    The idea

    Reorder L0→L1→…→Ln into L0→Ln→L1→Ln-1→…, e.g. 1→2→3→4 becomes 1→4→2→3. That is the first half woven with the reversed second half. Three known pieces: find middle, reverse, merge alternately.

    Brute force first

    Put all nodes in an array and relink with two indices from both ends. O(n) space.

    Step by step

    1. Find the middle with slow/fast (slow ends at the end of the first half).
    2. Cut: second = slow.next, slow.next = null.
    3. Reverse second.
    4. Weave: take one from the first half, one from the reversed half, until the second runs out.

    Java

    class Solution {
    public void reorderList(ListNode head) {
        if (head == null || head.next == null) return;
        // 1. middle: slow ends at the end of half one
        ListNode slow = head, fast = head;
        while (fast.next != null
                && fast.next.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        // 2. cut and reverse the second half
        ListNode prev = null, curr = slow.next;
        slow.next = null;
        while (curr != null) {
            ListNode next = curr.next;
            curr.next = prev;
            prev = curr;
            curr = next;
        }
        // 3. weave the two halves
        ListNode a = head, b = prev;
        while (b != null) {
            ListNode an = a.next, bn = b.next;
            a.next = b;
            b.next = an;
            a = an;
            b = bn;
        }
    }
}

    Time O(n) · Space O(1) — three linear passes, done in place.

    Dry run

    1→2→3→4→5: slow stops at 3, halves 1→2→3 and 4→5. Reverse → 5→4. Weave: 1,5,2,4,3.

    Watch out

    Forgetting slow.next = null leaves a cycle. Save both a.next and b.next before relinking.

  • Hard25. Reverse Nodes in k-Group — count k ahead, reverse that block, link, repeat.
    Show solution

    The idea

    Reverse the list k nodes at a time; a final group shorter than k stays as is. 1→2→3→4→5, k=2 gives 2→1→4→3→5. For each group: check that k nodes exist, reverse those k with the normal three-pointer flip, and connect the group to what came before and after. A dummy node plus a groupPrev pointer keeps the joins simple.

    Step by step

    1. dummy → head, groupPrev = dummy.
    2. Walk k steps from groupPrev to find the group's last node kth; if you hit null, stop.
    3. Remember groupNext = kth.next. Reverse the group, starting with prev = groupNext so the new tail already points onward.
    4. The old first node is now the tail: set groupPrev.next = kth, then groupPrev = oldFirst.
    5. Repeat; return dummy.next.

    Java

    class Solution {
    public ListNode reverseKGroup(ListNode head, int k) {
        ListNode dummy = new ListNode(0, head);
        ListNode groupPrev = dummy;
        while (true) {
            // find the k-th node of this group
            ListNode kth = groupPrev;
            for (int i = 0; i < k && kth != null; i++) {
                kth = kth.next;
            }
            if (kth == null) break; // fewer than k left

            ListNode groupNext = kth.next;
            ListNode first = groupPrev.next;
            // reverse the group; tail points to groupNext
            ListNode prev = groupNext, curr = first;
            while (curr != groupNext) {
                ListNode next = curr.next;
                curr.next = prev;
                prev = curr;
                curr = next;
            }
            groupPrev.next = kth;  // kth is the new front
            groupPrev = first;     // first is the new tail
        }
        return dummy.next;
    }
}

    Time O(n) · Space O(1) — each node is counted once and flipped once.

    Dry run

    k=3   d-1-2-3-4-5
group 1-2-3: kth=3, groupNext=4
reverse ->   d-3-2-1-4-5, groupPrev=1
from 1, walk 3: 4,5,null -> stop

    Watch out

    Check that a full group exists before reversing, or the short tail gets flipped. Starting prev at groupNext (not null) is what keeps the group attached to the rest.

Test yourself

Why do we need the next pointer at all?

After curr.next = prev, curr no longer points to the rest of the list. Without the saved bookmark we could never reach node curr+1 again.

What is the extra space of the recursive reversal?

O(n), for the call stack — one frame per node. The iterative version is O(1).

Getting the 1000th element: array or linked list, and why?

Array: O(1), jump straight to it. Linked list: O(n), follow 999 arrows from the head.
