Pattern 39 · Backtracking

Backtracking

Build an answer one choice at a time; when a choice leads nowhere, undo it and try the next one — choose, explore, un-choose.

Time to learn: about 3 hours · Prerequisites: Recursion, Tree traversals

When to use it — the signal

The question asks for all of something: "return all subsets", "all combinations that sum to", "all permutations", "every valid arrangement", "generate all valid parentheses", "can the word be found in the grid". The input is small (n ≤ 15–20), because the answer itself can be exponential.

The idea in plain words

Many problems are a series of small decisions. For the subsets of [1, 2, 3] you decide: start with 1 or not? then add 2 or not? then 3 or not? Each full series of decisions is one answer. There are 2 × 2 × 2 = 8 of them.

Backtracking walks through these decisions like a person walking through a maze:

  • Choose — take one option (add 1 to the current list, called the path).
  • Explore — call yourself recursively to make the remaining decisions.
  • Un-choose — when that call returns, remove 1 again, so the path is exactly as it was before. Now try the next option.

Drawn out, the decisions form a tree (the decision tree): the root is "nothing chosen yet" and every edge is one choice. Backtracking is just a depth-first walk over that tree. The un-choose step is what lets one single list be reused for every branch, instead of copying it at every step.

Pruning = cutting a branch as soon as you can prove it cannot lead to an answer (for example, the running sum is already bigger than the target). Pruning does not change the answer, it only skips useless work.

Analogy

Exploring a maze with a ball of string. At every fork you pick a corridor and unroll string as you walk (choose). You keep going (explore). If you hit a dead end, you walk back, rolling the string up to the last fork (un-choose), and try the next corridor. The string always shows exactly the path from the entrance to where you stand.

Watch it work

All subsets of [1, 2, 3]. Each circle is one choice; the path from the top {} to a circle is the current subset. Every circle is an answer, so we save a copy as soon as we arrive.

With pruning: Combination Sum

Candidates [2, 3], target 6. A number may be used again and again. The small chip next to each circle shows how much is left to reach the target. The candidates are sorted, so the moment one is too big, every later one is too big as well — we break out of the loop (pruning, shown in red).

Why it works

"Backtracking is a depth-first search over the decision tree. Each recursive call owns one decision; un-choosing after the call restores the state, so every branch starts from the same clean path. Pruning cuts subtrees that provably contain no answer, so the result is the same but faster."

Cost: subsets is O(2n · n) — 2n answers, each copied in O(n). That is fine because n is small and you must output every answer anyway.

The template to remember

void backtrack(state, path) {
    if (isComplete(path)) { res.add(new ArrayList<>(path)); return; }
    for (choice : choicesFrom(state)) {
        if (!valid(choice)) continue;   // or break, if sorted
        path.add(choice);               // choose
        backtrack(next(state), path);   // explore
        path.remove(path.size() - 1);  // un-choose
    }
}
Remember

Choose → explore → un-choose. Save a copy of the path. i + 1 = use each item once, i = reuse allowed, 0 = order matters (permutations).

Common mistakes
  • res.add(path) instead of res.add(new ArrayList<>(path)) — every saved answer is the same list, which ends up empty.
  • Forgetting the un-choose line — the path keeps growing and later branches start dirty.
  • Using continue where break is safe (sorted input) — still correct, just slower. Using break on unsorted input — wrong, you skip valid answers.
  • Looping from 0 instead of start in combinations — you get [2,3] and [3,2] as two answers.

Practice in this order

  • Medium78. Subsets — exactly the first animation.
    Show solution

    The idea

    Return every subset of distinct numbers, e.g. [1,2] → [], [1], [1,2], [2]. Key insight: picture a decision tree where each level chooses the next number to add, only from positions after the last one used (so [2,1] never appears next to [1,2]). Every node of that tree is a valid subset, so save the path at every call. Pattern: backtracking (choose, explore, un-choose).

    Step by step

    1. Call build(start = 0, path = []).
    2. First, save a copy of path: it is a subset.
    3. For i from start to the end: add nums[i], recurse with start = i + 1, then remove it.

    Java

    class Solution {
    public List<List<Integer>> subsets(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        build(nums, 0, new ArrayList<>(), result);
        return result;
    }

    private void build(int[] nums, int start, List<Integer> path,
                       List<List<Integer>> result) {
        result.add(new ArrayList<>(path)); // every node counts
        for (int i = start; i < nums.length; i++) {
            path.add(nums[i]);             // choose
            build(nums, i + 1, path, result); // explore
            path.remove(path.size() - 1);  // un-choose
        }
    }
}

    Time O(n · 2ⁿ) · Space O(n) besides the output — there are 2ⁿ subsets and each copy costs up to n; the path and recursion are n deep.

    Dry run

    [1,2,3]: save [] → add 1, save [1] → add 2, save [1,2] → add 3, save [1,2,3] → back, add 3, save [1,3] → back to [] → add 2, save [2] → add 3, save [2,3] → back → add 3, save [3]. 8 subsets.

    Watch out

    Save new ArrayList<>(path), not path, or every saved list ends up empty after backtracking. Recursing with start instead of i + 1 creates duplicates and very deep recursion. The bitmask method (count 0..2ⁿ − 1) is another way.

  • Medium77. Combinations — subsets, but only save when path size is k.
    Show solution

    The idea

    Return all ways to choose k numbers from 1..n, e.g. n = 4, k = 2 → [1,2] [1,3] [1,4] [2,3] [2,4] [3,4]. Key insight: it is the Subsets tree, but you save a path only when its size reaches k and then stop going deeper. Bonus pruning: if there are not enough numbers left to fill the path, stop the loop early. Pattern: backtracking with a size limit.

    Step by step

    1. build(start = 1, path = []).
    2. If path.size() == k, save a copy and return.
    3. need = k − path.size(). Try x from start up to n − need + 1 (any higher x leaves too few numbers).
    4. Add x, recurse with x + 1, remove x.

    Java

    class Solution {
    public List<List<Integer>> combine(int n, int k) {
        List<List<Integer>> result = new ArrayList<>();
        build(n, k, 1, new ArrayList<>(), result);
        return result;
    }

    private void build(int n, int k, int start,
                       List<Integer> path,
                       List<List<Integer>> result) {
        if (path.size() == k) {            // full: save it
            result.add(new ArrayList<>(path));
            return;
        }
        // stop early when too few numbers are left
        int need = k - path.size();
        for (int x = start; x <= n - need + 1; x++) {
            path.add(x);
            build(n, k, x + 1, path, result);
            path.remove(path.size() - 1);
        }
    }
}

    Time O(k · C(n, k)) · Space O(k) besides the output — C(n, k) combinations, each copied in O(k).

    Dry run

    n = 4, k = 2. Path [] → x up to 3. [1] → x 2..4: save [1,2], [1,3], [1,4]. [2] → save [2,3], [2,4]. [3] → save [3,4]. x = 4 is never tried at the first level (it could not get a partner).

    Watch out

    The pruning bound is an easy off-by-one: with need numbers still to pick, the largest first choice is n − need + 1. Without pruning the code is still correct, only slower.

  • Medium39. Combination Sum — the second animation; recurse with i.
    Show solution

    The idea

    Distinct positive candidates; find every combination that sums to target, where a number may be used many times, e.g. [2,3,6,7], target 7 → [2,2,3], [7]. Key insight: in the loop, recurse with i (not i + 1) so the same number can be picked again, but never go back to earlier numbers, so [2,3,2] does not repeat [2,2,3]. Sorting lets you stop as soon as a number is too big. Pattern: backtracking with reuse.

    Step by step

    1. Sort the candidates and call build(left = target, start = 0).
    2. If left == 0, save a copy of the path.
    3. For i from start: if c[i] > left, break (the rest are even bigger).
    4. Add c[i], recurse with left − c[i] and start i, then remove it.

    Java

    class Solution {
    public List<List<Integer>> combinationSum(int[] candidates,
                                              int target) {
        List<List<Integer>> result = new ArrayList<>();
        Arrays.sort(candidates);           // lets us stop early
        build(candidates, target, 0, new ArrayList<>(), result);
        return result;
    }

    private void build(int[] c, int left, int start,
                       List<Integer> path,
                       List<List<Integer>> result) {
        if (left == 0) {                   // exact sum
            result.add(new ArrayList<>(path));
            return;
        }
        for (int i = start; i < c.length; i++) {
            if (c[i] > left) break;        // rest are bigger
            path.add(c[i]);
            // i, not i + 1: the same number may repeat
            build(c, left - c[i], i, path, result);
            path.remove(path.size() - 1);
        }
    }
}

    Time O(N^(T/m)) roughly · Space O(T/m) — N candidates, T target, m the smallest candidate: the tree is at most T/m deep with up to N branches.

    Dry run

    [2,3,6,7], 7. [2] left 5 → [2,2] left 3 → [2,2,2] left 1 (next 2 > 1, break) → [2,2,3] left 0 save. [2,3] left 2 → 3 > 2 break. [3] left 4 → [3,3] left 1 break. [6] left 1 break. [7] left 0 save. Answer [[2,2,3],[7]].

    Watch out

    Using i + 1 forbids reuse (that is 40). Using 0 instead of i as the next start creates the same combination in different orders. The break is only correct because the array is sorted.

  • Medium90. Subsets II — sort, skip nums[i] == nums[i-1] when i > start.
    Show solution

    The idea

    Subsets again, but the input can have duplicates, and the answer must not, e.g. [1,2,2] gives [2] once, not twice. Key insight: sort so equal values sit next to each other. At one level of the tree (one loop), choosing the second 2 gives exactly the same subtrees as choosing the first 2, so skip a value equal to the one just before it in the same loop (i > start). Pattern: backtracking with duplicate skipping.

    Step by step

    1. Sort nums.
    2. In build(start), save a copy of the path first.
    3. For i from start: if i > start and nums[i] == nums[i − 1], skip.
    4. Otherwise add nums[i], recurse with i + 1, remove it.

    Java

    class Solution {
    public List<List<Integer>> subsetsWithDup(int[] nums) {
        Arrays.sort(nums);                 // equal values touch
        List<List<Integer>> result = new ArrayList<>();
        build(nums, 0, new ArrayList<>(), result);
        return result;
    }

    private void build(int[] nums, int start, List<Integer> path,
                       List<List<Integer>> result) {
        result.add(new ArrayList<>(path));
        for (int i = start; i < nums.length; i++) {
            // same value already tried at this position
            if (i > start && nums[i] == nums[i - 1]) continue;
            path.add(nums[i]);
            build(nums, i + 1, path, result);
            path.remove(path.size() - 1);
        }
    }
}

    Time O(n · 2ⁿ) · Space O(n) besides the output — worst case all values distinct.

    Dry run

    [1,2,2]: [] → [1] → [1,2] → [1,2,2] → back; at [1] the second 2 is skipped (i > start). Back at []: [2] → [2,2]; the second 2 at the top level is skipped. Result [], [1], [1,2], [1,2,2], [2], [2,2].

    Watch out

    The condition is i > start, not i > 0. With i > 0 you also skip the second 2 when going deeper, and lose [1,2,2] and [2,2].

  • Medium40. Combination Sum II — recurse with i + 1 and skip duplicates.
    Show solution

    The idea

    Like Combination Sum, but each candidate may be used once, and the candidates can contain duplicates, while the answer must not. Example: [10,1,2,7,6,1,5], target 8 → [1,1,6], [1,2,5], [1,7], [2,6]. Key insight: combine two tricks. Recurse with i + 1 (no reuse), and after sorting, skip equal values in the same loop exactly as in Subsets II.

    Step by step

    1. Sort the candidates; call build(left = target, start = 0).
    2. If left == 0, save a copy.
    3. For i from start: skip if i > start and c[i] == c[i − 1]; break if c[i] > left.
    4. Add c[i], recurse with left − c[i] and i + 1, remove it.

    Java

    class Solution {
    public List<List<Integer>> combinationSum2(int[] candidates,
                                               int target) {
        Arrays.sort(candidates);
        List<List<Integer>> result = new ArrayList<>();
        build(candidates, target, 0, new ArrayList<>(), result);
        return result;
    }

    private void build(int[] c, int left, int start,
                       List<Integer> path,
                       List<List<Integer>> result) {
        if (left == 0) {
            result.add(new ArrayList<>(path));
            return;
        }
        for (int i = start; i < c.length; i++) {
            if (i > start && c[i] == c[i - 1]) continue; // dup
            if (c[i] > left) break;        // rest are bigger
            path.add(c[i]);
            // i + 1: each number is used at most once
            build(c, left - c[i], i + 1, path, result);
            path.remove(path.size() - 1);
        }
    }
}

    Time O(n · 2ⁿ) · Space O(n) besides the output — each number is either in or out of a path.

    Dry run

    Sorted [1,1,2,5,6,7,10], 8. [1] → [1,1] → [1,1,6] save. [1,2] → [1,2,5] save. [1,7] save. Back at the top, the second 1 is skipped. [2] → [2,6] save. [5], [6], [7] find nothing; 10 > 8 breaks.

    Watch out

    The skip check goes before the break and uses i > start. Do not use a Set of lists to remove duplicates afterwards: it works but wastes a lot of time.

  • Medium22. Generate Parentheses — choose "(" if open < n, ")" if close < open.
    Show solution

    The idea

    Generate all valid strings of n pairs of brackets, e.g. n = 3 → "((()))", "(()())", "(())()", "()(())", "()()()". Key insight: build the string one character at a time and only make legal choices. You may add "(" while you have used fewer than n, and ")" only while it closes something (close < open). Every string that reaches length 2n is then valid. Pattern: backtracking with rules.

    Brute force first

    Generate all 2²ⁿ strings of brackets and keep the valid ones: O(2²ⁿ · n).

    Step by step

    1. build(open = 0, close = 0, sb = "").
    2. If the length is 2n, save the string.
    3. If open < n: append "(", recurse with open + 1, delete it.
    4. If close < open: append ")", recurse with close + 1, delete it.

    Java

    class Solution {
    public List<String> generateParenthesis(int n) {
        List<String> result = new ArrayList<>();
        build(n, 0, 0, new StringBuilder(), result);
        return result;
    }

    private void build(int n, int open, int close,
                       StringBuilder sb, List<String> result) {
        if (sb.length() == 2 * n) {
            result.add(sb.toString());
            return;
        }
        if (open < n) {                    // can still open
            sb.append('(');
            build(n, open + 1, close, sb, result);
            sb.deleteCharAt(sb.length() - 1);
        }
        if (close < open) {                // something to close
            sb.append(')');
            build(n, open, close + 1, sb, result);
            sb.deleteCharAt(sb.length() - 1);
        }
    }
}

    Time O(4ⁿ / √n) · Space O(n) besides the output — that is the Catalan number of valid strings, each of length 2n.

    Dry run

    n = 2. "" → "(" → "((" → "(()" → "(())" save. Back to "(" → "()" → "()(" → "()()" save. Answer ["(())", "()()"].

    Watch out

    The rule for ")" is close < open, not close < n; the second allows ")(" style strings. Remember to delete the last character after each recursive call when sharing one StringBuilder.

  • Medium79. Word Search — mark the cell, explore 4 neighbours, unmark.
    Show solution

    The idea

    Is word spelled in the grid by a path of neighbouring cells (up, down, left, right), using each cell at most once? Key insight: try every cell as the start. From a cell matching the current letter, mark it as "in use", try the 4 neighbours for the next letter, then unmark it so other paths can use it. Pattern: grid backtracking (DFS that undoes its marks).

    Step by step

    1. For each cell, if match(word, i = 0, r, c) is true, return true.
    2. In match: if i == word length, everything matched: true.
    3. If off-grid or the cell is not word[i]: false.
    4. Save the letter, set the cell to '#', and try the 4 neighbours with i + 1.
    5. Put the letter back and return whether any neighbour succeeded.

    Java

    class Solution {
    public boolean exist(char[][] board, String word) {
        for (int r = 0; r < board.length; r++) {
            for (int c = 0; c < board[0].length; c++) {
                if (match(board, word, 0, r, c)) return true;
            }
        }
        return false;
    }

    // can word[i..] be spelled starting at (r, c)?
    private boolean match(char[][] b, String word, int i,
                          int r, int c) {
        if (i == word.length()) return true; // all matched
        if (r < 0 || c < 0 || r >= b.length || c >= b[0].length
                || b[r][c] != word.charAt(i)) {
            return false;
        }
        char saved = b[r][c];
        b[r][c] = '#';                     // mark: in use
        boolean found = match(b, word, i + 1, r + 1, c)
                     || match(b, word, i + 1, r - 1, c)
                     || match(b, word, i + 1, r, c + 1)
                     || match(b, word, i + 1, r, c - 1);
        b[r][c] = saved;                   // unmark
        return found;
    }
}

    Time O(m·n · 3ᴸ) · Space O(L) — L = word length; after the first step each cell has at most 3 new directions; recursion is L deep.

    Dry run

    Board ABCE / SFCS / ADEE, word "SEE". S at (1,3) → E at (2,3) → E at (2,2) → i = 3 → true. For "ABCB", the path A-B-C reaches C at (0,2), but the only B next to it is (0,1), which is marked '#', so it fails.

    Watch out

    Forgetting to restore the cell breaks later searches from other starting cells. Check the length case (i == word.length()) before the bounds check, or a word that ends on the border fails.

  • Hard131. Palindrome Partitioning — choose the next palindrome piece.
    Show solution

    The idea

    Cut a string into pieces so that every piece is a palindrome (reads the same both ways), and return every such cutting, e.g. "aab" → ["a","a","b"], ["aa","b"]. Key insight: at each step, choose the next piece: try every end position, and go deeper only if s[start..end] is a palindrome. When start reaches the end of the string, the path is a full answer. Pattern: backtracking over cut positions.

    Step by step

    1. build(start = 0, path = []).
    2. If start == s.length(), save a copy of the path.
    3. For end from start to the last index: if s[start..end] is a palindrome, add it, recurse with end + 1, remove it.
    4. isPal checks with two pointers moving inward.

    Java

    class Solution {
    public List<List<String>> partition(String s) {
        List<List<String>> result = new ArrayList<>();
        build(s, 0, new ArrayList<>(), result);
        return result;
    }

    private void build(String s, int start, List<String> path,
                       List<List<String>> result) {
        if (start == s.length()) {         // whole string cut
            result.add(new ArrayList<>(path));
            return;
        }
        // try every next piece s[start..end]
        for (int end = start; end < s.length(); end++) {
            if (!isPal(s, start, end)) continue;
            path.add(s.substring(start, end + 1));
            build(s, end + 1, path, result);
            path.remove(path.size() - 1);
        }
    }

    private boolean isPal(String s, int lo, int hi) {
        while (lo < hi) {
            if (s.charAt(lo++) != s.charAt(hi--)) return false;
        }
        return true;
    }
}

    Time O(n · 2ⁿ) · Space O(n) besides the output — there are up to 2ⁿ⁻¹ ways to cut, each checked in O(n).

    Dry run

    "aab". start 0: "a" ok → start 1: "a" ok → start 2: "b" ok → save [a,a,b]. Back at start 1: "ab" no. Back at start 0: "aa" ok → start 2: "b" → save [aa,b]. "aab" is not a palindrome.

    Watch out

    substring(start, end + 1): the end index of substring is exclusive. To speed up palindrome checks, precompute a DP table pal[i][j], which keeps the same big-O but avoids repeated work.

Test yourself

Why must you save new ArrayList<>(path) and not path?

There is only one path list; it keeps being changed by choose and un-choose. Saving the list itself saves a reference that ends up empty at the end. A copy freezes the answer at that moment.

In Combination Sum, what changes if you recurse with i + 1 instead of i?

Each candidate can be used at most once — that is Combination Sum II. With i the same number can be picked again.

Why is break allowed in the pruning line?

The candidates are sorted. If c[i] is already bigger than what is left, every c[j] with j > i is at least as big, so none of them can fit either.

How many subsets does a 20-element array have, and is backtracking OK?

220 ≈ one million. Yes — you must output them all, and a million is fine. At n = 40 it would not be.
