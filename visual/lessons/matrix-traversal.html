Matrix Traversal

Walk a 2D grid in an unusual order — a spiral, a rotation, a wipe, a staircase — by keeping a few boundary numbers and moving them inwards.

Time to learn: about 2 hours · Prerequisites: Two pointers, In-place tricks

When to use it — the signal

The input is an m × n matrix and the question says "spiral order", "rotate by 90 degrees in place", "if a cell is 0 set its whole row and column to 0", or "each row and each column is sorted — find a target". No graph search is needed: the order of visiting is fixed by the shape.

The idea in plain words

  • Spiral: keep four walls — top, bottom, left, right. Walk along the top wall, then move it down by one. Walk down the right wall, then move it left. Bottom wall right-to-left, move it up. Left wall bottom-to-top, move it right. Repeat until the walls cross. A 3 × 4 matrix is done after 12 cells.
  • Rotate 90° clockwise = two simple moves. Transpose (flip across the main diagonal, so row i becomes column i), then reverse each row. In place means without making a copy — just swaps.
  • Set zeroes: you cannot wipe while scanning, or new zeros would wipe even more. First remember which rows and columns contain a zero, then wipe in a second pass.
  • Sorted rows and columns: stand at the top-right corner. Everything to your left is smaller, everything below is bigger. Too big → step left (that whole column is too big). Too small → step down (that whole row is too small). At most m + n steps.
Analogy

Spiral order is peeling an orange in one long strip: go around the outside, then the ring inside it, and so on. The staircase search is walking down a staircase in a dark building where each step tells you "too high" or "too low" — you only ever go left or down, never back.

Why it works

"Spiral: the four walls shrink by one after each side, so each cell is added exactly once — O(m·n)." "Rotate: a 90° clockwise turn sends (i, j) to (j, n−1−i); transpose does (i, j) → (j, i) and reversing the row does the n−1−i part." "Staircase: from the top-right, one comparison rules out a whole row or a whole column, so at most m + n steps."

The template to remember

// Spiral: four walls, shrink after each side
while (top <= bot && left <= right) {
    top row  → top++;     right col → right--;
    if (top <= bot)    bottom row ← bot--;
    if (left <= right) left col ↑  left++;
}
// Rotate clockwise = transpose + reverse rows
// (counter-clockwise = transpose + reverse columns)
// Staircase: start top-right
if (v > target) c--; else r++;
Remember

Spiral = four walls. Rotate = transpose + reverse. Zeroes = remember, then wipe. Sorted grid = start top-right.

Common mistakes
  • Spiral: forgetting the if (top <= bot) / if (left <= right) checks — a single middle row is then added twice.
  • Transposing the full matrix (j from 0) — every pair swaps twice and nothing changes. Start j at i + 1.
  • Set zeroes: wiping during the first scan.
  • Staircase from the top-left: both moves (right, down) make the number bigger, so you cannot decide which way to go.

Practice in this order

  • Easy867. Transpose Matrix — warm-up for rotate.
    Show solution

    The idea

    Transposing flips the grid over its main diagonal: row 0 becomes column 0, row 1 becomes column 1, and so on. A 2 × 3 grid becomes 3 × 2. So make a new grid with the sizes swapped and copy each matrix[r][c] into t[c][r]. Pattern: index mapping.

    Step by step

    1. Read rows and cols.
    2. Create t = new int[cols][rows], with the sizes swapped.
    3. For every cell (r, c), set t[c][r] = matrix[r][c].
    4. Return t.

    Java

    class Solution {
    public int[][] transpose(int[][] matrix) {
        int rows = matrix.length, cols = matrix[0].length;
        // the answer has the sizes swapped
        int[][] t = new int[cols][rows];
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                t[c][r] = matrix[r][c]; // row becomes column
            }
        }
        return t;
    }
}

    Time O(rows · cols) · Space O(rows · cols) — every cell is copied once into the new grid.

    Dry run

    [[1,2,3],[4,5,6]] (2 × 3). Row 0 (1,2,3) becomes column 0, row 1 (4,5,6) becomes column 1. Result [[1,4],[2,5],[3,6]].

    Watch out

    You cannot do this in place when the grid is not square, because the shape changes. Swapping in place (as in Rotate Image) only works for n × n.

  • Medium54. Spiral Matrix — animation 1.
    Show solution

    The idea

    Read the grid in a spiral: along the top row, down the right column, back along the bottom, up the left, then repeat one ring further in. Keep four walls (top, bottom, left, right). After you walk a side, move that wall one step inwards. Pattern: boundary shrinking.

    Step by step

    1. Set top = 0, bottom = rows−1, left = 0, right = cols−1.
    2. While top ≤ bottom and left ≤ right: read the top row from left to right, then do top++.
    3. Read the right column from top to bottom, then do right--.
    4. If rows remain (top ≤ bottom), read the bottom row from right to left, then bottom--.
    5. If columns remain (left ≤ right), read the left column from bottom to top, then left++.

    Java

    class Solution {
    public List<Integer> spiralOrder(int[][] matrix) {
        List<Integer> res = new ArrayList<>();
        int top = 0, bottom = matrix.length - 1;
        int left = 0, right = matrix[0].length - 1;
        while (top <= bottom && left <= right) {
            for (int c = left; c <= right; c++)   // go right
                res.add(matrix[top][c]);
            top++;
            for (int r = top; r <= bottom; r++)   // go down
                res.add(matrix[r][right]);
            right--;
            if (top <= bottom) {                  // go left
                for (int c = right; c >= left; c--)
                    res.add(matrix[bottom][c]);
                bottom--;
            }
            if (left <= right) {                  // go up
                for (int r = bottom; r >= top; r--)
                    res.add(matrix[r][left]);
                left++;
            }
        }
        return res;
    }
}

    Time O(rows · cols) · Space O(1) extra — each cell is read once; only the answer list grows.

    Dry run

    3 × 4 grid 1..12. Top row 1,2,3,4. Right column 8,12. Bottom row 11,10,9. Left column 5. The walls are now top = 1, bottom = 1, left = 1, right = 2, so the inner row gives 6,7. Result 1,2,3,4,8,12,11,10,9,5,6,7.

    Watch out

    The two if checks are the classic bug. Without them, a single remaining row or column is read twice (try [[1],[2],[3]]).

  • Medium59. Spiral Matrix II — same walls, write 1..n² instead of reading.
    Show solution

    The idea

    The same spiral walk as Spiral Matrix, but instead of reading cells you write the numbers 1, 2, 3, … n² into them. The four walls move in exactly the same way. Pattern: boundary shrinking.

    Step by step

    1. Make an n × n grid and set next = 1.
    2. Set the walls top, bottom, left, right to the edges.
    3. Fill the top row left to right, then top++. Fill the right column downwards, then right--.
    4. If top ≤ bottom, fill the bottom row right to left and do bottom--. If left ≤ right, fill the left column upwards and do left++.
    5. Repeat until the walls cross, then return the grid.

    Java

    class Solution {
    public int[][] generateMatrix(int n) {
        int[][] g = new int[n][n];
        int top = 0, bottom = n - 1, left = 0, right = n - 1;
        int next = 1;
        while (top <= bottom && left <= right) {
            for (int c = left; c <= right; c++)
                g[top][c] = next++;
            top++;
            for (int r = top; r <= bottom; r++)
                g[r][right] = next++;
            right--;
            if (top <= bottom) {
                for (int c = right; c >= left; c--)
                    g[bottom][c] = next++;
                bottom--;
            }
            if (left <= right) {
                for (int r = bottom; r >= top; r--)
                    g[r][left] = next++;
                left++;
            }
        }
        return g;
    }
}

    Time O(n²) · Space O(1) extra — each cell is written once.

    Dry run

    n = 3. Top 1,2,3. Right 4,5. Bottom 6,7. Left 8. Centre 9. Result [[1,2,3],[8,9,4],[7,6,5]].

    Watch out

    next++ must run once per cell. Writing the same cell twice (a missing wall check) leaves a gap at the end, such as a 0 in the middle.

  • Medium48. Rotate Image — animation 2.
    Show solution

    The idea

    Turn an n × n picture 90° clockwise without a second grid. A clockwise turn is the same as two simple moves: transpose (swap [r][c] with [c][r]), then reverse every row. Both moves are done with swaps in place. Pattern: in-place index tricks.

    Brute force first

    Copy into a new grid with res[c][n-1-r] = m[r][c], which uses O(n²) extra memory. The problem forbids that.

    Step by step

    1. Transpose: for each r, and only for c > r (the upper triangle), swap m[r][c] and m[c][r].
    2. Reverse each row with two pointers i and j that meet in the middle.
    3. Done. No return value, because the grid changes in place.

    Java

    class Solution {
    public void rotate(int[][] matrix) {
        int n = matrix.length;
        // 1) transpose: swap across the main diagonal
        for (int r = 0; r < n; r++) {
            for (int c = r + 1; c < n; c++) {
                int tmp = matrix[r][c];
                matrix[r][c] = matrix[c][r];
                matrix[c][r] = tmp;
            }
        }
        // 2) reverse every row
        for (int[] row : matrix) {
            for (int i = 0, j = n - 1; i < j; i++, j--) {
                int tmp = row[i];
                row[i] = row[j];
                row[j] = tmp;
            }
        }
    }
}

    Time O(n²) · Space O(1) — each cell is swapped a constant number of times.

    Dry run

    [[1,2,3],[4,5,6],[7,8,9]]. After the transpose: [[1,4,7],[2,5,8],[3,6,9]]. After reversing the rows: [[7,4,1],[8,5,2],[9,6,3]].

    Watch out

    Start the inner loop at c = r + 1. If it starts at 0, every pair is swapped twice and the grid ends up unchanged. For counter-clockwise, reverse the rows first and transpose second (or reverse columns).

  • Medium73. Set Matrix Zeroes — then do the O(1)-memory version.
    Show solution

    The idea

    If a cell is 0, its whole row and column must become 0. You cannot clear as you scan, because the new zeros would spread wrongly. First record which rows and columns to clear, then clear them. For O(1) memory, store those marks in row 0 and column 0 themselves, and keep two flags for whether row 0 and column 0 had a zero to begin with. Pattern: first row/column as markers.

    Brute force first

    Keep a boolean[] rowZero and a boolean[] colZero: O(rows + cols) extra space, simple and fine as a first version.

    Step by step

    1. Set two flags: does row 0 contain a 0? Does column 0 contain a 0?
    2. For every inner cell (r ≥ 1, c ≥ 1) that is 0, mark m[r][0] = 0 and m[0][c] = 0.
    3. For every inner cell, if its row mark or its column mark is 0, set it to 0.
    4. Finally clear row 0 if its flag is set, and column 0 if its flag is set.

    Java

    class Solution {
    public void setZeroes(int[][] m) {
        int rows = m.length, cols = m[0].length;
        boolean firstRowZero = false, firstColZero = false;
        for (int c = 0; c < cols; c++)
            if (m[0][c] == 0) firstRowZero = true;
        for (int r = 0; r < rows; r++)
            if (m[r][0] == 0) firstColZero = true;
        // use row 0 and column 0 as the marks
        for (int r = 1; r < rows; r++) {
            for (int c = 1; c < cols; c++) {
                if (m[r][c] == 0) {
                    m[r][0] = 0; // mark this row
                    m[0][c] = 0; // mark this column
                }
            }
        }
        // clear the inner cells from the marks
        for (int r = 1; r < rows; r++) {
            for (int c = 1; c < cols; c++) {
                if (m[r][0] == 0 || m[0][c] == 0) m[r][c] = 0;
            }
        }
        // the mark row and column go last
        if (firstRowZero)
            for (int c = 0; c < cols; c++) m[0][c] = 0;
        if (firstColZero)
            for (int r = 0; r < rows; r++) m[r][0] = 0;
    }
}

    Time O(rows · cols) · Space O(1) — the marks live inside the grid.

    Dry run

    [[0,1,2,0],[3,4,5,2],[1,3,1,5]]. Row 0 has zeros, so firstRowZero is true. Column 0 has a 0 at the top, so firstColZero is true. There are no inner zeros, so there are no new marks. Inner clear: m[0][3] is 0, so column 3's inner cells become 0. Then row 0 and column 0 are cleared. Result [[0,0,0,0],[0,4,5,0],[0,3,1,0]].

    Watch out

    Clear row 0 and column 0 last. Clearing them first wipes out the marks and zeros the whole grid.

  • Medium240. Search a 2D Matrix II — animation 4.
    Show solution

    The idea

    Each row is sorted left to right and each column top to bottom. Stand at the top-right corner. Everything to your left is smaller and everything below is bigger. If the value is too big, the whole column below is too big, so step left. If it is too small, the whole row to the left is too small, so step down. Each step rules out a row or a column. Pattern: staircase search.

    Brute force first

    Scan every cell (O(m · n)), or binary search every row (O(m log n)).

    Step by step

    1. Start at r = 0, c = cols−1.
    2. If matrix[r][c] == target, return true.
    3. If it is bigger than the target, do c--. If it is smaller, do r++.
    4. When you walk off the grid, return false.

    Java

    class Solution {
    public boolean searchMatrix(int[][] matrix, int target) {
        // start at the top-right corner
        int r = 0, c = matrix[0].length - 1;
        while (r < matrix.length && c >= 0) {
            int v = matrix[r][c];
            if (v == target) return true;
            if (v > target) c--; // whole column below is bigger
            else r++;            // whole row to the left is smaller
        }
        return false;
    }
}

    Time O(m + n) · Space O(1) — each step removes a row or a column, so there are at most m + n steps.

    Dry run

    target 5. Start at 15: too big, go left. 11 is too big, go left. 7 is too big, go left. 4 is too small, go down. 5 is found.

    Watch out

    Starting at the top-left does not work: both right and down are bigger, so you cannot tell which way to go. The bottom-left corner also works, with the moves mirrored.

  • Medium498. Diagonal Traverse — cells on one diagonal share r + c.
    Show solution

    The idea

    All cells on one diagonal share the same r + c. Diagonal d = 0 is [0][0], d = 1 is [0][1] and [1][0], and so on, up to d = rows + cols − 2. Walk the diagonals in order. Even ones go up-right (r falls, c rises) and odd ones go down-left. The only hard part is the start cell. Pattern: diagonal index r + c.

    Step by step

    1. Loop d from 0 to rows + cols − 2.
    2. Even d: start at r = min(d, rows−1), c = d − r, and step r--, c++ while inside the grid.
    3. Odd d: start at c = min(d, cols−1), r = d − c, and step r++, c-- while inside.
    4. Write each value into the answer array in order.

    Java

    class Solution {
    public int[] findDiagonalOrder(int[][] mat) {
        int rows = mat.length, cols = mat[0].length;
        int[] res = new int[rows * cols];
        int i = 0;
        // diagonal d holds the cells with r + c == d
        for (int d = 0; d < rows + cols - 1; d++) {
            if (d % 2 == 0) {
                // even: go up-right, start as low as we can
                int r = Math.min(d, rows - 1);
                int c = d - r;
                while (r >= 0 && c < cols) res[i++] = mat[r--][c++];
            } else {
                // odd: go down-left, start as far right
                int c = Math.min(d, cols - 1);
                int r = d - c;
                while (c >= 0 && r < rows) res[i++] = mat[r++][c--];
            }
        }
        return res;
    }
}

    Time O(rows · cols) · Space O(1) extra — each cell is visited exactly once.

    Dry run

    3 × 3 grid 1..9. d=0: 1. d=1 (down-left): 2,4. d=2 (up-right from [2][0]): 7,5,3. d=3: 6,8. d=4: 9. Result 1,2,4,7,5,3,6,8,9.

    Watch out

    Using min to clamp the start is the key. Without it, wide or tall grids start outside the grid. Test with a single row such as [[1,2,3]].

  • Medium289. Game of Life — in place with two-bit states.
    Show solution

    The idea

    Every cell's next state depends on the old states of its 8 neighbours, so you cannot overwrite cells as you go. Trick: store two bits per cell. Bit 0 is the state now and bit 1 is the state next. Count live neighbours using & 1 (now only), set bit 1 by the rules, then shift every cell right by one. Pattern: in-place state encoding.

    Brute force first

    Copy the board first and read neighbours from the copy: simple, but O(m · n) extra space.

    Step by step

    1. For each cell, count the neighbours with board[nr][nc] & 1 equal to 1, skipping the cell itself and cells outside the grid.
    2. A live cell with 2 or 3 live neighbours stays alive: set bit 1 (|= 2).
    3. A dead cell with exactly 3 live neighbours is born: set bit 1.
    4. Every other cell keeps bit 1 = 0, so it dies or stays dead.
    5. Second pass: board[r][c] >>= 1 moves "next" into "now".

    Java

    class Solution {
    public void gameOfLife(int[][] board) {
        int rows = board.length, cols = board[0].length;
        // bit 0 = state now, bit 1 = state next
        for (int r = 0; r < rows; r++) {
            for (int c = 0; c < cols; c++) {
                int live = 0;
                for (int dr = -1; dr <= 1; dr++) {
                    for (int dc = -1; dc <= 1; dc++) {
                        if (dr == 0 && dc == 0) continue;
                        int nr = r + dr, nc = c + dc;
                        if (nr >= 0 && nr < rows && nc >= 0
                                && nc < cols) {
                            live += board[nr][nc] & 1; // now
                        }
                    }
                }
                boolean alive = (board[r][c] & 1) == 1;
                if (alive && (live == 2 || live == 3))
                    board[r][c] |= 2; // stays alive
                if (!alive && live == 3)
                    board[r][c] |= 2; // is born
            }
        }
        // shift the next state into place
        for (int r = 0; r < rows; r++)
            for (int c = 0; c < cols; c++)
                board[r][c] >>= 1;
    }
}

    Time O(m · n) · Space O(1) — 8 neighbour checks per cell and no copy.

    Dry run

    [[1,1],[1,0]]. The dead cell [1][1] has 3 live neighbours, so it becomes 0b10. The three live cells each have 2 live neighbours, so they become 0b11. After the shift the board is all 1s: [[1,1],[1,1]].

    Watch out

    Count with & 1, not the raw value. A cell already marked 2 or 3 would otherwise count wrongly.

Test yourself

How do you rotate 90° counter-clockwise?

Transpose, then reverse each column (or: reverse each row first, then transpose).

In the staircase search, why not start at the top-left?

From the top-left both neighbours are bigger, so a comparison does not tell you which direction to move. Top-right (or bottom-left) has one smaller and one bigger direction.

How does Set Matrix Zeroes get O(1) extra memory?

Use row 0 and column 0 as the "has a zero" marks, plus one extra boolean for whether row 0 itself (or column 0) originally had a zero. Wipe the inner cells first, then row 0 and column 0 last.
