Pattern 47 · Dynamic programming

Grid DP

When you can only move right or down, each cell's answer comes from the cell above and the cell to its left — fill the grid row by row.

Time to learn: about 2 hours · Prerequisites: DP intro, LCS & edit distance

When to use it — the signal

A grid and movement only right / down (or any direction that never goes back): "number of unique paths", "minimum path sum", "paths with obstacles", "largest square of 1s", "dungeon game". If you may move in all four directions, it is a graph problem (BFS / Dijkstra), not grid DP.

The idea in plain words

A robot starts at the top-left of a 3 × 4 grid and may only step right or down. How many different routes reach the bottom-right?

The last step into any cell came either from the cell above or from the cell to the left. So: paths(cell) = paths(above) + paths(left). The top row and the left column have exactly 1 path each (go straight). Fill row by row, left to right, and every cell you need is already done.

Change "+" to "min, plus this cell's cost" and you have Minimum Path Sum. Change the question to "biggest square of 1s whose bottom-right corner is here" and the cell looks at three neighbours — up, left and up-left — and takes the smallest plus 1: Maximal Square.

Memory trick: each row only needs the row above, so one array of length n is enough (dp[j] += dp[j−1] for unique paths).

Analogy

Walking through a city laid out in blocks where every street is one-way, either east or south. The number of ways to reach a crossing is the ways to reach the crossing just north of it plus the ways to reach the one just west — write the count at each crossing as you go.

Watch it work

1. Unique Paths (3 × 4)

Blue = the two cells this one adds (above and left), yellow = being filled.

2. Minimum Path Sum

Each cell has a cost; find the cheapest route from top-left to bottom-right (right / down moves). dp[i][j] = cheapest total to reach (i, j), including its own cost.

3. Maximal Square

Find the largest square made only of 1s. dp[i][j] = side of the biggest all-1 square whose bottom-right corner is (i, j). A square of side k there needs squares of side k − 1 above, to the left and up-left — so take the smallest of those three, plus 1.

Why it works

"With only right and down moves, every route into a cell passes through its top or left neighbour, and those are computed earlier in row-major order. So each cell combines two (or three) finished answers in O(1), and the whole grid is O(m × n)."

The template to remember

for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++) {
        if (i == 0 || j == 0) dp[i][j] = base(i, j);           // edges
        else dp[i][j] = combine(dp[i-1][j], dp[i][j-1]);  // up, left (+ up-left)
    }
// one row is enough: dp[j] = combine(dp[j] /* up */, dp[j-1] /* left */)
Remember

Right/down only → up + left. Paths: add. Cost: min + cell. Square: min of three + 1.

Common mistakes
  • Forgetting the edge cells (top row / left column have only one neighbour).
  • Obstacles (Unique Paths II): an obstacle cell is 0, and so is everything after an obstacle in the first row / column.
  • Maximal Square: returning the side instead of the area, or comparing chars with ints ('1' vs 1).
  • Using grid DP when moves can go up or left — then cells depend on each other in a cycle; use BFS / Dijkstra.

Practice in this order

  • Medium62. Unique Paths — the first animation.
    Show solution

    The idea

    A robot moves only right or down on an m×n grid; count the paths from the top-left to the bottom-right. Any cell is entered from above or from the left, so paths(r,c) = paths(r-1,c) + paths(r,c-1). First row and column have exactly 1 path. Pattern: grid DP, keeping one row.

    Step by step

    1. Make a row array of n ones (the top row).
    2. For every next row, for c = 1..n−1: row[c] += row[c-1]. Before the add, row[c] still holds "from above".
    3. Return row[n-1].

    Java

    class Solution {
    public int uniquePaths(int m, int n) {
        // row[c] = paths to cell (r, c) in the current row
        int[] row = new int[n];
        Arrays.fill(row, 1);           // top row: one path
        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                // from above (old row[c]) + from left
                row[c] = row[c] + row[c - 1];
            }
        }
        return row[n - 1];
    }
}

    Time O(m · n) · Space O(n) — one pass over the grid, one row kept.

    Dry run

    m = 3, n = 3: [1,1,1] → [1,2,3] → [1,3,6]. Answer 6.

    Watch out

    The maths answer C(m+n−2, m−1) works too, but intermediate products overflow an int unless you divide as you go.

  • Medium63. Unique Paths II — obstacles are 0.
    Show solution

    The idea

    Unique Paths, but some cells are rocks (value 1) that no path may enter. Same rule, except a rock cell has 0 paths. Pattern: grid DP with blocked cells.

    Step by step

    1. row[0] = 1 for the start, everything else 0.
    2. Go through each grid row and each column c.
    3. If the cell is a rock, set row[c] = 0.
    4. Else if c > 0, row[c] += row[c-1] (above + left).
    5. Return row[n-1].

    Java

    class Solution {
    public int uniquePathsWithObstacles(int[][] grid) {
        int n = grid[0].length;
        int[] row = new int[n]; // paths into each column
        row[0] = 1;                    // the start cell
        for (int[] cells : grid) {
            for (int c = 0; c < n; c++) {
                if (cells[c] == 1) {
                    row[c] = 0;        // rock: no path in
                } else if (c > 0) {
                    row[c] += row[c - 1]; // above + left
                }
            }
        }
        return row[n - 1];
    }
}

    Time O(m · n) · Space O(n) — one row of counts.

    Dry run

    [[0,0,0],[0,1,0],[0,0,0]]: row 0 [1,1,1]; row 1 [1,0,1]; row 2 [1,1,2]. Answer 2.

    Watch out

    A rock on the start or the end cell gives 0. Do not pre-fill the first row with 1s: a rock in it blocks every cell to its right.

  • Medium64. Minimum Path Sum — the second animation.
    Show solution

    The idea

    Find the cheapest top-left to bottom-right path moving only right or down, where each cell adds its number. The cheapest way into a cell comes from the cheaper of the cell above and the cell to the left. dp[r][c] = grid[r][c] + min(up, left). Pattern: grid DP, min path.

    Step by step

    1. Walk cells row by row.
    2. Start cell: its own value.
    3. First row: only from the left. First column: only from above.
    4. Others: the smaller of up and left, plus the cell.
    5. Return the bottom-right value.

    Java

    class Solution {
    public int minPathSum(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        // dp[r][c] = cheapest sum to reach (r, c)
        int[][] dp = new int[m][n];
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                int before;              // best way in
                if (r == 0 && c == 0) before = 0;  // start
                else if (r == 0) before = dp[r][c - 1];
                else if (c == 0) before = dp[r - 1][c];
                else before = Math.min(dp[r - 1][c],
                                       dp[r][c - 1]);
                dp[r][c] = before + grid[r][c];
            }
        }
        return dp[m - 1][n - 1];
    }
}

    Time O(m · n) · Space O(m · n) — one cell each (can be cut to one row, or done in place in grid).

    Dry run

    [[1,3,1],[1,5,1],[4,2,1]]: row 0 [1,4,5]; row 1 [2,7,6]; row 2 [6,8,7]. Answer 7 (1→3→1→1→1).

    Watch out

    Greedy "step to the cheaper neighbour" fails; you must compare whole path sums.

  • Medium120. Triangle — fill from the bottom row up.
    Show solution

    The idea

    Find the smallest top-to-bottom sum in a number triangle, stepping to the same index or index + 1 in the next row. Working from the bottom up is cleanest: each cell's best = its value + the smaller of the two cells below it. The top then holds the answer. Pattern: grid DP filled bottom-up.

    Step by step

    1. Array best of size n + 1, all 0 (a fake row under the bottom).
    2. For r from the last row up to 0, for c = 0..r: best[c] = tri[r][c] + min(best[c], best[c+1]).
    3. Return best[0].

    Java

    class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {
        int n = triangle.size();
        // best[c] = cheapest path from (r, c) to the bottom
        int[] best = new int[n + 1]; // 0s under the bottom
        for (int r = n - 1; r >= 0; r--) {
            for (int c = 0; c <= r; c++) {
                // go down-left (c) or down-right (c + 1)
                best[c] = triangle.get(r).get(c)
                        + Math.min(best[c], best[c + 1]);
            }
        }
        return best[0];                // the top
    }
}

    Time O(n2) · Space O(n) — every cell once, one row kept.

    Dry run

    [[2],[3,4],[6,5,7],[4,1,8,3]]: bottom [4,1,8,3]; row 2 [7,6,10]; row 1 [9,10]; row 0 [11]. Answer 11.

    Watch out

    Going left to right in a row is safe bottom-up, because best[c+1] is still from the row below when you read it. Top-down needs extra edge handling.

  • Medium221. Maximal Square — the third animation.
    Show solution

    The idea

    Largest square of all 1s in a 0/1 matrix; return its area. dp[r][c] = side of the biggest all-1 square whose bottom-right corner is this cell. A square of side k here needs squares of side k−1 above, left and up-left, so dp = 1 + min(up, left, diag). Pattern: grid DP.

    Brute force first

    From every cell, grow a square while the next row and column are all 1s: O((mn)2) worst case.

    Step by step

    1. Table one bigger in each direction, all 0 (padding).
    2. For each '1' cell: dp[r][c] = 1 + min(dp[r-1][c], dp[r][c-1], dp[r-1][c-1]).
    3. '0' cells stay 0.
    4. Track the biggest side; return side × side.

    Java

    class Solution {
    public int maximalSquare(char[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        // dp[r][c] = side of the biggest all-1 square whose
        // bottom-right corner is (r-1, c-1); row/col 0 pad
        int[][] dp = new int[m + 1][n + 1];
        int best = 0;
        for (int r = 1; r <= m; r++) {
            for (int c = 1; c <= n; c++) {
                if (matrix[r - 1][c - 1] == '1') {
                    // limited by up, left and up-left
                    int up = dp[r - 1][c];
                    int left = dp[r][c - 1];
                    int diag = dp[r - 1][c - 1];
                    dp[r][c] = 1 + Math.min(diag,
                                   Math.min(up, left));
                    best = Math.max(best, dp[r][c]);
                }
            }
        }
        return best * best;            // area, not side
    }
}

    Time O(m · n) · Space O(m · n) — one cell each (one row is enough if needed).

    Dry run

    Rows 10100 / 10111 / 11111 / 10010: at (2,3), up 1, left 1, diag 1 → 2; also (2,4) → 2. Best side 2 → area 4.

    Watch out

    The matrix holds char '1' and '0', not ints. Return the area, not the side.

  • Medium1277. Count Square Submatrices — same table, answer = sum of dp.
    Show solution

    The idea

    Count every all-1 square of every size. Use the Maximal Square table: if dp[r][c] = k, this cell is the bottom-right corner of squares of side 1, 2, …, k, which is k squares. So the answer is the sum of the table. Pattern: grid DP + sum.

    Step by step

    1. Same padded table and same rule as problem 221.
    2. For each 1 cell, dp = 1 + min(up, left, diag).
    3. Add dp to the total.
    4. Return the total.

    Java

    class Solution {
    public int countSquares(int[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        int[][] dp = new int[m + 1][n + 1];  // padded
        int total = 0;
        for (int r = 1; r <= m; r++) {
            for (int c = 1; c <= n; c++) {
                if (matrix[r - 1][c - 1] == 1) {
                    int up = dp[r - 1][c];
                    int left = dp[r][c - 1];
                    int diag = dp[r - 1][c - 1];
                    dp[r][c] = 1 + Math.min(diag,
                                   Math.min(up, left));
                    // a corner with side k ends k squares:
                    // sizes 1, 2, ..., k
                    total += dp[r][c];
                }
            }
        }
        return total;
    }
}

    Time O(m · n) · Space O(m · n) — one cell each.

    Dry run

    [[1,1],[1,1]]: dp 1, 1, 1, then the corner 1 + min(1,1,1) = 2. Sum 1+1+1+2 = 5 (four 1×1 and one 2×2).

    Watch out

    Here the matrix holds ints 0/1, unlike 221's chars.

  • Hard174. Dungeon Game — fill from the bottom-right backwards.
    Show solution

    The idea

    A knight goes from the top-left to the princess at the bottom-right moving right or down; cells add or remove health, and health must stay ≥ 1 at all times. Find the least starting health. Going forward fails because you would need to track two things (current health and lowest point). Going backwards works: need[r][c] = least health on entering this cell, which is max(1, min(need below, need right) - cell). Pattern: grid DP filled from the bottom-right.

    Step by step

    1. Table one bigger, filled with a huge value (walls).
    2. The two fake cells next to the princess get 1 (leave her cell with at least 1 health).
    3. Fill from the bottom-right to the top-left: next = cheaper of down and right.
    4. need = max(1, next - dungeon[r][c]).
    5. Return need[0][0].

    Java

    class Solution {
    public int calculateMinimumHP(int[][] dungeon) {
        int m = dungeon.length, n = dungeon[0].length;
        // need[r][c] = least health when ENTERING (r, c)
        // so you can still reach the princess alive
        int[][] need = new int[m + 1][n + 1];
        for (int[] row : need)
            Arrays.fill(row, Integer.MAX_VALUE); // walls
        need[m][n - 1] = 1;   // fake cells next to the
        need[m - 1][n] = 1;   // princess: arrive with 1 HP
        for (int r = m - 1; r >= 0; r--) {
            for (int c = n - 1; c >= 0; c--) {
                // cheaper of going down or right next
                int next = Math.min(need[r + 1][c],
                                    need[r][c + 1]);
                // health never allowed below 1
                need[r][c] = Math.max(1,
                        next - dungeon[r][c]);
            }
        }
        return need[0][0];
    }
}

    Time O(m · n) · Space O(m · n) — one cell each.

    Dry run

    [[-2,-3,3],[-5,-10,1],[10,30,-5]]: princess cell need max(1, 1+5) = 6; (1,2): max(1, 6−1) = 5; (0,2): 2; (0,1): max(1, 2+3) = 5; (1,0) works out to 6, so (0,0): max(1, min(6, 5) + 2) = 7.

    Watch out

    The max(1, …) matters: a big health potion cannot make the needed health 0 or negative. Using MAX_VALUE as walls is safe because it is only compared, never added to.

Test yourself

Unique paths in a 2 × 2 grid?

2 — right then down, or down then right. dp = [[1,1],[1,2]].

Why min of three neighbours in Maximal Square, not max?

The square of side k needs all three neighbouring squares to be at least k − 1. The smallest one is the limit.

How do you get Unique Paths down to O(n) memory?

Keep one row: dp[j] += dp[j − 1]. Before the update dp[j] is the value from the row above; dp[j − 1] is already the current row's left cell.
