Bit Tricks

Every int is a row of 0s and 1s; AND, OR, XOR and shifts work on all the bits at once, which turns some problems into a single line with O(1) extra space.

Time to learn: about 2 hours · Prerequisites: Big-O, Arrays and hashing

When to use it — the signal

"Every element appears twice except one", "without extra space", "count the 1 bits", "power of two", "without using + or −", "all subsets" with n ≤ 20, "missing number" from 0..n, "reverse the bits".

The idea in plain words

A number is stored in binary: each position is worth double the one to its right — 1, 2, 4, 8, 16... So 13 = 8 + 4 + 1 = 1101. Each 0/1 is a bit.

  • a & b (AND): a bit is 1 only where both have a 1. 12 & 10 = 1100 & 1010 = 1000 = 8.
  • a | b (OR): 1 where either has a 1. 12 | 10 = 1110 = 14.
  • a ^ b (XOR): 1 where they are different. 12 ^ 10 = 0110 = 6.
  • a << 1 moves every bit one place left = times 2; a >> 1 moves right = divide by 2 (rounding down).

Three facts carry most interview questions: x ^ x = 0 and x ^ 0 = x (so XOR-ing pairs cancels them), and n & (n − 1) removes the lowest 1 bit of n (so it counts bits, and n & (n − 1) == 0 means n is a power of two).

Test bit i with (n >> i) & 1; set it with n | (1 << i); clear it with n & ~(1 << i).

Analogy

A row of light switches. AND is "on only if both rows have it on", OR is "on if either does", XOR is "flip the switch where the second row says 1" — flip the same switch twice and it is back where it started. A shift slides the whole row one place along.

Watch it work

The operators on a = 12 and b = 10, bit by bit. Columns are bit values 16, 8, 4, 2, 1.

Single Number with XOR

In [4, 1, 2, 1, 2] every number appears twice except one. XOR everything: pairs cancel to 0, the lonely one survives.

n & (n − 1): erase the lowest 1 bit

Count the 1 bits of n = 13 (1101). Subtracting 1 turns the lowest 1 into 0 and every 0 to its right into 1; AND-ing with n wipes exactly that lowest 1.

Counting Bits (0 to n)

For every i from 0 to 8, how many 1 bits? i >> 1 is i without its last bit, and we already know its answer.

Why it works

"XOR is its own inverse and order does not matter, so every pair cancels to 0 and only the unpaired value remains. n & (n − 1) clears the lowest set bit because subtracting 1 flips that bit and all the zeros below it, so the loop runs once per 1 bit."

The template to remember

(n >> i) & 1      // is bit i set?
n | (1 << i)       // set bit i
n & ~(1 << i)      // clear bit i
n ^ (1 << i)       // flip bit i
n & (n - 1)       // drop the lowest 1 bit; == 0 means power of two (n > 0)
n & -n            // keep only the lowest 1 bit
x ^ x == 0, x ^ 0 == x   // pairs cancel
for (int m = 0; m < (1 << n); m++)  // every subset of n items
Remember

XOR cancels pairs. n & (n−1) eats the lowest 1. Shift left doubles, shift right halves.

Common mistakes
  • Operator precedence: n & 1 == 0 is parsed as n & (1 == 0) — always write (n & 1) == 0.
  • Using >> on negative numbers in Java keeps the sign bit; use >>> for "unsigned" shifts (LC 190, 191).
  • 1 << 31 is negative and 1 << 32 is 1 for ints; use 1L << for long masks.
  • Power-of-two check without n > 0: 0 & (−1) is 0, but 0 is not a power of two.
  • Single Number II (every number three times) cannot use plain XOR — count each bit mod 3.

Practice in this order

  • Easy136. Single Number — XOR everything.
    Show solution

    The idea

    Every number appears twice except one; find it in O(n) time and O(1) space. XOR (^, "exclusive or": a bit is 1 when the two bits differ) has two handy rules: x ^ x = 0 and x ^ 0 = x, and order does not matter. XOR everything: each pair cancels to 0 and only the single number is left.

    Brute force first

    Count each number in a HashMap and return the one with count 1. O(n) time but O(n) space.

    Step by step

    1. Start with res = 0.
    2. XOR every number into res.
    3. Return res.

    Java

    class Solution {
    public int singleNumber(int[] nums) {
        int res = 0;
        // pairs cancel: x ^ x = 0, and x ^ 0 = x
        for (int x : nums) res ^= x;
        return res;
    }
}

    Time O(n) · Space O(1) — one pass, one variable.

    Dry run

    [4,1,2,1,2]
0^4 = 4, 4^1 = 5, 5^2 = 7, 7^1 = 6, 6^2 = 4
answer 4

    Watch out

    Works for negative numbers too, since XOR works bit by bit. It only works when the others appear an even number of times; "appears three times" (problem 137) needs bit counting instead.

  • Easy191. Number of 1 Bits — n &= n − 1 until 0.
    Show solution

    The idea

    Count the 1 bits in a number. The trick: n & (n - 1) erases the lowest 1 bit. Subtracting 1 flips that lowest 1 to 0 and the zeros below it to 1s; AND-ing with the original keeps everything above and clears the rest. So count how many times you can do it before n becomes 0.

    Brute force first

    Check all 32 bits one by one: (n >>> i) & 1. Always 32 steps; also fine.

    Step by step

    1. count = 0.
    2. While n != 0: n &= n - 1 and count++.
    3. Return count.

    Java

    class Solution {
    public int hammingWeight(int n) {
        int count = 0;
        while (n != 0) {
            n &= n - 1; // clear the lowest 1 bit
            count++;
        }
        return count;
    }
}

    Time O(number of 1 bits), at most 32 · Space O(1).

    Dry run

    n = 11 = 1011
1011 & 1010 = 1010  (count 1)
1010 & 1001 = 1000  (count 2)
1000 & 0111 = 0000  (count 3)  -> answer 3

    Watch out

    Loop on n != 0, not n > 0: a number with the top bit set is negative in Java, and n > 0 would stop at once. Integer.bitCount(n) is the built-in.

  • Easy338. Counting Bits — ans[i] = ans[i >> 1] + (i & 1).
    Show solution

    The idea

    Return the number of 1 bits for every i from 0 to n. Reuse earlier answers (a tiny dynamic programming): i >> 1 is i with its last bit dropped, a smaller number we already solved. So ans[i] = ans[i >> 1] + (i & 1), where i & 1 is that dropped last bit.

    Brute force first

    Count the bits of each number separately with n & (n - 1). O(n log n).

    Step by step

    1. Make ans of size n + 1; ans[0] = 0.
    2. For i from 1 to n: ans[i] = ans[i >> 1] + (i & 1).
    3. Return ans.

    Java

    class Solution {
    public int[] countBits(int n) {
        int[] ans = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            // bits of i = bits of i/2 + its last bit
            ans[i] = ans[i >> 1] + (i & 1);
        }
        return ans;
    }
}

    Time O(n) · Space O(1) besides the output — one step per number.

    Dry run

    i=1 (1):   ans[0] + 1 = 1
i=2 (10):  ans[1] + 0 = 1
i=3 (11):  ans[1] + 1 = 2
i=5 (101): ans[2] + 1 = 2   -> n=5 gives [0,1,1,2,1,2]

    Watch out

    Wrap (i & 1) in brackets: in Java + binds tighter than &, so ans[i >> 1] + i & 1 means (ans[i >> 1] + i) & 1.

  • Easy268. Missing Number — XOR all indices and all values.
    Show solution

    The idea

    The array has n different numbers from 0..n, with one missing. XOR all the indexes 0..n together with all the values: every number that is present appears twice (once as an index, once as a value) and cancels; the missing one appears once and is left. Pattern: XOR pairs cancel.

    Brute force first

    Sort and find the first index where nums[i] != i: O(n log n). The sum formula n(n+1)/2 − sum is O(n) too.

    Step by step

    1. Start with res = n (the one index the loop does not cover).
    2. For each i: res ^= i ^ nums[i].
    3. Return res.

    Java

    class Solution {
    public int missingNumber(int[] nums) {
        int res = nums.length; // index n has no slot
        for (int i = 0; i < nums.length; i++)
            res ^= i ^ nums[i]; // present numbers cancel
        return res;
    }
}

    Time O(n) · Space O(1) — one pass.

    Dry run

    nums = [3,0,1], n = 3
res = 3
i=0: 3 ^ 0 ^ 3 = 0
i=1: 0 ^ 1 ^ 0 = 1
i=2: 1 ^ 2 ^ 1 = 2   -> answer 2

    Watch out

    Do not forget n itself: start res at nums.length, otherwise an array missing n (like [0,1]) gives the wrong answer.

  • Easy190. Reverse Bits — take the last bit, push it in from the right, 32 times.
    Show solution

    The idea

    Reverse the order of the 32 bits of a number. Build the answer one bit at a time: shift the answer left to make room, copy n's last bit into the free spot, then shift n right to expose its next bit. After 32 rounds, n's first bit is the answer's last bit. Pattern: take a bit out, push it in from the right.

    Step by step

    1. res = 0.
    2. Repeat 32 times: res = (res << 1) | (n & 1).
    3. Then n >>>= 1 (unsigned shift, fills with 0).
    4. Return res.

    Java

    class Solution {
    // treat n as an unsigned value
    public int reverseBits(int n) {
        int res = 0;
        for (int i = 0; i < 32; i++) {
            res = (res << 1) | (n & 1); // push n's last bit
            n >>>= 1;                   // next bit of n
        }
        return res;
    }
}

    Time O(1), exactly 32 steps · Space O(1).

    Dry run

    4-bit version, n = 1101
res 0001, n 0110
res 0010, n 0011
res 0101, n 0001
res 1011, n 0000   -> 1101 reversed is 1011

    Watch out

    Run all 32 rounds even when n becomes 0, or the zeros that belong at the end are lost (1 must become 1000...0, not 1). Use >>> so n fills with zeros from the left; with >> the answer happens to be the same here, but >>> is the safe habit for unsigned bit work.

  • Medium371. Sum of Two Integers — XOR adds without carry, (a & b) << 1 is the carry.
    Show solution

    The idea

    Add two numbers without + or -. Adding in binary is two parts: a ^ b adds each column without the carry (1+1 gives 0), and (a & b) << 1 is the carry (a 1 where both columns were 1, moved one column left). Add those two the same way, again and again, until there is no carry.

    Step by step

    1. While b != 0 (there is still something to add):
    2. carry = (a & b) << 1.
    3. a = a ^ b (sum without carry).
    4. b = carry.
    5. Return a.

    Java

    class Solution {
    public int getSum(int a, int b) {
        while (b != 0) {
            int carry = (a & b) << 1; // columns with 1 + 1
            a = a ^ b;                // add without carry
            b = carry;                // now add the carry
        }
        return a;
    }
}

    Time O(1), at most 32 rounds · Space O(1) — the carry moves left one column each round.

    Dry run

    a = 2 (10), b = 3 (11)
carry = 10<<1 = 100, a = 01, b = 100
carry = 0,           a = 101 = 5, b = 0  -> answer 5

    Watch out

    Negative numbers just work in Java: ints are two's complement and the carry falls off the 32nd bit. In Python the same loop never ends, so this answer is Java (or C++) friendly.

  • Medium78. Subsets — mask m from 0 to 2ⁿ − 1, bit i = take item i.
    Show solution

    The idea

    Return every subset of distinct numbers. With n items there are 2n subsets, and the numbers 0 .. 2n − 1 written in binary list them all: in the number m (the "mask"), bit i = 1 means "take item i". For [1,2,3], mask 101 is [1,3]. Pattern: bitmask enumeration.

    Brute force first

    Backtracking (take or skip each item) gives the same 2n subsets; it is the other standard answer, with the same cost.

    Step by step

    1. n = nums.length; loop m from 0 to (1 << n) - 1.
    2. For each mask, start an empty list.
    3. For each i from 0 to n − 1: if (m >> i) & 1 is 1, add nums[i].
    4. Add the list to the result.

    Java

    class Solution {
    public List<List<Integer>> subsets(int[] nums) {
        int n = nums.length;
        List<List<Integer>> res = new ArrayList<>();
        for (int m = 0; m < (1 << n); m++) {
            List<Integer> sub = new ArrayList<>();
            for (int i = 0; i < n; i++)
                if (((m >> i) & 1) == 1) sub.add(nums[i]);
            res.add(sub); // bit i of m = take nums[i]
        }
        return res;
    }
}

    Time O(n · 2n) · Space O(n · 2n) for the output — 2n masks, n bits each.

    Dry run

    nums = [1,2,3]
m=0 000 []      m=1 001 [1]     m=2 010 [2]    m=3 011 [1,2]
m=4 100 [3]     m=5 101 [1,3]   m=6 110 [2,3]  m=7 111 [1,2,3]

    Watch out

    1 << n only works for n up to 30 in an int; here n ≤ 10. Do not forget the empty subset (mask 0).

  • Medium260. Single Number III — XOR all, split the numbers by one differing bit.
    Show solution

    The idea

    Exactly two numbers appear once, all others twice. XOR everything: the pairs cancel and we get x = a ^ b. Since a != b, x has at least one 1 bit, a place where a and b differ. Take its lowest one, x & -x, and split all numbers into two groups by that bit: a and b fall into different groups, and each pair falls into one group together. XOR each group to get a and b.

    Brute force first

    Count with a HashMap and return the two numbers with count 1. O(n) space.

    Step by step

    1. x = XOR of all numbers (= a ^ b).
    2. bit = x & -x: keeps only the lowest 1 bit of x.
    3. For each number: if (num & bit) != 0, XOR it into a, else into b.
    4. Return [a, b].

    Java

    class Solution {
    public int[] singleNumber(int[] nums) {
        int x = 0;
        for (int v : nums) x ^= v;  // x = a ^ b
        // lowest 1 bit of x: a and b differ there
        int bit = x & -x;
        int a = 0, b = 0;
        for (int v : nums) {
            if ((v & bit) != 0) a ^= v; // group with the bit
            else b ^= v;                // group without it
        }
        return new int[]{a, b};
    }
}

    Time O(n) · Space O(1) — two passes.

    Dry run

    nums = [1,2,1,3,2,5]
x = 3 ^ 5 = 011 ^ 101 = 110, bit = 010
bit set:   2,3,2 -> XOR = 3
bit clear: 1,1,5 -> XOR = 5     -> answer [3,5]

    Watch out

    x & -x also works when x is Integer.MIN_VALUE (it returns x itself), so there is no overflow trouble. Compare with != 0, not == 1, since the bit may be anywhere.

Test yourself

What are 6 & 3, 6 | 3 and 6 ^ 3?

110 and 011: AND = 010 = 2, OR = 111 = 7, XOR = 101 = 5.

What does 40 & 39 equal, and what does it tell you?

40 = 101000, 39 = 100111, AND = 100000 = 32. It is not 0, so 40 is not a power of two (it has two 1 bits).

Why does XOR find the single number even when the pairs are not next to each other?

XOR is commutative and associative, so the order does not matter: you can mentally regroup it as (1 ^ 1) ^ (2 ^ 2) ^ 4 = 0 ^ 0 ^ 4 = 4.

How do you check if a number is odd without %?

(n & 1) == 1 — the last bit is 1 for odd numbers.
