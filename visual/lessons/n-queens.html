N-Queens

Place one queen per row; if a row has no safe square, take back the queen above and move it — place, check, undo.

Time to learn: about 2 hours · Prerequisites: Backtracking, Permutations

When to use it — the signal

"Place items on a board so that no two attack / conflict", "fill the grid so every rule holds" (Sudoku), "all valid arrangements under constraints". You fill positions one by one and can tell early that a partial arrangement is already broken.

The idea in plain words

A queen in chess attacks everything in her row, her column and both diagonals. The puzzle: put n queens on an n × n board so no two attack each other. For n = 4 there are 2 solutions.

Two queens can never share a row, so put exactly one queen per row, top to bottom. The only decision per row is: which column?

  • For the current row, try columns 0, 1, 2, 3 in turn.
  • If the square is attacked by a queen already placed, skip it.
  • If it is safe, place the queen (choose) and move on to the next row (explore).
  • If the next rows fail, remove the queen (un-choose) and try the next column.
  • If no column in a row works, this row returns "failed" and the row above moves its queen. That stepping back is the backtrack.

Checking "is it attacked?" quickly: keep three sets — used columns, used row − col values (one per ↘ diagonal), used row + col values (one per ↙ diagonal). Each check is O(1).

Analogy

Seating guests at a wedding, one table per row, where some guests cannot sit in view of each other. You seat table 1, then table 2. When table 3 has no acceptable seat at all, you do not tear up the whole plan — you just go back to table 2 and move that guest to their next possible seat.

Watch it work

Why row − col and row + col name the diagonals

Moving one step along a ↘ diagonal adds 1 to both row and column, so row − col never changes. Moving along a ↙ diagonal adds 1 to the row and subtracts 1 from the column, so row + col never changes. One number per diagonal → a set can remember which diagonals are taken.

Why it works

"One queen per row turns the board into a sequence of column choices. A partial board that already has an attack can never become a solution, so we cut it at once instead of finishing it. The three sets make each check O(1), and un-choosing removes the queen from all three."

Cost: roughly O(n!) in the worst case — far less in practice thanks to pruning. n ≤ 9 in interviews.

The template to remember

void solve(int row) {
    if (row == n) { save(); return; }
    for (int c = 0; c < n; c++) {
        if (cols.contains(c) || diag.contains(row - c) || anti.contains(row + c)) continue;
        cols.add(c); diag.add(row - c); anti.add(row + c); board[row][c] = 'Q';
        solve(row + 1);
        cols.remove(c); diag.remove(row - c); anti.remove(row + c); board[row][c] = '.';
    }
}
Remember

One queen per row. Three sets: col, row−col, row+col. Place, recurse, remove from all three.

Common mistakes
  • Mixing up the diagonals: row − col is ↘, row + col is ↙. Using an array instead of a set? Shift row − col by n − 1 so the index is never negative.
  • Removing the queen from the board but forgetting one of the three sets (or the other way round).
  • Checking the whole board for attacks every time — O(n) per check, still correct but slow and long to write.
  • Building the output strings from a board that is later changed — build each row string when you save.

Test yourself

Why do we never need a "used rows" set?

The recursion places exactly one queen in each row and moves to the next row, so two queens can never be in the same row.

Squares (0, 3) and (2, 1): same diagonal?

0 + 3 = 3 and 2 + 1 = 3 → yes, the same ↙ diagonal.

What happens when a row has no safe square?

The loop ends without placing anything and the call returns. The caller (the row above) runs its un-choose line and tries its next column — that is the backtrack.
