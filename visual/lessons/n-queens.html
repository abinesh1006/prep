N-Queens

Place one queen per row; if a row has no safe square, take back the queen above and move it — place, check, undo.

Time to learn: about 2 hours · Prerequisites: Backtracking, Permutations

When to use it — the signal

"Place items on a board so that no two attack / conflict", "fill the grid so every rule holds" (Sudoku), "all valid arrangements under constraints". You fill positions one by one and can tell early that a partial arrangement is already broken.

The idea in plain words

A queen in chess attacks everything in her row, her column and both diagonals. The puzzle: put n queens on an n × n board so no two attack each other. For n = 4 there are 2 solutions.

Two queens can never share a row, so put exactly one queen per row, top to bottom. The only decision per row is: which column?

  • For the current row, try columns 0, 1, 2, 3 in turn.
  • If the square is attacked by a queen already placed, skip it.
  • If it is safe, place the queen (choose) and move on to the next row (explore).
  • If the next rows fail, remove the queen (un-choose) and try the next column.
  • If no column in a row works, this row returns "failed" and the row above moves its queen. That stepping back is the backtrack.

Checking "is it attacked?" quickly: keep three sets — used columns, used row − col values (one per ↘ diagonal), used row + col values (one per ↙ diagonal). Each check is O(1).

Analogy

Seating guests at a wedding, one table per row, where some guests cannot sit in view of each other. You seat table 1, then table 2. When table 3 has no acceptable seat at all, you do not tear up the whole plan — you just go back to table 2 and move that guest to their next possible seat.

Watch it work

4-Queens, row by row. Blue Q = queens already placed, yellow = the queen just placed, red × = a square we tried that is attacked.

Why row − col and row + col name the diagonals

Moving one step along a ↘ diagonal adds 1 to both row and column, so row − col never changes. Moving along a ↙ diagonal adds 1 to the row and subtracts 1 from the column, so row + col never changes. One number per diagonal → a set can remember which diagonals are taken.

Why it works

"One queen per row turns the board into a sequence of column choices. A partial board that already has an attack can never become a solution, so we cut it at once instead of finishing it. The three sets make each check O(1), and un-choosing removes the queen from all three."

Cost: roughly O(n!) in the worst case — far less in practice thanks to pruning. n ≤ 9 in interviews.

The template to remember

void solve(int row) {
    if (row == n) { save(); return; }
    for (int c = 0; c < n; c++) {
        if (cols.contains(c) || diag.contains(row - c) || anti.contains(row + c)) continue;
        cols.add(c); diag.add(row - c); anti.add(row + c); board[row][c] = 'Q';
        solve(row + 1);
        cols.remove(c); diag.remove(row - c); anti.remove(row + c); board[row][c] = '.';
    }
}
Remember

One queen per row. Three sets: col, row−col, row+col. Place, recurse, remove from all three.

Common mistakes
  • Mixing up the diagonals: row − col is ↘, row + col is ↙. Using an array instead of a set? Shift row − col by n − 1 so the index is never negative.
  • Removing the queen from the board but forgetting one of the three sets (or the other way round).
  • Checking the whole board for attacks every time — O(n) per check, still correct but slow and long to write.
  • Building the output strings from a board that is later changed — build each row string when you save.

Practice in this order

  • Hard51. N-Queens — the animation, save every solution.
    Show solution

    The idea

    Place n queens on an n×n board so none attack each other, and return every board. Each row holds exactly one queen, so go row by row and pick a column. A column is safe if no earlier queen shares its column or either diagonal. On a "/" diagonal r + c is constant, on a "\" diagonal r - c is constant, so three boolean arrays answer "attacked?" in O(1). Pattern: backtracking with constraint sets.

    Step by step

    1. Make a board of '.' and three arrays: col[n], d1[2n] for r + c, d2[2n] for r − c + n (shifted so it is never negative).
    2. In row r, try each column c that is not attacked.
    3. Mark the three arrays, put 'Q', recurse to row r + 1.
    4. Undo: put '.', clear the marks.
    5. When r == n, copy the board rows into strings and save.

    Java

    class Solution {
    public List<List<String>> solveNQueens(int n) {
        List<List<String>> res = new ArrayList<>();
        char[][] board = new char[n][n];
        for (char[] row : board) Arrays.fill(row, '.');
        place(0, n, board, new boolean[n],
              new boolean[2 * n], new boolean[2 * n], res);
        return res;
    }

    // col[c]: column c taken
    // d1[r + c]: "/" diagonal taken (r + c is constant)
    // d2[r - c + n]: "\" diagonal taken (r - c constant)
    void place(int r, int n, char[][] b, boolean[] col,
               boolean[] d1, boolean[] d2,
               List<List<String>> res) {
        if (r == n) {                       // all rows done
            List<String> sol = new ArrayList<>();
            for (char[] row : b) sol.add(new String(row));
            res.add(sol);
            return;
        }
        for (int c = 0; c < n; c++) {
            if (col[c] || d1[r + c] || d2[r - c + n])
                continue;                   // attacked
            col[c] = d1[r + c] = d2[r - c + n] = true;
            b[r][c] = 'Q';                  // place
            place(r + 1, n, b, col, d1, d2, res);
            b[r][c] = '.';                  // remove
            col[c] = d1[r + c] = d2[r - c + n] = false;
        }
    }
}

    Time O(n!) roughly · Space O(n2) — row r has at most n − r safe columns; the board itself is n×n.

    Dry run

    n = 4: row 0 col 0 → row 1 col 2 → row 2 has no safe column → back; row 1 col 3 → row 2 col 1 → row 3 stuck → back to row 0, col 1 → row 1 col 3 → row 2 col 0 → row 3 col 2 → save [".Q..","...Q","Q...","..Q."].

    Watch out

    r - c ranges from −(n−1) to n−1, so add n before indexing. n = 2 and n = 3 have no solutions; return an empty list.

  • Hard52. N-Queens II — count instead of saving.
    Show solution

    The idea

    Same search as N-Queens, but only the number of boards is needed. Let the recursive function return how many ways the rows below can be finished; a full board counts 1. No board strings, no copies. Pattern: backtracking that counts.

    Step by step

    1. Keep the same col, d1, d2 arrays.
    2. count(r): if r == n return 1.
    3. Otherwise sum count(r + 1) over every safe column, marking before and unmarking after.
    4. Return count(0).

    Java

    class Solution {
    boolean[] col, d1, d2;
    int n;

    public int totalNQueens(int n) {
        this.n = n;
        col = new boolean[n];
        d1 = new boolean[2 * n];       // r + c
        d2 = new boolean[2 * n];       // r - c + n
        return count(0);
    }

    // number of ways to finish from row r down
    int count(int r) {
        if (r == n) return 1;          // a full board
        int ways = 0;
        for (int c = 0; c < n; c++) {
            if (col[c] || d1[r + c] || d2[r - c + n])
                continue;              // attacked
            col[c] = d1[r + c] = d2[r - c + n] = true;
            ways += count(r + 1);
            col[c] = d1[r + c] = d2[r - c + n] = false;
        }
        return ways;
    }
}

    Time O(n!) roughly · Space O(n) — only three flag arrays and the recursion stack.

    Dry run

    n = 4: row 0 col 0 → 0 ways; col 1 → 1 way; col 2 → 1 way; col 3 → 0 ways. Total 2.

    Watch out

    Return the sum, do not keep a global counter that is never reset if the same object is reused. Expected values to remember: n = 8 gives 92.

  • Medium36. Valid Sudoku — the same "sets per row / column / box" check, no backtracking.
    Show solution

    The idea

    Check a partly filled 9×9 Sudoku: no digit may repeat in a row, a column, or a 3×3 box. No solving needed. Keep "seen" flags per row, per column and per box; the box number is (r/3)*3 + c/3. Pattern: hashing / seen sets.

    Step by step

    1. Make three 9×9 boolean tables: row, col, box (index = which row/col/box, then digit).
    2. Walk every cell; skip '.'.
    3. Digit d = ch - '1' (0..8), box b = (r/3)*3 + c/3.
    4. If any of the three flags is already true, return false; else set all three.
    5. If the walk ends, return true.

    Java

    class Solution {
    public boolean isValidSudoku(char[][] board) {
        // seen[r][d]: digit d already in row r, etc.
        boolean[][] row = new boolean[9][9];
        boolean[][] col = new boolean[9][9];
        boolean[][] box = new boolean[9][9];
        for (int r = 0; r < 9; r++) {
            for (int c = 0; c < 9; c++) {
                char ch = board[r][c];
                if (ch == '.') continue;      // empty cell
                int d = ch - '1'; // '1'..'9' -> 0..8
                int b = (r / 3) * 3 + c / 3;  // box 0..8
                if (row[r][d] || col[c][d] || box[b][d])
                    return false; // repeat found
                row[r][d] = col[c][d] = box[b][d] = true;
            }
        }
        return true;
    }
}

    Time O(81) = O(1) · Space O(1) — the board is always 9×9, the tables are fixed size.

    Dry run

    Cell (0,0) = '5' → row 0, col 0, box 0 mark 5. Later (1,0)='6' etc. In the bad board, '8' at (0,0) and '8' at (3,0) share column 0 → col[0][7] already true → false.

    Watch out

    Box index: (r / 3) * 3 + c / 3, with integer division. Writing r / 3 + c / 3 mixes boxes. A valid board need not be solvable; do not try to solve it.

  • Hard37. Sudoku Solver — next empty cell, try 1–9, undo.
    Show solution

    The idea

    Fill every '.' so the Sudoku rules hold (one solution is guaranteed). Go through the cells in order; at an empty cell try digits 1–9 that are not already in its row, column or box, place one, and continue. If a later cell has no option, come back and try the next digit. Pattern: backtracking with constraint sets (like N-Queens).

    Step by step

    1. Record the given digits in row, col, box flag tables.
    2. solve(i) handles cell number i (0..80): r = i/9, c = i%9.
    3. If the cell is filled, go to i + 1.
    4. Else for d = 1..9 that is allowed: write it, mark, and if solve(i+1) returns true, stop.
    5. If no digit worked, undo and return false so the caller tries its next digit.

    Java

    class Solution {
    boolean[][] row = new boolean[9][10];
    boolean[][] col = new boolean[9][10];
    boolean[][] box = new boolean[9][10];

    public void solveSudoku(char[][] board) {
        for (int r = 0; r < 9; r++) // record givens
            for (int c = 0; c < 9; c++)
                if (board[r][c] != '.')
                    mark(r, c, board[r][c] - '0', true);
        solve(board, 0);
    }

    // fill cells from index i (0..80) onward
    boolean solve(char[][] b, int i) {
        if (i == 81) return true;            // board full
        int r = i / 9, c = i % 9;
        if (b[r][c] != '.') return solve(b, i + 1);
        for (int d = 1; d <= 9; d++) {
            if (row[r][d] || col[c][d]
                    || box[r / 3 * 3 + c / 3][d]) continue;
            b[r][c] = (char) ('0' + d);      // try d
            mark(r, c, d, true);
            if (solve(b, i + 1)) return true; // it worked
            mark(r, c, d, false);            // undo
            b[r][c] = '.';
        }
        return false;                        // dead end
    }

    void mark(int r, int c, int d, boolean v) {
        row[r][d] = col[c][d] = box[r / 3 * 3 + c / 3][d] = v;
    }
}

    Time O(9e) worst case for e empty cells, fast in practice · Space O(81) — recursion depth is at most 81 and the tables are fixed.

    Dry run

    First empty cell (0,2): row 0 has 5,3,7; column 2 has 8; box 0 has 5,3,6,9,8 → 1, 2, 4 allowed; try 1… later dead ends force a change to 4, which is in the final answer "534678912".

    Watch out

    Return true up the stack as soon as the board is full, or the undo step erases the finished solution. The method is void: change board in place.

  • Hard212. Word Search II — grid backtracking plus a trie for pruning.
    Show solution

    The idea

    Find which dictionary words can be traced in a letter grid by moving up, down, left, right without reusing a cell. Searching each word separately repeats a lot of work. Put all words in a trie (a tree where each edge is a letter, so shared prefixes share a path) and run one DFS from every cell, walking the trie in step with the grid. If the trie has no child for the next letter, stop right away. Pattern: grid backtracking + trie pruning.

    Brute force first

    Run Word Search (problem 79) once per word: O(W · m · n · 4L), too slow for 3×104 words.

    Step by step

    1. Insert every word into a trie; store the whole word on its last node.
    2. From every cell, call dfs(r, c, root).
    3. In dfs: stop if off the grid, if the cell is in use ('#'), or if the trie node has no child for this letter.
    4. If the child node holds a word, add it and set it to null (so it is found once).
    5. Mark the cell '#', recurse in four directions with the child node, then restore the letter.

    Java

    class Solution {
    static class Node {
        Node[] next = new Node[26];
        String word;             // set where a word ends
    }

    public List<String> findWords(char[][] board,
                                  String[] words) {
        Node root = new Node();
        for (String w : words) { // build the trie
            Node cur = root;
            for (char ch : w.toCharArray()) {
                int k = ch - 'a';
                if (cur.next[k] == null)
                    cur.next[k] = new Node();
                cur = cur.next[k];
            }
            cur.word = w;
        }
        List<String> res = new ArrayList<>();
        for (int r = 0; r < board.length; r++)
            for (int c = 0; c < board[0].length; c++)
                dfs(board, r, c, root, res);
        return res;
    }

    void dfs(char[][] b, int r, int c, Node parent,
             List<String> res) {
        if (r < 0 || c < 0 || r >= b.length
                || c >= b[0].length) return;   // off grid
        char ch = b[r][c];
        if (ch == '#') return;                 // in path
        Node node = parent.next[ch - 'a'];
        if (node == null) return; // no word here
        if (node.word != null) {
            res.add(node.word);
            node.word = null; // no duplicates
        }
        b[r][c] = '#';                         // mark used
        dfs(b, r + 1, c, node, res);
        dfs(b, r - 1, c, node, res);
        dfs(b, r, c + 1, node, res);
        dfs(b, r, c - 1, node, res);
        b[r][c] = ch;                          // unmark
    }
}

    Time O(m · n · 4 · 3L−1) · Space O(total letters in words) — L is the longest word; after the first step each cell has at most 3 new directions; the trie holds every letter once.

    Dry run

    Words oath, pea, eat, rain. From 'o' (0,0): o → a (0,1) → t (1,1) → h (2,1) → node holds "oath", save it. From 'e' (1,3): e → a (1,2) → t (1,1) → "eat". No cell is 'p', so the trie stops "pea" at once; "rain" stops because no 'a' touches 'r'. Result [oath, eat].

    Watch out

    Clear node.word after adding it, or a word reachable by two paths appears twice. Always restore the cell letter after the four calls.

Test yourself

Why do we never need a "used rows" set?

The recursion places exactly one queen in each row and moves to the next row, so two queens can never be in the same row.

Squares (0, 3) and (2, 1): same diagonal?

0 + 3 = 3 and 2 + 1 = 3 → yes, the same ↙ diagonal.

What happens when a row has no safe square?

The loop ends without placing anything and the call returns. The caller (the row above) runs its un-choose line and tries its next column — that is the backtrack.
