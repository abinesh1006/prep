Stacks and Queues

A stack hands back the most recent thing you put in; a queue hands back the oldest. Picking the right one makes "matching", "undo" and "in order of arrival" problems almost write themselves.

Time to learn: about 2 hours · Prerequisites: Arrays and hashing, Big-O

When to use it — the signal

Stack: "valid / balanced brackets", "nested", "undo", "evaluate an expression", "the most recent unmatched ...", "backspace". Queue: "in the order they arrive", "level by level", "first come first served", "recent requests".

The idea in plain words

A stack is a pile where you can only touch the top. push puts something on top, pop takes the top off, peek looks at the top without removing it. The last thing in is the first thing out — people call this LIFO (last in, first out).

A queue is a line. offer adds to the back, poll removes from the front. The first thing in is the first thing out — FIFO.

  • Push 1, 2, 3 onto a stack and pop: you get 3.
  • Offer 1, 2, 3 into a queue and poll: you get 1.
  • All four operations are O(1) — constant time, no matter how big it gets.

Why a stack is so useful: many problems have the shape "the newest open thing must be closed first". In { [ ( ) ] } the ( opened last, so it must close first. A stack keeps exactly the "still open" things, newest on top.

In Java use ArrayDeque for both (never the old Stack class): push / pop / peek for a stack, offer / poll / peek for a queue.

Analogy

A stack is a pile of plates in a canteen: you put a clean plate on top and the next person takes the top plate. A queue is the line at a shop counter: whoever came first is served first, and new people join at the back.

Min Stack

Design a stack whose getMin() is O(1). Trick: a second stack remembers "the minimum so far" at every height.

Evaluate Reverse Polish Notation

In RPN the operator comes after its two numbers: 3 4 + 2 * 7 - means ((3 + 4) * 2) - 7. Numbers wait on a stack; an operator eats the top two.

Why it works

"Brackets close in the reverse order they opened, so the bracket that must close next is always the newest unclosed one — exactly what the top of a stack holds. Each character is pushed and popped at most once, so it is O(n)."

The template to remember

// Stack: deal with the newest unfinished thing first
Deque<T> st = new ArrayDeque<>();
for (T x : input) {
    if (opens(x)) st.push(x);          // wait for a partner
    else combine(st.pop(), x);         // newest partner
}
// Queue: deal with the oldest first
Deque<T> q = new ArrayDeque<>();
q.offer(start);
while (!q.isEmpty()) { T x = q.poll(); /* ... q.offer(next) */ }

Every problem here deals with the newest unfinished thing first, which is a stack; ArrayDeque is the Java class for it (and for queues), and a StringBuilder doubles as a stack of characters.

Remember

Plates → stack → newest first. Shop line → queue → oldest first. "Matching / nested / undo" means stack; "in order / level by level" means queue.

Common mistakes
  • Calling pop() or peek() on an empty stack — check isEmpty() first (a lone ) must return false, not crash).
  • Forgetting the final st.isEmpty() check: "((" has no wrong closer but is still invalid.
  • In RPN, popping in the wrong order: the first pop is the right operand. 5 2 - is 3, not −3.
  • Using java.util.Stack (old and synchronized) — use ArrayDeque.
  • Min Stack with a single min variable: after popping the minimum you no longer know the next one.

Practice in this order

  • Easy20. Valid Parentheses — the animation above.
    Show solution

    The idea

    A string of brackets is valid when every opener is closed by the same type, in the right order: "([])" is valid, "(]" and "([)]" are not. The most recent unclosed opener must be closed first, which is exactly what a stack (last in, first out) gives you. Pattern: matching with a stack.

    Step by step

    1. Walk the string. For an opener, push the closer you now expect (( → push )).
    2. For a closer, the stack must be non-empty and its top must equal this character; pop it. Otherwise return false.
    3. At the end, valid only if the stack is empty.

    Java

    class Solution {
    public boolean isValid(String s) {
        Deque<Character> stack = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (c == '(') stack.push(')');      // expect )
            else if (c == '[') stack.push(']');
            else if (c == '{') stack.push('}');
            else if (stack.isEmpty() || stack.pop() != c) {
                return false;         // wrong closer
            }
        }
        return stack.isEmpty();       // all closed
    }
}

    Time O(n) · Space O(n) — one pass; the stack can hold every character in the worst case.

    Dry run

    "([])"   char  stack (top right)
         (     )
         [     ) ]
         ]     )      pop ] ok
         )     empty  pop ) ok  -> true

    Watch out

    Two classic misses: a closer with an empty stack ("]") and leftover openers at the end ("("). Use ArrayDeque rather than the old Stack class.

  • Easy232. Implement Queue using Stacks — pour the in-stack into an out-stack only when out is empty.
    Show solution

    The idea

    Make a queue (first in, first out) out of two stacks. Pouring one stack into another reverses the order, so the oldest item ends up on top. Keep an in stack for pushes and an out stack for pops, and only pour when out is empty. Each item is moved at most once, so every operation is O(1) amortized (averaged over many calls).

    Step by step

    1. push(x): push onto in.
    2. pop()/peek(): if out is empty, move everything from in to out; then pop/peek out.
    3. empty(): both stacks empty.

    Java

    class MyQueue {
    private final Deque<Integer> in = new ArrayDeque<>();
    private final Deque<Integer> out = new ArrayDeque<>();

    public void push(int x) { in.push(x); }

    public int pop() {
        peek();                 // make sure out is filled
        return out.pop();
    }

    public int peek() {
        if (out.isEmpty()) {    // pour only when empty
            while (!in.isEmpty()) out.push(in.pop());
        }
        return out.peek();
    }

    public boolean empty() {
        return in.isEmpty() && out.isEmpty();
    }
}

    Time O(1) amortized per call · Space O(n) — each element is pushed and popped at most twice in total.

    Dry run

    push1 push2    in [1,2]  out []
peek           in []     out [2,1]  top 1
pop -> 1       out [2]
push3          in [3]    out [2]
pop -> 2 (out not empty, no pour); pop -> pour 3 -> 3

    Watch out

    Pouring while out still has items breaks the order. Pour only when out is empty.

  • Easy844. Backspace String Compare — # pops the last letter.
    Show solution

    The idea

    Type each string into an editor where # is backspace, then compare: "ab#c" and "ad#c" both become "ac". Simulating with a stack (a StringBuilder works as one) is the clear answer: letters push, # pops if there is something to pop.

    Step by step

    1. Write build(s): for each char, if it is # delete the last char (if any), else append it.
    2. Return build(s).equals(build(t)).

    Java

    class Solution {
    public boolean backspaceCompare(String s, String t) {
        return build(s).equals(build(t));
    }

    private String build(String s) {
        StringBuilder sb = new StringBuilder(); // the stack
        for (char c : s.toCharArray()) {
            if (c != '#') sb.append(c);          // push
            else if (sb.length() > 0) {
                sb.deleteCharAt(sb.length() - 1); // pop
            }
        }
        return sb.toString();
    }
}

    Time O(n + m) · Space O(n + m) — each character is pushed or popped once.

    Dry run

    "ab##": a → "a", b → "ab", # → "a", # → "". "c#d#": "c", "", "d", "". Equal → true.

    Watch out

    A # on an empty text does nothing; do not crash. The follow-up asks for O(1) space: walk both strings from the end with two pointers, counting pending backspaces to skip letters.

  • Medium155. Min Stack — a second stack of "min so far".
    Show solution

    The idea

    A stack with push, pop, top and getMin, all O(1). The trick: store, next to every value, the minimum of the stack at that moment. When you pop, the minimum below is still recorded with the new top, so nothing needs recomputing.

    Brute force first

    Scan the whole stack in getMin: O(n) per call.

    Step by step

    1. Each stack entry is a pair {value, minSoFar}.
    2. push(x): minSoFar = stack empty ? x : min(x, top's minSoFar).
    3. pop and top work on the pair's value; getMin returns the top's minSoFar.

    Java

    class MinStack {
    // each entry: {value, minimum at this depth}
    private final Deque<int[]> stack = new ArrayDeque<>();

    public void push(int val) {
        int min = stack.isEmpty()
            ? val : Math.min(val, stack.peek()[1]);
        stack.push(new int[]{val, min});
    }

    public void pop() { stack.pop(); }

    public int top() { return stack.peek()[0]; }

    public int getMin() { return stack.peek()[1]; }
}

    Time O(1) per call · Space O(n) — one extra number stored per element.

    Dry run

    push -2   [(-2,-2)]
push 0    [(-2,-2) (0,-2)]
push -3   [(-2,-2) (0,-2) (-3,-3)]   getMin -3
pop       [(-2,-2) (0,-2)]           top 0, getMin -2

    Watch out

    The version with a separate min stack must push to it on x <= min (not just <), or duplicate minimums break after a pop. Storing pairs avoids that trap.

  • Medium150. Evaluate Reverse Polish Notation — numbers wait, operators eat two.
    Show solution

    The idea

    Evaluate Reverse Polish Notation, where the operator comes after its two numbers: ["2","1","+","3","*"] means (2+1)×3 = 9. Numbers wait on a stack; an operator pops the top two, applies itself, and pushes the result.

    Step by step

    1. For each token: if it is + - * /, pop b (top) then a, push a op b.
    2. Otherwise push Integer.parseInt(token).
    3. The single number left on the stack is the answer.

    Java

    class Solution {
    public int evalRPN(String[] tokens) {
        Deque<Integer> st = new ArrayDeque<>();
        for (String t : tokens) {
            switch (t) {
                case "+" -> st.push(st.pop() + st.pop());
                case "*" -> st.push(st.pop() * st.pop());
                case "-" -> {
                    int b = st.pop(), a = st.pop();
                    st.push(a - b);
                }
                case "/" -> {
                    int b = st.pop(), a = st.pop();
                    st.push(a / b);   // truncates toward 0
                }
                default -> st.push(Integer.parseInt(t));
            }
        }
        return st.pop();
    }
}

    Time O(n) · Space O(n) — one push or pop per token.

    Dry run

    4 13 5 / +
push 4, 13, 5       [4,13,5]
/  13/5 = 2         [4,2]
+  4+2 = 6          [6]

    Watch out

    Order matters for - and /: the first pop is the right operand. "-11" is a number, not an operator, so compare whole tokens, not the first character.

  • Medium394. Decode String — push (count, text so far) on [, combine on ].
    Show solution

    The idea

    Expand k[text] into text repeated k times, with nesting: "3[a2[c]]" → "accaccacc". When you hit [, you must pause the outer work, decode the inner part, then come back: that is a stack. Push the count and the text built so far on [; on ], pop them and attach the repeated inner text.

    Step by step

    1. Keep cur (text being built) and num (digits being read; can be several digits).
    2. Digit: num = num*10 + d. Letter: append to cur.
    3. [: push num and cur; reset both.
    4. ]: pop k and prev; cur = prev + cur repeated k times.
    5. Return cur.

    Java

    class Solution {
    public String decodeString(String s) {
        Deque<Integer> counts = new ArrayDeque<>();
        Deque<StringBuilder> texts = new ArrayDeque<>();
        StringBuilder cur = new StringBuilder();
        int num = 0;
        for (char c : s.toCharArray()) {
            if (Character.isDigit(c)) {
                num = num * 10 + (c - '0');   // multi-digit
            } else if (c == '[') {
                counts.push(num);             // save state
                texts.push(cur);
                cur = new StringBuilder();
                num = 0;
            } else if (c == ']') {
                int k = counts.pop();
                StringBuilder prev = texts.pop();
                prev.append(cur.toString().repeat(k));
                cur = prev;           // back outside
            } else {
                cur.append(c);
            }
        }
        return cur.toString();
    }
}

    Time O(output length) · Space O(output length) — every output character is written a bounded number of times.

    Dry run

    "3[a2[c]]"
3 [   push (3,"")      cur=""
a     cur="a"
2 [   push (2,"a")     cur=""
c     cur="c"
]     pop (2,"a")      cur="a"+"cc"="acc"
]     pop (3,"")       cur="accaccacc"

    Watch out

    Counts can have several digits ("10[a]"), so build num digit by digit. Reset num to 0 after pushing it.

  • Medium735. Asteroid Collision — a left-mover fights the right-movers on top of the stack.
    Show solution

    The idea

    Positive asteroids move right, negative move left, same speed. When a right-mover meets a left-mover, the smaller explodes (both if equal). Only a left-mover arriving after right-movers can collide, and it hits the most recent right-mover first, so survivors go on a stack.

    Step by step

    1. For each asteroid a: assume it survives.
    2. While a < 0 and the stack top is positive: if top < −a, pop it and keep going; if top == −a, pop it and a dies too; if top > −a, a dies.
    3. If a survived, push it.
    4. The stack from bottom to top is the answer.

    Java

    class Solution {
    public int[] asteroidCollision(int[] asteroids) {
        Deque<Integer> st = new ArrayDeque<>();
        for (int a : asteroids) {
            boolean alive = true;
            while (alive && a < 0
                    && !st.isEmpty() && st.peek() > 0) {
                int top = st.peek();
                if (top < -a) {
                    st.pop();           // top explodes
                } else {
                    if (top == -a) st.pop(); // both explode
                    alive = false;      // a explodes
                }
            }
            if (alive) st.push(a);
        }
        int[] res = new int[st.size()];
        for (int i = res.length - 1; i >= 0; i--) {
            res[i] = st.pop();          // stack top = last
        }
        return res;
    }
}

    Time O(n) · Space O(n) — each asteroid is pushed and popped at most once.

    Dry run

    [10, 2, -5]
10 push       [10]
2  push       [10,2]
-5: 2 < 5 pop [10];  10 > 5 -> -5 dies
result [10]

    Watch out

    A left-mover with nothing (or only left-movers) below it never collides: [-2,-1,1,2] stays as is. Equal sizes destroy both.

  • Hard224. Basic Calculator — push (result, sign) when you enter a bracket.
    Show solution

    The idea

    Evaluate a string with +, -, brackets, spaces and unary minus, like "(1+(4+5+2)-3)+(6+8)" = 23. Without brackets you just keep a running result and the sign of the next number. A bracket starts a fresh sub-sum, so on ( push the current result and sign on a stack, and on ) combine: outer + sign × inner.

    Step by step

    1. result = 0, sign = 1, read multi-digit numbers into num.
    2. On + or -: add sign*num to result, reset num, set sign to +1 or −1.
    3. On (: push result, push sign; reset result = 0, sign = 1.
    4. On ): finish the inner number; then result = popped result + popped sign * result.
    5. At the end add the last sign*num.

    Java

    class Solution {
    public int calculate(String s) {
        Deque<Integer> st = new ArrayDeque<>();
        int result = 0, sign = 1, num = 0;
        for (char c : s.toCharArray()) {
            if (Character.isDigit(c)) {
                num = num * 10 + (c - '0');
            } else if (c == '+' || c == '-') {
                result += sign * num;        // close number
                num = 0;
                sign = (c == '+') ? 1 : -1;
            } else if (c == '(') {
                st.push(result);             // save outer
                st.push(sign);
                result = 0;
                sign = 1;
            } else if (c == ')') {
                result += sign * num;
                num = 0;
                int outerSign = st.pop();
                int outer = st.pop();
                result = outer + outerSign * result;
            }                                // spaces: skip
        }
        return result + sign * num;
    }
}

    Time O(n) · Space O(n) — one pass; the stack grows with bracket depth.

    Dry run

    "1-(2+3)"
1        num=1
-        result=1, sign=-1
(        push 1, push -1; result=0, sign=1
2 + 3    result=2, sign=1, num=3
)        result=5 -> 1 + (-1)*5 = -4

    Watch out

    Unary minus ("-(2+3)", "(-2)") needs no special case here: it simply adds 0 and sets sign = −1. Do not forget the last number after the loop.

Test yourself

What does the bracket checker return for "([)]", and at which character does it decide?

false, at the ): the top of the stack is [, which is not the partner of ).

Push 4, 8, 1 and pop once on a stack; offer 4, 8, 1 and poll once on a queue. What comes out?

The stack gives 1 (newest). The queue gives 4 (oldest).

Why does Min Stack store a minimum for every height instead of one variable?

Because after popping the current minimum you would need the minimum of what is left. Saving it per height means it is already there, so getMin stays O(1).

What is 2 1 + 3 * in RPN?

(2 + 1) * 3 = 9.
