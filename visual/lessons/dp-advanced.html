Advanced DP

Four DP shapes that show up in hard rounds: a few named states per day, a table filled by interval length, a set of visited nodes stored as bits, and a pair of answers returned from every tree node.

Time to learn: about 4 hours · Prerequisites: DP intro, Knapsack, Tree recursion, Bit tricks

When to use it — the signal

State machine: "buy and sell with a cooldown / a fee / at most k transactions" — each day you are in one of a few situations. Interval DP: "burst balloons", "merge stones", "cut a stick", "minimum cost to merge / split a range" — the answer for [l, r] is built from smaller ranges. Bitmask DP: n ≤ 16–20 and "visit all nodes", "assign every worker", "every subset" — store the visited set as bits. Tree DP: "no two adjacent nodes", "best path / cover in a tree" — each node returns a small tuple to its parent.

The idea in plain words

  • State-machine DP: name the situations. For stocks with cooldown: hold (I own a share), sold (I sold today, so tomorrow is a forced rest), rest (no share, free to buy). Each day, every state is the best of the arrows pointing into it. Three numbers per day, O(n) time, O(1) memory.
  • Interval DP: dp[l][r] = the best answer for the range between l and r. Fill short ranges first, then longer ones, because a long range is split at some k into two shorter ranges that are already solved. For burst balloons the trick is to pick k as the last balloon to burst in the range — then its neighbours at that moment are exactly l and r.
  • Bitmask DP: a set of up to 16 cities fits in one int — bit i is 1 when city i is visited ({0, 1, 3} = 1011₂ = 11). dp[mask][i] = cheapest way to visit exactly the cities in mask and stand at i. 2ⁿ · n states, each tried from n previous cities → O(2ⁿ · n²).
  • Tree DP: post-order (children first). Each node returns two numbers — best if I take this node, best if I skip it — and the parent combines them.
Analogy

State machine: a traffic light — at any moment it is red, amber or green, and only some changes are allowed. Interval DP: deciding the order to demolish a row of buildings by picking the one that falls last. Bitmask DP: a passport with one stamp slot per country — the set of stamps plus where you are now is all you need to plan the rest of the trip.

Watch it work

1. State machine — Best Time to Buy and Sell Stock with Cooldown

Prices [1, 2, 3, 0, 2]. Badges are each state's best profit so far. (Each state also has an arrow to itself — "keep holding" and "keep resting" — not drawn.)

2. Interval DP — Burst Balloons, filled by length

Balloons [3, 1, 5, 8], padded with a 1 at each end: b = [1, 3, 1, 5, 8, 1]. dp[l][r] = most coins from bursting everything strictly between l and r.

3. Bitmask DP — visit every city once (small travelling salesman)

4 cities, start and end at city 0. A column is the set of visited cities; a row is the city we stand at. Only sets that include city 0 matter.

4. Tree DP — House Robber III

Houses form a tree; you cannot rob a parent and its child on the same night. Every node returns r (best if I rob this house) and s (best if I skip it).

Why it works

"State machine: today's best in each state depends only on yesterday's three numbers, and every allowed move is one arrow." "Interval DP: if k is the last balloon in (l, r), the left part and the right part never touch each other, so they are independent smaller problems." "Bitmask: the future of the tour depends only on which cities are done and where I am, not on the order I visited them." "Tree DP: a node's choice only constrains its direct children, so two numbers per child are enough."

The template to remember

// Interval DP: by length, then left end, then split
for (len = 2; len < n; len++)
  for (l = 0; l + len < n; l++) { r = l + len;
    for (k = l + 1; k < r; k++) dp[l][r] = best(dp[l][k] ⊕ dp[k][r]); }
// Bitmask: bit i = "i is in the set"
in = (mask >> i & 1) == 1;  add = mask | 1 << i;  remove = mask ^ 1 << i;
// Tree DP: return a tuple
int[] dfs(node) { L = dfs(left); R = dfs(right); return combine(L, R); }
Remember

Name the states and draw the arrows. Intervals: fill by length, pick k as the last action. Small n + "all of them" → bitmask. Trees → return {take, skip}.

Common mistakes
  • Stock DP: updating hold first and then using the new hold for sold — compute all from yesterday's values (use temporaries).
  • Burst Balloons with k as the first balloon to burst — the neighbours then change and the halves are not independent.
  • Interval DP looping l then r from 0 — you read cells that are not filled yet. Loop by length.
  • Bitmask DP for n = 25 — 2²⁵ · 25 is too much. It is for n ≤ ~16–20.
  • House Robber III with memo on node + "can rob" boolean is fine, but the {rob, skip} pair is simpler and needs no map.

Test yourself

In the cooldown problem, why does rest come from yesterday's sold and not today's?

Selling today forces a rest tomorrow, so the sold state turns into rest one day later — that one-day delay is the cooldown.

Why do we pad the balloons with 1 at both ends?

A balloon at the edge has a missing neighbour that counts as 1. Padding makes every range (l, r) have real values at l and r.

How many states does the TSP bitmask DP have for n = 15?

2¹⁵ × 15 ≈ 491,000 states, each with up to 15 transitions — about 7 million steps, fine.

What does a null child return in House Robber III, and why?

{0, 0}: there is no house, so robbing or skipping it gives nothing.
