Advanced DP

Four DP shapes that show up in hard rounds: a few named states per day, a table filled by interval length, a set of visited nodes stored as bits, and a pair of answers returned from every tree node.

Time to learn: about 4 hours · Prerequisites: DP intro, Knapsack, Tree recursion, Bit tricks

When to use it — the signal

State machine: "buy and sell with a cooldown / a fee / at most k transactions" — each day you are in one of a few situations. Interval DP: "burst balloons", "merge stones", "cut a stick", "minimum cost to merge / split a range" — the answer for [l, r] is built from smaller ranges. Bitmask DP: n ≤ 16–20 and "visit all nodes", "assign every worker", "every subset" — store the visited set as bits. Tree DP: "no two adjacent nodes", "best path / cover in a tree" — each node returns a small tuple to its parent.

The idea in plain words

  • State-machine DP: name the situations. For stocks with cooldown: hold (I own a share), sold (I sold today, so tomorrow is a forced rest), rest (no share, free to buy). Each day, every state is the best of the arrows pointing into it. Three numbers per day, O(n) time, O(1) memory.
  • Interval DP: dp[l][r] = the best answer for the range between l and r. Fill short ranges first, then longer ones, because a long range is split at some k into two shorter ranges that are already solved. For burst balloons the trick is to pick k as the last balloon to burst in the range — then its neighbours at that moment are exactly l and r.
  • Bitmask DP: a set of up to 16 cities fits in one int — bit i is 1 when city i is visited ({0, 1, 3} = 1011₂ = 11). dp[mask][i] = cheapest way to visit exactly the cities in mask and stand at i. 2ⁿ · n states, each tried from n previous cities → O(2ⁿ · n²).
  • Tree DP: post-order (children first). Each node returns two numbers — best if I take this node, best if I skip it — and the parent combines them.
Analogy

State machine: a traffic light — at any moment it is red, amber or green, and only some changes are allowed. Interval DP: deciding the order to demolish a row of buildings by picking the one that falls last. Bitmask DP: a passport with one stamp slot per country — the set of stamps plus where you are now is all you need to plan the rest of the trip.

Watch it work

1. State machine — Best Time to Buy and Sell Stock with Cooldown

Prices [1, 2, 3, 0, 2]. Badges are each state's best profit so far. (Each state also has an arrow to itself — "keep holding" and "keep resting" — not drawn.)

2. Interval DP — Burst Balloons, filled by length

Balloons [3, 1, 5, 8], padded with a 1 at each end: b = [1, 3, 1, 5, 8, 1]. dp[l][r] = most coins from bursting everything strictly between l and r.

3. Bitmask DP — visit every city once (small travelling salesman)

4 cities, start and end at city 0. A column is the set of visited cities; a row is the city we stand at. Only sets that include city 0 matter.

4. Tree DP — House Robber III

Houses form a tree; you cannot rob a parent and its child on the same night. Every node returns r (best if I rob this house) and s (best if I skip it).

Why it works

"State machine: today's best in each state depends only on yesterday's three numbers, and every allowed move is one arrow." "Interval DP: if k is the last balloon in (l, r), the left part and the right part never touch each other, so they are independent smaller problems." "Bitmask: the future of the tour depends only on which cities are done and where I am, not on the order I visited them." "Tree DP: a node's choice only constrains its direct children, so two numbers per child are enough."

The template to remember

// Interval DP: by length, then left end, then split
for (len = 2; len < n; len++)
  for (l = 0; l + len < n; l++) { r = l + len;
    for (k = l + 1; k < r; k++) dp[l][r] = best(dp[l][k] ⊕ dp[k][r]); }
// Bitmask: bit i = "i is in the set"
in = (mask >> i & 1) == 1;  add = mask | 1 << i;  remove = mask ^ 1 << i;
// Tree DP: return a tuple
int[] dfs(node) { L = dfs(left); R = dfs(right); return combine(L, R); }
Remember

Name the states and draw the arrows. Intervals: fill by length, pick k as the last action. Small n + "all of them" → bitmask. Trees → return {take, skip}.

Common mistakes
  • Stock DP: updating hold first and then using the new hold for sold — compute all from yesterday's values (use temporaries).
  • Burst Balloons with k as the first balloon to burst — the neighbours then change and the halves are not independent.
  • Interval DP looping l then r from 0 — you read cells that are not filled yet. Loop by length.
  • Bitmask DP for n = 25 — 2²⁵ · 25 is too much. It is for n ≤ ~16–20.
  • House Robber III with memo on node + "can rob" boolean is fine, but the {rob, skip} pair is simpler and needs no map.

Practice in this order

  • Medium309. Stock with Cooldown — animation 1.
    Show solution

    The idea

    Buy and sell as often as you like, but after a sale you must skip one day. Each day you are in one of three states: hold (you own a share), sold (you sold today, so tomorrow is a cooldown) and rest (no share, free to buy). Each state's best profit today comes from yesterday's states. Pattern: state machine DP.

    Brute force first

    Try buy, sell or wait on every day with recursion: O(3ⁿ) without memo.

    Step by step

    1. Day 0: hold = −price, sold = 0, rest = 0.
    2. newHold = max(hold, rest − p): keep the share, or buy today (only from rest, never right after a sale).
    3. newSold = hold + p: sell today.
    4. newRest = max(rest, sold): stay free, or come out of cooldown.
    5. The answer is max(sold, rest), because you should not end holding a share.

    Java

    class Solution {
    public int maxProfit(int[] prices) {
        // profit at the end of today, in each state
        int hold = -prices[0]; // own a share
        int sold = 0;          // sold today -> cooldown next
        int rest = 0;          // free, may buy tomorrow
        for (int i = 1; i < prices.length; i++) {
            int p = prices[i];
            int newHold = Math.max(hold, rest - p); // keep / buy
            int newSold = hold + p;                 // sell today
            int newRest = Math.max(rest, sold);     // wait
            hold = newHold;
            sold = newSold;
            rest = newRest;
        }
        return Math.max(sold, rest); // end without a share
    }
}

    Time O(n) · Space O(1) — three numbers updated per day.

    Dry run

    prices   1    2    3    0    2
hold    -1   -1   -1    1    1
sold     0    1    2   -1    3
rest     0    0    1    2    2     answer max(3, 2) = 3

    Watch out

    Compute all three new values from the old ones (use temporaries). Buying from sold instead of rest breaks the cooldown.

  • Medium714. Stock with Transaction Fee — two states, pay fee on sell.
    Show solution

    The idea

    Unlimited trades, but each sale costs a fee. Two states per day: free (no share) and hold (own one). Selling moves hold → free and pays the fee. Buying moves free → hold. Pattern: state machine DP.

    Brute force first

    Recursion over buy, sell or wait each day: exponential without memo.

    Step by step

    1. hold = −prices[0], free = 0.
    2. Each day: newFree = max(free, hold + p − fee).
    3. newHold = max(hold, free − p).
    4. Return free.

    Java

    class Solution {
    public int maxProfit(int[] prices, int fee) {
        int hold = -prices[0]; // best profit while owning
        int free = 0;          // best profit with no share
        for (int i = 1; i < prices.length; i++) {
            int p = prices[i];
            int newFree = Math.max(free, hold + p - fee); // sell
            int newHold = Math.max(hold, free - p);       // buy
            free = newFree;
            hold = newHold;
        }
        return free;
    }
}

    Time O(n) · Space O(1) — two numbers per day.

    Dry run

    [1,3,2,8,4,9], fee 2. Buy at 1 and sell at 8 for 8 − 1 − 2 = 5, then buy at 4 and sell at 9 for 3. Total 8. The DP finds this: free ends at 8.

    Watch out

    Charge the fee only once per trade (on the sale here). Charging it on both buy and sell doubles it.

  • Medium337. House Robber III — animation 4.
    Show solution

    The idea

    Houses form a binary tree, and you cannot rob a house together with its direct parent or child. For every node, return two answers: the best total if this node is skipped, and the best total if it is robbed. If you rob it, both children must be skipped. If you skip it, each child takes its own better option. Pattern: tree DP returning a pair.

    Brute force first

    Plain recursion "rob me + grandchildren, or skip me + children" recomputes subtrees and becomes exponential without a memo.

    Step by step

    1. dfs(null) = {0, 0}.
    2. Get l = dfs(left) and r = dfs(right).
    3. rob = node.val + l.skip + r.skip.
    4. skip = max(l.skip, l.rob) + max(r.skip, r.rob).
    5. At the root, return max(skip, rob).

    Java

    class Solution {
    public int rob(TreeNode root) {
        int[] r = dfs(root);
        return Math.max(r[0], r[1]);
    }

    // {best if we skip node, best if we rob node}
    private int[] dfs(TreeNode node) {
        if (node == null) return new int[]{0, 0};
        int[] l = dfs(node.left), r = dfs(node.right);
        // rob: children must be skipped
        int rob = node.val + l[0] + r[0];
        // skip: each child is free to be robbed or not
        int skip = Math.max(l[0], l[1]) + Math.max(r[0], r[1]);
        return new int[]{skip, rob};
    }
}

    Time O(n) · Space O(h) — each node is visited once; the recursion depth is the tree height.

    Dry run

    [3,2,3,null,3,null,1]. Left child 2 gives {skip 3, rob 2}. Right child 3 gives {skip 1, rob 3}. Root: rob = 3 + 3 + 1 = 7, skip = 3 + 3 = 6. The answer is 7.

    Watch out

    "Skip" does not force the children to be robbed. Each child takes its own max. That is the common mistake.

  • Hard312. Burst Balloons — animation 2.
    Show solution

    The idea

    Bursting balloon i gives left · i · right coins from its current neighbours. The order changes the neighbours, so pick the last balloon to burst in a range instead of the first. If k is the last one burst between walls l and r, its neighbours at that moment are exactly l and r, and the two sides are independent. Pattern: interval DP.

    Brute force first

    Try every burst order: O(n!).

    Step by step

    1. Pad the array with 1 at both ends, so v has n + 2 values.
    2. dp[l][r] = best coins from bursting everything strictly between l and r.
    3. For lengths from small to large, and each k strictly between l and r: v[l]·v[k]·v[r] + dp[l][k] + dp[k][r].
    4. Keep the max. The answer is dp[0][n+1].

    Java

    class Solution {
    public int maxCoins(int[] nums) {
        int n = nums.length;
        // pad with 1 on both sides
        int[] v = new int[n + 2];
        v[0] = v[n + 1] = 1;
        for (int i = 0; i < n; i++) v[i + 1] = nums[i];
        // dp[l][r] = best coins bursting all between l and r
        // (l and r themselves stay)
        int[][] dp = new int[n + 2][n + 2];
        for (int len = 2; len <= n + 1; len++) {
            for (int l = 0; l + len <= n + 1; l++) {
                int r = l + len;
                for (int k = l + 1; k < r; k++) {
                    // k is the LAST balloon burst in (l, r)
                    int coins = v[l] * v[k] * v[r]
                              + dp[l][k] + dp[k][r];
                    dp[l][r] = Math.max(dp[l][r], coins);
                }
            }
        }
        return dp[0][n + 1];
    }
}

    Time O(n³) · Space O(n²) — n² intervals, each trying up to n split points.

    Dry run

    [1,5] padded to 1,1,5,1. If 5 is last: 1·5·1 + dp(burst 1 first) = 5 + 1·1·5 = 10. If 1 is last: 1·1·1 + 1·5·1 = 6. The best is 10.

    Watch out

    Thinking "which balloon goes first" fails, because the neighbours then depend on what remains. Fill shorter intervals before longer ones.

  • Hard1547. Minimum Cost to Cut a Stick — same interval shape, k = first cut.
    Show solution

    The idea

    Cutting a stick costs its current length. Choose the cut order that makes the total smallest. Add the ends 0 and n to the sorted cuts. For the piece between positions i and j, choose the first cut k inside it: that cut costs pos[j] − pos[i] and splits the piece into two independent pieces. Pattern: interval DP (the same shape as Burst Balloons).

    Brute force first

    Try every cut order: O(m!).

    Step by step

    1. Sort the cuts and build pos = [0, cuts…, n].
    2. dp[i][j] = min cost for all cuts strictly between pos[i] and pos[j]. Neighbours (j = i + 1) cost 0.
    3. For each length and each k between i and j: pos[j] − pos[i] + dp[i][k] + dp[k][j].
    4. Return dp[0][m+1].

    Java

    class Solution {
    public int minCost(int n, int[] cuts) {
        int m = cuts.length;
        // positions: 0, sorted cuts, n
        int[] pos = new int[m + 2];
        Arrays.sort(cuts);
        for (int i = 0; i < m; i++) pos[i + 1] = cuts[i];
        pos[m + 1] = n;
        // dp[i][j] = min cost to make every cut strictly
        // between pos[i] and pos[j]
        int[][] dp = new int[m + 2][m + 2];
        for (int len = 2; len <= m + 1; len++) {
            for (int i = 0; i + len <= m + 1; i++) {
                int j = i + len;
                dp[i][j] = Integer.MAX_VALUE;
                for (int k = i + 1; k < j; k++) {
                    // k is the FIRST cut; it costs the length
                    int cost = pos[j] - pos[i]
                             + dp[i][k] + dp[k][j];
                    dp[i][j] = Math.min(dp[i][j], cost);
                }
            }
        }
        return dp[0][m + 1];
    }
}

    Time O(m³) · Space O(m²) — m = number of cuts, not n.

    Dry run

    n = 7, cuts [1,3,4,5]. The best order is 3, 5, 1, 4: 7 + 4 + 3 + 2 = 16.

    Watch out

    Build the DP over the cut indices, not over stick positions 0..n (n can be 10⁶). Sort the cuts first.

  • Hard847. Shortest Path Visiting All Nodes — BFS over (node, mask).
    Show solution

    The idea

    Find the shortest walk that visits every node, where you may start anywhere and reuse edges. Plain BFS on nodes is not enough, because the same node can be "fresh" with different sets of visited nodes. So BFS over the state (node, mask), where mask is a bitmask of the visited nodes (bit i set = node i seen). n ≤ 12, so there are at most 12 · 4096 states. Pattern: BFS over bitmask states.

    Brute force first

    Try every order of nodes with shortest paths between them: O(n! · n).

    Step by step

    1. Push (i, 1 << i) for every node i: a multi-source start.
    2. BFS level by level and count steps.
    3. Pop (node, mask). If mask == full (all bits set), return steps.
    4. For each neighbour, newMask = mask | (1 << next). If (next, newMask) is unseen, mark it and push it.

    Java

    class Solution {
    public int shortestPathLength(int[][] graph) {
        int n = graph.length, full = (1 << n) - 1;
        // state = (node, mask of visited nodes)
        boolean[][] seen = new boolean[n][1 << n];
        Deque<int[]> q = new ArrayDeque<>();
        for (int i = 0; i < n; i++) { // start anywhere
            q.offer(new int[]{i, 1 << i});
            seen[i][1 << i] = true;
        }
        int steps = 0;
        while (!q.isEmpty()) {
            for (int size = q.size(); size > 0; size--) {
                int[] cur = q.poll();
                int node = cur[0], mask = cur[1];
                if (mask == full) return steps;
                for (int next : graph[node]) {
                    int nm = mask | (1 << next);
                    if (!seen[next][nm]) {
                        seen[next][nm] = true;
                        q.offer(new int[]{next, nm});
                    }
                }
            }
            steps++;
        }
        return -1; // graph is connected, so never reached
    }
}

    Time O(2ⁿ · n²) · Space O(2ⁿ · n) — each state is seen once, and has up to n edges.

    Dry run

    A star with centre 0 and leaves 1,2,3. Start at 1: 1→0→2→0→3 is 4 steps, and the state mask goes 0010, 0011, 0111, 0111, 1111. The answer is 4.

    Watch out

    Mark states as seen when you push them, not when you pop them, or the queue blows up. A single node gives 0.

  • Hard968. Binary Tree Cameras — tree DP with three states.
    Show solution

    The idea

    Place the fewest cameras so every node is watched. A camera covers itself, its parent and its children. Go bottom-up (post-order: children before parent). Each node reports one of three states: 0 not covered, 1 has a camera, 2 covered. Greedy: never put a camera on a leaf; put it on the leaf's parent, which also covers the grandparent. Pattern: tree DP with three states.

    Brute force first

    Try camera or no camera on every node: O(2ⁿ).

    Step by step

    1. A null child returns 2 (covered), so leaves see "covered" children.
    2. If either child is 0 (uncovered), this node must hold a camera: count it and return 1.
    3. Else if either child is 1, this node is covered: return 2.
    4. Else both children are covered but nothing watches this node: return 0 and let the parent handle it.
    5. After the DFS, if the root returned 0, add one more camera.

    Java

    class Solution {
    // 0 = not covered, 1 = has a camera, 2 = covered
    private int cameras = 0;

    public int minCameraCover(TreeNode root) {
        // a root left uncovered needs its own camera
        if (dfs(root) == 0) cameras++;
        return cameras;
    }

    private int dfs(TreeNode node) {
        if (node == null) return 2; // null needs nothing
        int l = dfs(node.left), r = dfs(node.right);
        if (l == 0 || r == 0) { // a child is uncovered
            cameras++;
            return 1;
        }
        if (l == 1 || r == 1) return 2; // a child watches me
        return 0; // let my parent cover me
    }
}

    Time O(n) · Space O(h) — one post-order pass.

    Dry run

    [0,0,null,0,0]: the root has one child, and that child has two leaves. The leaves return 0, so the middle node gets a camera and returns 1. The root sees 1 and returns 2. Total 1.

    Watch out

    Forgetting the final root check gives a wrong answer for a single node (the answer is 1, not 0).

  • Hard188. Stock IV — states hold/free for each of k transactions.
    Show solution

    The idea

    At most k transactions. Keep two values for each transaction number j: hold[j] = best profit while holding the share bought in the j-th buy, and free[j] = best profit after completing j sales. Buy j uses the money from j − 1 sales. Pattern: state machine DP over k transactions.

    Brute force first

    Recursion over (day, transactions left, holding?): the same DP but with a memo table, O(n · k) states.

    Step by step

    1. hold[1..k] = −∞ (impossible yet), free[0..k] = 0.
    2. For each price p, for j = 1..k:
    3. hold[j] = max(hold[j], free[j−1] − p) (buy).
    4. free[j] = max(free[j], hold[j] + p) (sell).
    5. Return free[k].

    Java

    class Solution {
    public int maxProfit(int k, int[] prices) {
        // hold[j] = best profit owning a share in buy #j
        // free[j] = best profit after j full transactions
        int[] hold = new int[k + 1];
        int[] free = new int[k + 1];
        Arrays.fill(hold, Integer.MIN_VALUE / 2);
        for (int p : prices) {
            for (int j = 1; j <= k; j++) {
                // buy #j uses the profit from j-1 sales
                hold[j] = Math.max(hold[j], free[j - 1] - p);
                free[j] = Math.max(free[j], hold[j] + p);
            }
        }
        return free[k];
    }
}

    Time O(n · k) · Space O(k) — k states updated each day.

    Dry run

    k = 2, [3,2,6,5,0,3]. Buy at 2 and sell at 6 for +4, then buy at 0 and sell at 3 for +3. free[2] ends at 7.

    Watch out

    Use MIN_VALUE / 2 for "impossible" so that adding a price does not overflow. If k ≥ n/2, the limit no longer matters (that is unlimited trading), which is a common speed-up.

Test yourself

In the cooldown problem, why does rest come from yesterday's sold and not today's?

Selling today forces a rest tomorrow, so the sold state turns into rest one day later — that one-day delay is the cooldown.

Why do we pad the balloons with 1 at both ends?

A balloon at the edge has a missing neighbour that counts as 1. Padding makes every range (l, r) have real values at l and r.

How many states does the TSP bitmask DP have for n = 15?

2¹⁵ × 15 ≈ 491,000 states, each with up to 15 transitions — about 7 million steps, fine.

What does a null child return in House Robber III, and why?

{0, 0}: there is no house, so robbing or skipping it gives nothing.
