String and StringBuilder

A Java String is an array of characters that can never change. Every "change" builds a brand new string by copying. That is why s += c in a loop is secretly O(n²), and why StringBuilder, a growable char array you are allowed to change, exists.

Time to learn: about 1.5 hours · Prerequisites: Array & ArrayList, Big-O

Use it when you need…
  • String: a fixed piece of text to read, compare, hash, use as a map key: charAt O(1), length O(1), hashCode cached;
  • StringBuilder: to build text piece by piece: append amortized O(1), setLength O(1) to undo in backtracking, reverse O(n);
  • char[]: to edit text in place: swap, overwrite, sort letters, two pointers.

In plain words

When you write String s = "cat"; Java creates an object holding the letters c, a, t in a private array, and s points at it. Nobody can ever change those letters: the array is private and no method writes to it. Methods like toUpperCase, replace, substring and + all return a new String and leave the old one alone.

Why make it unchangeable (immutable)? Because then a String can be shared freely: many variables, many threads and many HashMap keys can point at the same object with no risk that someone edits it underneath them. Its hash code can be computed once and cached. And identical string literals in your code can share one object in the string pool.

The price: building a string by repeated + copies everything built so far, every single time. StringBuilder keeps a char array with spare room at the end, so adding a character usually just writes one slot.

Analogy

A String is a printed page: to fix one word you must reprint the whole page. A StringBuilder is a whiteboard with empty space on the right: you just keep writing. When the board is full you fetch one about twice as big and copy everything over once, which happens rarely. The string pool is a shared photocopy shelf: everyone who asks for the same printed text gets the same sheet.

What it looks like in memory

A variable never holds the text itself, only a reference (an arrow) to a String object. The object holds the characters and a cached hash. Literals written in your code live in the string pool; new String(...) always makes a separate object.

Watch the operations

1. Immutability: "changing" a string makes a new object

Two variables share one String. Then one of them is "changed" with +=. Watch what really happens to the arrows.

2. The string pool, == and equals

== on objects asks "same object?" (same arrow). equals asks "same characters?". The pool makes == work by accident for literals, which is exactly why people get burnt by it.

3. Why s += c in a loop is O(n²)

Build "abcdef" one character at a time. Each += creates a new string and copies all the characters so far. Count the copies.

4. StringBuilder growth: double + 2

new StringBuilder(4), then append 11 letters. When the buffer is full Java allocates 2 × capacity + 2 and copies once, the same amortized trick as ArrayList.

5. char[] trick: edit in place, convert once

Strings cannot be edited, so for "reverse", "swap", "sort the letters" convert once to a char[], work in place with two pointers, and build one String at the end.

Build it yourself

Interviewers sometimes ask "how does StringBuilder work?" or "implement a dynamic string buffer". The core is a char array, a length and a growth rule. Tested against java.util.StringBuilder with 90,000 random operations; the capacities match Java's exactly (16, 34, 70, 142, 286).

import java.util.Arrays;

// A growable char buffer, the core of StringBuilder.
class MyStringBuilder {
    private char[] buf = new char[class="n">16];   // Java's default
    private int len = class="n">0;                 // chars in use

    MyStringBuilder append(char c) {
        ensure(len + class="n">1);
        buf[len++] = c;
        return this;                 // chaining
    }

    MyStringBuilder append(String s) {
        ensure(len + s.length());
        s.getChars(class="n">0, s.length(), buf, len);  // bulk copy
        len += s.length();
        return this;
    }

    // Grow like Java: double + 2, or more if needed.
    private void ensure(int need) {
        if (need <= buf.length) return;
        int cap = Math.max(buf.length * class="n">2 + class="n">2, need);
        buf = Arrays.copyOf(buf, cap);
    }

    int length() { return len; }
    char charAt(int i) { return buf[i]; }
    void setCharAt(int i, char c) { buf[i] = c; }

    void setLength(int n) {          // n <= len: cut the end
        len = n;                 // O(1): backtracking undo
    }

    MyStringBuilder reverse() {
        for (int i = class="n">0, j = len - class="n">1; i < j; i++, j--) {
            char t = buf[i]; buf[i] = buf[j]; buf[j] = t;
        }
        return this;
    }

    int capacity() { return buf.length; }

    @Override public String toString() {
        return new String(buf, class="n">0, len);   // one copy
    }
}

The two char tricks used everywhere, tested too:

class CharTricks {
    // reverse: String -> char[] -> swap -> String
    static String reverse(String s) {
        char[] c = s.toCharArray();      // one copy, O(n)
        for (int i = class="n">0, j = c.length - class="n">1; i < j; i++, j--) {
            char t = c[i]; c[i] = c[j]; c[j] = t;
        }
        return new String(c);            // one more copy
    }

    // anagram: count letters in an int[26]
    static boolean isAnagram(String a, String b) {
        if (a.length() != b.length()) return false;
        int[] cnt = new int[class="n">26];
        for (int i = class="n">0; i < a.length(); i++) {
            cnt[a.charAt(i) - 'a']++;     // 'c' - 'a' = 2
            cnt[b.charAt(i) - 'a']--;
        }
        for (int x : cnt) if (x != class="n">0) return false;
        return true;
    }
}

The real Java classes

  • String fields (Java 9+): private final byte[] value, byte coder (LATIN1 = 1 byte per char, UTF16 = 2 bytes per char), int hash (cached, 0 until first used) and boolean hashIsZero. This is "compact strings" (JEP 254): plain English text uses half the memory of Java 8, which stored a char[]. The class is final, so nobody can subclass it and break immutability.
  • hashCode = s[0]·31^(n−1) + … + s[n−1], computed on first call and cached. That makes Strings fast HashMap keys.
  • String pool: literals and compile-time constants are interned automatically. It lives in the normal heap since Java 7 (it used to be in PermGen) and is garbage collected. intern() adds or finds a string in it.
  • Concatenation: a + b + c in one expression is compiled (Java 9+) to a single invokedynamic call (StringConcatFactory) that sizes the result once; before Java 9 it became new StringBuilder().append(a).append(b).append(c).toString(). Either way, one expression is fine; the problem is += inside a loop, where each iteration copies everything again. The compiler does not fix that for you.
  • substring (since Java 7u6) copies the characters: O(k) time and memory for a k-char result. Before that it shared the parent's array in O(1), which caused memory leaks (a tiny substring kept a huge array alive). So s.substring(i) inside a loop over i is O(n²).
  • StringBuilder extends AbstractStringBuilder: byte[] value (also compact), coder, int count. Default capacity 16; new StringBuilder(str) starts at str.length() + 16. Growth: 2 × old + 2, or the needed size if bigger. It never shrinks (trimToSize() if you care).
  • StringBuffer is the same thing with every method synchronized: the legacy thread-safe version. Like Vector and Stack, do not use it in new code.
  • Other costs: equals checks the reference, then the length, then compares bytes (vectorized). compareTo is lexicographic. toCharArray, split, toUpperCase, replace, trim and strip all return new objects (O(n)). String.join, repeat (Java 11) and text blocks (Java 15) exist.

Why and when to use it

  • String for keys, comparisons, read-only scanning (charAt in a loop is fine and allocates nothing).
  • StringBuilder whenever you build output piece by piece: joining results, building paths in DFS / backtracking (append, recurse, setLength back), decoding strings, "remove adjacent duplicates" (use it as a stack of chars).
  • char[] when you edit by index: reverse, swap, in-place compression, sorting letters for an anagram key (Arrays.sort(c); new String(c)).
  • int[26] / int[128] instead of a HashMap<Character, Integer> for letter counts: O(1) with no boxing. c - 'a' turns a letter into an index.

When not to use it

  • Do not use += on a String inside a loop: StringBuilder.
  • Do not use == to compare text: equals (or Objects.equals(a, b) if either can be null; "abc".equals(s) is null-safe).
  • Do not call substring repeatedly to "move forward" in a string: keep an index into the original instead (O(1) per step).
  • Do not use StringBuffer or new String("literal"): legacy synchronized class and a pointless extra object.
  • Do not keep passwords in a String: it stays in memory until garbage collected and cannot be wiped. Use a char[] and overwrite it.
  • Many prefix queries over many words: a trie beats repeated startsWith.

Used in these patterns

  • Strings & palindromes and Two pointers: charAt from both ends, char[] reversal.
  • Sliding window and Arrays & hashing: int[26] / int[128] counts, anagram keys.
  • Backtracking and Permutations: StringBuilder append, recurse, setLength to undo.
  • Stack basics: StringBuilder as a char stack (remove duplicates, decode string).
  • Trie: building words character by character.
  • LCS & edit distance: charAt lookups into a DP table, rebuilding the answer with StringBuilder.
Remember

String is immutable: every change is a new object and a full copy. Compare with equals, never ==. += in a loop is O(n²): use StringBuilder (amortized O(1) append, capacity 2×+2). substring copies, O(k). Need to edit by index? toCharArray(), work, new String(c).

Common mistakes
  • if (s == "yes"): works in a quick test with literals (pooled), fails with input read at run time. Use "yes".equals(s).
  • s.replace('a', 'b'); on its own line does nothing: the result is thrown away. Write s = s.replace(...).
  • sb.append(c + 1) where c is a char appends a number (char + int = int). Use (char) (c + 1).
  • "" + a + b with chars a, b gives text, but a + b + "" first adds their codes as ints. Order matters.
  • sb.toString() inside a loop just to check something: each call copies O(n). Check sb.charAt / sb.length instead.
  • Comparing a StringBuilder with equals: StringBuilder does not override it (reference check). Use sb.toString().equals(...) or sb.compareTo(other) == 0 (Java 11+).
  • s.split(".") or split("|"): split takes a regex, so these split on every character. Escape: split("\\.").

Interview questions on the internals

Why is String immutable in Java?

Safe sharing (pool, threads, method arguments) with no defensive copies, a hash code that can be cached so Strings are fast map keys, and security (a checked file name or URL cannot be changed after the check). The class is final and its array private and never written after construction.

What is the string pool?

A table of unique String objects in the heap. Literals and compile-time constants are added automatically, so equal literals share one object. intern() returns the pooled copy of any string. It is garbage collected since Java 7.

How many objects does new String("hi") create?

Up to two: the "hi" literal in the pool (if not already there, created when the class loads) plus one new String in the heap every time the line runs. That is why it is pointless.

== vs equals for Strings?

== compares references (same object). equals compares the characters. Literals often share a pooled object so == may look right in tests, but strings built at run time are different objects.

Why is s += c in a loop O(n²), and does the compiler fix it?

Each += creates a new string and copies all existing characters: 1 + 2 + … + n = O(n²). The compiler optimizes a single expression (StringBuilder or invokedynamic), but it creates a fresh builder per iteration, so the copy of the whole string still happens every time. Use one StringBuilder outside the loop.

How does StringBuilder grow, and what does append cost?

Default capacity 16; when full, new capacity = 2 × old + 2 (or the needed size if bigger), then one array copy. Geometric growth makes append amortized O(1).

What does substring cost?

O(k) for a k-char result: it copies the characters (since Java 7u6). Older Java shared the original array in O(1) but leaked memory. So avoid substring in tight loops; pass indexes instead.

StringBuilder vs StringBuffer?

Same API; StringBuffer has synchronized methods (thread-safe, slower). In single-threaded code, which is almost always, use StringBuilder.

How does Java store "hello" in memory since Java 9?

Compact strings: a byte[] plus a coder flag. If every char fits in Latin-1 it uses one byte per char, otherwise UTF-16 with two bytes per char. Java 8 always used a char[] (two bytes per char).

Why prefer char[] for a password?

A String cannot be wiped and may stay in memory (or the pool) until garbage collected, visible in a heap dump. A char[] can be overwritten with zeros right after use.
