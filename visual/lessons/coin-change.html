Coin Change

For every amount from 0 up to the target, work out the answer once — using the answers for smaller amounts you already have.

Time to learn: about 2 hours · Prerequisites: DP intro

When to use it — the signal

You have a set of item sizes you may use any number of times (coins, stamps, square numbers, words) and a target total. "Fewest coins to make amount", "number of ways to make amount", "can it be made at all". This is the unbounded knapsack family.

The idea in plain words

Coins [1, 2, 5], amount 7. Greedy ("take the biggest coin first") happens to work here, but not always: with coins [1, 3, 4] and amount 6, greedy takes 4+1+1 (3 coins) while 3+3 needs only 2. So we must try every option — cleverly.

Think about the last coin you put down. If it was a 2, then the rest was the best way to make 7 − 2 = 5. So:

dp[a] = 1 + min(dp[a − 1], dp[a − 2], dp[a − 5]) — "fewest coins for amount a".

  • dp[0] = 0: making 0 needs no coins.
  • Fill a = 1, 2, 3 … 7 in order; every cell only looks at smaller amounts, already filled.
  • An amount that cannot be made stays at "infinity" (we use amount + 1), and the answer becomes −1.

Counting ways (Coin Change II) is the same table with + instead of min — but the order of the two loops decides whether you count combinations (1+2 and 2+1 are the same) or orderings (they are different).

Analogy

A shop assistant who keeps a cheat sheet: "fewest coins for 1 cent, 2 cents, 3 cents…". To give 7 cents, they look at three lines of the sheet — 6, 5 and 2 cents — add one coin to the best one, and write the 7-cent line down for next time.

Watch it work

1. Fewest coins

Coins [1, 2, 5], amount 7. The labels under the table point at the cells each new cell depends on (amount minus each coin); the green one is the winner.

2. Number of ways — coins in the outer loop

Coins [1, 2, 5], amount 5. dp[a] = number of ways to make a. We process one coin type at a time: after the pass for coin 1, dp counts ways using only 1s; after coin 2, ways using 1s and 2s; and so on.

3. Why loop order matters — the wrong order counts orderings

Swap the loops (amount outside, coins inside) and you count sequences: 1+2 and 2+1 become two different ways. Coins [1, 2], amount 3: the right answer is 2 (1+1+1, 1+2), but this order gives 3.

Why it works

"Every way to make amount a ends with some last coin c, and what comes before it is a way to make a − c. Since a − c < a, filling amounts in increasing order means those answers are ready. For counting, putting coins in the outer loop fixes the order in which coin types appear, so each combination is counted exactly once."

The template to remember

// fewest items: min over the last item
for (int a = 1; a <= T; a++) for (int c : coins)
    if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
// count combinations: coins OUTSIDE
for (int c : coins) for (int a = c; a <= T; a++) dp[a] += dp[a - c];
// count orderings: amount OUTSIDE
for (int a = 1; a <= T; a++) for (int c : coins) if (c <= a) dp[a] += dp[a - c];
Remember

Last coin → look back by each coin. Min coins: any loop order. Count ways: coins outside = combinations, amount outside = orderings.

Common mistakes
  • Using Integer.MAX_VALUE as infinity and then adding 1 — it overflows to a negative number. Use amount + 1.
  • Forgetting to return −1 when the amount cannot be made (coins [2], amount 3).
  • dp[0] = 0 in the counting version — it must be 1, or every count stays 0.
  • Trying greedy (biggest coin first): fails for coins [1, 3, 4], amount 6.

  • Medium322. Coin Change — the first animation.
    Show solution

    The idea

    Fewest coins (unlimited of each kind) that add up to amount, or −1. coins = [1,2,5], amount = 11 → 5+5+1 = 3 coins. Whatever the best answer for a is, its last coin c leaves a − c, which must itself be made the best way: dp[a] = min over c of dp[a-c] + 1. Pattern: unbounded knapsack / 1-D DP over amounts.

    Brute force first

    Greedy "biggest coin first" fails (coins [1,3,4], amount 6: greedy 4+1+1 = 3, best 3+3 = 2). Plain recursion over every coin choice is exponential.

    Step by step

    1. dp[0] = 0; every other entry starts at amount + 1, meaning "impossible".
    2. For a = 1..amount, for each coin c ≤ a: dp[a] = min(dp[a], dp[a-c] + 1).
    3. If dp[amount] is still amount + 1, return −1, else return it.

    Java

    class Solution {
    public int coinChange(int[] coins, int amount) {
        // dp[a] = fewest coins that make amount a
        int INF = amount + 1; // "impossible" marker
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, INF);
        dp[0] = 0;                     // 0 coins make 0
        for (int a = 1; a <= amount; a++) {
            for (int c : coins) {
                if (c <= a) {          // c is the last coin
                    dp[a] = Math.min(dp[a], dp[a - c] + 1);
                }
            }
        }
        return dp[amount] == INF ? -1 : dp[amount];
    }
}

    Time O(amount · coins) · Space O(amount) — every amount tries every coin once.

    Dry run

    coins [1,2,5]: dp0=0, dp1=1, dp2=1, dp3=2, dp4=2, dp5=1, dp6=2, dp7=2, dp8=3, dp9=3, dp10=2, dp11=min(dp10, dp9, dp6)+1 = 3.

    Watch out

    Use amount + 1 as "infinity", not Integer.MAX_VALUE: MAX_VALUE + 1 overflows to a negative number and wins every min. amount = 0 needs 0 coins.

  • Medium518. Coin Change II — the second animation, coins outside.
    Show solution

    The idea

    Count the coin sets that make amount (1+2 and 2+1 are the same set). amount 5, coins [1,2,5] → 4. Put the coin loop outside: first count everything using only coin 1, then allow coin 2, and so on. Each set is then built in one fixed coin order, so it is counted once. Pattern: unbounded knapsack, counting combinations.

    Step by step

    1. dp[0] = 1 (one way to make 0: no coins).
    2. For each coin c (outer loop):
    3. for a = c..amount (inner loop, going up so c can be reused): dp[a] += dp[a-c].
    4. Return dp[amount].

    Java

    class Solution {
    public int change(int amount, int[] coins) {
        // dp[a] = number of coin SETS that make a
        int[] dp = new int[amount + 1];
        dp[0] = 1;                     // one way: no coins
        for (int c : coins) {          // coins OUTSIDE
            for (int a = c; a <= amount; a++) {
                dp[a] += dp[a - c];    // add one more c
            }
        }
        return dp[amount];
    }
}

    Time O(amount · coins) · Space O(amount) — one pass over the amounts per coin.

    Dry run

    After coin 1: dp = [1,1,1,1,1,1]. After coin 2: [1,1,2,2,3,3]. After coin 5: dp5 = 3 + dp0 = 4. Answer 4.

    Watch out

    Swapping the loops (amount outside) counts orderings instead, which is problem 377. Going upward in a is what allows a coin many times.

  • Medium377. Combination Sum IV — the third animation is correct here: orders count.
    Show solution

    The idea

    Count ordered sequences of numbers (repeats allowed) that sum to target; (1,2) and (2,1) both count. [1,2,3], target 4 → 7. The last number of a sequence can be any x, leaving t − x: dp[t] = sum of dp[t-x]. Put the amount loop outside so every order is counted. Pattern: 1-D DP counting permutations.

    Step by step

    1. dp[0] = 1 (the empty sequence).
    2. For t = 1..target (outer loop):
    3. for each x in nums (inner loop) with x ≤ t: dp[t] += dp[t-x].
    4. Return dp[target].

    Java

    class Solution {
    public int combinationSum4(int[] nums, int target) {
        // dp[t] = number of ORDERED sequences summing to t
        int[] dp = new int[target + 1];
        dp[0] = 1;                     // the empty sequence
        for (int t = 1; t <= target; t++) { // amount OUTSIDE
            for (int x : nums) {             // last number
                if (x <= t) dp[t] += dp[t - x];
            }
        }
        return dp[target];
    }
}

    Time O(target · n) · Space O(target) — each amount sums over every number.

    Dry run

    nums [1,2,3]: dp0=1, dp1=1, dp2=dp1+dp0=2, dp3=dp2+dp1+dp0=4, dp4=dp3+dp2+dp1=7.

    Watch out

    Some unreachable middle values can exceed int during the sums; Java wraps silently and the final answer (guaranteed to fit) still comes out right because only additions are used.

  • Medium279. Perfect Squares — coins are 1, 4, 9, 16…
    Show solution

    The idea

    Fewest perfect squares that sum to n. 12 = 4+4+4 → 3. It is Coin Change where the coins are 1, 4, 9, 16… up to n: dp[a] = min over j of dp[a - j²] + 1. Pattern: unbounded knapsack / min coins.

    Step by step

    1. dp[0] = 0.
    2. For a = 1..n start with dp[a] = a (all ones).
    3. For every j with j² ≤ a: dp[a] = min(dp[a], dp[a - j*j] + 1).
    4. Return dp[n].

    Java

    class Solution {
    public int numSquares(int n) {
        // dp[a] = fewest perfect squares summing to a
        int[] dp = new int[n + 1];
        for (int a = 1; a <= n; a++) {
            dp[a] = a; // worst case: 1+1+...+1
            for (int j = 1; j * j <= a; j++) {
                // last "coin" is j*j
                dp[a] = Math.min(dp[a], dp[a - j * j] + 1);
            }
        }
        return dp[n];
    }
}

    Time O(n √n) · Space O(n) — each amount tries about √a squares.

    Dry run

    n = 13: dp4 = 1, dp9 = 1, dp13 = min(dp12+1, dp9+1, dp4+1) = min(4, 2, 2) = 2 (9 + 4).

    Watch out

    Greedy "largest square first" fails: 12 → 9+1+1+1 = 4 squares, but 4+4+4 = 3. (A maths shortcut, Lagrange's four-square theorem, says the answer is always ≤ 4.)

  • Medium139. Word Break — "coins" are dictionary words that end at position i.
    Show solution

    The idea

    Can the string be cut into dictionary words? "leetcode" with ["leet","code"] → yes. ok[i] = the first i letters can be cut. The last word ends at i and starts at some j, so ok[i] is true if ok[j] is true and s[j..i) is a word. The words act like "coins" that end at i. Pattern: 1-D DP over prefixes.

    Brute force first

    Recursively try every first word and recurse on the rest: exponential on inputs like "aaaa…ab".

    Step by step

    1. Put the words in a HashSet.
    2. ok[0] = true (empty prefix).
    3. For each end i, try each start j < i: if ok[j] and the slice is a word, set ok[i] = true and stop.
    4. Return ok[n].

    Java

    class Solution {
    public boolean wordBreak(String s,
                             List<String> wordDict) {
        Set<String> dict = new HashSet<>(wordDict);
        int n = s.length();
        // ok[i] = the first i letters split into words
        boolean[] ok = new boolean[n + 1];
        ok[0] = true;                  // empty prefix
        for (int i = 1; i <= n; i++) {
            for (int j = 0; j < i; j++) {
                // s[j..i) is the last word, s[0..j) splits
                String last = s.substring(j, i);
                if (ok[j] && dict.contains(last)) {
                    ok[i] = true;
                    break;
                }
            }
        }
        return ok[n];
    }
}

    Time O(n3) · Space O(n) — n2 (i, j) pairs, each substring costs up to O(n) (n ≤ 300).

    Dry run

    "leetcode": ok0 = T; ok4 = T ("leet"); ok8: j = 4, ok4 is T and "code" is a word → T.

    Watch out

    "catsandog": cats+and leaves "og", cat+sand leaves "og": false. Only try j where ok[j] is true; that is the whole speed-up.

  • Medium983. Minimum Cost For Tickets — last ticket was 1, 7 or 30 days.
    Show solution

    The idea

    Buy 1-day, 7-day or 30-day passes to cover all travel days as cheaply as possible. dp[d] = cheapest cover for every trip up to day d. On a non-travel day nothing new is needed: dp[d] = dp[d-1]. On a travel day, the last pass bought covers d and was 1, 7 or 30 days long. Pattern: 1-D DP over days, "what was the last choice".

    Step by step

    1. Mark travel days in a boolean array up to the last travel day.
    2. dp[0] = 0.
    3. For each day d: if not travelling, copy dp[d−1].
    4. Else dp[d] = min(dp[d-1] + c1, dp[max(0,d-7)] + c7, dp[max(0,d-30)] + c30).
    5. Return dp[lastDay].

    Java

    class Solution {
    public int mincostTickets(int[] days, int[] costs) {
        int last = days[days.length - 1];
        boolean[] travel = new boolean[last + 1];
        for (int d : days) travel[d] = true;
        // dp[d] = cheapest cover for all trips on days 1..d
        int[] dp = new int[last + 1];
        for (int d = 1; d <= last; d++) {
            if (!travel[d]) { // no trip: costs nothing
                dp[d] = dp[d - 1];
                continue;
            }
            // the last ticket bought covers day d
            int one = dp[d - 1] + costs[0];
            int week = dp[Math.max(0, d - 7)] + costs[1];
            int month = dp[Math.max(0, d - 30)] + costs[2];
            dp[d] = Math.min(one, Math.min(week, month));
        }
        return dp[last];
    }
}

    Time O(D) · Space O(D) — D is the last travel day (≤ 365).

    Dry run

    days [1,4,6,7,8,20], costs [2,7,15]: dp1=2, dp4=4, dp6=6, dp7=min(8, dp0+7)=7, dp8=min(9, dp1+7=9, 15)=9, dp20=min(11, dp13+7=16, 15)=11.

    Watch out

    Clamp with max(0, d-7): early in the year a 7-day pass reaches back before day 1. A week pass can be cheaper than one day pass, so always compare all three.

Test yourself

Coins [2], amount 3 — what does the table hold at the end?

dp = [0, ∞, 1, ∞]. dp[3] is still "infinity" (4), so the answer is −1.

Why does the inner loop in Coin Change II start at a = c?

An amount smaller than the coin cannot end with that coin, and a − c would be negative.

Is the loop order important for the min-coins version?

No. A minimum does not care about order — both loop orders give the same result. Order only matters when counting.
