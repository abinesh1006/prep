Minimum Spanning Tree (Kruskal and Prim)

Connect every node with the cheapest total cable: Kruskal takes the cheapest edges first and skips any that would close a loop; Prim grows one tree, always adding the cheapest edge leaving it.

Time to learn: about 2 hours · Prerequisites: Union-Find, Heap, Greedy

When to use it — the signal

"Connect all points / cities / houses with the minimum total cost", "minimum cable / road / pipe", "cheapest network". Every node must be reachable, nobody cares about any single path's length — only the sum.

The idea in plain words

6 villages, 9 possible roads, each with a building cost. You want every village connected (directly or through others) for the lowest total cost. The answer is always a tree: exactly 5 roads for 6 villages (n − 1), because a 6th road would make a loop, and a loop always has one road you could remove and stay connected. A tree that touches every node is a spanning tree; the cheapest one is the MST.

Kruskal (greedy on edges): sort the roads by cost. Walk the list from cheapest; build a road only if its two villages are not yet connected — Union-Find answers that in O(1). Stop after n − 1 roads. Time O(E log E) for the sort.

Prim (greedy on nodes): start with one village. Repeatedly add the cheapest road from "inside" to an "outside" village. With a heap that is O(E log V); for a complete graph (every pair of points can be joined, as in LC 1584) a simple array version is O(n²) and is fastest.

Analogy

Kruskal is a shopper with a price-sorted catalogue who buys the cheapest useful item each time and skips items they effectively already own. Prim is a spreading town: every year it builds the single cheapest road from the town's edge to a new village.

Watch it work

1. Kruskal. Edges sorted by cost along the top. Green = built, red = skipped because it would close a loop. The badge on each village is its Union-Find leader (same leader = already connected).

2. Prim on Min Cost to Connect All Points. Points [0,0] [2,2] [3,10] [5,2] [7,0]; cost of joining two points = |x1 − x2| + |y1 − y2| (Manhattan distance). Every pair can be joined, so instead of a heap we keep best[i] = cheapest known link from the tree to point i. Blue lines are those best links (candidates); green ones are built.

Why it works

"The cut property: for any split of the nodes into two sides, the cheapest edge crossing the split belongs to some MST. Kruskal's next non-loop edge and Prim's cheapest edge leaving the tree are both such cheapest crossing edges, so the greedy choice is always safe."

The template to remember

// Kruskal: edge list, sparse graphs
sort(edges by w);
for (e : edges) if (uf.union(e.a, e.b)) { total += e.w; if (++used == n - 1) break; }
// Prim (heap): adjacency list
pq.add({0, start});
while (!pq.isEmpty()) {
    {w, u} = pq.poll(); if (in[u]) continue;
    in[u] = true; total += w;
    for (edge u -> v, c) if (!in[v]) pq.add({c, v});
}

Kruskal is "sort, then union-find"; Prim is "grow one tree, always take the cheapest way out". Which structure wins depends on density, which is why 1584 drops the heap.

Remember

Kruskal = sort edges + Union-Find, skip loops, stop at n − 1. Prim = grow one tree by the cheapest outgoing edge. Complete graph → array Prim O(n²).

Common mistakes
  • Confusing MST with shortest paths — MST minimises the total, not the distance from one source (that is Dijkstra).
  • For LC 1584, building all n² edges and sorting them for Kruskal — works, but array Prim is simpler and faster.
  • Prim with a heap: forgetting if (in[u]) continue; — the same node is added twice and the total is too big.
  • Not checking that the graph is connected (used < n − 1 at the end means no spanning tree exists → often return −1).

Practice in this order

  • Medium1584. Min Cost to Connect All Points — exactly animation 2.
    Show solution

    The idea

    Connect all points with the least total wire, where joining two points costs their Manhattan distance |x1 − x2| + |y1 − y2|. That is a minimum spanning tree (MST: the cheapest set of edges that connects every node with no loops). Every pair of points can be joined, so the graph is complete (about n² edges). Key insight: for such a dense graph, array Prim is the cleanest: grow one tree, and keep best[i] = cheapest link from the tree to point i.

    Brute force first

    Kruskal: build all n²/2 edges, sort them, and union. Correct, but O(n² log n) time and O(n²) memory.

    Step by step

    1. best = ∞ for all points, best[0] = 0 (start the tree at point 0).
    2. Repeat n times: pick the point u outside the tree with the smallest best.
    3. Add u to the tree and add best[u] to the total.
    4. For every point v still outside, set best[v] = min(best[v], dist(u, v)).
    5. Return the total.

    Java

    class Solution {
    public int minCostConnectPoints(int[][] points) {
        int n = points.length;
        // best[i] = cheapest known link from the tree to i
        int[] best = new int[n];
        Arrays.fill(best, Integer.MAX_VALUE);
        boolean[] inTree = new boolean[n];
        best[0] = 0;                   // start the tree at 0
        int total = 0;
        for (int added = 0; added < n; added++) {
            // 1. cheapest point still outside the tree
            int u = -1;
            for (int i = 0; i < n; i++) {
                if (!inTree[i] && (u == -1 || best[i] < best[u])) {
                    u = i;
                }
            }
            inTree[u] = true;          // 2. build that link
            total += best[u];
            // 3. u may offer cheaper links to the others
            for (int v = 0; v < n; v++) {
                if (inTree[v]) continue;
                int d = Math.abs(points[u][0] - points[v][0])
                      + Math.abs(points[u][1] - points[v][1]);
                best[v] = Math.min(best[v], d);
            }
        }
        return total;
    }
}

    Time O(n²) · Space O(n) — n rounds, each scanning all points twice; no edge list is stored.

    Dry run

    Points [0,0] [2,2] [3,10] [5,2] [7,0]. Take [0,0]. Cheapest next: [2,2] (4). Then [5,2] (3 from [2,2]). Then [7,0] (4 from [5,2]). Then [3,10] (9 from [2,2]). Total 4 + 3 + 4 + 9 = 20.

    Watch out

    Skip points already in the tree when picking the next one and when updating best. One point alone costs 0. With the heap version of Prim, ignore popped points that are already in the tree.

  • Medium1135. Connecting Cities With Minimum Cost — plain Kruskal; −1 if not connected.
    Show solution

    The idea

    Cities 1..n and possible roads [a, b, cost]. Connect all cities with minimum total cost, or −1 if impossible. Key insight: this is a plain MST, and Kruskal is the natural fit for an edge list. Sort roads by cost and take each one that joins two not-yet-connected groups; Union-Find answers "already connected?". If fewer than n − 1 roads get built, the cities cannot all be connected.

    Step by step

    1. Sort the connections by cost.
    2. Make a Union-Find for cities 1..n.
    3. For each road, if union(a, b) succeeds, add its cost and count it.
    4. Once n − 1 roads are built, return the total.
    5. If the loop ends first, return −1 (unless n is 1).

    Java

    class Solution {
    private int[] parent;

    public int minimumCost(int n, int[][] connections) {
        parent = new int[n + 1];       // cities are 1..n
        for (int i = 0; i <= n; i++) parent[i] = i;
        // cheapest roads first
        Arrays.sort(connections,
                Comparator.comparingInt(c -> c[2]));
        int total = 0, built = 0;
        for (int[] c : connections) {
            if (union(c[0], c[1])) {   // joins two groups
                total += c[2];
                if (++built == n - 1) return total; // done
            }
        }
        return n == 1 ? 0 : -1;        // not all connected
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;    // would close a loop
        parent[ra] = rb;
        return true;
    }
}

    Time O(E log E) · Space O(n) — sorting the roads dominates; the unions are nearly O(1).

    Dry run

    n = 3, roads [1,2,5], [1,3,6], [2,3,1]. Sorted: (2,3,1), (1,2,5), (1,3,6). Take 2–3 (1). Take 1–2 (5), 2 built = n − 1 → return 6.

    Watch out

    A tree on n nodes has exactly n − 1 edges; counting built edges is how you detect a disconnected graph. Cities are 1-indexed, so the parent array needs n + 1 slots.

  • Medium1319. Number of Operations to Make Network Connected — Union-Find: count spare edges vs components.
    Show solution

    The idea

    n computers, some cables. You may unplug any cable and plug it between two other computers. Find the fewest moves to connect everything, or −1. Key insight: first, n computers need at least n − 1 cables, otherwise −1. If there are enough, cables that sit inside a group are spare, and each move joins two groups. So the answer is number of components − 1, counted with Union-Find.

    Step by step

    1. If connections.length < n − 1, return −1.
    2. Start with components = n.
    3. For each cable, if union merges two groups, subtract 1.
    4. Return components − 1.

    Java

    class Solution {
    private int[] parent;

    public int makeConnected(int n, int[][] connections) {
        // n computers need at least n - 1 cables
        if (connections.length < n - 1) return -1;
        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        int components = n;
        for (int[] c : connections) {
            if (union(c[0], c[1])) components--;
        }
        // one moved cable joins two components
        return components - 1;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        parent[ra] = rb;
        return true;
    }
}

    Time O(n + E·α(n)) · Space O(n) — one union per cable.

    Dry run

    n = 6, cables 0–1, 0–2, 0–3, 1–2, 1–3 (5 cables ≥ 5, enough). Groups after unions: {0,1,2,3}, {4}, {5} → 3 components. Answer 2. Two cables (1–2, 1–3) were spare.

    Watch out

    Do the "enough cables" check first; with enough cables, the spare ones are guaranteed to be at least components − 1, so you never need to count them.

  • Hard1168. Optimize Water Distribution in a Village — add a virtual node 0 for wells, then Kruskal.
    Show solution

    The idea

    Each house can either build its own well (cost wells[i−1]) or get water through pipes from another house. Find the minimum total cost so every house has water. Key insight: add a virtual node 0, "the water source". Building a well at house i is just an edge 0 – i with cost wells[i−1]. Now every house must be connected to node 0, which is an ordinary MST over n + 1 nodes. Solve it with Kruskal.

    Step by step

    1. Make edges (0, i, wells[i−1]) for every house, and add all pipes.
    2. Sort all edges by cost.
    3. Union-Find over nodes 0..n. Take each edge that joins two groups and add its cost.
    4. Stop after n edges (n + 1 nodes need n edges).

    Java

    class Solution {
    private int[] parent;

    public int minCostToSupplyWater(int n, int[] wells,
                                    int[][] pipes) {
        // node 0 = "the water source"; a well at house i
        // is just a pipe 0 -> i that costs wells[i - 1]
        List<int[]> edges = new ArrayList<>();
        for (int i = 1; i <= n; i++) {
            edges.add(new int[]{0, i, wells[i - 1]});
        }
        edges.addAll(Arrays.asList(pipes));
        edges.sort(Comparator.comparingInt(e -> e[2]));
        parent = new int[n + 1];
        for (int i = 0; i <= n; i++) parent[i] = i;
        int total = 0, built = 0;
        for (int[] e : edges) {
            if (union(e[0], e[1])) {
                total += e[2];
                if (++built == n) break; // n + 1 nodes joined
            }
        }
        return total;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        parent[ra] = rb;
        return true;
    }
}

    Time O((n + P) log(n + P)) · Space O(n + P) — P pipes; sorting the combined edge list dominates.

    Dry run

    n = 3, wells [1,2,2], pipes 1–2 (1), 2–3 (1). Edges sorted: 0–1 (1), 1–2 (1), 2–3 (1), 0–2 (2), 0–3 (2). Take the first three: total 3 (one well at house 1, pipes to 2 and 3).

    Watch out

    Without the virtual node, you would have to decide separately which houses get wells, which is much harder. Pipes may repeat between the same two houses with different costs; Kruskal just skips the dearer one.

  • Hard1489. Critical and Pseudo-Critical Edges in MST — rerun Kruskal without / forcing each edge.
    Show solution

    The idea

    An edge is critical if removing it makes every MST more expensive (or impossible), and pseudo-critical if it is in some MST but not all. Return both lists of original edge indices. Key insight: n ≤ 100 and E ≤ 200, so it is fine to rerun Kruskal for each edge. Without edge i, a higher MST cost means it is critical. Otherwise, forcing edge i into the tree first and still getting the best cost means it is pseudo-critical.

    Step by step

    1. Copy the edges with their original index, then sort by weight.
    2. Compute best = normal Kruskal MST cost.
    3. For each edge i: run Kruskal skipping i. If the cost is greater than best (or the graph is disconnected), i is critical.
    4. Else run Kruskal with i built first. If the cost equals best, i is pseudo-critical.
    5. Return [critical, pseudo].

    Java

    class Solution {
    public List<List<Integer>> findCriticalAndPseudoCriticalEdges(
            int n, int[][] edges) {
        int m = edges.length;
        // copy as {u, v, weight, original index}
        int[][] es = new int[m][];
        for (int i = 0; i < m; i++) {
            es[i] = new int[]{edges[i][0], edges[i][1],
                              edges[i][2], i};
        }
        Arrays.sort(es, Comparator.comparingInt(e -> e[2]));
        int best = mst(n, es, -1, -1);
        List<Integer> critical = new ArrayList<>();
        List<Integer> pseudo = new ArrayList<>();
        for (int i = 0; i < m; i++) {
            if (mst(n, es, i, -1) > best) {
                critical.add(es[i][3]);  // worse without it
            } else if (mst(n, es, -1, i) == best) {
                pseudo.add(es[i][3]);    // some MST can use it
            }
        }
        return List.of(critical, pseudo);
    }

    // Kruskal that skips edge `skip` and builds edge `force`
    // first (-1 = none). MAX_VALUE if it cannot connect all.
    private int mst(int n, int[][] es, int skip, int force) {
        int[] parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        int total = 0, built = 0;
        if (force != -1) {
            union(parent, es[force][0], es[force][1]);
            total += es[force][2];
            built++;
        }
        for (int i = 0; i < es.length; i++) {
            if (i == skip) continue;
            if (union(parent, es[i][0], es[i][1])) {
                total += es[i][2];
                built++;
            }
        }
        return built == n - 1 ? total : Integer.MAX_VALUE;
    }

    private int find(int[] parent, int x) {
        if (parent[x] != x) parent[x] = find(parent, parent[x]);
        return parent[x];
    }

    private boolean union(int[] parent, int a, int b) {
        int ra = find(parent, a), rb = find(parent, b);
        if (ra == rb) return false;
        parent[ra] = rb;
        return true;
    }
}

    Time O(E² · α(n)) · Space O(n + E) — up to 2 Kruskal runs per edge on the already sorted list (plus one sort, O(E log E)).

    Dry run

    4 nodes, a square with all weights 1. best = 3. Skipping any edge still gives 3, so none is critical. Forcing any edge still gives 3, so all four are pseudo-critical: [[], [0,1,2,3]].

    Watch out

    Sorting loses the original order, so store the index in the copy. Disconnected must count as "worse" (here MAX_VALUE). Check critical first: a critical edge would also pass the forcing test, but must not be listed as pseudo-critical.

Test yourself

How many edges does an MST of n nodes have, and why?

n − 1. It must connect all n nodes (at least n − 1 edges) and has no loop (at most n − 1 edges).

In Kruskal, what tells you an edge would form a loop?

Its two endpoints already have the same Union-Find root, i.e. union returns false.

When is Prim preferable to Kruskal?

On dense graphs, especially complete ones like "connect all points": array Prim is O(n²) with no sorting and no edge list.
