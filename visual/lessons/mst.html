Minimum Spanning Tree (Kruskal and Prim)

Connect every node with the cheapest total cable: Kruskal takes the cheapest edges first and skips any that would close a loop; Prim grows one tree, always adding the cheapest edge leaving it.

Time to learn: about 2 hours · Prerequisites: Union-Find, Heap, Greedy

When to use it — the signal

"Connect all points / cities / houses with the minimum total cost", "minimum cable / road / pipe", "cheapest network". Every node must be reachable, nobody cares about any single path's length — only the sum.

The idea in plain words

6 villages, 9 possible roads, each with a building cost. You want every village connected (directly or through others) for the lowest total cost. The answer is always a tree: exactly 5 roads for 6 villages (n − 1), because a 6th road would make a loop, and a loop always has one road you could remove and stay connected. A tree that touches every node is a spanning tree; the cheapest one is the MST.

Kruskal (greedy on edges): sort the roads by cost. Walk the list from cheapest; build a road only if its two villages are not yet connected — Union-Find answers that in O(1). Stop after n − 1 roads. Time O(E log E) for the sort.

Prim (greedy on nodes): start with one village. Repeatedly add the cheapest road from "inside" to an "outside" village. With a heap that is O(E log V); for a complete graph (every pair of points can be joined, as in LC 1584) a simple array version is O(n²) and is fastest.

Analogy

Kruskal is a shopper with a price-sorted catalogue who buys the cheapest useful item each time and skips items they effectively already own. Prim is a spreading town: every year it builds the single cheapest road from the town's edge to a new village.

Watch it work

Why it works

"The cut property: for any split of the nodes into two sides, the cheapest edge crossing the split belongs to some MST. Kruskal's next non-loop edge and Prim's cheapest edge leaving the tree are both such cheapest crossing edges, so the greedy choice is always safe."

The template to remember

// Kruskal: edge list, sparse graphs
sort(edges by w);
for (e : edges) if (uf.union(e.a, e.b)) { total += e.w; if (++used == n - 1) break; }
// Prim (heap): adjacency list
pq.add({0, start});
while (!pq.isEmpty()) {
    {w, u} = pq.poll(); if (in[u]) continue;
    in[u] = true; total += w;
    for (edge u -> v, c) if (!in[v]) pq.add({c, v});
}
Remember

Kruskal = sort edges + Union-Find, skip loops, stop at n − 1. Prim = grow one tree by the cheapest outgoing edge. Complete graph → array Prim O(n²).

Common mistakes
  • Confusing MST with shortest paths — MST minimises the total, not the distance from one source (that is Dijkstra).
  • For LC 1584, building all n² edges and sorting them for Kruskal — works, but array Prim is simpler and faster.
  • Prim with a heap: forgetting if (in[u]) continue; — the same node is added twice and the total is too big.
  • Not checking that the graph is connected (used < n − 1 at the end means no spanning tree exists → often return −1).

Test yourself

How many edges does an MST of n nodes have, and why?

n − 1. It must connect all n nodes (at least n − 1 edges) and has no loop (at most n − 1 edges).

In Kruskal, what tells you an edge would form a loop?

Its two endpoints already have the same Union-Find root, i.e. union returns false.

When is Prim preferable to Kruskal?

On dense graphs, especially complete ones like "connect all points": array Prim is O(n²) with no sorting and no edge list.
