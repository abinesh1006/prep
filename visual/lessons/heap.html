Heaps

A heap always knows its smallest (or largest) item, lets you remove it, and accepts new items — each in O(log n) — using a tree that secretly lives in a plain array.

Time to learn: about 2 hours · Prerequisites: Big-O, Stacks and queues

When to use it — the signal

"Repeatedly take the smallest / largest", "k largest", "k closest", "merge k sorted", "schedule the next task", "median of a stream", "cheapest next step" (Dijkstra). If you would sort again and again after every insert, you want a heap.

The idea in plain words

A min-heap is a binary tree with one rule: every parent is ≤ its children. So the smallest value is always at the root. It does not keep everything sorted — only "parent beats children" — and that weaker rule is why it is fast.

The tree is always complete (filled level by level, left to right), so it fits in an array with no gaps:

  • children of index i are at 2i + 1 and 2i + 2
  • parent of index i is at (i − 1) / 2
  • example: index 1's children are 3 and 4; index 4's parent is (4 − 1) / 2 = 1

Insert (sift-up): put the new value at the end of the array, then while it is smaller than its parent, swap them. It climbs at most the height of the tree, about log₂ n levels — 20 swaps for a million items.

Poll / remove the min (sift-down): take the root, move the last value into the root, then while it is bigger than its smaller child, swap with that child. Again at most log₂ n steps.

In Java: PriorityQueue<Integer> is a min-heap. For a max-heap, pass Collections.reverseOrder().

Analogy

A company org chart where every boss is more senior than the people under them. A new hire joins at the bottom; if they are more senior than their boss, they swap places, and keep climbing until their boss outranks them. When the CEO leaves, the newest bottom person temporarily takes the seat and gets demoted step by step until everyone below is junior to them.

Watch it work

Insert 5, 3, 8, 1, 4, 2 into an empty min-heap. Watch the tree and the array — they are the same data, drawn two ways.

Poll: remove the minimum with sift-down

Starting from the heap we just built, [1, 3, 2, 5, 4, 8], poll twice.

Why it works

"A heap only promises that every parent is smaller than its children, so the root is the minimum. Insert and poll each repair that promise along one root-to-leaf path, and a complete tree has height log n, so both are O(log n); peek is O(1)."

The template to remember

PriorityQueue<Integer> minH = new PriorityQueue<>();
PriorityQueue<Integer> maxH = new PriorityQueue<>(Collections.reverseOrder());
PriorityQueue<int[]> byDist = new PriorityQueue<>((a, b) -> a[0] - b[0]);
minH.offer(x);      // O(log n)  sift-up
minH.peek();        // O(1)      the smallest
minH.poll();        // O(log n)  sift-down
// array view: kids 2i+1, 2i+2   parent (i-1)/2
Remember

Insert at the end and bubble up; remove the root, put the last in its place, sink down. Kids 2i+1, 2i+2 — parent (i−1)/2.

Common mistakes
  • Thinking a heap is sorted. Only the root is guaranteed; iterating a PriorityQueue does not give sorted order.
  • Sift-down swapping with the left child instead of the smaller child — the rule breaks one level up.
  • Comparator (a, b) -> a - b can overflow for huge values; use Integer.compare(a, b).
  • pq.remove(x) of an arbitrary element is O(n), not O(log n).
  • Building a heap from n items with n offers is O(n log n); new PriorityQueue<>(list) heapifies in O(n).

  • Easy1046. Last Stone Weight — max-heap, poll two, offer the difference.
    Show solution

    The idea

    Each turn, smash the two heaviest stones: equal weights both vanish, otherwise the difference goes back. Return the last stone's weight, or 0. "Give me the biggest, again and again, while new items arrive" is exactly what a max-heap does (a tree-shaped structure where the top is always the largest; insert and remove cost O(log n)).

    Brute force first

    Sort the array every turn and take the last two: O(n² log n).

    Step by step

    1. Put all stones in a max-heap (PriorityQueue with Collections.reverseOrder()).
    2. While at least two stones remain: poll y (heaviest) and x.
    3. If y != x, offer y - x.
    4. Return the remaining stone or 0.

    Java

    class Solution {
    public int lastStoneWeight(int[] stones) {
        PriorityQueue<Integer> heap =
            new PriorityQueue<>(Collections.reverseOrder());
        for (int s : stones) heap.offer(s);
        while (heap.size() > 1) {
            int y = heap.poll();      // heaviest
            int x = heap.poll();      // second heaviest
            if (y != x) heap.offer(y - x);
        }
        return heap.isEmpty() ? 0 : heap.peek();
    }
}

    Time O(n log n) · Space O(n) — at most n smashes, each a few heap operations.

    Dry run

    {8,7,4,2,1,1}
8,7 -> 1     {4,2,1,1,1}
4,2 -> 2     {2,1,1,1}
2,1 -> 1     {1,1,1}
1,1 -> gone  {1}   -> 1

    Watch out

    Java's PriorityQueue is a min-heap by default; pass Collections.reverseOrder() for a max-heap. Return 0 when everything is destroyed.

  • Easy703. Kth Largest Element in a Stream — size-k min-heap.
    Show solution

    The idea

    A class that is given a stream of numbers and after every add returns the k-th largest so far. Keep only the k largest numbers in a min-heap of size k. The smallest of those k (the heap's top) is exactly the k-th largest. When the heap grows past k, poll the top, since it can never be the answer again.

    Brute force first

    Keep all numbers in a list and sort on every add: O(n log n) per call.

    Step by step

    1. Store k and a min-heap.
    2. Constructor: add each starting number.
    3. add(val): offer val; if size > k, poll; return peek().

    Java

    class KthLargest {
    private final int k;
    // min-heap of the k largest seen; top = k-th largest
    private final PriorityQueue<Integer> heap =
        new PriorityQueue<>();

    public KthLargest(int k, int[] nums) {
        this.k = k;
        for (int x : nums) add(x);
    }

    public int add(int val) {
        heap.offer(val);
        if (heap.size() > k) heap.poll(); // drop smallest
        return heap.peek();
    }
}

    Time O(log k) per add · Space O(k) — the heap never holds more than k+1 numbers.

    Dry run

    k=3, nums 4 5 8 2   heap {4,5,8}  (2 was dropped)
add 3   {3,4,5,8} -> drop 3   top 4
add 5   {4,5,5,8} -> drop 4   top 5
add 10  drop 5 -> {5,8,10}    top 5
add 9   drop 5 -> {8,9,10}    top 8

    Watch out

    The starting array can be shorter than k (even empty), so do not peek before the heap has k items; LeetCode guarantees k items exist whenever an answer is asked. Using a max-heap here is the common mix-up: the k-th largest needs a min-heap.

  • Medium973. K Closest Points to Origin — max-heap by distance, size k.
    Show solution

    The idea

    Return the k points closest to the origin (0, 0), in any order. Keep the k best seen so far in a max-heap by distance: the top is the farthest of the kept points, so when a closer point arrives and the heap grows past k, poll the top. Compare squared distances x² + y²; the square root does not change the order.

    Brute force first

    Sort all points by distance and take the first k: O(n log n).

    Step by step

    1. Max-heap with comparator "bigger distance first".
    2. For each point: offer it; if size > k, poll (removes the farthest).
    3. The heap now holds the k closest; return them as an array.

    Java

    class Solution {
    public int[][] kClosest(int[][] points, int k) {
        // max-heap by distance: top = farthest kept
        PriorityQueue<int[]> heap = new PriorityQueue<>(
            (a, b) -> Integer.compare(dist(b), dist(a)));
        for (int[] p : points) {
            heap.offer(p);
            if (heap.size() > k) {
                heap.poll();           // drop farthest
            }
        }
        return heap.toArray(new int[0][]);
    }

    private int dist(int[] p) {
        // squared distance; sqrt keeps the same order
        return p[0] * p[0] + p[1] * p[1];
    }
}

    Time O(n log k) · Space O(k) — each point costs one heap operation on a heap of size k.

    Dry run

    [[3,3],[5,-1],[-2,4]], k=2    dist 18, 26, 20
add 18        {18}
add 26        {26,18}
add 20        {26,20,18} -> drop 26
answer [3,3] and [-2,4]

    Watch out

    The comparator must be reversed (dist(b) vs dist(a)) for a max-heap. Quickselect gives O(n) average time if the interviewer asks for better than O(n log k).

  • Medium621. Task Scheduler — max-heap of counts plus a cooldown queue.
    Show solution

    The idea

    Tasks are letters; the same letter needs at least n time units between runs; one task or idle per unit. Find the fewest units. Greedy: at each step run the task with the most remaining copies that is not cooling down. A max-heap of counts picks it, and a queue holds tasks waiting out their cooldown with the time they become ready.

    Step by step

    1. Count each letter; push every count into a max-heap.
    2. Each time unit t++: if the heap has a task, poll it, decrease the count, and if copies remain add (count, t + n) to the cooldown queue.
    3. If the queue's front is ready (readyAt == t), move it back into the heap.
    4. Stop when both heap and queue are empty; return t.

    Java

    class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] count = new int[26];
        for (char c : tasks) count[c - 'A']++;
        PriorityQueue<Integer> heap =
            new PriorityQueue<>(Collections.reverseOrder());
        for (int c : count) if (c > 0) heap.offer(c);

        // cooling tasks: {remainingCount, readyAtTime}
        Deque<int[]> cooling = new ArrayDeque<>();
        int time = 0;
        while (!heap.isEmpty() || !cooling.isEmpty()) {
            time++;
            if (!heap.isEmpty()) {
                int left = heap.poll() - 1; // run one
                if (left > 0) {
                    cooling.offer(
                        new int[]{left, time + n});
                }
            }                                 // else: idle
            if (!cooling.isEmpty()
                    && cooling.peek()[1] == time) {
                heap.offer(cooling.poll()[0]); // ready
            }
        }
        return time;
    }
}

    Time O(total time) · Space O(26) — at most 26 distinct counts, so each heap step is effectively constant.

    Dry run

    AAABBB, n=2     heap {3,3}
t1 run A   cooling A(2 left, ready after t3)
t2 run B   cooling B(2 left, ready after t4)
t3 idle    A back in heap
t4 run A   B back in heap
t5 run B   t6 idle   t7 run A   t8 run B  -> 8

    Watch out

    Move a task back into the heap only when its ready time has arrived, and check that after running this unit's task. The answer counts idle units too, so return elapsed time, not the number of tasks. The other well-known answer is a formula: if the top count is max and c letters share it, the result is max(tasks.length, (max-1)(n+1) + c), in O(n).

  • Medium912. Sort an Array — write heapsort with your own sift-down.
    Show solution

    The idea

    Sort an array in O(n log n) without built-in sort. Heapsort: first rearrange the array into a max-heap in place (each index i has children 2i+1 and 2i+2, and every parent ≥ its children). Then repeatedly swap the top (the largest) to the end, shrink the heap by one, and sift down the new top to repair the heap.

    Brute force first

    Bubble or insertion sort: O(n²), which times out on n = 50 000.

    Step by step

    1. Build: for i from n/2 - 1 down to 0, sift down i (leaves are already heaps).
    2. For end from n−1 down to 1: swap a[0] with a[end], then sift down 0 within size end.
    3. Sift down(i, size): while i has a child, pick the bigger child; if it beats a[i], swap and move to it, else stop.

    Java

    class Solution {
    public int[] sortArray(int[] a) {
        int n = a.length;
        // 1. build a max-heap, bottom-up
        for (int i = n / 2 - 1; i >= 0; i--) {
            siftDown(a, i, n);
        }
        // 2. move the max to the end, repair, repeat
        for (int end = n - 1; end > 0; end--) {
            swap(a, 0, end);
            siftDown(a, 0, end);   // heap is a[0..end-1]
        }
        return a;
    }

    private void siftDown(int[] a, int i, int size) {
        while (2 * i + 1 < size) {
            int child = 2 * i + 1;        // left
            if (child + 1 < size
                    && a[child + 1] > a[child]) {
                child++;                  // right is bigger
            }
            if (a[i] >= a[child]) break;  // heap ok
            swap(a, i, child);
            i = child;
        }
    }

    private void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}

    Time O(n log n) · Space O(1) — building is O(n), then n sift-downs of O(log n), all inside the array.

    Dry run

    [5,2,3,1]  build: already a max-heap (5 on top)
swap 5 to end  [1,2,3 | 5]  sift 1 -> [3,2,1 | 5]
swap 3 to end  [1,2 | 3,5]  sift 1 -> [2,1 | 3,5]
swap 2 to end  [1 | 2,3,5]  -> [1,2,3,5]

    Watch out

    Check the right child exists (child + 1 < size) before comparing it. After the swap, sift down only inside the shrunken heap (size = end), or the sorted tail gets pulled back in. Heapsort is not stable.

  • Hard23. Merge k Sorted Lists — heap holds the head of each list.
    Show solution

    The idea

    Merge k sorted linked lists into one. The next output node is always the smallest among the current fronts of the k lists. A min-heap holding one node per list hands you that smallest front in O(log k); after you take a node, push its next so that list stays represented.

    Brute force first

    Merge lists one by one into the result: O(k·N) for N total nodes. Or dump all values, sort, and rebuild: O(N log N).

    Step by step

    1. Min-heap of nodes ordered by val; offer every non-null head.
    2. dummy head and tail pointer.
    3. Poll the smallest, append it, offer its next if not null.
    4. When the heap is empty, return dummy.next.

    Java

    class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        PriorityQueue<ListNode> heap = new PriorityQueue<>(
            (a, b) -> Integer.compare(a.val, b.val));
        for (ListNode head : lists) {
            if (head != null) heap.offer(head);
        }
        ListNode dummy = new ListNode(), tail = dummy;
        while (!heap.isEmpty()) {
            ListNode node = heap.poll();   // smallest front
            tail.next = node;
            tail = node;
            if (node.next != null) {
                heap.offer(node.next);
            }
        }
        return dummy.next;
    }
}

    Time O(N log k) · Space O(k) — N nodes each pass through a heap of at most k.

    Dry run

    lists 1-4-5, 1-3-4, 2-6      heap {1,1,2}
poll 1 (push 4)   poll 1 (push 3)   poll 2 (push 6)
poll 3 (push 4)   poll 4  poll 4 (push 5)  poll 5  poll 6
-> 1 1 2 3 4 4 5 6

    Watch out

    Do not offer null heads. Compare with Integer.compare rather than a.val - b.val to stay safe from overflow on extreme values.

Test yourself

In a heap array, where are the children of index 2, and where is the parent of index 6?

Children at 5 and 6. Parent of 6 is (6 − 1) / 2 = 2.

Is [1, 4, 2, 7, 3] a valid min-heap?

No. Index 1 (value 4) has a child at index 4 with value 3, and 3 < 4.

Why does poll move the last element to the root instead of promoting a child?

Removing the last slot keeps the tree complete (no gaps in the array). Then a single sift-down fixes the order.

You need the largest values but Java's PriorityQueue is a min-heap. What do you do?

new PriorityQueue<>(Collections.reverseOrder()), or a comparator (a, b) -> Integer.compare(b, a).
