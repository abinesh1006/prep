Advanced Shortest Paths

Beyond Dijkstra: Bellman-Ford when the number of edges is limited (or weights are negative), 0-1 BFS when weights are only 0 or 1, and Floyd–Warshall when you need every pair.

Time to learn: about 3 hours · Prerequisites: Graph basics, Dijkstra, Grid BFS / DFS

When to use it — the signal

"Cheapest price with at most k stops" or "negative weights" → Bellman-Ford. "Each move costs 0 or 1" (free moves along an arrow, pay 1 to change direction or remove an obstacle) → 0-1 BFS. "Distance between every pair of cities", "n ≤ 100–400" → Floyd–Warshall.

The idea in plain words

Relax an edge u → v with weight w = "if going through u is cheaper, update v": if (dist[u] + w < dist[v]) dist[v] = dist[u] + w. All three algorithms are just different orders of relaxing.

  • Bellman-Ford: relax every edge, in rounds. After round 1 you know the best price using at most 1 edge, after round 2 at most 2 edges, and so on. With "at most k stops" you run exactly k + 1 rounds — and each round must read the previous round's prices (a copy), or a path could sneak in extra edges in one round. O(k · E).
  • 0-1 BFS: like normal BFS, but use a deque. A 0-cost edge does not make you "further away", so push its node to the front; a 1-cost edge goes to the back. The deque then always pops nodes in order of distance, like Dijkstra without a heap. O(V + E).
  • Floyd–Warshall: a table d[i][j] of all pairs. For each city k in turn, ask for every pair: "is going i → k → j cheaper?". Three nested loops, k on the outside. O(V³).
Analogy

Bellman-Ford is news spreading by daily phone calls: on day 1 only your direct friends know the cheapest fare, on day 2 their friends, and so on — limiting the days limits the number of hops. 0-1 BFS is a queue at a theme park where fast-pass holders (0-cost) jump to the front. Floyd–Warshall is adding one new airport hub at a time and checking every route that could now go through it.

Watch it work

1. Bellman-Ford rounds — Cheapest Flights Within K Stops (k = 1)

From city 0 to city 3 with at most 1 stop (= at most 2 flights). The overall cheapest route 0 → 1 → 2 → 3 costs 400 but has 2 stops, so it is not allowed.

2. 0-1 BFS — free edges jump the queue

Edge weights are 0 or 1. Badges show dist from node 0.

3. Floyd–Warshall — every pair, one stop-over city at a time

Why it works

"After round r of Bellman-Ford, every price is the cheapest using at most r edges, because any such path is a path of r − 1 edges plus one more edge, which we just relaxed — reading the previous round's copy keeps that exact." "In 0-1 BFS the deque only ever holds two distance values, d and d + 1, with the d's at the front, so it pops in distance order like Dijkstra." "Floyd–Warshall: after processing k, d[i][j] is the cheapest path whose stop-overs are only cities 0..k."

The template to remember

// Bellman-Ford with at most k stops
for (round = 0; round <= k; round++) {
    tmp = price.clone();
    for (edge u→v,w) if (price[u] + w < tmp[v]) tmp[v] = price[u] + w;
    price = tmp;
}
// 0-1 BFS: w == 0 ? offerFirst(v) : offerLast(v)
// Floyd: k OUTSIDE, then i, then j
d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
Remember

Limited stops → Bellman-Ford with a copy each round. 0/1 weights → deque, 0 to the front. All pairs → Floyd, k outermost.

Common mistakes
  • Bellman-Ford with k stops without the copy — one round can chain several edges and break the stop limit.
  • Running Dijkstra on "at most k stops" — it throws away a more expensive path with fewer stops that you may need.
  • Floyd–Warshall with k as the inner loop — the answers come out wrong.
  • INF + w overflowing when INF is Integer.MAX_VALUE: check for INF first, or use a smaller INF like 1e9.

  • Medium743. Network Delay Time — solve it with both Dijkstra and Bellman-Ford.
    Show solution

    The idea

    A signal starts at node k and travels along weighted, one-way edges. How long until every node has it? That is the largest shortest distance from k. All weights are positive, so use Dijkstra: always settle the closest unsettled node next, using a min-heap (a priority queue that hands out the smallest item first). Bellman-Ford also works: relax all edges n − 1 times, O(n · E).

    Step by step

    1. Build an adjacency list: for each u, the list of (v, w).
    2. Set dist[] = infinity everywhere and dist[k] = 0. Push (k, 0) on the heap.
    3. Pop the smallest (u, d). If d > dist[u], it is an old entry, so skip it.
    4. For each edge u→v with weight w: if d + w < dist[v], update dist[v] and push (v, dist[v]).
    5. Finally, if any node is still at infinity, return −1. Otherwise return the max of dist.

    Java

    class Solution {
    public int networkDelayTime(int[][] times, int n, int k) {
        // adjacency list: graph.get(u) = list of {v, w}
        List<List<int[]>> graph = new ArrayList<>();
        for (int i = 0; i <= n; i++) graph.add(new ArrayList<>());
        for (int[] t : times) graph.get(t[0]).add(new int[]{t[1], t[2]});
        int[] dist = new int[n + 1];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[k] = 0;
        // min-heap of {node, distance}
        PriorityQueue<int[]> pq =
            new PriorityQueue<>((x, y) -> x[1] - y[1]);
        pq.offer(new int[]{k, 0});
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int u = cur[0], d = cur[1];
            if (d > dist[u]) continue; // stale entry
            for (int[] e : graph.get(u)) {
                int v = e[0], nd = d + e[1];
                if (nd < dist[v]) {
                    dist[v] = nd;
                    pq.offer(new int[]{v, nd});
                }
            }
        }
        int ans = 0;
        for (int i = 1; i <= n; i++) {
            if (dist[i] == Integer.MAX_VALUE) return -1;
            ans = Math.max(ans, dist[i]); // last one to hear
        }
        return ans;
    }
}

    Time O(E log E) · Space O(n + E) — each edge can push one heap entry.

    Dry run

    times [[2,1,1],[2,3,1],[3,4,1]], k = 2. Pop 2 (0): dist1 = 1, dist3 = 1. Pop 1 (1), then pop 3 (1): dist4 = 2. Pop 4 (2). The max distance is 2.

    Watch out

    Nodes are numbered 1..n, so size the arrays n + 1 and skip index 0 when taking the max. Skipping old heap entries keeps it fast.

  • Medium787. Cheapest Flights Within K Stops — animation 1.
    Show solution

    The idea

    Find the cheapest price from src to dst using at most k stops, which is at most k + 1 flights. Bellman-Ford with a twist: run exactly k + 1 rounds, and in each round extend paths by one flight only, reading prices from a copy of the last round. After round r, cost[v] is the cheapest price using at most r flights. Pattern: Bellman-Ford with limited rounds.

    Brute force first

    DFS over every path with up to k + 1 flights: exponential.

    Step by step

    1. cost[] = infinity everywhere and cost[src] = 0.
    2. Repeat k + 1 times: next = cost.clone().
    3. For each flight u→v with price p: if cost[u] is known and cost[u] + p < next[v], set next[v].
    4. cost = next.
    5. Return cost[dst], or −1 if it is still infinity.

    Java

    class Solution {
    public int findCheapestPrice(int n, int[][] flights,
                                 int src, int dst, int k) {
        final int INF = Integer.MAX_VALUE;
        int[] cost = new int[n];
        Arrays.fill(cost, INF);
        cost[src] = 0;
        // k stops = at most k + 1 flights = k + 1 rounds
        for (int round = 0; round <= k; round++) {
            // read only last round's prices
            int[] next = cost.clone();
            for (int[] f : flights) {
                int u = f[0], v = f[1], price = f[2];
                if (cost[u] == INF) continue;
                if (cost[u] + price < next[v]) {
                    next[v] = cost[u] + price;
                }
            }
            cost = next;
        }
        return cost[dst] == INF ? -1 : cost[dst];
    }
}

    Time O(k · E) · Space O(n) — k + 1 passes over all flights, with two arrays.

    Dry run

    0→1 100, 1→2 100, 0→2 500, k = 1. Round 1: cost1 = 100, cost2 = 500. Round 2: 2 via 1 = 200 < 500, so cost2 = 200. The answer is 200. With k = 0 only round 1 runs, and the answer is 500.

    Watch out

    Reading from cost while writing into the same array lets one round chain several flights, which breaks the stop limit. Always read the old copy.

  • Medium1334. City With the Smallest Number of Neighbors — Floyd–Warshall.
    Show solution

    The idea

    For each city, count how many other cities are within the distance threshold. Return the city with the fewest, and on a tie the larger index. That needs shortest distances between all pairs. n ≤ 100, so Floyd–Warshall fits: for each city m, check whether going i → m → j is shorter than the best i → j so far.

    Brute force first

    Run Dijkstra from every city: O(n · E log E). That also works, but Floyd is shorter to write.

    Step by step

    1. Make an n × n table: 0 on the diagonal, the road length for each road (both ways), and a big number elsewhere.
    2. Triple loop with m on the outside: d[i][j] = min(d[i][j], d[i][m] + d[m][j]).
    3. For each city i, count the j ≠ i with d[i][j] ≤ threshold.
    4. Keep the city with the smallest count, using ≤ so that later (larger) cities win ties.

    Java

    class Solution {
    public int findTheCity(int n, int[][] edges,
                           int distanceThreshold) {
        final int INF = 1_000_000_000;
        int[][] d = new int[n][n];
        for (int i = 0; i < n; i++) {
            Arrays.fill(d[i], INF);
            d[i][i] = 0;
        }
        for (int[] e : edges) { // roads go both ways
            d[e[0]][e[1]] = e[2];
            d[e[1]][e[0]] = e[2];
        }
        // allow city m as a middle stop, one m at a time
        for (int m = 0; m < n; m++)
            for (int i = 0; i < n; i++)
                for (int j = 0; j < n; j++)
                    if (d[i][m] + d[m][j] < d[i][j])
                        d[i][j] = d[i][m] + d[m][j];
        int bestCity = -1, bestCount = Integer.MAX_VALUE;
        for (int i = 0; i < n; i++) {
            int count = 0;
            for (int j = 0; j < n; j++)
                if (i != j && d[i][j] <= distanceThreshold) count++;
            // <= so that the larger index wins ties
            if (count <= bestCount) {
                bestCount = count;
                bestCity = i;
            }
        }
        return bestCity;
    }
}

    Time O(n³) · Space O(n²) — three nested loops over the cities.

    Dry run

    Example 1, threshold 4: city 0 reaches {1, 2}, city 1 reaches {0, 2, 3}, city 2 reaches {0, 1, 3}, city 3 reaches {1, 2}. Cities 0 and 3 both have 2, and the larger index wins, so the answer is 3.

    Watch out

    The middle city m must be the outer loop. Use a "big" value like 10⁹ instead of Integer.MAX_VALUE, because adding two MAX_VALUEs overflows to a negative number.

  • Hard2290. Minimum Obstacle Removal to Reach Corner — 0-1 BFS on a grid.
    Show solution

    The idea

    Move from the top-left to the bottom-right of the grid. Stepping onto an empty cell costs 0 and stepping onto an obstacle costs 1 (you remove it). Minimise the total cost. With only 0 and 1 costs, use 0-1 BFS: a deque where cost-0 moves go to the front and cost-1 moves go to the back. The deque then stays sorted by distance, like Dijkstra without a heap.

    Brute force first

    Dijkstra with a heap: O(mn log mn). That is correct but slower.

    Step by step

    1. dist = infinity everywhere, dist[0][0] = 0, and push (0,0).
    2. Pop from the front. For each of the 4 neighbours, w = grid value (0 or 1).
    3. If dist[cur] + w < dist[next], update it. Push to the front if w = 0, to the back if w = 1.
    4. When the deque is empty, return the bottom-right distance.

    Java

    class Solution {
    public int minimumObstacles(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        int[][] dist = new int[m][n];
        for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        Deque<int[]> dq = new ArrayDeque<>();
        dist[0][0] = 0;
        dq.offerFirst(new int[]{0, 0});
        while (!dq.isEmpty()) {
            int[] cur = dq.pollFirst();
            int r = cur[0], c = cur[1];
            for (int[] d : dirs) {
                int nr = r + d[0], nc = c + d[1];
                if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
                int w = grid[nr][nc]; // 1 = must remove
                if (dist[r][c] + w < dist[nr][nc]) {
                    dist[nr][nc] = dist[r][c] + w;
                    // cost 0 to the front, cost 1 to the back
                    if (w == 0) dq.offerFirst(new int[]{nr, nc});
                    else dq.offerLast(new int[]{nr, nc});
                }
            }
        }
        return dist[m - 1][n - 1];
    }
}

    Time O(m · n) · Space O(m · n) — each cell is improved only a few times, and deque operations are O(1).

    Dry run

    [[0,1,1],[1,1,0],[1,1,0]]. Every way out of the top-left meets at least two 1s, for example right(1), right(1), down(0), down(0). The answer is 2.

    Watch out

    The weight is the value of the cell you enter, not the one you leave. The start cell is always 0.

  • Hard1368. Minimum Cost to Make a Valid Path in a Grid — follow the arrow = 0, change it = 1.
    Show solution

    The idea

    Each cell has an arrow (1 right, 2 left, 3 down, 4 up). Following the arrow is free; going any other way means changing that arrow, which costs 1. Find the cheapest way to reach the bottom-right. That is a graph with 0 and 1 edge weights, so use 0-1 BFS.

    Brute force first

    Dijkstra with a heap works in O(mn log mn).

    Step by step

    1. Keep the direction list in the same order as the signs: right, left, down, up.
    2. Start with dist[0][0] = 0 in the deque.
    3. Pop the front cell. For each direction i, the cost is 0 if grid[r][c] == i + 1, otherwise 1.
    4. Relax the neighbour. Push it to the front for cost 0, to the back for cost 1.
    5. Return dist[m−1][n−1].

    Java

    class Solution {
    public int minCost(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        // sign 1 right, 2 left, 3 down, 4 up
        int[][] dirs = {{0, 1}, {0, -1}, {1, 0}, {-1, 0}};
        int[][] dist = new int[m][n];
        for (int[] row : dist) Arrays.fill(row, Integer.MAX_VALUE);
        Deque<int[]> dq = new ArrayDeque<>();
        dist[0][0] = 0;
        dq.offerFirst(new int[]{0, 0});
        while (!dq.isEmpty()) {
            int[] cur = dq.pollFirst();
            int r = cur[0], c = cur[1];
            for (int i = 0; i < 4; i++) {
                int nr = r + dirs[i][0], nc = c + dirs[i][1];
                if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
                // follow the arrow = free, change it = 1
                int w = (grid[r][c] == i + 1) ? 0 : 1;
                if (dist[r][c] + w < dist[nr][nc]) {
                    dist[nr][nc] = dist[r][c] + w;
                    if (w == 0) dq.offerFirst(new int[]{nr, nc});
                    else dq.offerLast(new int[]{nr, nc});
                }
            }
        }
        return dist[m - 1][n - 1];
    }
}

    Time O(m · n) · Space O(m · n) — 4 edges per cell, each deque step O(1).

    Dry run

    [[1,2],[4,3]]. The arrow at (0,0) points right, so (0,1) costs 0. The arrow at (0,1) points left, so going down costs 1. The arrow at (1,1) does not matter. The answer is 1.

    Watch out

    The cost depends on the arrow of the cell you are leaving (the reverse of 2290). Mixing up the order of the direction list is the usual bug.

  • Medium1462. Course Schedule IV — Floyd–Warshall on true/false reachability.
    Show solution

    The idea

    Course a is a prerequisite of b if there is a chain a → … → b. You get many questions "is u before v?", so work out all of reachability once. Floyd–Warshall with true/false: if i reaches m and m reaches j, then i reaches j. n ≤ 100, so n³ is fine. Pattern: transitive closure.

    Brute force first

    Run a BFS for each query: O(q · (n + E)). That is fine too, but the table answers each query in O(1).

    Step by step

    1. Make a boolean table reach[n][n] and set reach[a][b] = true for each prerequisite pair.
    2. For m (outer), i, j: if reach[i][m] and reach[m][j], set reach[i][j] = true.
    3. Answer each query with reach[u][v].

    Java

    class Solution {
    public List<Boolean> checkIfPrerequisite(int numCourses,
            int[][] prerequisites, int[][] queries) {
        int n = numCourses;
        // reach[i][j] = true if i must come before j
        boolean[][] reach = new boolean[n][n];
        for (int[] p : prerequisites) reach[p[0]][p[1]] = true;
        // i before m and m before j  =>  i before j
        for (int m = 0; m < n; m++)
            for (int i = 0; i < n; i++)
                if (reach[i][m])
                    for (int j = 0; j < n; j++)
                        if (reach[m][j]) reach[i][j] = true;
        List<Boolean> res = new ArrayList<>();
        for (int[] q : queries) res.add(reach[q[0]][q[1]]);
        return res;
    }
}

    Time O(n³ + q) · Space O(n²) — one closure, then O(1) per query.

    Dry run

    n = 3, pairs 1→2, 1→0, 2→0. Through m = 2: 1 reaches 2 and 2 reaches 0, so 1 reaches 0 (already true). The queries (1,0) and (1,2) are both true.

    Watch out

    Keep m as the outer loop. Skipping the inner j-loop when reach[i][m] is false is a cheap speed-up.

Test yourself

Why does Bellman-Ford need V − 1 rounds without a stop limit?

A shortest path without cycles uses at most V − 1 edges, and each round extends the known paths by one edge.

How do you detect a negative cycle with Bellman-Ford?

Run one extra (V-th) round. If any price still gets cheaper, a negative cycle is reachable.

When is 0-1 BFS better than Dijkstra?

When every weight is 0 or 1: it gives the same answer in O(V + E) without a heap.

Why must k be the outer loop in Floyd–Warshall?

The table after step k must mean "paths using only 0..k as stop-overs". With k inside, you would combine entries that were not finished yet.
