Advanced Shortest Paths

Beyond Dijkstra: Bellman-Ford when the number of edges is limited (or weights are negative), 0-1 BFS when weights are only 0 or 1, and Floyd–Warshall when you need every pair.

Time to learn: about 3 hours · Prerequisites: Graph basics, Dijkstra, Grid BFS / DFS

When to use it — the signal

"Cheapest price with at most k stops" or "negative weights" → Bellman-Ford. "Each move costs 0 or 1" (free moves along an arrow, pay 1 to change direction or remove an obstacle) → 0-1 BFS. "Distance between every pair of cities", "n ≤ 100–400" → Floyd–Warshall.

The idea in plain words

Relax an edge u → v with weight w = "if going through u is cheaper, update v": if (dist[u] + w < dist[v]) dist[v] = dist[u] + w. All three algorithms are just different orders of relaxing.

  • Bellman-Ford: relax every edge, in rounds. After round 1 you know the best price using at most 1 edge, after round 2 at most 2 edges, and so on. With "at most k stops" you run exactly k + 1 rounds — and each round must read the previous round's prices (a copy), or a path could sneak in extra edges in one round. O(k · E).
  • 0-1 BFS: like normal BFS, but use a deque. A 0-cost edge does not make you "further away", so push its node to the front; a 1-cost edge goes to the back. The deque then always pops nodes in order of distance, like Dijkstra without a heap. O(V + E).
  • Floyd–Warshall: a table d[i][j] of all pairs. For each city k in turn, ask for every pair: "is going i → k → j cheaper?". Three nested loops, k on the outside. O(V³).
Analogy

Bellman-Ford is news spreading by daily phone calls: on day 1 only your direct friends know the cheapest fare, on day 2 their friends, and so on — limiting the days limits the number of hops. 0-1 BFS is a queue at a theme park where fast-pass holders (0-cost) jump to the front. Floyd–Warshall is adding one new airport hub at a time and checking every route that could now go through it.

Why it works

"After round r of Bellman-Ford, every price is the cheapest using at most r edges, because any such path is a path of r − 1 edges plus one more edge, which we just relaxed — reading the previous round's copy keeps that exact." "In 0-1 BFS the deque only ever holds two distance values, d and d + 1, with the d's at the front, so it pops in distance order like Dijkstra." "Floyd–Warshall: after processing k, d[i][j] is the cheapest path whose stop-overs are only cities 0..k."

The template to remember

// Bellman-Ford with at most k stops
for (round = 0; round <= k; round++) {
    tmp = price.clone();
    for (edge u→v,w) if (price[u] + w < tmp[v]) tmp[v] = price[u] + w;
    price = tmp;
}
// 0-1 BFS: w == 0 ? offerFirst(v) : offerLast(v)
// Floyd: k OUTSIDE, then i, then j
d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
Remember

Limited stops → Bellman-Ford with a copy each round. 0/1 weights → deque, 0 to the front. All pairs → Floyd, k outermost.

Common mistakes
  • Bellman-Ford with k stops without the copy — one round can chain several edges and break the stop limit.
  • Running Dijkstra on "at most k stops" — it throws away a more expensive path with fewer stops that you may need.
  • Floyd–Warshall with k as the inner loop — the answers come out wrong.
  • INF + w overflowing when INF is Integer.MAX_VALUE: check for INF first, or use a smaller INF like 1e9.

Test yourself

Why does Bellman-Ford need V − 1 rounds without a stop limit?

A shortest path without cycles uses at most V − 1 edges, and each round extends the known paths by one edge.

How do you detect a negative cycle with Bellman-Ford?

Run one extra (V-th) round. If any price still gets cheaper, a negative cycle is reachable.

When is 0-1 BFS better than Dijkstra?

When every weight is 0 or 1: it gives the same answer in O(V + E) without a heap.

Why must k be the outer loop in Floyd–Warshall?

The table after step k must mean "paths using only 0..k as stop-overs". With k inside, you would combine entries that were not finished yet.
