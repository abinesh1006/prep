Tree Recursion (the 3 questions)

Almost every tree problem is one small function per node: decide what you need from your children, what you hand back to your parent, and what you pass down.

Time to learn: about 3 hours · Prerequisites: Recursion, Tree traversals

When to use it — the signal

A binary tree plus words like "depth", "height", "balanced", "diameter", "path sum", "for every node", "subtree", "same / symmetric / invert". If the answer for a node can be built from the answers of its two subtrees, it is this pattern.

The idea in plain words

Do not think about the whole tree. Stand on one node and answer three questions:

  1. What do I need from my children? (Example: the height of my left subtree and of my right subtree.)
  2. What do I return to my parent? (Example: my own height = 1 + the taller child.)
  3. What do I pass down to my children? (Example: how much of the target sum is still left to find.)

Answers that travel up (from children to parent, as return values) make a bottom-up solution — a node finishes only after its children, like post-order. Information that travels down (as parameters) makes a top-down solution — like pre-order. Many problems use one direction; some use both.

The base case is almost always the empty spot: if (node == null) return ... with the answer for an empty tree (height 0, sum false, count 0).

A second trick for "longest / biggest anywhere" problems: what the parent needs (one straight branch it can extend) is different from the answer (a path that may bend at this node). So you return one thing and update a global best variable with the other.

Cost: every node is handled once → O(n) time; the call stack holds one root-to-node path → O(h) space.

Analogy

A company where every manager only talks to their two direct reports. To find the company's deepest chain of command, the CEO does not walk the whole org chart. Each manager asks their two reports "how deep is your team?", takes the bigger number, adds 1 for themselves, and reports that up (bottom-up). To share a budget, the CEO instead tells each report "you have this much left" and they pass the rest down (top-down).

Watch it work

1. Maximum depth — bottom-up, answers travel up

The 3 questions: need → the depth of each child; return → 1 + max(left, right); pass down → nothing. The badge under a node is the number it returned to its parent.

2. Diameter — return one thing, record another

Diameter = the number of edges on the longest path between any two nodes. The path may bend at a node: go down its left side and down its right side. The parent cannot use a bent path (it can only extend one straight branch), so each node returns its height but records left + right in a global best.

3. Path Sum — top-down, information travels down

Is there a root-to-leaf path whose values add up to 22? The 3 questions: pass down → how much is still needed; return → true / false; need from children → did either side find it? The badge shows what is still needed after paying for that node.

Why it works

"I answer three questions for one node — what I need from my children, what I return, what I pass down — and trust the recursive calls for the subtrees. The base case is the null node. Each node is visited once, so O(n) time and O(h) stack. When the best answer can bend at a node but the parent can only extend one branch, I return the branch and keep the answer in a global variable."

The template to remember

int best;                                 // only if the answer can bend
Info dfs(TreeNode node, Down fromParent) {  // Q3: what I pass down
    if (node == null) return emptyAnswer;
    Info l = dfs(node.left, next(fromParent, node));   // Q1: ask
    Info r = dfs(node.right, next(fromParent, node));  //     children
    best = Math.max(best, combineThroughMe(l, r));  // optional
    return whatParentNeeds(l, r, node);        // Q2: what I return
}
Remember

Need from children? Return to parent? Pass down? Up = return values (bottom-up). Down = parameters (top-down). "Anywhere in the tree" = return one branch, record the bend in best.

Common mistakes
  • Returning the diameter instead of the height — the parent then extends a bent path, which is not a real path.
  • Mixing up edges and nodes: diameter in LeetCode counts edges (l + r with null = 0), not nodes.
  • Path Sum: checking remain == 0 at a null node — a node with one child would wrongly count as a leaf end. Check at real leaves only.
  • Using a static field for best and not resetting it between test cases.
  • Calling the height function again inside every node (e.g. Balanced Tree) — that is O(n²). Return the height and the answer together in one pass.

Practice in this order

  • Easy104. Maximum Depth of Binary Tree — animation 1.
    Show solution

    The idea

    Depth = number of nodes on the longest path from the root down to a leaf. [3,9,20,null,null,15,7] → 3. Tree recursion: an empty tree has depth 0; otherwise my depth is 1 plus the deeper of my two subtrees. Trust that the calls on the children return the right answer.

    Step by step

    1. Null node: return 0.
    2. Get the left subtree's depth and the right subtree's depth.
    3. Return 1 + the bigger one.

    Java

    class Solution {
    public int maxDepth(TreeNode root) {
        if (root == null) return 0;      // empty: depth 0
        int left = maxDepth(root.left);  // trust the call
        int right = maxDepth(root.right);
        return 1 + Math.max(left, right); // me + deeper side
    }
}

    Time O(n) · Space O(h) — each node once; recursion as deep as the tree.

    Dry run

    depth(9) = 1, depth(15) = depth(7) = 1, depth(20) = 2, depth(3) = 1 + max(1, 2) = 3.

    Watch out

    A very deep, chain-like tree can overflow the call stack; the BFS version (count floors) avoids that.

  • Easy226. Invert Binary Tree — swap children, trust both calls.
    Show solution

    The idea

    Mirror the tree: every node's left and right children swap. [4,2,7,1,3,6,9] → [4,7,2,9,6,3,1]. At each node, swap its two children, then invert each of them; recursion handles the rest.

    Step by step

    1. Null node: return null.
    2. Swap root.left and root.right using a temp variable.
    3. Invert the (new) left and the (new) right subtree.
    4. Return root.

    Java

    class Solution {
    public TreeNode invertTree(TreeNode root) {
        if (root == null) return null;
        TreeNode tmp = root.left;        // swap my children
        root.left = root.right;
        root.right = tmp;
        invertTree(root.left); // then fix each side
        invertTree(root.right);
        return root;
    }
}

    Time O(n) · Space O(h) — one swap per node.

    Dry run

    At 4: swap 2 and 7 → children 7, 2. Recurse into 7: swap 6, 9 → 9, 6. Recurse into 2: swap 1, 3 → 3, 1. Result [4,7,2,9,6,3,1].

    Watch out

    Without a temp variable you write root.left = root.right first and lose the old left child.

  • Easy112. Path Sum — animation 3.
    Show solution

    The idea

    Is there a root-to-leaf path whose values add up to targetSum? Subtract each node's value from the target on the way down; at a leaf, the path works if what is left is exactly 0.

    Step by step

    1. Null node: false.
    2. rest = targetSum − root.val.
    3. If root is a leaf, return rest == 0.
    4. Otherwise return hasPathSum(left, rest) or hasPathSum(right, rest).

    Java

    class Solution {
    public boolean hasPathSum(TreeNode root, int targetSum) {
        if (root == null) return false;   // no path here
        int rest = targetSum - root.val;  // what is left
        if (root.left == null && root.right == null) {
            return rest == 0; // leaf: exact hit?
        }
        return hasPathSum(root.left, rest)
            || hasPathSum(root.right, rest);
    }
}

    Time O(n) · Space O(h) — each node visited at most once.

    Dry run

    Target 22: 5 → rest 17; 4 → 13; 11 → 2; 7 → −5 (leaf, no); 2 → 0 (leaf, yes) → true.

    Watch out

    The path must end at a leaf. For tree [1,2] and target 1, the root alone is not a leaf, so the answer is false; checking "rest == 0" at a null child would wrongly say true.

  • Easy110. Balanced Binary Tree — return height, or −1 for "already unbalanced".
    Show solution

    The idea

    A tree is balanced if, at every node, the left and right subtree heights differ by at most 1. Compute heights bottom-up and use −1 as a special signal meaning "already unbalanced somewhere below", so one pass is enough.

    Brute force first

    At every node compute both heights from scratch and recurse: O(n²) on a chain-shaped tree.

    Step by step

    1. height(null) = 0.
    2. Get the left height; if it is −1, return −1 straight away.
    3. Same for the right height.
    4. If they differ by more than 1, return −1.
    5. Otherwise return 1 + max(left, right). Balanced means the root's result is not −1.

    Java

    class Solution {
    public boolean isBalanced(TreeNode root) {
        return height(root) != -1;
    }

    // height of the subtree, or -1 if it is unbalanced
    private int height(TreeNode n) {
        if (n == null) return 0;
        int left = height(n.left);
        if (left == -1) return -1;        // pass failure up
        int right = height(n.right);
        if (right == -1) return -1;
        if (Math.abs(left - right) > 1) return -1;
        return 1 + Math.max(left, right);
    }
}

    Time O(n) · Space O(h) — each node is visited once.

    Dry run

    [1,2,2,3,3,null,null,4,4]: the 4s have height 1; the 3 above them 2; the other 3 is 1; so the left 2 has height 3 (2 vs 1 is fine). The right 2 is a leaf, height 1. At the root |3 − 1| = 2 → −1 → false.

    Watch out

    Checking only the root's two heights is not enough; every node must pass the test. Pass the −1 all the way up.

  • Easy543. Diameter of Binary Tree — animation 2.
    Show solution

    The idea

    The diameter is the longest path (counted in edges) between any two nodes, and it may not pass through the root. Every path has a highest node where it bends; there its length is left height + right height. So compute heights and, at each node, update a global best with left + right.

    Step by step

    1. Keep best = 0 as a field.
    2. height(null) = 0.
    3. At each node get left and right heights.
    4. Update best = max(best, left + right).
    5. Return 1 + max(left, right) to the parent.

    Java

    class Solution {
    private int best = 0;   // longest path seen, in edges

    public int diameterOfBinaryTree(TreeNode root) {
        height(root);
        return best;
    }

    // returns height (nodes on the longest way down)
    private int height(TreeNode n) {
        if (n == null) return 0;
        int left = height(n.left);
        int right = height(n.right);
        // path that bends at n: left arm + right arm
        best = Math.max(best, left + right);
        return 1 + Math.max(left, right);
    }
}

    Time O(n) · Space O(h) — one visit per node.

    Dry run

    [1,2,3,4,5]: height(4) = height(5) = 1; at 2: best = 2, height 2; height(3) = 1; at 1: best = 2 + 1 = 3. Answer 3.

    Watch out

    What you return (one arm, the height) is different from what you record (both arms, the path). Mixing them up is the classic bug.

  • Medium1448. Count Good Nodes in Binary Tree — pass the max so far down.
    Show solution

    The idea

    A node is "good" if no node on the path from the root to it has a bigger value. Carry the biggest value seen so far down the recursion; a node is good if its value is ≥ that maximum.

    Step by step

    1. Start with count(root, Integer.MIN_VALUE).
    2. Null node: 0 good nodes.
    3. This node is good if val ≥ maxSoFar.
    4. New max = max(maxSoFar, val); add the counts from both children using it.

    Java

    class Solution {
    public int goodNodes(TreeNode root) {
        return count(root, Integer.MIN_VALUE);
    }

    // good nodes in n's subtree; maxSoFar = biggest above
    private int count(TreeNode n, int maxSoFar) {
        if (n == null) return 0;
        int good = n.val >= maxSoFar ? 1 : 0;
        int newMax = Math.max(maxSoFar, n.val);
        return good + count(n.left, newMax)
                    + count(n.right, newMax);
    }
}

    Time O(n) · Space O(h) — one visit per node.

    Dry run

    [3,1,4,3,null,1,5]: 3 good (max 3). 1 no. Its child 3 good (3 ≥ 3). 4 good (max 4). 1 under 4 no. 5 good. Total 4.

    Watch out

    Use ≥, not >: a node equal to the max so far still counts as good. Start with MIN_VALUE so the root is always good.

  • Hard124. Binary Tree Maximum Path Sum — diameter's trick with sums; drop negative branches with max(0, ...).
    Show solution

    The idea

    Find the path with the largest sum; it can start and end anywhere. Like the diameter: at each node the best path that bends here is val + left gain + right gain, and what you hand the parent is val + the better single arm. A negative arm only hurts, so treat it as 0 (just do not take it).

    Step by step

    1. Keep best = Integer.MIN_VALUE.
    2. gain(null) = 0.
    3. left = max(0, gain(left child)); right = max(0, gain(right child)).
    4. Update best with val + left + right.
    5. Return val + max(left, right).

    Java

    class Solution {
    private int best = Integer.MIN_VALUE;

    public int maxPathSum(TreeNode root) {
        gain(root);
        return best;
    }

    // best sum of a path that starts at n and goes down
    private int gain(TreeNode n) {
        if (n == null) return 0;
        // a negative branch only hurts: take 0 instead
        int left = Math.max(0, gain(n.left));
        int right = Math.max(0, gain(n.right));
        // path that bends at n uses both arms
        best = Math.max(best, n.val + left + right);
        // the parent can only use one arm of mine
        return n.val + Math.max(left, right);
    }
}

    Time O(n) · Space O(h) — each node visited once.

    Dry run

    [-10,9,20,null,null,15,7]: gain(15) = 15, gain(7) = 7; at 20: best = 42, return 35. gain(9) = 9. At −10: path −10 + 9 + 35 = 34 < 42. Answer 42.

    Watch out

    Start best at MIN_VALUE, not 0: if every value is negative the answer is the biggest single node (like −1), not 0.

Test yourself

Answer the 3 questions for "count the nodes in a tree".

Need: the count of each subtree. Return: 1 + left + right. Pass down: nothing. Base case: null returns 0.

Is Path Sum top-down or bottom-up? What travels in each direction?

Both: the remaining sum travels down as a parameter; true / false travels up as the return value.

Why does the diameter need a global variable but max depth does not?

For depth, what the parent needs (my height) is also the answer. For diameter, the answer (a path bending at me, l + r) is not what the parent can use (one straight branch, 1 + max), so the bend is recorded separately.

What is the space complexity of max depth on a balanced tree of 1,000,000 nodes?

O(h) = about log₂(1,000,000) ≈ 20 frames on the call stack.
