In-place Array Tricks

Four small tricks that rearrange or answer questions about an array without making a copy of it: partition with three pointers, rotate by reversing, put each value at its own index, and multiply from both sides.

Time to learn: about 2.5 hours · Prerequisites: Two pointers, Prefix sum

When to use it — the signal

"In place", "O(1) extra space", "do not allocate another array", "without division". Also: the values are a range 0..n or 1..n ("missing number", "find the duplicate", "first missing positive"), only 2 or 3 distinct values to sort, or "rotate by k".

The idea in plain words

In-place means without making a copy of the array: you only swap or overwrite cells, using a few extra variables — O(1) extra space.

  • Dutch flag (Sort Colors): three zones. Everything left of low is 0, everything right of high is 2, and mid walks through the unknown middle sending each number to its zone. One pass.
  • Rotate by reversal: to rotate [1..7] right by 3 → [5, 6, 7, 1, 2, 3, 4]: reverse everything, then reverse the first 3, then reverse the other 4. Three reversals, no extra array.
  • Cyclic sort: when values are 0..n, value v "belongs" at index v. Keep swapping each value to its home. Afterwards the first index whose value is wrong is the missing number. (Alternative: XOR all indices and all values — pairs cancel out, the missing one remains.)
  • Product of Array Except Self: the answer at i is (product of everything left of i) × (product of everything right of i). Fill the left products in one pass and multiply in the right products on the way back.
Analogy

Sorting laundry into three baskets — but the "baskets" are the two ends of the same table: socks are pushed to the left end, shirts to the right end, and towels stay in the middle. For cyclic sort, think of hotel guests each holding a room number: whoever is in the wrong room walks to their own room and swaps with whoever is there.

Watch it work

Sort Colors (Dutch national flag) on [2, 0, 2, 1, 1, 0]. Green on the left = settled 0s, green on the right = settled 2s.

Rotate right by k = 3 using three reversals on [1, 2, 3, 4, 5, 6, 7].

Missing Number by cyclic sort on [4, 0, 5, 1, 2] (values 0..5, one is missing). Value v belongs at index v; the value 5 has no slot (n = 5), so it is left wherever it ends up.

Product of Array Except Self on [2, 3, 4, 5], without division. Pass 1 stores the product of everything left of each index; pass 2 multiplies in everything right.

Why it works (the one sentence to say in an interview)

"Each trick keeps an invariant while swapping in place: in the Dutch flag, everything before low is 0 and after high is 2; in cyclic sort, every swap sends one value to its final index so there are at most n swaps; and product-except-self is just left-product × right-product computed in two passes."

The template to remember

// Dutch flag (3 values)
while (mid <= high)
    if (a[mid] == 0) swap(a, low++, mid++);
    else if (a[mid] == 1) mid++;
    else swap(a, mid, high--);

// Rotate right by k: reverse all, reverse [0,k), reverse [k,n)

// Cyclic sort (values 0..n-1 or 1..n)
while (i < n)
    if (a[i] < n && a[a[i]] != a[i]) swap(a, i, a[i]);
    else i++;

// Missing number by XOR: x = n; for i: x ^= i ^ a[i]; return x;

When the problem says "O(1) extra space", the array itself becomes the data structure: its slots are reused as markers, homes or scratch space.

Remember

3 values → 3 pointers. Rotate → 3 reversals. Values 0..n → value v lives at index v. "Except self" → left × right.

Common mistakes
  • Dutch flag: moving mid after swapping with high. The number that came back from the right has not been looked at yet.
  • Dutch flag: while (mid < high) instead of <= — the last unknown cell is skipped.
  • Rotate: forgetting k %= n (k can be larger than n).
  • Cyclic sort: swapping when a[v] == v already (a duplicate) — an endless loop. Check a[v] != v, not v != i.
  • Product except self: using division — fails when the array has a 0, and the problem usually forbids it.

Practice in this order

  • Easy283. Move Zeroes — write pointer keeps non-zeros, rest becomes 0.
    Show solution

    The idea

    Push all 0s to the end, keep the other numbers in their order, no extra array. [0,1,0,3,12] → [1,3,12,0,0]. The insight: a write pointer w marks where the next non-zero belongs. Copy every non-zero to w, then fill the rest with 0.

    Brute force first

    Copy non-zeros into a new array and pad with zeros: O(n) time but O(n) space, and the problem says in place.

    Step by step

    1. w = 0.
    2. For each number: if it is not 0, write it to nums[w] and w++.
    3. After the loop, set nums[w..n-1] to 0.

    Java

    class Solution {
    public void moveZeroes(int[] nums) {
        int w = 0; // next slot for a non-zero
        for (int x : nums) {
            if (x != 0) nums[w++] = x;
        }
        while (w < nums.length) nums[w++] = 0;
    }
}

    Time O(n) · Space O(1) — one pass plus filling the tail.

    Dry run

    [0,1,0,3,12]: 1 → slot 0, 3 → slot 1, 12 → slot 2; w = 3, fill slots 3,4 with 0 → [1,3,12,0,0].

    Watch out

    Writing never overtakes reading (w is always ≤ the read index), so nothing is lost. A swap version (swap(nums[w], nums[i])) does it in one pass with fewer writes.

  • Easy268. Missing Number — cyclic sort, XOR, or n(n+1)/2 − sum.
    Show solution

    The idea

    The array holds n different numbers from 0..n, so exactly one is missing. [3,0,1] → 2. The insight: the full set 0..n adds up to n(n+1)/2; subtract the actual sum and what is left is the missing one. (XOR of all indexes and values also works, since equal numbers cancel.)

    Brute force first

    Sort and look for the first gap: O(n log n). Or a hash set: O(n) time, O(n) space.

    Step by step

    1. n = nums.length.
    2. Expected sum = n * (n + 1) / 2.
    3. Subtract every number in the array.
    4. What remains is the missing number.

    Java

    class Solution {
    public int missingNumber(int[] nums) {
        int n = nums.length;
        int missing = n * (n + 1) / 2; // sum of 0..n
        for (int x : nums) missing -= x;
        return missing;
    }
}

    Time O(n) · Space O(1) — one pass, one variable.

    Dry run

    [3,0,1], n = 3: expected 0+1+2+3 = 6; 6 − 3 − 0 − 1 = 2.

    Watch out

    n ≤ 104, so n(n+1)/2 fits in int; for huge n use long or the XOR trick. The missing number can be 0 or n itself.

  • Medium75. Sort Colors — the Dutch flag animation.
    Show solution

    The idea

    Sort an array of only 0s, 1s and 2s in place, in one pass. [2,0,2,1,1,0] → [0,0,1,1,2,2]. The insight: Dutch national flag. Three pointers split the array into zone of 0s [0, lo), 1s [lo, i), unknown [i, hi], 2s (hi, end]. Look at nums[i] and send it to the right zone.

    Brute force first

    Count the 0s, 1s and 2s, then rewrite the array: two passes, also fine (O(n)). The one-pass version is what the follow-up asks.

    Step by step

    1. lo = 0, i = 0, hi = n - 1.
    2. If nums[i] == 0: swap with lo, then lo++, i++.
    3. If it is 1: just i++.
    4. If it is 2: swap with hi, hi--, and do not move i (the swapped-in value is still unknown).
    5. Stop when i > hi.

    Java

    class Solution {
    public void sortColors(int[] nums) {
        int lo = 0, i = 0, hi = nums.length - 1;
        while (i <= hi) {
            if (nums[i] == 0) swap(nums, lo++, i++);
            else if (nums[i] == 1) i++;
            else swap(nums, i, hi--); // re-check nums[i]
        }
    }

    private void swap(int[] a, int x, int y) {
        int t = a[x]; a[x] = a[y]; a[y] = t;
    }
}

    Time O(n) · Space O(1) — each step either moves i forward or shrinks hi.

    Dry run

    [2,0,1]  lo=0 i=0 hi=2
i=0: 2 -> swap with hi -> [1,0,2] hi=1
i=0: 1 -> i=1
i=1: 0 -> swap with lo -> [0,1,2] lo=1 i=2
i > hi, stop

    Watch out

    After swapping a 2 to the back, do not i++: the number that came from hi has not been looked at yet. After swapping a 0, you can move i because nums[lo] was already checked (it is a 1).

  • Medium189. Rotate Array — three reversals.
    Show solution

    The idea

    Shift every number k places right, wrapping around, in place. [1,2,3,4,5,6,7], k = 3 → [5,6,7,1,2,3,4]. The insight: three reversals. Reverse all → [7,6,5,4,3,2,1]; reverse the first k → [5,6,7,...]; reverse the rest → [...,1,2,3,4].

    Brute force first

    Rotate by 1, k times: O(n · k). Or copy into a new array at (i + k) % n: O(n) time, O(n) space.

    Step by step

    1. k %= n (rotating by n changes nothing).
    2. Reverse the whole array.
    3. Reverse the first k numbers.
    4. Reverse the remaining n − k numbers.

    Java

    class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        k %= n;                 // k may exceed n
        reverse(nums, 0, n - 1);
        reverse(nums, 0, k - 1);
        reverse(nums, k, n - 1);
    }

    private void reverse(int[] a, int l, int r) {
        while (l < r) {
            int t = a[l]; a[l++] = a[r]; a[r--] = t;
        }
    }
}

    Time O(n) · Space O(1) — every number is swapped about twice.

    Dry run

    [1,2,3,4,5,6,7], k = 3: reverse all → [7,6,5,4,3,2,1]; first 3 → [5,6,7,4,3,2,1]; last 4 → [5,6,7,1,2,3,4].

    Watch out

    Always do k %= n first; k can be larger than n (k = 5, n = 2 means rotate by 1).

  • Medium238. Product of Array Except Self — left pass, right pass.
    Show solution

    The idea

    For each i, the product of every number except nums[i], without division. [1,2,3,4] → [24,12,8,6]. The insight: answer[i] = (product of everything left of i) × (product of everything right of i). Fill the left products in one pass, then multiply in the right products on a pass backwards.

    Brute force first

    For each i multiply all the others: O(n²). Dividing the total by nums[i] is banned and breaks on zeros.

    Step by step

    1. ans[0] = 1; going right, ans[i] = ans[i - 1] * nums[i - 1]: ans now holds left products.
    2. Keep right = 1. Walk i from n − 1 down to 0.
    3. ans[i] *= right, then right *= nums[i].
    4. Return ans.

    Java

    class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] ans = new int[n];
        ans[0] = 1;
        for (int i = 1; i < n; i++) {
            ans[i] = ans[i - 1] * nums[i - 1]; // left part
        }
        int right = 1;
        for (int i = n - 1; i >= 0; i--) {
            ans[i] *= right;   // times the right part
            right *= nums[i];
        }
        return ans;
    }
}

    Time O(n) · Space O(1) extra (the output array does not count) — two passes.

    Dry run

    nums     [1, 2, 3, 4]
left     [1, 1, 2, 6]
right    [24,12, 4, 1]
answer   [24,12, 8, 6]

    Watch out

    Do not divide: zeros break it. Multiply by right before updating it with nums[i], or each answer includes its own number.

  • Medium442. Find All Duplicates in an Array — mark seen values by negating a[v − 1].
    Show solution

    The idea

    Values are in 1..n and each appears once or twice; list the ones that appear twice, with O(1) extra space. [4,3,2,7,8,2,3,1] → [2,3]. The insight: use the array itself as the "seen" table. For value v, look at slot v - 1: make it negative the first time; if it is already negative, v is a duplicate.

    Brute force first

    A hash set of seen values: O(n) time but O(n) space.

    Step by step

    1. For each number, take v = Math.abs(nums[i]) (it may already be negated).
    2. Look at slot v - 1.
    3. If nums[v - 1] is negative, v was seen before: add v to the answer.
    4. Otherwise negate it to mark v as seen.

    Java

    class Solution {
    public List<Integer> findDuplicates(int[] nums) {
        List<Integer> res = new ArrayList<>();
        for (int i = 0; i < nums.length; i++) {
            int v = Math.abs(nums[i]); // may be marked
            if (nums[v - 1] < 0) res.add(v); // seen twice
            else nums[v - 1] = -nums[v - 1]; // mark seen
        }
        return res;
    }
}

    Time O(n) · Space O(1) extra — the sign bit of each slot is the "seen" flag.

    Dry run

    [4,3,2,7,8,2,3,1]
4 -> negate slot 3;  3 -> slot 2;  2 -> slot 1
7 -> slot 6;  8 -> slot 7
2 -> slot 1 already negative -> add 2
3 -> slot 2 already negative -> add 3
1 -> negate slot 0           result [2,3]

    Watch out

    Always use Math.abs(nums[i]): the value you read may have been negated by an earlier step. The trick only works because every value is between 1 and n.

  • Hard41. First Missing Positive — cyclic sort for values 1..n, ignore the rest.
    Show solution

    The idea

    Smallest positive integer not in the array, in O(n) time and O(1) space. [3,4,-1,1] → 2. The insight: the answer is in 1..n+1. Cyclic sort: put each value v in 1..n at index v - 1 by swapping; ignore negatives, zeros and numbers > n. Then the first index i with nums[i] != i + 1 gives the answer.

    Brute force first

    Put everything in a hash set and test 1, 2, 3, ...: O(n) time but O(n) space. Sorting is O(n log n).

    Step by step

    1. For each i: while nums[i] is in 1..n and is not already at its home nums[i] - 1, swap it home.
    2. The home check nums[nums[i] - 1] != nums[i] also stops endless swaps with duplicates.
    3. Scan: the first i where nums[i] != i + 1 means i + 1 is missing.
    4. If every slot is correct, the answer is n + 1.

    Java

    class Solution {
    public int firstMissingPositive(int[] nums) {
        int n = nums.length;
        for (int i = 0; i < n; i++) {
            // send nums[i] to its home index nums[i]-1
            while (nums[i] > 0 && nums[i] <= n
                    && nums[nums[i] - 1] != nums[i]) {
                int j = nums[i] - 1;
                int t = nums[i]; nums[i] = nums[j]; nums[j] = t;
            }
        }
        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) return i + 1;
        }
        return n + 1;
    }
}

    Time O(n) · Space O(1) — every swap puts one value in its final home, so at most n swaps overall.

    Dry run

    [3,4,-1,1]
i=0: 3 -> index 2   [-1,4,3,1]   -1 stays
i=1: 4 -> index 3   [-1,1,3,4]   1 -> index 0  [1,-1,3,4]
scan: index 1 holds -1, not 2 -> answer 2

    Watch out

    Compute j = nums[i] - 1 before swapping; writing nums[nums[i]-1] after changing nums[i] swaps the wrong slot. The duplicate check stops [1,1] from looping forever.

Test yourself

In the Dutch flag, why do we move mid after swapping with low but not after swapping with high?

The value coming from low is already checked (it is a 1, or low == mid). The value coming from high has never been looked at.

Rotate [1, 2, 3, 4, 5] right by 2 with reversals. What are the three steps?

Reverse all → [5, 4, 3, 2, 1]; reverse first 2 → [4, 5, 3, 2, 1]; reverse the rest → [4, 5, 1, 2, 3].

Why does XOR find the missing number?

x ^ x = 0 and x ^ 0 = x. XOR-ing all indices 0..n and all values cancels every number that appears in both, leaving only the missing one.

Why not compute the total product and divide by a[i]?

A zero in the array breaks division, and the problem forbids it. Left × right products need no division.
