Union-Find (Disjoint Set Union)

Keep groups as little trees stored in one parent array: find walks up to a group's leader, union hangs one leader under another, and two small tricks make both almost O(1).

Time to learn: about 2 hours · Prerequisites: Graph basics, Recursion

When to use it — the signal

"Number of connected components", "are x and y in the same group", "merge accounts / friend circles / provinces", "which edge makes a cycle (redundant connection)", edges arriving one at a time, Kruskal's MST.

The idea in plain words

Start with 6 people, each in their own group of 1. Every group has a leader (called the root). Each person only remembers one thing: parent[x] = someone above them in their group. A leader is their own parent: parent[x] == x.

  • find(x): follow parents upward until you reach the leader. Two people are in the same group exactly when find gives the same leader.
  • union(a, b): find both leaders. If they are the same, nothing to do (and if a and b were joined by an edge, that edge closes a cycle). Otherwise make one leader the parent of the other — two groups become one, so components goes down by 1.

Two tricks keep the trees flat: union by rank — hang the shorter tree under the taller one, so heights grow very slowly; path compression — after find(x) walks up, point every node on the way straight at the leader, so the next find is one hop. Together each operation is O(α(n)), which is at most 4 for any realistic n — practically constant.

Analogy

Clubs at a school. Each student knows who recruited them, and the chain ends at the club president. To check whether two students are in the same club, both ask up the chain until they reach a president. When two clubs merge, the smaller club's president simply starts reporting to the bigger club's president. And after someone asks up the chain once, they write down the president's name directly — next time it is one question.

Watch it work

1. Parent array and forest in sync. Six nodes, operations union(0,1), union(2,3), union(1,3), union(4,5), union(5,3), union(1,2), then find(5). Arrows point from a child to its parent.

2. Redundant Connection. Edges [1,2], [2,3], [3,4], [1,4], [1,5] — a tree plus one extra edge. Union the edges one by one; the first edge whose ends already share a leader is the one that makes a cycle.

Why it works

"Each group is a tree with one root, so 'same group' means 'same root'. Union by rank keeps every tree's height O(log n), and path compression flattens paths as we use them, giving O(α(n)) amortised per operation — effectively constant."

The template to remember

int[] parent = new int[n], rank = new int[n];  // parent[i] = i
int find(int x) {
    return parent[x] == x ? x : (parent[x] = find(parent[x]));
}
boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;
    if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
    parent[rb] = ra;
    if (rank[ra] == rank[rb]) rank[ra]++;
    components--; return true;
}

Union-find answers one question — "are these two in the same group?" — and its whole state is one int array. Every extra structure here only translates the problem's names (letters, emails, grid cells) into array indices.

Remember

Same root = same group. Union says false = this edge makes a cycle. Components = n − successful unions.

Common mistakes
  • Linking parent[a] = b instead of parent[find(a)] = find(b) — you must link the leaders, not the nodes.
  • Comparing parent[a] == parent[b] instead of find(a) == find(b).
  • Forgetting to initialise parent[i] = i (Java arrays start at 0 = everyone points at node 0).
  • Off-by-one when nodes are numbered 1..n — allocate n + 1.

Practice in this order

  • Medium323. Number of Connected Components — start at n, subtract every successful union.
    Show solution

    The idea

    n nodes, a list of undirected edges; how many separate groups (connected components) are there? Key insight with Union-Find (a structure where each node points to a leader, and find returns the group's leader): start with n groups of one. Every edge that joins two different groups merges them, so the count drops by 1. Edges inside one group change nothing.

    Step by step

    1. parent[i] = i: everyone is their own leader. components = n.
    2. For each edge, call union(a, b).
    3. union finds both leaders. If they are the same, return false. Otherwise point one leader at the other and return true.
    4. Subtract 1 for every true. Return components.

    Java

    class Solution {
    private int[] parent;

    public int countComponents(int n, int[][] edges) {
        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i; // own leader
        int components = n;            // everyone alone at first
        for (int[] e : edges) {
            if (union(e[0], e[1])) components--; // two merged
        }
        return components;
    }

    private int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]); // path compression
        }
        return parent[x];
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;    // already one group
        parent[ra] = rb;
        return true;
    }
}

    Time O(n + E·α(n)) · Space O(n) — α is the inverse-Ackermann function, effectively a constant; path compression keeps the trees flat.

    Dry run

    n = 5, edges 0–1, 1–2, 3–4. Start 5. Union 0,1 → 4. Union 1,2 → 3. Union 3,4 → 2. Answer 2.

    Watch out

    Always compare find(a) with find(b), never parent[a] with parent[b]; parents can differ while the leaders are equal. Adding union by size/rank makes the worst case safe too. DFS counting also works in O(n + E).

  • Medium547. Number of Provinces — same thing from a matrix.
    Show solution

    The idea

    Number of Provinces again, now with Union-Find instead of DFS. The matrix says which cities are directly connected. Key insight: start with n provinces and subtract 1 every time a 1 in the matrix joins two different groups. Pattern: Union-Find component counting.

    Step by step

    1. Set every city as its own leader; provinces = n.
    2. Loop over pairs i < j (the matrix is symmetric, so the upper half is enough).
    3. If isConnected[i][j] == 1 and union(i, j) merged two groups, subtract 1.
    4. Return provinces.

    Java

    class Solution {
    private int[] parent;

    public int findCircleNum(int[][] isConnected) {
        int n = isConnected.length;
        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;
        int provinces = n;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) { // upper half only
                if (isConnected[i][j] == 1 && union(i, j)) {
                    provinces--;
                }
            }
        }
        return provinces;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        parent[ra] = rb;
        return true;
    }
}

    Time O(n²·α(n)) · Space O(n) — every matrix cell above the diagonal is read once.

    Dry run

    [[1,1,0],[1,1,0],[0,0,1]]. Start 3. (0,1) is 1 → union → 2. (0,2) and (1,2) are 0. Answer 2.

    Watch out

    Subtract only when the union actually merged (returned true). Counting every 1 in the matrix counts the diagonal and both halves too.

  • Medium684. Redundant Connection — exactly animation 2.
    Show solution

    The idea

    A tree with n nodes got one extra edge, which created exactly one cycle. Return the edge that can be removed, and if several work, the one that appears last in the input. Key insight: add edges one by one with Union-Find. The first edge whose two ends are already connected closes the cycle, and because it is the last edge of that cycle in input order, it is the answer.

    Step by step

    1. Make a parent array for nodes 1..n.
    2. Go through the edges in order.
    3. If union(a, b) returns false, the two ends already had the same leader: return this edge.

    Java

    class Solution {
    private int[] parent;

    public int[] findRedundantConnection(int[][] edges) {
        int n = edges.length;          // nodes are 1..n
        parent = new int[n + 1];
        for (int i = 0; i <= n; i++) parent[i] = i;
        for (int[] e : edges) {
            // both ends already connected -> this edge
            // closes a loop, so it is the extra one
            if (!union(e[0], e[1])) return e;
        }
        return new int[0];             // never happens
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        parent[ra] = rb;
        return true;
    }
}

    Time O(n·α(n)) · Space O(n) — one union per edge.

    Dry run

    [[1,2],[1,3],[2,3]]. Union 1,2 ok. Union 1,3 ok (now 1, 2, 3 share a leader). Union 2,3: same leader → return [2,3].

    Watch out

    Nodes are numbered 1..n, so the parent array needs size n + 1. DFS works too (for each edge, check whether its ends are already reachable) but costs O(n²).

  • Medium990. Satisfiability of Equality Equations — union all "==", then check every "!=".
    Show solution

    The idea

    Equations like "a==b" and "b!=c" over single letters. Can all hold at once? Key insight: equality is transitive (a==b and b==c give a==c), so "==" builds groups, and Union-Find builds them. Do all unions first, then check each "!=": if both letters share a leader, they were forced equal, so it is impossible.

    Step by step

    1. Make a parent array of 26 letters.
    2. Pass 1: for each "x==y", union x and y.
    3. Pass 2: for each "x!=y", if find(x) == find(y), return false.
    4. Return true.

    Java

    class Solution {
    private final int[] parent = new int[26]; // a..z

    public boolean equationsPossible(String[] equations) {
        for (int i = 0; i < 26; i++) parent[i] = i;
        // pass 1: glue together everything that is equal
        for (String e : equations) {
            if (e.charAt(1) == '=') {
                union(e.charAt(0) - 'a', e.charAt(3) - 'a');
            }
        }
        // pass 2: a "!=" inside one group is a contradiction
        for (String e : equations) {
            if (e.charAt(1) == '!'
                    && find(e.charAt(0) - 'a')
                       == find(e.charAt(3) - 'a')) {
                return false;
            }
        }
        return true;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private void union(int a, int b) {
        parent[find(a)] = find(b);
    }
}

    Time O(n·α(26)) · Space O(1) — two passes over n equations; the array has 26 slots.

    Dry run

    ["a==b","b==c","a!=c"]. Pass 1: a, b, c in one group. Pass 2: a!=c, but find(a) == find(c) → false.

    Watch out

    Checking "!=" while still doing unions (in one pass) is wrong: a later "==" can join letters you already accepted as different. And "a!=a" must return false, which the check handles since a's leader equals itself.

  • Medium721. Accounts Merge — union emails, group by leader.
    Show solution

    The idea

    Each account is a name plus emails. Two accounts belong to the same person if they share any email, and this chains (A shares with B, B with C). Merge them and return each person's name with sorted emails. Key insight: Union-Find over accounts. Map each email to the first account that had it; when a later account lists the same email, union the two accounts. Then group every email under its account's leader.

    Step by step

    1. One Union-Find node per account.
    2. For each email in account i: if the map has no owner yet, owner = i; otherwise union(owner, i).
    3. For each email in the map, find the leader of its owner and add the email to that leader's sorted set (TreeSet).
    4. For each group, output the leader's name followed by its sorted emails.

    Java

    class Solution {
    private int[] parent;

    public List<List<String>> accountsMerge(
            List<List<String>> accounts) {
        int n = accounts.size();
        parent = new int[n];           // one node per account
        for (int i = 0; i < n; i++) parent[i] = i;
        // email -> first account that listed it
        Map<String, Integer> owner = new HashMap<>();
        for (int i = 0; i < n; i++) {
            List<String> acc = accounts.get(i);
            for (int j = 1; j < acc.size(); j++) {
                Integer prev = owner.putIfAbsent(acc.get(j), i);
                if (prev != null) union(prev, i); // shared email
            }
        }
        // leader account -> its emails, kept sorted
        Map<Integer, TreeSet<String>> groups = new HashMap<>();
        for (var entry : owner.entrySet()) {
            int leader = find(entry.getValue());
            groups.computeIfAbsent(leader, k -> new TreeSet<>())
                  .add(entry.getKey());
        }
        List<List<String>> result = new ArrayList<>();
        for (var entry : groups.entrySet()) {
            List<String> row = new ArrayList<>();
            row.add(accounts.get(entry.getKey()).get(0)); // name
            row.addAll(entry.getValue());
            result.add(row);
        }
        return result;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private void union(int a, int b) {
        parent[find(a)] = find(b);
    }
}

    Time O(N log N) · Space O(N) — N = total emails; sorting the emails dominates, the unions are nearly O(1).

    Dry run

    Accounts 0: John [js, jny], 1: John [js, j00], 2: Mary [m], 3: John [jb]. js is seen in 0 then in 1 → union(0, 1). Groups: leader of 0 and 1 → {j00, jny, js}, 2 → {m}, 3 → {jb}. Three accounts out.

    Watch out

    Two different people can share a name, so never merge by name, only by email. Remember to put the name first in each output row, and sort the emails.

  • Hard305. Number of Islands II — land arrives one cell at a time; union with land neighbours.
    Show solution

    The idea

    An m×n grid starts as all water. Land is added one cell at a time; after each addition, report the number of islands. Key insight: rerunning a flood fill after every addition is too slow. With Union-Find, a new land cell adds 1 island, then each successful union with a land neighbour removes 1, because two islands just became one. Pattern: online (incremental) Union-Find.

    Brute force first

    After each addition, count islands with DFS: O(k·m·n) for k positions.

    Step by step

    1. Number each cell r·n + c. parent = −1 means water.
    2. For a new position: if it is already land, just repeat the current count.
    3. Otherwise set parent[id] = id and add 1 to islands.
    4. For each of the 4 neighbours that is land, if union merged two groups, subtract 1.
    5. Append the count.

    Java

    class Solution {
    private int[] parent;

    public List<Integer> numIslands2(int m, int n,
                                     int[][] positions) {
        parent = new int[m * n];
        Arrays.fill(parent, -1);       // -1 = still water
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        List<Integer> result = new ArrayList<>();
        int islands = 0;
        for (int[] p : positions) {
            int id = p[0] * n + p[1];  // cell -> one number
            if (parent[id] != -1) {    // already land
                result.add(islands);
                continue;
            }
            parent[id] = id;
            islands++;                 // a new island of 1 cell
            for (int[] d : dirs) {
                int r = p[0] + d[0], c = p[1] + d[1];
                if (r < 0 || c < 0 || r >= m || c >= n) continue;
                int nb = r * n + c;
                if (parent[nb] != -1 && union(id, nb)) {
                    islands--;         // merged with a neighbour
                }
            }
            result.add(islands);
        }
        return result;
    }

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        parent[ra] = rb;
        return true;
    }
}

    Time O(m·n + k·α(m·n)) · Space O(m·n) — the array is filled once; each position does 4 near-constant unions.

    Dry run

    3×3, positions (0,0), (0,1), (1,2), (2,1). (0,0) → 1. (0,1) → 2, merges with (0,0) → 1. (1,2) → 2, no land neighbour. (2,1) → 3. Output [1,1,2,3].

    Watch out

    The same position can be added twice; without the "already land" check you count it as a new island. Two neighbours may already be in the same island, which is why you subtract only when union returns true.

Test yourself

When is Union-Find better than BFS/DFS for counting components?

When edges arrive one at a time and you must answer after each (online), or when you only need "same group?" checks. BFS would have to restart each time.

What does path compression change in the parent array?

Every node visited by find gets parent[x] = root, so the tree becomes flatter; the groups themselves do not change.

A graph with n nodes has n − 1 edges and union never returns false. What is it?

A tree: connected (n − 1 successful unions leave 1 component) and acyclic (no union failed).
