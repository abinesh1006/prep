Union-Find (Disjoint Set Union)

Keep groups as little trees stored in one parent array: find walks up to a group's leader, union hangs one leader under another, and two small tricks make both almost O(1).

Time to learn: about 2 hours · Prerequisites: Graph basics, Recursion

When to use it — the signal

"Number of connected components", "are x and y in the same group", "merge accounts / friend circles / provinces", "which edge makes a cycle (redundant connection)", edges arriving one at a time, Kruskal's MST.

The idea in plain words

Start with 6 people, each in their own group of 1. Every group has a leader (called the root). Each person only remembers one thing: parent[x] = someone above them in their group. A leader is their own parent: parent[x] == x.

  • find(x): follow parents upward until you reach the leader. Two people are in the same group exactly when find gives the same leader.
  • union(a, b): find both leaders. If they are the same, nothing to do (and if a and b were joined by an edge, that edge closes a cycle). Otherwise make one leader the parent of the other — two groups become one, so components goes down by 1.

Two tricks keep the trees flat: union by rank — hang the shorter tree under the taller one, so heights grow very slowly; path compression — after find(x) walks up, point every node on the way straight at the leader, so the next find is one hop. Together each operation is O(α(n)), which is at most 4 for any realistic n — practically constant.

Analogy

Clubs at a school. Each student knows who recruited them, and the chain ends at the club president. To check whether two students are in the same club, both ask up the chain until they reach a president. When two clubs merge, the smaller club's president simply starts reporting to the bigger club's president. And after someone asks up the chain once, they write down the president's name directly — next time it is one question.

Watch it work

1. Parent array and forest in sync. Six nodes, operations union(0,1), union(2,3), union(1,3), union(4,5), union(5,3), union(1,2), then find(5). Arrows point from a child to its parent.

2. Redundant Connection. Edges [1,2], [2,3], [3,4], [1,4], [1,5] — a tree plus one extra edge. Union the edges one by one; the first edge whose ends already share a leader is the one that makes a cycle.

Why it works

"Each group is a tree with one root, so 'same group' means 'same root'. Union by rank keeps every tree's height O(log n), and path compression flattens paths as we use them, giving O(α(n)) amortised per operation — effectively constant."

The template to remember

int[] parent = new int[n], rank = new int[n];  // parent[i] = i
int find(int x) {
    return parent[x] == x ? x : (parent[x] = find(parent[x]));
}
boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;
    if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
    parent[rb] = ra;
    if (rank[ra] == rank[rb]) rank[ra]++;
    components--; return true;
}
Remember

Same root = same group. Union says false = this edge makes a cycle. Components = n − successful unions.

Common mistakes
  • Linking parent[a] = b instead of parent[find(a)] = find(b) — you must link the leaders, not the nodes.
  • Comparing parent[a] == parent[b] instead of find(a) == find(b).
  • Forgetting to initialise parent[i] = i (Java arrays start at 0 = everyone points at node 0).
  • Off-by-one when nodes are numbered 1..n — allocate n + 1.

Test yourself

When is Union-Find better than BFS/DFS for counting components?

When edges arrive one at a time and you must answer after each (online), or when you only need "same group?" checks. BFS would have to restart each time.

What does path compression change in the parent array?

Every node visited by find gets parent[x] = root, so the tree becomes flatter; the groups themselves do not change.

A graph with n nodes has n − 1 edges and union never returns false. What is it?

A tree: connected (n − 1 successful unions leave 1 component) and acyclic (no union failed).
