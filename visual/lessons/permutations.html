Pattern 40 · Backtracking

Permutations

Fill the answer one slot at a time with any number you have not used yet; a used[] array remembers which ones are taken.

Time to learn: about 2 hours · Prerequisites: Backtracking, Recursion

When to use it — the signal

"Return all permutations", "all possible orderings / arrangements", "every way to arrange these letters", "next permutation". Order matters: [1,2] and [2,1] are different answers. If the input "may contain duplicates", you also need the sort-and-skip rule.

The idea in plain words

A permutation of [1, 2, 3] is the three numbers in some order. There are 3 × 2 × 1 = 6 of them: 3 choices for the first slot, 2 left for the second, 1 for the last.

This is the backtracking pattern, with one difference from subsets: at every slot you may pick any number that is not already in the path — even one to the left. So the loop always starts at index 0, and a boolean array used[i] says "nums[i] is already in the path, skip it".

  • Choose: mark used[i] = true and add nums[i] to the path.
  • Explore: recurse to fill the next slot.
  • Un-choose: set used[i] = false and remove the last number.
  • When the path has all n numbers, save a copy.

Duplicates. With [1, 1, 2] the plain method makes [1,1,2] twice (first 1 then second 1, and the other way round). Fix: sort so equal numbers sit next to each other, then skip a number if it equals the one before it and the one before it is not in use. That forces equal copies to be used in left-to-right order only, so each distinct arrangement is built once.

Analogy

Seating guests at a row of chairs. For the first chair you may pick any guest. Once someone sits, they wear a "seated" badge (used[]). For the next chair you only look at guests without a badge. When you take someone off a chair to try another seating, you take their badge off too. If two guests are identical twins, swapping them gives the same photo — so the younger twin may only sit after the older one.

Watch it work

All permutations of [1, 2, 3]. The yellow cells in used[] are the numbers already in the path.

Duplicates: [1, 1, 2]

After sorting, the two 1s sit side by side (index 0 and index 1). The rule: skip nums[i] if it equals nums[i−1] and used[i−1] is false. In words: the second 1 may only be picked when the first 1 is already in the path. Red = skipped by this rule.

Why it works

"Each level of the recursion fills one slot, and used[] guarantees each element appears once in the path, so we generate exactly the n! orderings. For duplicates, sorting groups equal values and the !used[i-1] rule fixes the order in which equal copies may be used, so two identical arrangements are never built."

Cost: O(n · n!) — n! answers, each copied in O(n). n is at most about 8–10 in these problems.

The template to remember

for (int i = 0; i < n; i++) {             // 0, not start: order matters
    if (used[i]) continue;
    if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue; // duplicates only
    used[i] = true;  path.add(nums[i]);
    backtrack(nums, used, path);
    used[i] = false; path.remove(path.size() - 1);
}
Remember

Order matters → loop from 0 with used[]. Duplicates → sort + skip if twin is unused.

Common mistakes
  • Forgetting to sort before applying the duplicate rule — equal values are not neighbours, so the rule does nothing.
  • Writing used[i-1] instead of !used[i-1]. Surprisingly, both give the right answer, but !used prunes much earlier — use it and know why.
  • Using path.contains(x) instead of used[] — O(n) per check, and wrong when values repeat.
  • Forgetting used[i] = false on the way back.

Test yourself

Why does the permutation loop start at 0 but the subset loop at start?

In permutations order matters, so a number to the left may still go in a later slot. In subsets order does not matter, so we only look right to avoid building {1,2} and {2,1}.

How many permutations does [1, 1, 2, 2] have?

4! / (2! · 2!) = 6. The duplicate rule produces exactly these 6.

What does !used[i-1] mean in plain words?

"The identical number just before me is not in the path right now — it was already tried in this same slot and un-chosen. Picking me here would rebuild the same branch."
