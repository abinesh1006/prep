Permutations

Fill the answer one slot at a time with any number you have not used yet; a used[] array remembers which ones are taken.

Time to learn: about 2 hours · Prerequisites: Backtracking, Recursion

When to use it — the signal

"Return all permutations", "all possible orderings / arrangements", "every way to arrange these letters", "next permutation". Order matters: [1,2] and [2,1] are different answers. If the input "may contain duplicates", you also need the sort-and-skip rule.

The idea in plain words

A permutation of [1, 2, 3] is the three numbers in some order. There are 3 × 2 × 1 = 6 of them: 3 choices for the first slot, 2 left for the second, 1 for the last.

This is the backtracking pattern, with one difference from subsets: at every slot you may pick any number that is not already in the path — even one to the left. So the loop always starts at index 0, and a boolean array used[i] says "nums[i] is already in the path, skip it".

  • Choose: mark used[i] = true and add nums[i] to the path.
  • Explore: recurse to fill the next slot.
  • Un-choose: set used[i] = false and remove the last number.
  • When the path has all n numbers, save a copy.

Duplicates. With [1, 1, 2] the plain method makes [1,1,2] twice (first 1 then second 1, and the other way round). Fix: sort so equal numbers sit next to each other, then skip a number if it equals the one before it and the one before it is not in use. That forces equal copies to be used in left-to-right order only, so each distinct arrangement is built once.

Analogy

Seating guests at a row of chairs. For the first chair you may pick any guest. Once someone sits, they wear a "seated" badge (used[]). For the next chair you only look at guests without a badge. When you take someone off a chair to try another seating, you take their badge off too. If two guests are identical twins, swapping them gives the same photo — so the younger twin may only sit after the older one.

Watch it work

All permutations of [1, 2, 3]. The yellow cells in used[] are the numbers already in the path.

Duplicates: [1, 1, 2]

After sorting, the two 1s sit side by side (index 0 and index 1). The rule: skip nums[i] if it equals nums[i−1] and used[i−1] is false. In words: the second 1 may only be picked when the first 1 is already in the path. Red = skipped by this rule.

Why it works

"Each level of the recursion fills one slot, and used[] guarantees each element appears once in the path, so we generate exactly the n! orderings. For duplicates, sorting groups equal values and the !used[i-1] rule fixes the order in which equal copies may be used, so two identical arrangements are never built."

Cost: O(n · n!) — n! answers, each copied in O(n). n is at most about 8–10 in these problems.

The template to remember

for (int i = 0; i < n; i++) {             // 0, not start: order matters
    if (used[i]) continue;
    if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue; // duplicates only
    used[i] = true;  path.add(nums[i]);
    backtrack(nums, used, path);
    used[i] = false; path.remove(path.size() - 1);
}
Remember

Order matters → loop from 0 with used[]. Duplicates → sort + skip if twin is unused.

Common mistakes
  • Forgetting to sort before applying the duplicate rule — equal values are not neighbours, so the rule does nothing.
  • Writing used[i-1] instead of !used[i-1]. Surprisingly, both give the right answer, but !used prunes much earlier — use it and know why.
  • Using path.contains(x) instead of used[] — O(n) per check, and wrong when values repeat.
  • Forgetting used[i] = false on the way back.

Practice in this order

  • Medium46. Permutations — the first animation.
    Show solution

    The idea

    Given distinct numbers, list every ordering. [1,2,3] → 6 orderings (3! = 3×2×1). Think of n empty slots: fill slot 1 with any unused number, slot 2 with any number still unused, and so on. A used[] array remembers which numbers are already in the current ordering. Pattern: backtracking (choose, explore, un-choose).

    Step by step

    1. Keep a path (the ordering being built) and used[i] flags.
    2. If path has n numbers, save a copy of it.
    3. Otherwise try every index i that is not used: mark it, add nums[i], recurse.
    4. After the recursive call returns, remove the number and clear the flag so the next choice starts clean.

    Java

    class Solution {
    public List<List<Integer>> permute(int[] nums) {
        List<List<Integer>> res = new ArrayList<>();
        boolean[] used = new boolean[nums.length];
        build(nums, used, new ArrayList<>(), res);
        return res;
    }

    void build(int[] nums, boolean[] used,
               List<Integer> path, List<List<Integer>> res) {
        if (path.size() == nums.length) { // every slot filled
            res.add(new ArrayList<>(path)); // save a copy
            return;
        }
        for (int i = 0; i < nums.length; i++) {
            if (used[i]) continue; // already placed
            used[i] = true;
            path.add(nums[i]);              // choose
            build(nums, used, path, res);   // explore
            path.remove(path.size() - 1);   // un-choose
            used[i] = false;
        }
    }
}

    Time O(n · n!) · Space O(n) — n! orderings, each copied in O(n); the recursion and path are n deep (output not counted).

    Dry run

    [1,2,3]: pick 1 → pick 2 → pick 3 → save [1,2,3]; undo 3, undo 2, pick 3 → pick 2 → save [1,3,2]; undo back to the empty path, pick 2 first … six saves in total.

    Watch out

    Save new ArrayList<>(path), not path itself: the same list object keeps changing, and you would end up with n! references to one empty list.

  • Medium47. Permutations II — the second animation.
    Show solution

    The idea

    Same as Permutations, but the input may have repeats, and [1,1,2] must give only 3 orderings, not 6. Sort so equal values sit together. Then, for one slot, only the first unused copy of a value may be tried; a later twin would build exactly the same orderings again. Pattern: backtracking with duplicate skipping.

    Brute force first

    Generate all n! orderings and drop repeats with a Set: correct but wastes time on duplicates and memory on the set.

    Step by step

    1. Sort nums.
    2. Build orderings exactly as in problem 46 with used[].
    3. Skip index i when nums[i] == nums[i-1] and used[i-1] is false: the twin on the left was already tried in this slot and then released.
    4. Save a copy when the path is full.

    Java

    class Solution {
    public List<List<Integer>> permuteUnique(int[] nums) {
        Arrays.sort(nums); // equal values side by side
        List<List<Integer>> res = new ArrayList<>();
        build(nums, new boolean[nums.length],
              new ArrayList<>(), res);
        return res;
    }

    void build(int[] nums, boolean[] used,
               List<Integer> path, List<List<Integer>> res) {
        if (path.size() == nums.length) {
            res.add(new ArrayList<>(path));
            return;
        }
        for (int i = 0; i < nums.length; i++) {
            if (used[i]) continue;
            // same value as the left twin, and the twin is
            // not in the path: this slot already tried it
            if (i > 0 && nums[i] == nums[i - 1]
                    && !used[i - 1]) continue;
            used[i] = true;
            path.add(nums[i]);
            build(nums, used, path, res);
            path.remove(path.size() - 1);
            used[i] = false;
        }
    }
}

    Time O(n · n!) worst case · Space O(n) — at most n! orderings (fewer with repeats); recursion depth n.

    Dry run

    [1,1,2] (indexes a, b, c). Slot 1: try 1a → builds [1,1,2] and [1,2,1]. Back in slot 1, 1b is skipped (1a is not used, same value). Try 2 → [2,1,1] (inside, 1b is skipped again after 1a is released). 3 orderings.

    Watch out

    The condition is !used[i-1]. Using used[i-1] also gives correct answers but explores far more dead branches. Forgetting to sort breaks the skip entirely.

  • Medium784. Letter Case Permutation — two choices per letter.
    Show solution

    The idea

    For each letter you may write it lower or upper case; digits stay as they are. "a1b2" → 2 letters → 2×2 = 4 strings. Walk the string left to right and branch only on letters. Pattern: backtracking with two choices per position (a binary decision tree).

    Step by step

    1. Turn the string into a char[] you can change in place.
    2. At index i: if it is the end, save the string.
    3. If c[i] is a digit, just move to i + 1.
    4. If it is a letter, set it lower and recurse, then set it upper and recurse.

    Java

    class Solution {
    public List<String> letterCasePermutation(String s) {
        List<String> res = new ArrayList<>();
        build(s.toCharArray(), 0, res);
        return res;
    }

    void build(char[] c, int i, List<String> res) {
        if (i == c.length) { // decided every char
            res.add(new String(c));
            return;
        }
        if (Character.isDigit(c[i])) {  // digit: one choice
            build(c, i + 1, res);
            return;
        }
        c[i] = Character.toLowerCase(c[i]);
        build(c, i + 1, res);           // choice 1: lower
        c[i] = Character.toUpperCase(c[i]);
        build(c, i + 1, res);           // choice 2: upper
    }
}

    Time O(2L · n) · Space O(n) — L letters give 2L strings of length n; recursion depth n.

    Dry run

    "3z4": '3' digit → 'z' lower → '4' digit → save "3z4"; back, 'Z' upper → save "3Z4". Result ["3z4","3Z4"].

    Watch out

    No explicit undo is needed because each branch overwrites c[i] before recursing. Do not branch on digits, or you will save each string twice.

  • Medium17. Letter Combinations of a Phone Number — one slot per digit.
    Show solution

    The idea

    Each digit 2–9 maps to letters on an old phone keypad. "23" → pick one of "abc", then one of "def" → 9 strings. One slot per digit, try every letter in that slot. Pattern: backtracking over a fixed number of slots.

    Step by step

    1. Store the keypad as an array KEYS[digit].
    2. If the input is empty, return an empty list.
    3. At position i, loop over the letters of digits[i]: append one, recurse to i + 1, delete it.
    4. When i reaches the end, save the built string.

    Java

    class Solution {
    static final String[] KEYS = {"", "", "abc", "def",
        "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"};

    public List<String> letterCombinations(String digits) {
        List<String> res = new ArrayList<>();
        if (digits.isEmpty()) return res;  // "" gives []
        build(digits, 0, new StringBuilder(), res);
        return res;
    }

    void build(String d, int i, StringBuilder sb,
               List<String> res) {
        if (i == d.length()) { // one letter per digit
            res.add(sb.toString());
            return;
        }
        String keys = KEYS[d.charAt(i) - '0'];
        for (char ch : keys.toCharArray()) {
            sb.append(ch);                  // choose
            build(d, i + 1, sb, res);       // next digit
            sb.deleteCharAt(sb.length() - 1); // undo
        }
    }
}

    Time O(4n · n) · Space O(n) — at most 4 letters per digit (7 and 9), each result has length n.

    Dry run

    "23": 'a' then 'd','e','f' → ad, ae, af; 'b' → bd, be, bf; 'c' → cd, ce, cf.

    Watch out

    "" must return [], not [""]; without the early return the recursion saves one empty string.

  • Medium31. Next Permutation — not backtracking: find the dip from the right, swap, reverse.
    Show solution

    The idea

    Rearrange the array into the next bigger ordering in dictionary order (wrap to the smallest if it is already the biggest). [1,2,3] → [1,3,2]. From the right, the longest descending tail cannot grow any bigger, so change the number just before it (the "dip"): swap it with the smallest bigger number in the tail, then make the tail as small as possible by reversing it. Pattern: scan from the right + swap + reverse.

    Brute force first

    List all permutations in sorted order and find the one after the current: O(n · n!), hopeless past n = 10.

    Step by step

    1. Walk i from n-2 down while nums[i] >= nums[i+1]; stop at the first dip.
    2. If a dip exists, walk j from the end down to the first nums[j] > nums[i] and swap them.
    3. Reverse nums[i+1..end] (it is descending, reversing makes it ascending).
    4. If there was no dip (i = -1), the reverse alone turns the biggest ordering into the smallest.

    Java

    class Solution {
    public void nextPermutation(int[] nums) {
        int i = nums.length - 2;
        // 1. from the right, find the first "dip"
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;
        if (i >= 0) {
            // 2. rightmost number bigger than nums[i]
            int j = nums.length - 1;
            while (nums[j] <= nums[i]) j--;
            swap(nums, i, j);
        }
        // 3. the tail is descending: reverse to ascending
        reverse(nums, i + 1, nums.length - 1);
    }

    void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }

    void reverse(int[] a, int l, int r) {
        while (l < r) swap(a, l++, r--);
    }
}

    Time O(n) · Space O(1) — at most three linear passes, all in place.

    Dry run

    [1,3,2]: from the right 3 > 2, then 1 < 3 → dip at i = 0 (value 1). Rightmost bigger than 1 is 2 (j = 2); swap → [2,3,1]. Reverse tail [3,1] → [2,1,3].

    Watch out

    Use >= and <= in the two scans so duplicates work ([1,5,1] → [5,1,1]). Swap with the rightmost bigger value, not the first one you meet from the left.

  • Hard60. Permutation Sequence — count blocks of (n−1)! instead of generating.
    Show solution

    The idea

    Return the k-th ordering of 1..n in sorted order without listing them. For n = 4, the orderings starting with 1 are the first 3! = 6, those starting with 2 are the next 6, and so on. So (k-1) / 3! tells you the first digit; repeat with the remainder for the next slot. Pattern: counting blocks with factorials (factorial number system).

    Brute force first

    Generate orderings in order (or call Next Permutation k-1 times): O(k · n), up to 9! × 9 steps.

    Step by step

    1. Precompute factorials and a list of unused digits 1..n.
    2. Make k 0-based: k--.
    3. For each slot, block size = (digits left − 1)!. Index = k / block.
    4. Take and remove that digit from the list, set k %= block, continue.

    Java

    class Solution {
    public String getPermutation(int n, int k) {
        List<Integer> left = new ArrayList<>();
        int[] fact = new int[n + 1];
        fact[0] = 1;
        for (int i = 1; i <= n; i++) {
            fact[i] = fact[i - 1] * i;
            left.add(i); // digits 1..n unused
        }
        k--;                             // make k 0-based
        StringBuilder sb = new StringBuilder();
        for (int slot = n; slot >= 1; slot--) {
            int block = fact[slot - 1]; // perms per digit
            int idx = k / block; // which block k is in
            sb.append(left.remove(idx));
            k %= block; // position in the block
        }
        return sb.toString();
    }
}

    Time O(n2) · Space O(n) — n slots, each remove from the list costs O(n); n ≤ 9 so it is tiny.

    Dry run

    n = 4, k = 9 → k = 8. Block 6: 8/6 = 1 → digit 2, k = 2, left [1,3,4]. Block 2: 2/2 = 1 → 3, k = 0, left [1,4]. Block 1: 0 → 1, then 4. Answer "2314".

    Watch out

    Forgetting k-- is the classic off-by-one: with 1-based k the last ordering of each block lands in the next block.

Test yourself

Why does the permutation loop start at 0 but the subset loop at start?

In permutations order matters, so a number to the left may still go in a later slot. In subsets order does not matter, so we only look right to avoid building {1,2} and {2,1}.

How many permutations does [1, 1, 2, 2] have?

4! / (2! · 2!) = 6. The duplicate rule produces exactly these 6.

What does !used[i-1] mean in plain words?

"The identical number just before me is not in the path right now — it was already tried in this same slot and un-chosen. Picking me here would rebuild the same branch."
