Pattern 14 · Linked lists

Fast and Slow Pointers

Two pointers walk the same list at different speeds (or with a fixed gap). Where they are when one finishes tells you the middle, whether there is a loop, where the loop starts, or which node is n-th from the end.

Time to learn: about 2 hours · Prerequisites: Reverse a linked list, Two pointers

When to use it — the signal

A linked list (or a "next" function like i → nums[i]) and the words "middle", "cycle" / "loop", "where the cycle begins", "n-th from the end", "palindrome list", "happy number", "find the duplicate with O(1) space". You cannot index a list, and you want one pass with O(1) memory.

The idea in plain words

  • Middle: slow moves 1 node per turn, fast moves 2. When fast reaches the end of a 5-node list, it has walked 4 nodes and slow has walked 2 — slow is on node 3, the middle. No need to count the length first.
  • Cycle: if the last node points back into the list, fast never reaches null — it goes round and round. Inside the loop fast gains one node on slow every turn, so it must eventually land on the same node as slow. Meeting = there is a cycle. Reaching null = there is not.
  • Cycle start: after they meet, put one pointer back at the head and move both one step at a time. They meet again exactly at the first node of the loop (a neat bit of arithmetic, explained below).
  • N-th from the end: start fast n nodes ahead of slow, then move both one step at a time. When fast falls off the end, slow is exactly n nodes behind it — at the node you want.
Analogy

Two runners on a track. If the track is a straight road, the fast runner just reaches the end first. If it is a circular track, the fast runner laps the slow one and they meet — that is how you know the road loops. And if two friends walk holding a 2-metre rope, when the front one reaches the wall, the back one is exactly 2 metres from it.

Watch it work

Middle of the list, first with 5 nodes, then with 6. Blue = slow, orange = fast.

Cycle detection and cycle start (Floyd's algorithm). Node 6 points back to node 3, so the list loops 3 → 4 → 5 → 6 → 3 forever. Blue = slow, orange = fast, green = they are on the same node.

Remove the 2nd node from the end of 1 → 2 → 3 → 4 → 5 (that is node 4), in one pass. A dummy node D in front lets slow stop before the node to delete, even when it is the head.

Why it works

"Fast covers twice the distance of slow, so when fast is at the end slow is halfway. In a cycle, fast closes the gap by one node every step, so it cannot jump over slow and they must meet. If the tail before the loop has length a and they meet b steps into the loop of length c, then 2(a + b) = a + b + kc, so a = kc − b: walking a steps from the head and a steps from the meeting point lands both on the loop start."

The template to remember

ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) { /* cycle: reset one to head, both step 1 */ }
}
// no cycle: slow is the middle
// n-th from end: fast goes n (+1 with dummy) ahead, then both step 1
Remember

1 step and 2 steps: middle, cycle. Meet → restart one at head, both 1 step: cycle start. Fixed gap: n-th from the end.

Common mistakes
  • Loop condition fast.next != null alone — crashes when fast itself is null. Check fast != null && fast.next != null.
  • Comparing values (slow.val == fast.val) instead of nodes (slow == fast) — two different nodes can hold the same value.
  • Remove-nth without a dummy: removing the head (n = length) needs a special case.
  • For "first middle" of an even list (needed when splitting for merge sort), start fast at head.next.

Practice in this order

  • Easy876. Middle of the Linked List — first animation.
    Show solution

    The idea

    Return the middle node; with an even count return the second middle (1→2→3→4 gives 3). Send a slow pointer one step and a fast pointer two steps at a time. When fast falls off the end, slow has gone exactly half as far. Pattern: fast and slow pointers.

    Brute force first

    Count the nodes in one pass, then walk count / 2 steps in a second pass. Also O(n), but two passes.

    Step by step

    1. Start slow and fast at head.
    2. While fast and fast.next are not null: slow one step, fast two steps.
    3. Return slow.

    Java

    class Solution {
    public ListNode middleNode(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;       // 1 step
            fast = fast.next.next;  // 2 steps
        }
        return slow;
    }
}

    Time O(n) · Space O(1) — fast covers the list once; two pointers only.

    Dry run

    1-2-3-4-5     slow  fast
start         1     1
step 1        2     3
step 2        3     5   (fast.next is null) -> 3

    Watch out

    The loop condition decides which middle you get: fast != null && fast.next != null gives the second middle. Check fast before fast.next or you get a NullPointerException.

  • Easy141. Linked List Cycle — meet or reach null.
    Show solution

    The idea

    Does the list loop back on itself? If there is a cycle, a fast runner (2 steps) laps a slow runner (1 step) and they meet; if there is no cycle, fast reaches null. This is Floyd's cycle detection (tortoise and hare).

    Brute force first

    Store every visited node in a HashSet; seeing a node twice means a cycle. O(n) time, O(n) space.

    Step by step

    1. slow = fast = head.
    2. While fast and fast.next exist: move slow 1, fast 2.
    3. If they point to the same node, return true.
    4. Loop ended → fast hit null → return false.

    Java

    class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) return true; // lapped
        }
        return false; // fast fell off the end
    }
}

    Time O(n) · Space O(1) — inside the cycle the gap shrinks by one each step, so they meet within one lap.

    Dry run

    3→2→0→-4→(back to 2): slow 2, fast 0; slow 0, fast 2; slow -4, fast -4 → meet → true.

    Watch out

    Compare node references (slow == fast), not values; two different nodes can hold the same value. Check after moving, not before, since both start at head.

  • Easy202. Happy Number — "next" is the digit-square sum; detect the loop.
    Show solution

    The idea

    Replace n by the sum of the squares of its digits, again and again. Happy if it reaches 1 (19 → 82 → 68 → 100 → 1). Otherwise the numbers repeat in a loop forever. Treat "next number" as a next pointer and run Floyd's cycle detection on it: slow applies the step once, fast twice.

    Brute force first

    Keep a HashSet of numbers seen; stop at 1 (happy) or a repeat (not happy). O(log n) space per step, also accepted.

    Step by step

    1. Write next(n): sum of squares of the digits.
    2. slow = n, fast = next(n).
    3. While fast != 1 and slow != fast: slow = next(slow), fast = next(next(fast)).
    4. Return fast == 1.

    Java

    class Solution {
    private int next(int n) {
        int sum = 0;
        while (n > 0) {
            int d = n % 10;   // last digit
            sum += d * d;
            n /= 10;
        }
        return sum;
    }

    public boolean isHappy(int n) {
        int slow = n, fast = next(n);
        while (fast != 1 && slow != fast) {
            slow = next(slow);
            fast = next(next(fast));
        }
        return fast == 1;
    }
}

    Time O(log n) · Space O(1) — each step shrinks the number to at most 243 quickly, and the loop it falls into is short.

    Dry run

    n = 2: values go 2, 4, 16, 37, 58, 89, 145, 42, 20, 4, … (a loop). Slow and fast meet inside it at a number that is not 1 → false.

    Watch out

    Start fast one step ahead (or check after moving), otherwise slow == fast is true immediately. Also 1 is a fixed point (next(1) = 1), so stopping on fast == 1 is safe.

  • Medium142. Linked List Cycle II — second animation.
    Show solution

    The idea

    Return the node where the cycle begins (or null). First detect the cycle with slow/fast. Then the key fact: the distance from head to the cycle start equals the distance from the meeting point to the cycle start (going round). So restart one pointer at head and move both one step at a time; they meet at the start. Pattern: Floyd, phase 2.

    Brute force first

    Walk the list adding nodes to a HashSet; the first node already in the set is the start. O(n) space.

    Step by step

    1. Run slow (1 step) and fast (2 steps) until they meet; if fast hits null, return null.
    2. Put a new pointer p at head; keep slow at the meeting point.
    3. Move p and slow one step each until they are the same node.
    4. Return that node.

    Java

    class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {          // phase 1 done
                ListNode p = head;
                while (p != slow) {      // phase 2
                    p = p.next;
                    slow = slow.next;
                }
                return p;                // cycle start
            }
        }
        return null;                     // no cycle
    }
}

    Time O(n) · Space O(1) — each phase is at most a couple of passes over the list.

    Dry run

    Why it works: let a = steps from head to start, b = start to meeting point, c = cycle length. Fast walked twice as far: 2(a+b) = a+b+k·c, so a = k·c − b. Walking a steps from the meeting point lands exactly on the start. Example 3→2→0→-4→2…: meet at -4; p from 3 and slow from -4 both reach 2 after one step.

    Watch out

    Phase 2 must move both pointers one step at a time. Return null (not head) when there is no cycle.

  • Medium19. Remove Nth Node From End — third animation.
    Show solution

    The idea

    Remove the n-th node counting from the end: 1→2→3→4→5, n=2 removes 4. Put a lead pointer n steps ahead of a trailing one; when the lead reaches the last node, the trailing one is just before the node to delete. One pass. A dummy node handles deleting the head.

    Brute force first

    Count the length L, then walk to node L−n and unlink the next one. Two passes, still O(n).

    Step by step

    1. dummy → head; fast = slow = dummy.
    2. Move fast forward n steps.
    3. Move both until fast.next is null.
    4. slow.next = slow.next.next removes the target. Return dummy.next.

    Java

    class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        ListNode fast = dummy, slow = dummy;
        // open a gap of n nodes
        for (int i = 0; i < n; i++) fast = fast.next;
        while (fast.next != null) {
            fast = fast.next;
            slow = slow.next;
        }
        slow.next = slow.next.next; // skip the target
        return dummy.next;
    }
}

    Time O(n) · Space O(1) — one pass with a fixed gap.

    Dry run

    d-1-2-3-4-5, n=2
fast moves 2: fast=2, slow=d
move both:    fast=5, slow=3   (fast.next null)
3.next = 5  -> 1-2-3-5

    Watch out

    Without the dummy, removing the head (n = length) breaks. Stop at fast.next == null so slow sits before the target.

  • Medium287. Find the Duplicate Number — treat i → nums[i] as a list; the duplicate is the cycle start.
    Show solution

    The idea

    nums has n+1 numbers, each in 1..n, so one value repeats; find it without changing the array and with O(1) extra space. Think of each index i as a node whose next is nums[i]. Two indices point at the duplicate value, so the path from index 0 runs into a cycle, and the cycle's entrance is the duplicate. Use Floyd's cycle start (same as 142).

    Brute force first

    Sort a copy and look for equal neighbours (O(n log n)), or use a HashSet (O(n) space). Both break a rule of the problem.

    Step by step

    1. slow = nums[0], fast = nums[nums[0]].
    2. Move slow one hop (slow = nums[slow]) and fast two hops until they are equal.
    3. Reset slow = 0; move both one hop at a time until equal.
    4. That value is the duplicate.

    Java

    class Solution {
    public int findDuplicate(int[] nums) {
        int slow = nums[0], fast = nums[nums[0]];
        while (slow != fast) {     // phase 1: meet
            slow = nums[slow];
            fast = nums[nums[fast]];
        }
        slow = 0;
        while (slow != fast) {     // phase 2: entrance
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }
}

    Time O(n) · Space O(1) — two Floyd phases, just two integers.

    Dry run

    nums = [1,3,4,2,2]   hops: 0 -> 1 -> 3 -> 2 -> 4 -> 2 -> 4 ...
phase 1  slow: 1, 3, 2, 4    fast: 3, 4, 4, 4   meet at 4
phase 2  slow: 0, 1, 3, 2    fast: 4, 2, 4, 2   equal at 2

    The loop is 2 → 4 → 2, entered at 2, which is the duplicate.

    Watch out

    Phase 2 restarts at index 0 (the list's head), not at nums[0], because phase 1 began with one hop already done from 0. Binary search on the value range (count numbers ≤ mid) is the other O(1)-space answer, at O(n log n).

Test yourself

Why can't fast jump over slow inside the cycle without meeting it?

Each turn the gap between them shrinks by exactly 1 (fast +2, slow +1). A gap that shrinks by 1 must pass through 0.

What is the time and space of Floyd's algorithm?

O(n) time, O(1) space. A HashSet of visited nodes also works in O(n) time but needs O(n) space.

In remove-nth, why does fast move n + 1 steps and not n?

Because we need slow to stop on the node before the target, so we can change its next. Starting both at the dummy and making the gap n + 1 does that.
