Pattern 23 · Greedy & intervals

Intervals

Sort the intervals first; then one left-to-right sweep is enough to merge them, count overlaps, or find how many rooms you need.

Time to learn: about 2 hours · Prerequisites: Arrays and hashing, Heaps (for meeting rooms)

When to use it — the signal

The input is pairs [start, end]: meetings, bookings, time slots, ranges, balloons. Words like "merge overlapping", "insert an interval", "minimum number of rooms", "can a person attend all meetings", "remove the fewest to stop overlaps".

The idea in plain words

Two intervals [a, b] and [c, d] overlap when each one starts before the other ends: a ≤ d and c ≤ b. Checking every pair is O(n²).

After sorting by start, overlaps can only happen between neighbours in a chain, so a single sweep works:

  • Keep the last merged interval. The next interval either starts after it ends (a gap → start a new merged interval) or starts inside it (overlap → stretch the end).
  • Stretch with max(lastEnd, curEnd), because a short interval can sit completely inside a long one: [1, 4] and [2, 3] merge to [1, 4], not [1, 3].

How many rooms? Sort meetings by start. Keep a min-heap of end times — one entry per room in use, the top is the room that frees up first. A new meeting can reuse that room if it starts at or after the top's end; otherwise it needs a new room. The heap's final size is the answer.

Another way to count rooms: turn every meeting into two events, +1 at its start and −1 at its end, sort the events, and track the running total. The largest total is the number of rooms. Both are O(n log n) because of the sort.

Analogy

Booking a hotel's meeting rooms: you hand out rooms in order of start time. Before opening a new room, you check the room that becomes free soonest — if its meeting is over, the next group walks straight in. Merging intervals is like colouring the busy hours on a calendar: overlapping blocks melt into one long block.

Watch it work

Merge [[3,5], [1,4], [6,7], [2,3]]. Each row is one interval drawn on a time line from 1 to 7.

Meeting Rooms II (min-heap of end times)

Meetings [1,4), [2,6), [4,7), [5,8) — each ends just before its end time, so a meeting ending at 4 frees the room for one starting at 4. How many rooms are needed?

Why it works

"After sorting by start, an interval can only overlap the block just before it, because everything earlier ended no later than that block. For rooms, the heap top is the room that frees soonest — if even that one is busy, every room is busy, so we must open a new one."

The template to remember

Arrays.sort(iv, (a, b) -> Integer.compare(a[0], b[0]));  // sort by start
int[] last = null;
for (int[] cur : iv) {
    if (last == null || cur[0] > last[1]) { out.add(cur); last = cur; } // gap
    else last[1] = Math.max(last[1], cur[1]);              // overlap
}
// rooms: sort by start, min-heap of ends; reuse if ends.peek() <= start
// most non-overlapping (activity selection): sort by END, keep if start >= lastEnd

Sorting is the real data structure here: once intervals are in start order, a list for the output and (for rooms) a min-heap of end times are all you need.

Remember

Intervals → sort first. Merge: sort by start, stretch with max. Keep the most: sort by end. Rooms: heap of end times (or +1/−1 sweep).

Common mistakes
  • Forgetting max when stretching: [1,10] then [2,3] must stay [1,10].
  • Touching intervals: does [1,2] overlap [2,3]? In Merge Intervals yes (≤); in meetings ending at 2 and starting at 2, no. Read the problem.
  • (a, b) -> a[0] - b[0] overflows for huge values (LC 452 has ±2³¹); use Integer.compare.
  • Sorting by start when the problem asks for the maximum number of non-overlapping intervals — sort by end there.
  • In the +1/−1 sweep, at equal times process the −1 (end) before the +1 (start) when an ending meeting frees the room.

Practice in this order

  • Easy252. Meeting Rooms — sort, check each start against the previous end.
    Show solution

    The idea

    Can one person attend every meeting? Only if no two meetings overlap. After sorting by start, a meeting can only clash with the one right before it, so compare each start with the previous end. [[0,30],[5,10],[15,20]]: 5 < 30, so the answer is false.

    Brute force first

    Compare every pair of meetings for overlap. O(n²).

    Step by step

    1. Sort the meetings by start time.
    2. For each meeting from the second one on, compare its start with the previous meeting's end.
    3. If start < previous end, they overlap: return false.
    4. If no clash is found, return true.

    Java

    class Solution {
    public boolean canAttendMeetings(int[][] intervals) {
        Arrays.sort(intervals,
                (a, b) -> Integer.compare(a[0], b[0]));
        for (int i = 1; i < intervals.length; i++) {
            // starts before the previous one ends
            if (intervals[i][0] < intervals[i - 1][1])
                return false;
        }
        return true;
    }
}

    Time O(n log n) · Space O(log n) for the sort — the scan after sorting is linear.

    Dry run

    [[0,30],[5,10],[15,20]] sorted -> same
[5,10]: 5 < 30 -> overlap -> false
[[7,10],[2,4]] sorted -> [[2,4],[7,10]]: 7 >= 4 -> true

    Watch out

    A meeting ending at 10 and one starting at 10 do not clash, so the test is strict <. Empty input or one meeting is true.

  • Medium56. Merge Intervals — the first animation.
    Show solution

    The idea

    Combine all overlapping intervals: [[1,3],[2,6],[8,10]] becomes [[1,6],[8,10]]. Sort by start; then walk left to right keeping the last merged block. The next interval either starts inside that block (stretch its end) or after it (start a new block).

    Brute force first

    Repeatedly look for any two overlapping intervals and join them until none are left. O(n²) or worse.

    Step by step

    1. Sort by start.
    2. Put the first interval in the result.
    3. For each next interval, look at the last block in the result.
    4. If start <= last end, they overlap: set last end = max(last end, end).
    5. Otherwise add the interval as a new block.

    Java

    class Solution {
    public int[][] merge(int[][] intervals) {
        Arrays.sort(intervals,
                (a, b) -> Integer.compare(a[0], b[0]));
        List<int[]> res = new ArrayList<>();
        for (int[] cur : intervals) {
            if (!res.isEmpty()
                    && cur[0] <= res.get(res.size() - 1)[1]) {
                int[] last = res.get(res.size() - 1);
                // overlap: stretch the end
                last[1] = Math.max(last[1], cur[1]);
            } else {
                // gap: start a new block
                res.add(new int[]{cur[0], cur[1]});
            }
        }
        return res.toArray(new int[0][]);
    }
}

    Time O(n log n) · Space O(n) for the output — sorting dominates, the walk is linear.

    Dry run

    [[1,3],[2,6],[8,10],[15,18]]
[1,3]           -> res [[1,3]]
[2,6]:  2 <= 3  -> stretch to [1,6]
[8,10]: 8 > 6   -> new  [[1,6],[8,10]]
[15,18]         -> new  [[1,6],[8,10],[15,18]]

    Watch out

    Use max when stretching: in [[1,10],[2,3]] the second interval is inside the first, and setting the end to 3 would shrink it. Touching intervals like [1,4],[4,5] count as overlapping (<=).

  • Medium57. Insert Interval — copy the left ones, merge the middle, copy the right.
    Show solution

    The idea

    The intervals are sorted and do not overlap; add one new interval and merge where needed. Everything splits into three groups: intervals fully left of the new one (end before it starts), ones that overlap it, and ones fully right of it. Copy the left ones, melt the middle ones into the new interval, copy the right ones.

    Brute force first

    Add the new interval to the list and run Merge Intervals (problem 56). O(n log n) because of the sort; the list is already sorted, so we can do better.

    Step by step

    1. Walk with i. While intervals[i] ends before the new one starts, copy it.
    2. While intervals[i] starts at or before the new one's end, it overlaps: grow the new interval to [min of starts, max of ends].
    3. Add the grown new interval.
    4. Copy every interval that is left.

    Java

    class Solution {
    public int[][] insert(int[][] intervals, int[] newInterval) {
        List<int[]> res = new ArrayList<>();
        int i = 0, n = intervals.length;
        int s = newInterval[0], e = newInterval[1];
        // 1) ends before the new one starts
        while (i < n && intervals[i][1] < s)
            res.add(intervals[i++]);
        // 2) overlaps: melt into [s, e]
        while (i < n && intervals[i][0] <= e) {
            s = Math.min(s, intervals[i][0]);
            e = Math.max(e, intervals[i][1]);
            i++;
        }
        res.add(new int[]{s, e});
        // 3) starts after the new one ends
        while (i < n) res.add(intervals[i++]);
        return res.toArray(new int[0][]);
    }
}

    Time O(n) · Space O(n) for the output — one walk, no sorting.

    Dry run

    intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], new = [4,8]
left:    [1,2] (2 < 4)
overlap: [3,5] -> [3,8]; [6,7] -> [3,8]; [8,10] -> [3,10]
add [3,10]; right: [12,16]
result [[1,2],[3,10],[12,16]]

    Watch out

    Touching counts as overlap: [1,5] and new [5,7] merge to [1,7], so the first loop uses strict < and the second uses <=. Empty intervals just returns the new one.

  • Medium253. Meeting Rooms II — the second animation.
    Show solution

    The idea

    How many rooms are needed so every meeting gets one? Sort by start and keep a min-heap of end times, one per busy room; the top is the room that frees up first. A new meeting reuses that room if it starts at or after the top's end, otherwise it needs a new room. The heap size at the end is the answer.

    Brute force first

    For every moment a meeting starts, count how many meetings are running then; the maximum is the answer. O(n²).

    Step by step

    1. Sort the meetings by start.
    2. For each meeting: if the heap is not empty and heap top <= start, that room is free; remove it.
    3. Push this meeting's end time (it now holds a room).
    4. Return the heap size.

    Java

    class Solution {
    public int minMeetingRooms(int[][] intervals) {
        Arrays.sort(intervals,
                (a, b) -> Integer.compare(a[0], b[0]));
        // end time of each busy room; smallest on top
        PriorityQueue<Integer> ends = new PriorityQueue<>();
        for (int[] m : intervals) {
            if (!ends.isEmpty() && ends.peek() <= m[0])
                ends.poll(); // earliest room is free: reuse
            ends.offer(m[1]);
        }
        return ends.size();
    }
}

    Time O(n log n) · Space O(n) — sorting plus one heap push per meeting. The other common answer sorts starts and ends separately and sweeps them with two pointers (+1 room per start, −1 per end).

    Dry run

    [[0,30],[5,10],[15,20]]
[0,30]:  heap empty      -> push 30     heap [30]
[5,10]:  30 > 5 busy     -> push 10     heap [10,30]
[15,20]: 10 <= 15 free   -> pop, push 20 heap [20,30]
answer 2

    Watch out

    A meeting ending at 10 frees the room for one starting at 10, so the test is <=. Pop at most one room per meeting: we only need one room, and the heap size must stay equal to the rooms opened.

  • Medium435. Non-overlapping Intervals — sort by end, count the keepers.
    Show solution

    The idea

    Remove the fewest intervals so the rest do not overlap. Flip it: keep as many as possible. Greedy: sort by end and always keep the interval that finishes first, because it leaves the most room for the rest. Answer = total − kept.

    Brute force first

    Try every subset of intervals and keep the largest one with no overlaps. O(2n).

    Step by step

    1. Sort by end time.
    2. Keep the first interval; remember end = its end.
    3. For each next interval: if its start is >= end, it fits; keep it and set end to its end.
    4. Otherwise it overlaps a kept one: remove it (count it).
    5. Return the count of removed intervals.

    Java

    class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        Arrays.sort(intervals,
                (a, b) -> Integer.compare(a[1], b[1]));
        int removed = 0;
        int end = Integer.MIN_VALUE; // end of last kept one
        for (int[] x : intervals) {
            if (x[0] >= end) end = x[1]; // fits: keep it
            else removed++;              // overlaps: drop it
        }
        return removed;
    }
}

    Time O(n log n) · Space O(log n) for the sort — one pass after sorting.

    Dry run

    [[1,2],[2,3],[3,4],[1,3]] sorted by end -> [1,2],[2,3],[1,3],[3,4]
[1,2] keep end=2; [2,3] keep end=3
[1,3]: 1 < 3 drop (removed=1); [3,4] keep
answer 1

    Watch out

    Sorting by start is the common wrong move: [[1,100],[2,3],[4,5]] would keep the long one and remove two. Touching intervals ([1,2],[2,3]) do not overlap here, so the test is >=. Use Integer.compare, since values can be negative.

  • Medium452. Minimum Number of Arrows — sort by end, shoot at each end.
    Show solution

    The idea

    Each balloon covers [start, end] on the x-axis; an arrow shot at x bursts every balloon with start ≤ x ≤ end. Greedy: sort by end and shoot the first arrow at the first balloon's end. That arrow bursts every balloon that starts at or before that point; the first balloon starting after it needs a new arrow, shot at its end.

    Brute force first

    Try arrow positions at every balloon end and pick sets of positions that cover all: exponential.

    Step by step

    1. Sort balloons by end.
    2. Shoot one arrow at the first balloon's end; arrows = 1, pos = end.
    3. For each next balloon: if its start is <= pos, the current arrow already bursts it.
    4. Otherwise shoot a new arrow at this balloon's end: arrows++, pos = end.

    Java

    class Solution {
    public int findMinArrowShots(int[][] points) {
        // compare, not subtract: values reach +-2^31
        Arrays.sort(points,
                (a, b) -> Integer.compare(a[1], b[1]));
        int arrows = 1;
        int pos = points[0][1]; // first arrow
        for (int[] p : points) {
            if (p[0] > pos) {   // this balloon is missed
                arrows++;
                pos = p[1];     // shoot at its end
            }
        }
        return arrows;
    }
}

    Time O(n log n) · Space O(log n) for the sort — one pass after sorting.

    Dry run

    [[10,16],[2,8],[1,6],[7,12]] sorted by end -> [1,6],[2,8],[7,12],[10,16]
arrow at 6: bursts [1,6],[2,8]
[7,12]: 7 > 6 -> arrow at 12: bursts [7,12],[10,16]
answer 2

    Watch out

    The comparator a[1] - b[1] overflows with values like -231 and 231 − 1 and sorts wrongly; always use Integer.compare. Touching balloons share an arrow, so the miss test is strict >.

  • Medium986. Interval List Intersections — two pointers, advance the one that ends first.
    Show solution

    The idea

    Two lists of closed intervals, each sorted and non-overlapping. Two intervals [a1,a2] and [b1,b2] meet on [max(a1,b1), min(a2,b2)] if that range is not empty. Use two pointers, one per list; after comparing, move the one whose interval ends first, because it cannot meet anything later in the other list.

    Brute force first

    Compare every interval of the first list with every interval of the second. O(n · m).

    Step by step

    1. i = 0 in the first list, j = 0 in the second.
    2. Compute lo = max(starts) and hi = min(ends).
    3. If lo <= hi, add [lo, hi].
    4. Move the pointer whose interval has the smaller end.
    5. Stop when either list is used up.

    Java

    class Solution {
    public int[][] intervalIntersection(int[][] A, int[][] B) {
        List<int[]> res = new ArrayList<>();
        int i = 0, j = 0;
        while (i < A.length && j < B.length) {
            int lo = Math.max(A[i][0], B[j][0]);
            int hi = Math.min(A[i][1], B[j][1]);
            if (lo <= hi) res.add(new int[]{lo, hi});
            // the one that ends first is finished
            if (A[i][1] < B[j][1]) i++;
            else j++;
        }
        return res.toArray(new int[0][]);
    }
}

    Time O(n + m) · Space O(n + m) for the output — each step moves one pointer.

    Dry run

    A = [[0,2],[5,10],[13,23],[24,25]]
B = [[1,5],[8,12],[15,24],[25,26]]
[0,2]&[1,5]   -> [1,2]   move A
[5,10]&[1,5]  -> [5,5]   move B
[5,10]&[8,12] -> [8,10]  move A ... and so on
result [[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]]

    Watch out

    Intervals are closed, so a single shared point like [5,5] counts: use lo <= hi. If both end at the same time, moving either pointer is fine.

  • Hard759. Employee Free Time — merge everyone's intervals, report the gaps.
    Show solution

    The idea

    Each employee has a sorted list of working intervals. Find the finite gaps when nobody is working. Put every interval of every employee into one list, sort by start, and sweep like Merge Intervals while tracking the latest end so far; whenever the next interval starts after that end, the gap between them is free time for everyone.

    Brute force first

    Mark every time unit as busy or free on a timeline. Works only for small times; times go up to 108.

    Step by step

    1. Collect all intervals from all employees into one list.
    2. Sort it by start.
    3. Set end = the first interval's end.
    4. For each next interval: if its start is greater than end, add the gap [end, start].
    5. Then end = max(end, its end).

    Java

    class Solution {
    public List<Interval> employeeFreeTime(
            List<List<Interval>> schedule) {
        List<Interval> all = new ArrayList<>();
        for (List<Interval> emp : schedule) all.addAll(emp);
        all.sort((a, b) -> Integer.compare(a.start, b.start));
        List<Interval> free = new ArrayList<>();
        int end = all.get(0).end; // latest busy time so far
        for (Interval x : all) {
            if (x.start > end)          // nobody works here
                free.add(new Interval(end, x.start));
            end = Math.max(end, x.end);
        }
        return free;
    }
}

    Time O(N log N), N = total intervals · Space O(N) — one sort of all intervals. A min-heap holding one pointer per employee does the same in O(N log k) for k employees.

    Dry run

    schedule = [[[1,2],[5,6]], [[1,3]], [[4,10]]]
all sorted: [1,2] [1,3] [4,10] [5,6]
end=2 -> [1,3]: end=3 -> [4,10]: 4 > 3, gap [3,4], end=10
[5,6]: inside -> result [[3,4]]

    Watch out

    Gaps of zero length do not count: [1,3] and [3,5] give no free time, so the test is strict >. Use max for the end, because a long interval can cover several later short ones.

Why sort by start for merging but by end for "keep the most non-overlapping intervals"?

Merging needs neighbours to be next to each other (start order). Keeping the most is greedy: the interval that ends earliest leaves the most room for the rest.

In Meeting Rooms II, why compare only with the heap top and not with every room?

The top is the room that frees earliest. If it is still busy at this start time, all others are busy too; if it is free, using it is as good as any.
