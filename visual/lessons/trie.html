Trie (Prefix Tree)

A tree where every edge is one letter, so all words that start the same way share the same path — checking a word or a prefix costs only its length.

Time to learn: about 2 hours · Prerequisites: Arrays and hashing, Tree traversals (helpful)

When to use it — the signal

"Prefix", "starts with", "autocomplete", "search suggestions", "a dictionary of words and many lookups", "wildcard . matches any letter", "find all words from a list in a grid", "maximum XOR of two numbers" (a trie of bits).

The idea in plain words

A hash set can tell you whether "car" is a word, but not quickly whether any word starts with "ca". A trie (say "try", from retrieval) can.

Start with an empty root. To insert "cat", walk down: from the root follow the edge for c (create it if missing), then a, then t. Mark the last node "end of a word".

  • Insert "car": c and a already exist, so reuse them; only r is new. Shared prefixes are stored once.
  • Search "car": follow c → a → r. If you reach the end of the word and the node is marked end, it is a word.
  • startsWith "ca": follow c → a. If the path exists at all, some word starts with it — no end mark needed.

Every operation costs O(L) where L is the length of the word — it does not matter whether the dictionary holds 10 words or 10 million.

Each node is usually Node[] next = new Node[26] (one slot per letter a–z) plus a boolean end.

Analogy

A paper dictionary's thumb tabs: to find "car" you open the C section, then the CA pages, then CAR. Every word starting with "ca" lives in the same pages, so finding "is there any word beginning with ca?" is just opening that section.

Watch it work

Insert cat, car, do, dog. Each circle is a node, labelled with the letter on the edge into it. A node tagged end finishes a word.

search and startsWith

On the same trie: search("car"), search("ca"), startsWith("ca"), search("dot"). Both use one helper, find, that walks the path.

Why it works

"Every word is a path from the root, one letter per edge, so all words with the same prefix share the same node for that prefix. Insert and search walk at most L edges, so they are O(L) regardless of how many words are stored; the end flag separates a full word from a mere prefix."

The template to remember

class Node { Node[] next = new Node[26]; boolean end; }
void insert(String w) {
    Node cur = root;
    for (char ch : w.toCharArray()) {
        int c = ch - 'a';
        if (cur.next[c] == null) cur.next[c] = new Node();
        cur = cur.next[c];
    }
    cur.end = true;
}
// search: walk, then check end.  startsWith: walk, path exists = true

A trie shares the common start of words, so a prefix question walks one path instead of checking every word; an array of 26 children is faster and simpler than a HashMap when the alphabet is a–z.

Remember

Edge = letter, path = prefix, end flag = whole word. search needs the flag; startsWith only needs the path.

Common mistakes
  • Forgetting the end flag — then "ca" would be "found" after inserting "cat".
  • Putting the letter in the node and getting confused about the root. The root has no letter; the slot index next[c] is the letter.
  • Using HashMap<Character, Node> when the alphabet is just a–z: an array of 26 is faster and simpler.
  • Word Search II: not removing found words (or pruning dead branches), so the same word is reported twice or it times out.
  • Wildcard .: you must try all 26 children with recursion, not just one.

Practice in this order

  • Easy14. Longest Common Prefix — walk while the node has one child and is not an end.
    Show solution

    The idea

    Find the longest start that every word shares: ["flower","flow","flight"] → "fl". With a trie (a tree where each edge is a letter and each path from the top spells a prefix), the shared prefix is the path from the root while each node has exactly one child and no word has ended yet.

    Brute force first

    Compare characters column by column across all words until one differs or a word runs out (vertical scanning). Also O(total letters) and no extra memory, so it is a fine answer too.

    Step by step

    1. Insert every word into a trie; count each node's children and mark where words end.
    2. Start at the root with an empty answer.
    3. While the node has exactly one child and is not the end of a word, append that child's letter and move into it.
    4. Stop as soon as there is a fork (2+ children) or a word ends; the letters collected are the answer.

    Java

    class Solution {
    public String longestCommonPrefix(String[] strs) {
        TrieNode root = new TrieNode();
        for (String s : strs) { // 1. build the trie
            TrieNode cur = root;
            for (char c : s.toCharArray()) {
                int i = c - 'a';
                if (cur.next[i] == null) {
                    cur.next[i] = new TrieNode();
                    cur.kids++;          // one more branch
                }
                cur = cur.next[i];
            }
            cur.end = true;
        }
        // 2. walk while there is one road and no word ends
        StringBuilder sb = new StringBuilder();
        TrieNode cur = root;
        while (cur.kids == 1 && !cur.end) {
            for (int i = 0; i < 26; i++) {
                if (cur.next[i] != null) {
                    sb.append((char) ('a' + i));
                    cur = cur.next[i];
                    break;
                }
            }
        }
        return sb.toString();
    }
}

class TrieNode {
    TrieNode[] next = new TrieNode[26];
    int kids;        // how many children exist
    boolean end;     // a word ends at this node
}

    Time O(S) · Space O(S) — S is the total number of letters; each is inserted once.

    Dry run

    flower, flow, flight: root has one child f → "f"; f has one child l → "fl"; l has two children (o, i) → stop. Answer "fl".

    Watch out

    If one word is a prefix of another ("ab","abc"), the walk must stop where "ab" ends; that is why we also check end. An empty string in the list makes the answer "".

  • Medium208. Implement Trie (Prefix Tree) — exactly the animations.
    Show solution

    The idea

    Build the trie itself: insert a word, search for a whole word, and startsWith to check any word has this prefix. Each node has 26 child slots (one per letter a–z) and a flag "a word ends here". After inserting "apple", "app" is a prefix but not a word until it is inserted too.

    Step by step

    1. A node = an array of 26 children plus a boolean end.
    2. insert: walk letter by letter from the root, creating missing children; mark the last node end = true.
    3. A helper walk follows the letters and returns the last node, or null if a letter is missing.
    4. search = walk is not null and that node is an end. startsWith = walk is not null.

    Java

    class Trie {
    private static class Node {
        Node[] next = new Node[26]; // one slot per letter
        boolean end;                // a word ends here
    }
    private final Node root = new Node();

    public Trie() {}

    public void insert(String word) {
        Node cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.next[i] == null) cur.next[i] = new Node();
            cur = cur.next[i];
        }
        cur.end = true;            // mark the last letter
    }

    public boolean search(String word) {
        Node n = walk(word);
        return n != null && n.end; // must end exactly here
    }

    public boolean startsWith(String prefix) {
        return walk(prefix) != null; // any path is enough
    }

    // follow the letters; null if the path breaks
    private Node walk(String s) {
        Node cur = root;
        for (char c : s.toCharArray()) {
            cur = cur.next[c - 'a'];
            if (cur == null) return null;
        }
        return cur;
    }
}

    Time O(L) per call · Space O(total letters inserted) — L is the word length; each letter is one array step.

    Dry run

    insert "apple" makes a→p→p→l→e, end on e. search "apple" → reaches e, end true → true. search "app" → reaches second p, end false → false. startsWith "app" → true. insert "app" marks that p as end → search "app" now true.

    Watch out

    The classic bug is search returning true just because the path exists; it must also check the end flag. c - 'a' only works for lowercase letters.

  • Medium211. Design Add and Search Words — on . recurse into every child.
    Show solution

    The idea

    Like 208, but a search word may contain ., which matches any one letter. "b.." should find "bad". On a normal letter we follow one child; on a dot we must try every child, which is a small DFS (depth-first search: go deep down one branch, back up, try the next).

    Step by step

    1. addWord is exactly trie insert.
    2. dfs(word, i, node) answers: can word[i..] be matched starting at this node?
    3. If i reached the end, the answer is whether this node ends a word.
    4. If the letter is ., try every non-null child with i + 1 and return true if any works.
    5. Otherwise follow the one matching child (false if it is missing).

    Java

    class WordDictionary {
    private static class Node {
        Node[] next = new Node[26];
        boolean end;
    }
    private final Node root = new Node();

    public WordDictionary() {}

    public void addWord(String word) {
        Node cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.next[i] == null) cur.next[i] = new Node();
            cur = cur.next[i];
        }
        cur.end = true;
    }

    public boolean search(String word) {
        return dfs(word, 0, root);
    }

    // can word[i..] be matched starting from node n?
    private boolean dfs(String w, int i, Node n) {
        if (i == w.length()) return n.end;
        char c = w.charAt(i);
        if (c == '.') {                   // try every child
            for (Node kid : n.next) {
                if (kid != null && dfs(w, i + 1, kid)) {
                    return true;
                }
            }
            return false;
        }
        Node kid = n.next[c - 'a'];       // normal letter
        return kid != null && dfs(w, i + 1, kid);
    }
}

    Time O(L) for plain words, up to O(26^d · L) with d dots in the worst case · Space O(L) recursion — each dot can branch to every child.

    Dry run

    Words bad, dad, mad. search ".ad": dot → try b, d, m. Under b: 'a' exists, 'd' exists, end → true. Search "pad": no 'p' child → false.

    Watch out

    "b." must be false even though "ba" is a path: at the end check n.end, not just that the node exists. Words longer than any stored word fall off the trie and must return false, not crash.

  • Medium648. Replace Words — stop at the first end node on the path.
    Show solution

    The idea

    Replace each word in the sentence by its shortest dictionary root that is a prefix of it: with roots cat, bat, rat, "cattle" becomes "cat". Put the roots in a trie; while walking a word down the trie, the first node marked as an end is the shortest root.

    Brute force first

    For every word, try every root with startsWith and keep the shortest. O(words × roots × length).

    Step by step

    1. Insert every root into a trie, marking end nodes.
    2. Split the sentence on spaces.
    3. For each word, walk the trie letter by letter. If a letter is missing, keep the word as it is.
    4. If you reach an end node, replace the word with the letters walked so far and stop.
    5. Join the results with single spaces.

    Java

    class Solution {
    public String replaceWords(List<String> dictionary,
                               String sentence) {
        TrieNode root = new TrieNode();
        for (String r : dictionary) {      // trie of roots
            TrieNode cur = root;
            for (char c : r.toCharArray()) {
                int i = c - 'a';
                if (cur.next[i] == null) {
                    cur.next[i] = new TrieNode();
                }
                cur = cur.next[i];
            }
            cur.end = true;
        }
        StringBuilder sb = new StringBuilder();
        for (String word : sentence.split(" ")) {
            if (sb.length() > 0) sb.append(' ');
            sb.append(shortestRoot(root, word));
        }
        return sb.toString();
    }

    // first end node on the word's path, else the word
    private String shortestRoot(TrieNode root, String w) {
        TrieNode cur = root;
        for (int j = 0; j < w.length(); j++) {
            cur = cur.next[w.charAt(j) - 'a'];
            if (cur == null) return w;     // no root fits
            if (cur.end) return w.substring(0, j + 1);
        }
        return w;
    }
}

class TrieNode {
    TrieNode[] next = new TrieNode[26];
    boolean end;
}

    Time O(D + S) · Space O(D) — D letters in the dictionary, S letters in the sentence, each touched once.

    Dry run

    "cattle": c → a → t is an end (cat) → "cat". "the": no 't' at the root → "the". "battery": b → a → t end → "bat".

    Watch out

    Stop at the first end node, not the last, so roots "a" and "aa" turn "aaa" into "a". A word can end before any root does (word "ca" with root "cat"): return the word unchanged.

  • Medium1268. Search Suggestions System — walk the prefix, then DFS for 3 words.
    Show solution

    The idea

    After each letter typed of searchWord, list up to 3 products (alphabetically smallest) that start with what has been typed so far. Sort the products first; then insert them into a trie and let each node remember the first 3 words that pass through it. Because words arrive sorted, those first 3 are the 3 smallest.

    Brute force first

    For each prefix, scan the sorted product list and take the first 3 that start with it. O(L × n × m). A trie with a DFS for 3 words per prefix also works; storing the 3 words in each node skips that DFS.

    Step by step

    1. Sort products alphabetically.
    2. Insert each product into a trie; at every node on its path, add the product to that node's top list if it holds fewer than 3.
    3. Walk searchWord letter by letter from the root.
    4. After each letter, add the node's top list, or an empty list once the path has broken.

    Java

    class Solution {
    public List<List<String>> suggestedProducts(
            String[] products, String searchWord) {
        Arrays.sort(products); // words now arrive in order
        TrieNode root = new TrieNode();
        for (String p : products) {
            TrieNode cur = root;
            for (char c : p.toCharArray()) {
                int i = c - 'a';
                if (cur.next[i] == null) {
                    cur.next[i] = new TrieNode();
                }
                cur = cur.next[i];
                // keep the first 3 (smallest) words seen here
                if (cur.top.size() < 3) cur.top.add(p);
            }
        }
        List<List<String>> ans = new ArrayList<>();
        TrieNode cur = root;
        for (char c : searchWord.toCharArray()) {
            if (cur != null) cur = cur.next[c - 'a'];
            ans.add(cur == null
                    ? new ArrayList<>() : cur.top);
        }
        return ans;
    }
}

class TrieNode {
    TrieNode[] next = new TrieNode[26];
    List<String> top = new ArrayList<>(); // up to 3 words
}

    Time O(n log n · m + S) · Space O(S) — sorting dominates; S is the total letters, each node keeps at most 3 words.

    Dry run

    Products sorted: mobile, moneypot, monitor, mouse, mousepad. Node "m" keeps the first three: mobile, moneypot, monitor; so does "mo". Node "mou" only sees mouse, mousepad.

    Watch out

    Once a letter has no child, every later prefix also has none; keep the node null and keep adding empty lists (do not stop early, the answer needs one list per letter).

  • Medium421. Maximum XOR of Two Numbers — a trie of bits, go the opposite bit when you can.
    Show solution

    The idea

    Pick two numbers whose XOR is as big as possible (XOR sets a bit to 1 where the two numbers differ). For [3,10,5,25,2,8] the best is 5 XOR 25 = 28. Build a trie of the numbers' bits from the highest bit down; for each number, walk down choosing the opposite bit whenever it exists, because a 1 in a high bit beats everything below it.

    Brute force first

    Try every pair: O(n²), too slow for n up to 200,000.

    Step by step

    1. Each trie node has two children: bit 0 and bit 1.
    2. For each number x, insert its bits from bit 30 down to bit 0 (the numbers are non-negative, so 31 bits are enough).
    3. Then walk again from the root: at each bit, if the child with the opposite bit exists go there and set that bit in the result; otherwise follow the same bit.
    4. Keep the biggest result over all x.

    Java

    class Solution {
    public int findMaximumXOR(int[] nums) {
        TrieNode root = new TrieNode();
        int best = 0;
        for (int x : nums) {
            TrieNode cur = root; // insert x's bits
            for (int b = 30; b >= 0; b--) {
                int bit = (x >> b) & 1;
                if (cur.kid[bit] == null) {
                    cur.kid[bit] = new TrieNode();
                }
                cur = cur.kid[bit];
            }
            cur = root; // best partner for x
            int xor = 0;
            for (int b = 30; b >= 0; b--) {
                int bit = (x >> b) & 1;
                if (cur.kid[1 - bit] != null) {
                    xor |= 1 << b; // opposite bit: a 1
                    cur = cur.kid[1 - bit];
                } else {
                    cur = cur.kid[bit]; // forced to match
                }
            }
            best = Math.max(best, xor);
        }
        return best;
    }
}

class TrieNode {
    TrieNode[] kid = new TrieNode[2]; // kid[0], kid[1]
}

    Time O(31 · n) · Space O(31 · n) — each number adds and walks 31 levels.

    Dry run

    x = 5 (00101) when 25 (11001) is already in: bit 4: 5 has 0, a 1-child exists (25) → take it, result 10000. Bit 3: 5 has 0, 1 exists → 11000. Bit 2: 5 has 1, need 0 → 25 has 0 → 11100. Bits 1, 0 continue to give 11100 = 28.

    Watch out

    Inserting x before querying is fine (x XOR x = 0) and avoids a null root on the first number. Walk the bits in the same order you inserted them, top bit first.

  • Hard212. Word Search II — DFS the grid while walking the trie.
    Show solution

    The idea

    Find every word from a list that can be spelled on the grid by moving up/down/left/right without reusing a cell. Searching each word separately repeats work. Put all words in a trie and run one DFS from each cell while walking down the trie at the same time; when a path is not a prefix of any word, stop immediately.

    Brute force first

    Run the Word Search DFS (problem 79) once per word: O(words × cells × 4^L). Far too slow with many words.

    Step by step

    1. Insert every word into a trie and store the full word at its end node.
    2. From every cell, start a DFS with the trie root as the parent node.
    3. In the DFS, if the cell is off the grid, already used (#), or has no trie child for its letter, return.
    4. If the child node holds a word, record it and clear it so it is not reported twice.
    5. Mark the cell #, recurse in 4 directions with the child node, then restore the letter (backtracking).

    Java

    class Solution {
    public List<String> findWords(char[][] board,
                                  String[] words) {
        TrieNode root = new TrieNode();
        for (String w : words) { // trie of all words
            TrieNode cur = root;
            for (char c : w.toCharArray()) {
                int i = c - 'a';
                if (cur.next[i] == null) {
                    cur.next[i] = new TrieNode();
                }
                cur = cur.next[i];
            }
            cur.word = w;                 // store the word
        }
        List<String> found = new ArrayList<>();
        for (int r = 0; r < board.length; r++) {
            for (int c = 0; c < board[0].length; c++) {
                dfs(board, r, c, root, found);
            }
        }
        return found;
    }

    private void dfs(char[][] b, int r, int c,
                     TrieNode parent, List<String> found) {
        if (r < 0 || c < 0 || r >= b.length
                || c >= b[0].length) return;
        char ch = b[r][c];
        if (ch == '#') return;            // already on path
        TrieNode node = parent.next[ch - 'a'];
        if (node == null) return; // no word this way
        if (node.word != null) {
            found.add(node.word);
            node.word = null;             // report it once
        }
        b[r][c] = '#';                    // mark visited
        dfs(b, r + 1, c, node, found);
        dfs(b, r - 1, c, node, found);
        dfs(b, r, c + 1, node, found);
        dfs(b, r, c - 1, node, found);
        b[r][c] = ch;                     // undo the mark
    }
}

class TrieNode {
    TrieNode[] next = new TrieNode[26];
    String word;     // the full word if one ends here
}

    Time O(cells · 4 · 3^(L−1)) worst case · Space O(total letters in words) — each path branches at most 3 ways after the first step and stops early on non-prefixes; L is the longest word.

    Dry run

    Words oath, eat. From the 'o' at (0,0): o → a → t → h follows the trie and reaches the node holding "oath" → found. From 'e' at (1,3): e → a → t → "eat" found. "pea" never starts since no cell has 'p'.

    Watch out

    Always restore the cell after the recursion, or later searches see '#'. Clear node.word after finding it, or the same word can be added twice from two different paths.

Test yourself

After inserting "app" and "apple", what do search("appl") and startsWith("appl") return?

search = false (the node for "appl" is not marked end). startsWith = true (the path exists).

What is the time to insert or search a word of length L?

O(L) — one step per letter, independent of how many words are stored.

Why is a trie better than a HashSet for "how many words start with pre"?

A HashSet must check every word. A trie walks 3 letters to the "pre" node; everything below it (or a counter stored there) is the answer.
