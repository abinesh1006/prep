Dynamic programming: the idea

Dynamic programming (DP) is recursion that writes down every answer it works out, so the same small question is never solved twice.

Time to learn: about 3 hours · Prerequisites: Recursion, Big-O

When to use it — the signal

The question asks for a count ("how many ways"), a best value ("minimum cost", "maximum profit", "longest") or a yes/no ("can you reach"), and the choices at each step depend on the choices before — "climb 1 or 2 steps", "rob or skip each house". If a brute-force recursion would call the same arguments again and again, it is DP.

The idea in plain words

You can climb a staircase 1 or 2 steps at a time. How many different ways reach step 5? Think about the last move: you arrived either from step 4 (one step) or from step 3 (two steps). So ways(5) = ways(4) + ways(3). The same rule works for every step — that is the recurrence (the formula linking a big answer to smaller answers).

Written as plain recursion this is correct but slow: ways(5) asks for ways(3) twice, ways(2) three times. For step 40 the number of calls is over 100 million, because the same questions are recomputed endlessly.

DP fixes it by remembering. There are two ways to do it:

  • Memoization (top-down): keep the recursion, but store each result in an array the first time; the next time, look it up.
  • Tabulation (bottom-up): fill a table from the smallest step upwards: dp[0], dp[1], dp[2]… each from cells already filled. No recursion at all.

Often each cell only needs the last one or two cells, so the table can shrink to two variables — O(1) memory.

Recipe for every DP problem: (1) what does dp[i] mean, in one sentence? (2) what is the recurrence? (3) what are the smallest answers you know for sure (base cases)? (4) in which order do you fill it?

Analogy

A child asked "what is 1+1+1+1+1?" counts to 5. Then you write "+1" on the left: they answer 6 at once — they remembered the 5 instead of counting again. DP is writing your sub-answers on a notepad so you never have to count again.

Watch it work

1. Plain recursion — the repeated work

Each circle is one call ways(n); the number under it is what it returns. Red = a call whose answer we had already computed somewhere else.

2. Memoization — remember each answer

Same recursion, plus an array memo. Before working, look in it; after working, write the answer in it. Green chips in the memo row are answers already saved.

3. Table, then two variables

Turn it around: start from the bottom. dp[i] = number of ways to reach step i. dp[0] = 1 (one way to stand still at the bottom) and dp[1] = 1. Every later cell is the sum of the two before it.

4. House Robber — a choice in every cell

Houses hold [2, 7, 9, 3, 1] coins. You cannot rob two neighbours. dp[i] = most money from houses 0..i. For house i there are two options: skip it (keep dp[i−1]) or rob it (its coins + dp[i−2], because house i−1 must then be skipped). Take the bigger.

Why it works

"The problem has optimal substructure — the answer for n is built from answers for smaller n — and overlapping subproblems — the same smaller n is needed many times. Storing each subproblem's answer once turns exponential recursion into O(number of subproblems × work per subproblem)."

The template to remember

// 1. dp[i] means: ...one sentence...
int[] dp = new int[n + 1];
dp[0] = ...;                          // 2. base cases
for (int i = 1; i <= n; i++)          // 3. order: smaller first
    dp[i] = combine(dp[i - 1], dp[i - 2], ...); // 4. recurrence
return dp[n];
Remember

Same question asked twice → write the answer down. Define dp[i] in one sentence, find the last choice, fill smallest first.

Common mistakes
  • Starting to code before writing what dp[i] means — the recurrence then comes out wrong.
  • Wrong base cases (dp[0] for stairs is 1, not 0) or forgetting the n = 1 case (House Robber with one house).
  • Memo with 0 as "unknown" when 0 is a real answer — use -1 or an Integer[] with null.
  • Filling the table in an order where a cell needs one that is not filled yet.
  • int overflow for counting problems with big n — use long, or the requested modulo.

Test yourself

What two properties make a problem a DP problem?

Optimal substructure (big answer from smaller answers) and overlapping subproblems (the same smaller answer is needed many times).

Memoization vs tabulation: which one recurses?

Memoization (top-down) keeps the recursion and caches results. Tabulation (bottom-up) fills a table with loops, no recursion and no stack-overflow risk.

When can a DP table shrink to a few variables?

When each cell only reads a fixed number of recent cells (here the last two). Keep just those and slide them forward.

House Robber: dp = [2, 7, 11, 11, 12]. Why is dp[3] = 11 and not 3 + 7 = 10?

Robbing house 3 gives 3 + dp[1] = 10, skipping it keeps dp[2] = 11. The skip is bigger.
