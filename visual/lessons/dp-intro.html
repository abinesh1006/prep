Pattern 42 · Dynamic programming

Dynamic programming: the idea

Dynamic programming (DP) is recursion that writes down every answer it works out, so the same small question is never solved twice.

Time to learn: about 3 hours · Prerequisites: Recursion, Big-O

When to use it — the signal

The question asks for a count ("how many ways"), a best value ("minimum cost", "maximum profit", "longest") or a yes/no ("can you reach"), and the choices at each step depend on the choices before — "climb 1 or 2 steps", "rob or skip each house". If a brute-force recursion would call the same arguments again and again, it is DP.

The idea in plain words

You can climb a staircase 1 or 2 steps at a time. How many different ways reach step 5? Think about the last move: you arrived either from step 4 (one step) or from step 3 (two steps). So ways(5) = ways(4) + ways(3). The same rule works for every step — that is the recurrence (the formula linking a big answer to smaller answers).

Written as plain recursion this is correct but slow: ways(5) asks for ways(3) twice, ways(2) three times. For step 40 the number of calls is over 100 million, because the same questions are recomputed endlessly.

DP fixes it by remembering. There are two ways to do it:

  • Memoization (top-down): keep the recursion, but store each result in an array the first time; the next time, look it up.
  • Tabulation (bottom-up): fill a table from the smallest step upwards: dp[0], dp[1], dp[2]… each from cells already filled. No recursion at all.

Often each cell only needs the last one or two cells, so the table can shrink to two variables — O(1) memory.

Recipe for every DP problem: (1) what does dp[i] mean, in one sentence? (2) what is the recurrence? (3) what are the smallest answers you know for sure (base cases)? (4) in which order do you fill it?

Analogy

A child asked "what is 1+1+1+1+1?" counts to 5. Then you write "+1" on the left: they answer 6 at once — they remembered the 5 instead of counting again. DP is writing your sub-answers on a notepad so you never have to count again.

Watch it work

1. Plain recursion — the repeated work

Each circle is one call ways(n); the number under it is what it returns. Red = a call whose answer we had already computed somewhere else.

2. Memoization — remember each answer

Same recursion, plus an array memo. Before working, look in it; after working, write the answer in it. Green chips in the memo row are answers already saved.

3. Table, then two variables

Turn it around: start from the bottom. dp[i] = number of ways to reach step i. dp[0] = 1 (one way to stand still at the bottom) and dp[1] = 1. Every later cell is the sum of the two before it.

4. House Robber — a choice in every cell

Houses hold [2, 7, 9, 3, 1] coins. You cannot rob two neighbours. dp[i] = most money from houses 0..i. For house i there are two options: skip it (keep dp[i−1]) or rob it (its coins + dp[i−2], because house i−1 must then be skipped). Take the bigger.

Why it works

"The problem has optimal substructure — the answer for n is built from answers for smaller n — and overlapping subproblems — the same smaller n is needed many times. Storing each subproblem's answer once turns exponential recursion into O(number of subproblems × work per subproblem)."

The template to remember

// 1. dp[i] means: ...one sentence...
int[] dp = new int[n + 1];
dp[0] = ...;                          // 2. base cases
for (int i = 1; i <= n; i++)          // 3. order: smaller first
    dp[i] = combine(dp[i - 1], dp[i - 2], ...); // 4. recurrence
return dp[n];
Remember

Same question asked twice → write the answer down. Define dp[i] in one sentence, find the last choice, fill smallest first.

Common mistakes
  • Starting to code before writing what dp[i] means — the recurrence then comes out wrong.
  • Wrong base cases (dp[0] for stairs is 1, not 0) or forgetting the n = 1 case (House Robber with one house).
  • Memo with 0 as "unknown" when 0 is a real answer — use -1 or an Integer[] with null.
  • Filling the table in an order where a cell needs one that is not filled yet.
  • int overflow for counting problems with big n — use long, or the requested modulo.

Practice in this order

  • Easy70. Climbing Stairs — the first three animations.
    Show solution

    The idea

    You climb n steps taking 1 or 2 at a time; count the different ways. The last move onto step n was either a 1-step (from n−1) or a 2-step (from n−2), so ways(n) = ways(n-1) + ways(n-2). Pattern: 1-D DP (the Fibonacci recurrence), keeping only the last two values.

    Brute force first

    Plain recursion on the same formula recomputes the same steps again and again: O(2n).

    Step by step

    1. ways(0) = 1 (stand still), ways(1) = 1.
    2. For i = 2..n: cur = prev1 + prev2.
    3. Shift: prev2 = prev1, prev1 = cur.
    4. Return prev1.

    Java

    class Solution {
    public int climbStairs(int n) {
        // ways(i) = ways(i-1) + ways(i-2)
        int prev2 = 1;   // ways to reach step 0
        int prev1 = 1;   // ways to reach step 1
        for (int i = 2; i <= n; i++) {
            int cur = prev1 + prev2; // last move 1 or 2
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

    Time O(n) · Space O(1) — one loop, two variables.

    Dry run

    n = 4: ways 1, 1 → i=2: 2 → i=3: 3 → i=4: 5. Answer 5.

    Watch out

    n = 1 must return 1; the loop does not run and prev1 = 1 handles it. Values grow like Fibonacci; n ≤ 45 fits in an int.

  • Easy746. Min Cost Climbing Stairs — min instead of +.
    Show solution

    The idea

    Each step i has a cost you pay when you step off it; you may start on step 0 or 1 and want to reach the top (just past the last step). Cheapest cost to stand on step i is min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2]). Same shape as Climbing Stairs, with min instead of +. Pattern: 1-D DP.

    Step by step

    1. dp[0] = dp[1] = 0 (starting there is free).
    2. For i = 2..n: come from i−1 paying cost[i−1], or from i−2 paying cost[i−2]; keep the cheaper.
    3. Keep only the last two values.
    4. The top is index n; return dp[n].

    Java

    class Solution {
    public int minCostClimbingStairs(int[] cost) {
        // dp[i] = cheapest way to stand on step i
        // (you start free on step 0 or step 1)
        int prev2 = 0, prev1 = 0;      // dp[0], dp[1]
        for (int i = 2; i <= cost.length; i++) {
            int cur = Math.min(prev1 + cost[i - 1],
                               prev2 + cost[i - 2]);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;                  // the top = step n
    }
}

    Time O(n) · Space O(1) — one pass, two variables.

    Dry run

    [10,15,20]: dp0 = 0, dp1 = 0, dp2 = min(0+15, 0+10) = 10, dp3 = min(10+20, 0+15) = 15. Answer 15.

    Watch out

    The top is past the last step (index n), not the last step itself; looping only to n−1 is the common off-by-one.

  • Easy509. Fibonacci Number — the same recurrence.
    Show solution

    The idea

    F(0) = 0, F(1) = 1, F(n) = F(n−1) + F(n−2). Compute it bottom-up from the two smallest values instead of recursing. Pattern: 1-D DP with two rolling variables.

    Brute force first

    Direct recursion fib(n-1) + fib(n-2) is O(2n) because the same values are recomputed; memoizing fixes it to O(n).

    Step by step

    1. If n < 2 return n.
    2. a = F(0) = 0, b = F(1) = 1.
    3. Repeat n − 1 times: c = a + b, a = b, b = c.
    4. Return b.

    Java

    class Solution {
    public int fib(int n) {
        if (n < 2) return n;           // F(0)=0, F(1)=1
        int a = 0, b = 1;              // F(i-2), F(i-1)
        for (int i = 2; i <= n; i++) {
            int c = a + b;
            a = b;
            b = c;
        }
        return b;
    }
}

    Time O(n) · Space O(1) — one loop, two numbers.

    Dry run

    n = 4: (a,b) = (0,1) → (1,1) → (1,2) → (2,3). Answer 3.

    Watch out

    F(0) = 0, not 1. Off-by-one in the loop bounds shifts the whole sequence.

  • Medium198. House Robber — the fourth animation.
    Show solution

    The idea

    Houses in a row hold money; you cannot rob two neighbours. For house i you either skip it (keep the best so far) or rob it (its money plus the best up to i−2). best(i) = max(best(i-1), best(i-2) + nums[i]). Pattern: 1-D DP, take or skip.

    Brute force first

    Try every subset with no two neighbours: O(2n).

    Step by step

    1. prev2 = best up to i−2, prev1 = best up to i−1, both 0 at the start.
    2. For each house x: cur = max(prev1, prev2 + x).
    3. Shift the two variables.
    4. Return prev1.

    Java

    class Solution {
    public int rob(int[] nums) {
        // best(i) = max(best(i-1), best(i-2) + nums[i])
        int prev2 = 0;   // best up to house i-2
        int prev1 = 0;   // best up to house i-1
        for (int x : nums) {
            int cur = Math.max(prev1,      // skip house
                               prev2 + x); // rob house
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

    Time O(n) · Space O(1) — one pass with two numbers.

    Dry run

    [2,7,9,3,1]: best 2, 7, max(7, 2+9)=11, max(11, 7+3)=11, max(11, 11+1)=12. Answer 12.

    Watch out

    Greedy "take every other house" fails: [2,1,1,2] needs houses 0 and 3 for 4.

  • Medium213. House Robber II — houses in a circle: run twice, without first / without last.
    Show solution

    The idea

    Same as House Robber, but the houses form a circle, so the first and last are neighbours. Any valid plan leaves out the first house or the last house (or both). Run the line version twice: on houses 0..n−2 and on 1..n−1, and take the bigger. Pattern: break a circle into two lines.

    Step by step

    1. If there is one house, return its money.
    2. Write line(lo, hi): plain House Robber on a slice.
    3. Answer = max(line(0, n−2), line(1, n−1)).

    Java

    class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        if (n == 1) return nums[0];    // only one house
        // first and last are neighbours: never take both
        return Math.max(line(nums, 0, n - 2),  // no last
                        line(nums, 1, n - 1)); // no first
    }

    // plain House Robber on nums[lo..hi]
    int line(int[] nums, int lo, int hi) {
        int prev2 = 0, prev1 = 0;
        for (int i = lo; i <= hi; i++) {
            int cur = Math.max(prev1, prev2 + nums[i]);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

    Time O(n) · Space O(1) — two linear passes.

    Dry run

    [2,3,2]: without last → [2,3] best 3; without first → [3,2] best 3. Answer 3 (robbing both 2s is not allowed).

    Watch out

    n = 1 needs the special case: both slices would be empty and give 0.

  • Medium91. Decode Ways — like stairs: one digit or two digits.
    Show solution

    The idea

    Letters A–Z are coded 1–26; count how many ways a digit string can be decoded. "226" → 2-2-6, 22-6, 2-26 = 3. Like stairs: the last letter used one digit (valid if it is not '0') or two digits (valid if they form 10..26). ways(i) = [one ok] ways(i-1) + [two ok] ways(i-2). Pattern: 1-D DP over prefixes.

    Step by step

    1. If the string starts with '0', return 0.
    2. ways(0) = 1 (empty prefix), ways(1) = 1.
    3. For i = 2..n: one = digit i−1, two = digits i−2, i−1.
    4. cur = (one != '0' ? ways(i−1) : 0) + (10 ≤ two ≤ 26 ? ways(i−2) : 0).
    5. Shift the two variables; return the last.

    Java

    class Solution {
    public int numDecodings(String s) {
        // ways(i) = ways to decode the first i chars
        int prev2 = 1;   // ways(i-2); ways(0) = 1
        int prev1 = 1;   // ways(i-1)
        if (s.charAt(0) == '0') return 0;
        for (int i = 2; i <= s.length(); i++) {
            int cur = 0;
            char one = s.charAt(i - 1);      // last digit
            int two = (s.charAt(i - 2) - '0') * 10
                      + (one - '0'); // last 2 digits
            if (one != '0') cur += prev1;    // 1..9 alone
            if (two >= 10 && two <= 26)
                cur += prev2;                // 10..26 pair
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

    Time O(n) · Space O(1) — one pass, two counters.

    Dry run

    "226": ways0 = 1, ways1 = 1. i=2: '2' ok (+1), 22 ok (+1) → 2. i=3: '6' ok (+2), 26 ok (+1) → 3.

    Watch out

    '0' cannot stand alone, and "06" is not a two-digit code (it is < 10). "100" gives 0 because the last 0 has no partner.

  • Medium740. Delete and Earn — turn it into House Robber over values.
    Show solution

    The idea

    Taking a value v earns v points but deletes every v−1 and v+1. So if you take v once, take all copies: points[v] = v × count(v). Now values on a number line are "houses", and v and v+1 are neighbours. Run House Robber over points. Pattern: reduce to a known DP.

    Step by step

    1. Find the max value.
    2. Build points[v] = sum of every v in the array.
    3. House Robber over v = 0..max: cur = max(prev1, prev2 + points[v]).
    4. Return prev1.

    Java

    class Solution {
    public int deleteAndEarn(int[] nums) {
        int max = 0;
        for (int x : nums) max = Math.max(max, x);
        // points[v] = total you earn by taking every v
        int[] points = new int[max + 1];
        for (int x : nums) points[x] += x;
        // House Robber: values v-1 and v+1 are neighbours
        int prev2 = 0, prev1 = 0;
        for (int v = 0; v <= max; v++) {
            int cur = Math.max(prev1, prev2 + points[v]);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
}

    Time O(n + M) · Space O(M) — M is the largest value (≤ 104).

    Dry run

    [2,2,3,3,3,4]: points[2]=4, points[3]=9, points[4]=4. Robber: v2 → 4, v3 → max(4, 0+9)=9, v4 → max(9, 4+4)=9. Answer 9.

    Watch out

    Neighbours are by value, not by position in the input, so do not sort and rob the array directly.

Test yourself

What two properties make a problem a DP problem?

Optimal substructure (big answer from smaller answers) and overlapping subproblems (the same smaller answer is needed many times).

Memoization vs tabulation: which one recurses?

Memoization (top-down) keeps the recursion and caches results. Tabulation (bottom-up) fills a table with loops, no recursion and no stack-overflow risk.

When can a DP table shrink to a few variables?

When each cell only reads a fixed number of recent cells (here the last two). Keep just those and slide them forward.

House Robber: dp = [2, 7, 11, 11, 12]. Why is dp[3] = 11 and not 3 + 7 = 10?

Robbing house 3 gives 3 + dp[1] = 10, skipping it keeps dp[2] = 11. The skip is bigger.
