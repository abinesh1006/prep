Multi-source BFS

Put every starting point in the queue at once and run one BFS: the ripples spread from all of them together, so each cell learns its distance to the nearest source in a single pass.

Time to learn: about 1.5 hours · Prerequisites: Grid BFS / DFS, Tree BFS (level by level)

When to use it — the signal

"Minimum minutes until everything rots / burns / is infected", "distance to the nearest gate / 0 / land / exit" — many starting points, and every cell wants its distance to the closest one.

The idea in plain words

Suppose a 4 × 5 box of oranges has 2 rotten ones. Every minute, each rotten orange rots its fresh neighbours (up, down, left, right). How many minutes until no fresh orange is left?

The slow idea: run a BFS from the first rotten orange, then another from the second, and take the minimum per cell. With k sources that is k full BFS runs.

The trick: put all rotten oranges in the queue before starting. Now level 0 of the BFS is "every source", level 1 is "everything 1 step from some source", and so on. One BFS, O(R × C) total.

Process the queue one level at a time (read size = q.size() first, then poll exactly that many). Each level is one minute. At the end, if any fresh orange is left, it was unreachable → answer −1.

Analogy

Several fires start at the same moment in a forest. You do not simulate each fire separately — all of them spread at the same time, one ring of trees per minute. A tree burns when the nearest fire reaches it.

Watch it work

1. Rotting Oranges, minute by minute. F = fresh, a number = the minute that orange rotted (0 = rotten from the start), dark = empty.

2. Walls and Gates. ■ = wall, 0 = gate, ∞ = empty room. Fill every room with the distance to its nearest gate. Start a BFS from both gates at once; the first gate's ripple to reach a room wins.

Why it works

"Starting the BFS with all sources at distance 0 is the same as adding one invisible super-source connected to every real source. BFS from that super-source visits cells in increasing distance, so each cell is first reached by its nearest source."

The template to remember

for (every cell) if (isSource) q.add(cell);   // ALL sources first
int level = 0;
while (!q.isEmpty()) {
    for (int k = q.size(); k > 0; k--) {      // one ring
        cell = q.poll();
        for (each neighbour nb) if (unvisited(nb)) { mark(nb); q.add(nb); }
    }
    level++;                                // one minute passed
}

The one trick is in how the queue is filled: putting every source in before the loop starts makes the rings grow from all of them at once, so the first time a cell is reached is its distance to the nearest source.

Remember

Many starts, nearest wins → seed the queue with all of them. Freeze q.size() to count minutes.

Common mistakes
  • Running a separate BFS from every source — O(k × R × C), times out.
  • Using q.size() in the loop condition while adding — the level never ends. Read it once.
  • Rotting Oranges: counting one extra minute after the last orange rots (loop while fresh > 0), and forgetting the "0 fresh at the start → 0" case.
  • Forgetting the −1 when some fresh orange is unreachable.

  • Medium994. Rotting Oranges — exactly animation 1.
    Show solution

    The idea

    Each minute, every rotten orange (2) rots its fresh neighbours (1) up, down, left and right. How many minutes until no fresh orange is left, or −1 if one can never rot? Key insight: all rotten oranges spread at the same time, so put all of them in the queue first and run one BFS. Each BFS level is one minute. Pattern: multi-source BFS (BFS that starts from many cells at once).

    Brute force first

    Simulate minute by minute, scanning the whole grid each time to find oranges to rot: O((m·n)²) in the worst case.

    Step by step

    1. Scan the grid: queue every rotten orange and count the fresh ones.
    2. While the queue is not empty and some oranges are fresh, process one whole level (the current queue size).
    3. For each cell in the level, rot every fresh neighbour: set it to 2, lower fresh, queue it.
    4. After the level, add 1 to minutes.
    5. Return minutes if fresh == 0, else −1.

    Java

    class Solution {
    public int orangesRotting(int[][] grid) {
        int m = grid.length, n = grid[0].length;
        Deque<int[]> queue = new ArrayDeque<>();
        int fresh = 0;
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (grid[r][c] == 2) queue.add(new int[]{r, c});
                else if (grid[r][c] == 1) fresh++;
            }
        }
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        int minutes = 0;
        while (!queue.isEmpty() && fresh > 0) {
            // one loop of this = one minute
            for (int size = queue.size(); size > 0; size--) {
                int[] cell = queue.poll();
                for (int[] d : dirs) {
                    int r = cell[0] + d[0], c = cell[1] + d[1];
                    if (r >= 0 && c >= 0 && r < m && c < n
                            && grid[r][c] == 1) {
                        grid[r][c] = 2;     // it rots now
                        fresh--;
                        queue.add(new int[]{r, c});
                    }
                }
            }
            minutes++;
        }
        return fresh == 0 ? minutes : -1;
    }
}

    Time O(m·n) · Space O(m·n) — each orange is queued at most once.

    Dry run

    [[2,1,1],[1,1,0],[0,1,1]], fresh 6. Minute 1: (0,1), (1,0). Minute 2: (0,2), (1,1). Minute 3: (2,1). Minute 4: (2,2). fresh 0 → 4.

    Watch out

    If there are no fresh oranges at the start the answer is 0, not −1; the fresh > 0 condition in the loop handles it. Without that condition, the last level (which rots nothing) adds one extra minute.

  • Medium286. Walls and Gates — exactly animation 2 (premium; same as 542 in spirit).
    Show solution

    The idea

    Rooms are −1 (wall), 0 (gate) or INF (empty). Fill each empty room with the number of steps to its nearest gate. Key insight: start a single BFS from all gates together. BFS reaches cells in order of distance, so the first time any gate's wave touches a room, that is its nearest gate. Pattern: multi-source BFS.

    Brute force first

    BFS from every gate separately and keep the minimum: O(gates · m · n).

    Step by step

    1. Queue every gate (cell value 0).
    2. Pop a cell; its value is its distance here.
    3. For each neighbour that is still INF (empty and not reached), set it to here + 1 and queue it.
    4. Walls and already-filled rooms are not INF, so they are skipped automatically.

    Java

    class Solution {
    public void wallsAndGates(int[][] rooms) {
        final int EMPTY = Integer.MAX_VALUE;
        int m = rooms.length, n = rooms[0].length;
        Deque<int[]> queue = new ArrayDeque<>();
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (rooms[r][c] == 0) {   // every gate starts
                    queue.add(new int[]{r, c});
                }
            }
        }
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        while (!queue.isEmpty()) {
            int[] cell = queue.poll();
            int here = rooms[cell[0]][cell[1]];
            for (int[] d : dirs) {
                int r = cell[0] + d[0], c = cell[1] + d[1];
                if (r >= 0 && c >= 0 && r < m && c < n
                        && rooms[r][c] == EMPTY) {
                    rooms[r][c] = here + 1; // first = nearest
                    queue.add(new int[]{r, c});
                }
            }
        }
    }
}

    Time O(m·n) · Space O(m·n) — every room is filled and queued once.

    Dry run

    Row [INF, INF, 0, INF] with no walls. Queue the gate at index 2. Pop it: neighbours 1 and 3 become 1. Pop 1: index 0 becomes 2. Pop 3: nothing new. Result [2, 1, 0, 1].

    Watch out

    The value INF itself (Integer.MAX_VALUE) is the "not visited" mark; do not add 1 to it. Rooms no gate can reach stay INF, which is what the problem wants.

  • Medium542. 01 Matrix — all 0s are sources, distance to the nearest 0.
    Show solution

    The idea

    For every cell of a 0/1 matrix, return the distance to the nearest 0 (steps up, down, left, right). Key insight: flip the question. Instead of each 1 searching for a 0, let all 0s start one BFS together; the wave reaches each 1 first from its nearest 0. Pattern: multi-source BFS.

    Brute force first

    BFS from every 1 until it finds a 0: O((m·n)²) in the worst case.

    Step by step

    1. Make dist: 0 for every 0 cell (and queue it), −1 for every 1 cell (not reached yet).
    2. Pop a cell.
    3. For each neighbour with dist == −1, set dist = dist[cell] + 1 and queue it.
    4. When the queue is empty, dist is the answer.

    Java

    class Solution {
    public int[][] updateMatrix(int[][] mat) {
        int m = mat.length, n = mat[0].length;
        int[][] dist = new int[m][n];
        Deque<int[]> queue = new ArrayDeque<>();
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (mat[r][c] == 0) queue.add(new int[]{r, c});
                else dist[r][c] = -1;   // -1 = not reached
            }
        }
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        while (!queue.isEmpty()) {
            int[] cell = queue.poll();
            for (int[] d : dirs) {
                int r = cell[0] + d[0], c = cell[1] + d[1];
                if (r >= 0 && c >= 0 && r < m && c < n
                        && dist[r][c] == -1) {
                    dist[r][c] = dist[cell[0]][cell[1]] + 1;
                    queue.add(new int[]{r, c});
                }
            }
        }
        return dist;
    }
}

    Time O(m·n) · Space O(m·n) — each cell gets its distance once.

    Dry run

    [[0,0,0],[0,1,0],[1,1,1]]. Queue all six 0s. Their 1-neighbours (1,1), (2,0), (2,2) get 1. (2,1) is reached from (1,1) or (2,0) and gets 2. Result [[0,0,0],[0,1,0],[1,2,1]].

    Watch out

    Use a "not reached" mark (−1) that cannot be a real distance; starting 1-cells at 0 would mix them up with the real 0s. A two-pass DP (top-left then bottom-right) also works in O(m·n).

  • Medium1162. As Far from Land as Possible — all land is a source; answer is the last level.
    Show solution

    The idea

    In an n×n grid of land (1) and water (0), find the water cell whose nearest land is farthest away, and return that distance (−1 if there is no land or no water). Key insight: start a BFS from all land at once. The wave reaches every water cell at its distance to the nearest land, so the answer is simply the number of the last level the BFS reaches. Pattern: multi-source BFS.

    Step by step

    1. Queue every land cell.
    2. If the queue is empty (no land) or holds all n² cells (no water), return −1.
    3. Run BFS level by level, starting level at −1 and adding 1 at the start of each level (land is level 0).
    4. Turn each reached water cell into 1 so it is not visited again.
    5. When the queue empties, level is the farthest distance.

    Java

    class Solution {
    public int maxDistance(int[][] grid) {
        int n = grid.length;
        Deque<int[]> queue = new ArrayDeque<>();
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < n; c++) {
                if (grid[r][c] == 1) queue.add(new int[]{r, c});
            }
        }
        // all water or all land: no answer
        if (queue.isEmpty() || queue.size() == n * n) return -1;
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        int level = -1;
        while (!queue.isEmpty()) {
            level++;                    // land is level 0
            for (int size = queue.size(); size > 0; size--) {
                int[] cell = queue.poll();
                for (int[] d : dirs) {
                    int r = cell[0] + d[0], c = cell[1] + d[1];
                    if (r >= 0 && c >= 0 && r < n && c < n
                            && grid[r][c] == 0) {
                        grid[r][c] = 1; // mark visited
                        queue.add(new int[]{r, c});
                    }
                }
            }
        }
        return level;                   // the last level
    }
}

    Time O(n²) · Space O(n²) — each cell is queued once.

    Dry run

    [[1,0,0],[0,0,0],[0,0,0]]. Level 0: (0,0). Level 1: (0,1), (1,0). Level 2: (0,2), (1,1), (2,0). Level 3: (1,2), (2,1). Level 4: (2,2). Answer 4.

    Watch out

    Off-by-one: the last level processed adds no new cells but still counts, which is why level starts at −1. Forgetting the "all land / all water" check returns 0 instead of −1.

  • Medium1765. Map of Highest Peak — water cells are sources, height = BFS distance.
    Show solution

    The idea

    Assign a height to every cell: water cells must be 0, and two touching cells may differ by at most 1. Make the highest peak as tall as possible. Key insight: the tallest a land cell can be is its distance to the nearest water, and those distances follow the rule automatically. So it is the same as 01 Matrix: multi-source BFS from all water cells.

    Step by step

    1. Height 0 for water cells (queue them); −1 ("not set") for land.
    2. Pop a cell.
    3. Each neighbour still at −1 gets the popped cell's height + 1 and is queued.
    4. Return the height grid when the queue is empty.

    Java

    class Solution {
    public int[][] highestPeak(int[][] isWater) {
        int m = isWater.length, n = isWater[0].length;
        int[][] height = new int[m][n];
        Deque<int[]> queue = new ArrayDeque<>();
        for (int r = 0; r < m; r++) {
            for (int c = 0; c < n; c++) {
                if (isWater[r][c] == 1) {
                    queue.add(new int[]{r, c}); // height 0
                } else {
                    height[r][c] = -1;          // not set yet
                }
            }
        }
        int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        while (!queue.isEmpty()) {
            int[] cell = queue.poll();
            for (int[] d : dirs) {
                int r = cell[0] + d[0], c = cell[1] + d[1];
                if (r >= 0 && c >= 0 && r < m && c < n
                        && height[r][c] == -1) {
                    height[r][c] = height[cell[0]][cell[1]] + 1;
                    queue.add(new int[]{r, c});
                }
            }
        }
        return height;
    }
}

    Time O(m·n) · Space O(m·n) — every cell is set once.

    Dry run

    isWater = [[0,1],[0,0]]. Queue (0,1) with height 0. Its neighbours (0,0) and (1,1) get 1. Then (1,0) gets 2. Result [[1,0],[2,1]].

    Watch out

    Here 1 in the input means water, the opposite of most grid problems. Read the input carefully, and note the output is the new height grid, not the input.

  • Medium934. Shortest Bridge — DFS to collect island 1, then multi-source BFS to island 2.
    Show solution

    The idea

    The grid has exactly two islands. Find the fewest water cells to flip so they connect. Key insight: two phases. First, DFS finds one whole island (paint it 2 and put all its cells in the queue). Then multi-source BFS grows outward from that whole island one ring of water at a time; the number of rings crossed when you first touch the other island is the answer.

    Step by step

    1. Find any land cell. DFS from it, painting island 1 as 2 and queuing every one of its cells.
    2. Run BFS level by level with flips = 0.
    3. For each neighbour: if it is 1, that is island 2, so return flips.
    4. If it is 0 (water), paint it 2 and queue it.
    5. After each level, add 1 to flips.

    Java

    class Solution {
    private static final int[][] DIRS =
            {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    public int shortestBridge(int[][] grid) {
        int n = grid.length;
        Deque<int[]> queue = new ArrayDeque<>();
        // 1. paint the first island we meet as 2
        boolean found = false;
        for (int r = 0; r < n && !found; r++) {
            for (int c = 0; c < n && !found; c++) {
                if (grid[r][c] == 1) {
                    paint(grid, r, c, queue);
                    found = true;
                }
            }
        }
        // 2. grow from the whole island at once
        int flips = 0;
        while (!queue.isEmpty()) {
            for (int size = queue.size(); size > 0; size--) {
                int[] cell = queue.poll();
                for (int[] d : DIRS) {
                    int r = cell[0] + d[0], c = cell[1] + d[1];
                    if (r < 0 || c < 0 || r >= n || c >= n) {
                        continue;
                    }
                    if (grid[r][c] == 1) return flips; // island 2
                    if (grid[r][c] == 0) {
                        grid[r][c] = 2; // water, now visited
                        queue.add(new int[]{r, c});
                    }
                }
            }
            flips++;
        }
        return -1;
    }

    // DFS: paint island 1 and queue all of its cells
    private void paint(int[][] g, int r, int c,
                       Deque<int[]> queue) {
        if (r < 0 || c < 0 || r >= g.length || c >= g.length
                || g[r][c] != 1) {
            return;
        }
        g[r][c] = 2;
        queue.add(new int[]{r, c});
        for (int[] d : DIRS) paint(g, r + d[0], c + d[1], queue);
    }
}

    Time O(n²) · Space O(n²) — DFS and BFS each touch every cell at most once.

    Dry run

    [[0,1,0],[0,0,0],[0,0,1]]. DFS paints (0,1). Level 0 from (0,1): queue water (1,1), (0,2), (0,0); no 1 seen. flips 1. Level 1: queue water (2,1), (1,2), (1,0); still no 1. flips 2. Level 2: (2,1) has neighbour (2,2) = 1 → return 2.

    Watch out

    Stop the scan after the first island is painted; continuing would paint island 2 as well. Return when you see a 1 as a neighbour, and the answer is the number of water layers crossed, not layers + 1.

Test yourself

Why can't you just run BFS from the first rotten orange?

An orange near the second rotten orange would get a too-large time. All sources spread at the same time, so they must all start at level 0.

In Walls and Gates, why is a room never overwritten with a smaller number later?

BFS processes distance 1 rooms before distance 2 rooms, and so on. The first time a room is reached, the distance is already the smallest possible.

What is the time complexity with k sources on an R × C grid?

O(R × C), independent of k: each cell enters the queue at most once.
