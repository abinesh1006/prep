Multi-source BFS

Put every starting point in the queue at once and run one BFS: the ripples spread from all of them together, so each cell learns its distance to the nearest source in a single pass.

Time to learn: about 1.5 hours · Prerequisites: Grid BFS / DFS, Tree BFS (level by level)

When to use it — the signal

"Minimum minutes until everything rots / burns / is infected", "distance to the nearest gate / 0 / land / exit" — many starting points, and every cell wants its distance to the closest one.

The idea in plain words

Suppose a 4 × 5 box of oranges has 2 rotten ones. Every minute, each rotten orange rots its fresh neighbours (up, down, left, right). How many minutes until no fresh orange is left?

The slow idea: run a BFS from the first rotten orange, then another from the second, and take the minimum per cell. With k sources that is k full BFS runs.

The trick: put all rotten oranges in the queue before starting. Now level 0 of the BFS is "every source", level 1 is "everything 1 step from some source", and so on. One BFS, O(R × C) total.

Process the queue one level at a time (read size = q.size() first, then poll exactly that many). Each level is one minute. At the end, if any fresh orange is left, it was unreachable → answer −1.

Analogy

Several fires start at the same moment in a forest. You do not simulate each fire separately — all of them spread at the same time, one ring of trees per minute. A tree burns when the nearest fire reaches it.

Watch it work

1. Rotting Oranges, minute by minute. F = fresh, a number = the minute that orange rotted (0 = rotten from the start), dark = empty.

2. Walls and Gates. ■ = wall, 0 = gate, ∞ = empty room. Fill every room with the distance to its nearest gate. Start a BFS from both gates at once; the first gate's ripple to reach a room wins.

Why it works

"Starting the BFS with all sources at distance 0 is the same as adding one invisible super-source connected to every real source. BFS from that super-source visits cells in increasing distance, so each cell is first reached by its nearest source."

The template to remember

for (every cell) if (isSource) q.add(cell);   // ALL sources first
int level = 0;
while (!q.isEmpty()) {
    for (int k = q.size(); k > 0; k--) {      // one ring
        cell = q.poll();
        for (each neighbour nb) if (unvisited(nb)) { mark(nb); q.add(nb); }
    }
    level++;                                // one minute passed
}
Remember

Many starts, nearest wins → seed the queue with all of them. Freeze q.size() to count minutes.

Common mistakes
  • Running a separate BFS from every source — O(k × R × C), times out.
  • Using q.size() in the loop condition while adding — the level never ends. Read it once.
  • Rotting Oranges: counting one extra minute after the last orange rots (loop while fresh > 0), and forgetting the "0 fresh at the start → 0" case.
  • Forgetting the −1 when some fresh orange is unreachable.

Test yourself

Why can't you just run BFS from the first rotten orange?

An orange near the second rotten orange would get a too-large time. All sources spread at the same time, so they must all start at level 0.

In Walls and Gates, why is a room never overwritten with a smaller number later?

BFS processes distance 1 rooms before distance 2 rooms, and so on. The first time a room is reached, the distance is already the smallest possible.

What is the time complexity with k sources on an R × C grid?

O(R × C), independent of k: each cell enters the queue at most once.
