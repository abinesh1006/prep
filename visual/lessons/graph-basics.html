Graph Basics: DFS and BFS

A graph is dots (nodes) joined by lines (edges); you store it as "who are my neighbours" lists and walk it with DFS (go deep) or BFS (go wide), never stepping on the same node twice.

Time to learn: about 3 hours · Prerequisites: Stack basics, Tree BFS, Recursion

When to use it — the signal

The input is n nodes and a list of pairs — "edges", "connections", "friends", "prerequisites", "flights", "roads" — or the question asks "can you reach", "how many groups", "fewest steps". Build an adjacency list, then DFS or BFS.

The idea in plain words

Think of a map: cities are nodes and roads are edges. A tree is a graph too, but in a general graph there is no root, a city can have any number of roads, and roads can form loops (A → B → C → A).

  • Undirected: a two-way road. If 0 connects to 1, then 1 connects to 0. (Friendships.)
  • Directed: a one-way street, drawn with an arrow. 0 → 1 does not mean 1 → 0. (Course prerequisites, Twitter follows.)
  • Weighted: every road has a number on it — kilometres, minutes, rupees. (Flight prices.)

Problems usually hand you an edge list like [[0,1],[0,2],[1,3]]. That is awkward to search: to find 1's roads you must read the whole list. So the first thing you do is build an adjacency list — for every node, the list of its neighbours (adjacent = directly connected). Now "who are 1's neighbours?" is one lookup.

Then you walk the graph. DFS (depth-first search) keeps going down one road until it hits a dead end, then backs up — it uses a stack (or recursion). BFS (breadth-first search) visits everything 1 road away, then 2 roads away, then 3 — it uses a queue, and that is why BFS finds the fewest steps.

Because roads can loop, you keep a visited set: a node you have already seen is never entered again. With 6 nodes and 6 edges, each is touched about once, so the walk is O(V + E) — V = number of nodes, E = number of edges.

Analogy

Exploring a city with no map. DFS is the stubborn tourist: take any street, keep walking until a dead end, then walk back to the last crossroads with an unexplored street. BFS is a drop of ink on a paper map: it spreads to every street one block away, then two blocks, then three. Both tourists carry a notebook of streets already walked — that notebook is visited.

Watch it work

1. From edge list to adjacency list. 6 nodes, edges [[0,1],[0,2],[1,3],[1,4],[2,4],[4,5]], undirected. Watch the map fill in: every edge is written twice, once in each direction. Press ▶ or use the arrow keys to step.

2. DFS and BFS side by side on the same map. Left copy: DFS with a stack (take the newest). Right copy: BFS with a queue (take the oldest). The small badge on a node is the order it was visited. Both start at node 0.

3. Why we need visited. A triangle 0 – 1 – 2 has a loop. First BFS without the visited check, then with it.

Why it works

"Every node is marked visited the first time we reach it and is never processed again, and every edge is looked at once from each end, so the traversal is O(V + E). BFS processes nodes in order of distance from the start, so the first time it reaches a node is along a path with the fewest edges."

The template to remember

// 1. build
List<List<Integer>> adj = ...;   // n empty lists, add both directions
// 2. walk (BFS; swap Queue for a Stack and you get DFS)
boolean[] seen = new boolean[n];
Queue<Integer> q = new ArrayDeque<>();
q.add(start); seen[start] = true;
while (!q.isEmpty()) {
    int u = q.poll();
    for (int v : adj.get(u))
        if (!seen[v]) { seen[v] = true; q.add(v); }
}
// 3. count groups: loop over all nodes, start a walk from each unseen one
Remember

Edge list → adjacency list → walk with a visited set. Stack = deep (DFS, reachability, groups). Queue = wide (BFS, fewest steps).

Common mistakes
  • Forgetting the second add for undirected edges — half the roads become one-way.
  • Marking visited when you poll in BFS instead of when you add — the same node enters the queue many times.
  • Starting one walk from node 0 only — a graph can have several separate groups; loop over every node.
  • Recursive DFS on 100,000 nodes in a line — stack overflow. Use an explicit stack.

Practice in this order

  • Easy1971. Find if Path Exists in Graph — build the list, BFS from source, check destination.
    Show solution

    The idea

    We get n nodes and a list of two-way edges, and must say whether you can walk from source to destination. Example: edges 0–1, 1–2, so 0 can reach 2. The key insight: "can I reach it?" is just a walk that marks every node it touches. This is the basic BFS reachability pattern (BFS = breadth-first search: visit nodes ring by ring using a queue).

    Step by step

    1. Build an adjacency list: for each node, the list of its neighbours. Add every edge both ways, because roads are two-way.
    2. Put source in a queue and mark it seen.
    3. Take a node out. If it is destination, return true.
    4. Otherwise queue every neighbour not seen yet, marking it seen as you queue it.
    5. If the queue runs dry, destination was never reached: return false.

    Java

    class Solution {
    public boolean validPath(int n, int[][] edges,
                             int source, int destination) {
        // graph.get(u) = list of u's neighbours
        List<List<Integer>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }
        for (int[] e : edges) {
            graph.get(e[0]).add(e[1]);
            graph.get(e[1]).add(e[0]); // undirected: both ways
        }
        boolean[] seen = new boolean[n];
        Deque<Integer> queue = new ArrayDeque<>();
        queue.add(source);
        seen[source] = true;
        while (!queue.isEmpty()) {
            int u = queue.poll();
            if (u == destination) return true;
            for (int v : graph.get(u)) {
                if (!seen[v]) {
                    seen[v] = true;    // mark when queued
                    queue.add(v);
                }
            }
        }
        return false;                  // never reached it
    }
}

    Time O(n + E) · Space O(n + E) — every node and edge is handled once, and the list stores every edge twice.

    Dry run

    n = 6, edges 0–1, 0–2, 3–5, 5–4, 4–3, source 0, destination 5. Queue [0] → pop 0, add 1, 2 → pop 1 (nothing new) → pop 2 (nothing new) → queue empty. 5 is in the other group, so false.

    Watch out

    Mark a node as seen when you add it to the queue, not when you take it out, or the same node is queued many times. Also remember both directions of each edge; adding only e[0] → e[1] gives wrong answers. Union-Find solves this too.

  • Medium841. Keys and Rooms — the input is already an adjacency list; DFS from room 0.
    Show solution

    The idea

    Room i holds a list of keys, and key k opens room k. You start in room 0. Can you open every room? The input is already an adjacency list: room → rooms it unlocks. So it is plain reachability from node 0: walk, count the rooms you open, and compare with the total.

    Step by step

    1. Mark room 0 seen, push it on a stack, set opened = 1.
    2. Pop a room and look at each key in it.
    3. For a key to a room not seen yet: mark it, add 1 to opened, push it.
    4. When the stack is empty, return opened == rooms.size().

    Java

    class Solution {
    public boolean canVisitAllRooms(List<List<Integer>> rooms) {
        boolean[] seen = new boolean[rooms.size()];
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(0);
        seen[0] = true;
        int opened = 1;                // room 0 is open
        while (!stack.isEmpty()) {
            int room = stack.pop();
            for (int key : rooms.get(room)) {
                if (!seen[key]) {      // a new room to open
                    seen[key] = true;
                    opened++;
                    stack.push(key);
                }
            }
        }
        return opened == rooms.size();
    }
}

    Time O(rooms + keys) · Space O(rooms) — each room is opened once and each key read once.

    Dry run

    rooms = [[1],[2],[3],[]]. Stack [0] → pop 0, key 1 new, opened 2 → pop 1, key 2, opened 3 → pop 2, key 3, opened 4 → pop 3, no keys. 4 == 4, true.

    Watch out

    Keys can point back to rooms you already opened (even to the room itself). Without the seen check you loop forever. DFS with a stack or BFS with a queue both work: order does not matter, only reach.

  • Medium547. Number of Provinces — count how many walks you have to start.
    Show solution

    The idea

    isConnected[i][j] == 1 means cities i and j are directly linked. A province is a group of cities linked directly or through others. Count the groups. Key insight: every time you find a city nobody has visited, it starts a new group; a walk from it marks the whole group. So the answer is how many walks you had to start (counting connected components).

    Step by step

    1. Keep a seen array, all false.
    2. Loop over cities 0..n−1. If city i is not seen, add 1 to the count and run DFS from i.
    3. The DFS marks i, then for every j with isConnected[i][j] == 1 and not seen, recurses into j.
    4. After the loop, the count is the number of provinces.

    Java

    class Solution {
    public int findCircleNum(int[][] isConnected) {
        int n = isConnected.length;
        boolean[] seen = new boolean[n];
        int provinces = 0;
        for (int i = 0; i < n; i++) {
            if (!seen[i]) {            // untouched city
                provinces++;           // = a new province
                dfs(isConnected, seen, i);
            }
        }
        return provinces;
    }

    // visit every city reachable from u
    private void dfs(int[][] g, boolean[] seen, int u) {
        seen[u] = true;
        for (int v = 0; v < g.length; v++) {
            if (g[u][v] == 1 && !seen[v]) {
                dfs(g, seen, v);
            }
        }
    }
}

    Time O(n²) · Space O(n) — the DFS reads a full matrix row for each city; the recursion stack holds at most n cities.

    Dry run

    [[1,1,0],[1,1,0],[0,0,1]]. i = 0 not seen → count 1, DFS marks 0 and 1. i = 1 seen, skip. i = 2 not seen → count 2, DFS marks 2. Answer 2.

    Watch out

    The input is a matrix, not an edge list: loop over all j for a row instead of building a list. The diagonal is always 1 (city to itself); the seen check makes that harmless. Union-Find also works (see that lesson).

  • Medium797. All Paths From Source to Target — DFS that records the path (no visited needed: it is a DAG).
    Show solution

    The idea

    The graph is a DAG (directed, no cycles) given as graph[u] = nodes u points to. List every path from node 0 to node n−1. Key insight: because there are no cycles you can never walk in a circle, so you need no visited array; you just explore every branch. This is DFS with a path: add a node, go deeper, remove it on the way back (backtracking).

    Step by step

    1. Start the path as [0] and call DFS on 0.
    2. If the current node is n−1, save a copy of the path and return.
    3. Otherwise, for each next node v: add v to the path, recurse on v, then remove v.
    4. When DFS finishes, the result holds every path.

    Java

    class Solution {
    public List<List<Integer>> allPathsSourceTarget(
            int[][] graph) {
        List<List<Integer>> result = new ArrayList<>();
        List<Integer> path = new ArrayList<>();
        path.add(0);
        dfs(graph, 0, path, result);
        return result;
    }

    private void dfs(int[][] graph, int u, List<Integer> path,
                     List<List<Integer>> result) {
        if (u == graph.length - 1) {   // reached the target
            result.add(new ArrayList<>(path)); // save a copy
            return;
        }
        for (int v : graph[u]) {
            path.add(v);                   // step forward
            dfs(graph, v, path, result);
            path.remove(path.size() - 1);  // step back
        }
    }
}

    Time O(2ⁿ · n) · Space O(n) besides the output — a DAG can have up to 2ⁿ⁻² paths, each copied in O(n); the path and recursion are at most n deep.

    Dry run

    graph = [[1,2],[3],[3],[]]. Path [0] → add 1 → [0,1] → add 3 → [0,1,3] saved, back to [0,1] → back to [0] → add 2 → [0,2] → add 3 → [0,2,3] saved. Result [[0,1,3],[0,2,3]].

    Watch out

    Saving path itself instead of new ArrayList<>(path): every saved entry is the same list, and after backtracking they all end up as [0]. And do not forget to remove the last node after the recursive call.

  • Medium133. Clone Graph — BFS with a map old node → copy, which doubles as visited.
    Show solution

    The idea

    Make a deep copy of a connected graph: new nodes with the same values and the same links, sharing nothing with the original. Key insight: keep a map original → copy. It tells you whether a node has been copied (so it is your visited set) and it gives you the copy to link to. Pattern: BFS with a hash map.

    Step by step

    1. If the input is null, return null.
    2. Copy the start node, store it in the map, and put the original in a queue.
    3. Pop a node cur. For each neighbour nb: if nb has no copy yet, make one, store it, and queue nb.
    4. Always add copy(nb) to copy(cur).neighbors.
    5. Return the copy of the start node.

    Java

    class Solution {
    public Node cloneGraph(Node node) {
        if (node == null) return null;
        // original node -> its copy (also our visited set)
        Map<Node, Node> copies = new HashMap<>();
        copies.put(node, new Node(node.val));
        Deque<Node> queue = new ArrayDeque<>();
        queue.add(node);
        while (!queue.isEmpty()) {
            Node cur = queue.poll();
            for (Node nb : cur.neighbors) {
                if (!copies.containsKey(nb)) { // first time
                    copies.put(nb, new Node(nb.val));
                    queue.add(nb);
                }
                // copy of cur points to copy of nb
                copies.get(cur).neighbors.add(copies.get(nb));
            }
        }
        return copies.get(node);
    }
}

    Time O(V + E) · Space O(V) — each node is copied once and each edge linked once; the map and queue hold up to V nodes.

    Dry run

    1–2, 2–3, 3–4, 4–1. Copy 1′. Pop 1: neighbours 2 and 4 are new → copies 2′, 4′, link 1′→2′, 1′→4′. Pop 2: 1 already copied, link 2′→1′; 3 new → 3′, link 2′→3′. Pop 4: link 4′→1′, 4′→3′. Pop 3: link 3′→2′, 3′→4′. Done.

    Watch out

    Link the neighbour even when it is already in the map; skipping the link for visited nodes loses edges. Make the copy as you put a node in the queue, not when you take it out, or a node can be copied twice and the graph splits.

Test yourself

You need the fewest number of moves from A to B in an unweighted graph. DFS or BFS?

BFS. It reaches nodes in order of distance, so the first time it sees B is via a shortest path. DFS may find a long path first.

An undirected graph has 5 nodes and 4 edges. How many entries does the adjacency list hold?

8 — every undirected edge is stored once in each direction.

Why does a tree traversal not need a visited set, but a graph traversal does?

A tree has no loops and you only walk from parent to child, so you can never come back. A graph can have cycles, and undirected edges lead straight back to where you came from.

What is the time complexity of BFS on an adjacency list, and why not O(V²)?

O(V + E): each node is polled once and each neighbour list is read once, so total work is the number of nodes plus the total length of all lists (2E).
