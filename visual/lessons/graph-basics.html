Graph Basics: DFS and BFS

A graph is dots (nodes) joined by lines (edges); you store it as "who are my neighbours" lists and walk it with DFS (go deep) or BFS (go wide), never stepping on the same node twice.

Time to learn: about 3 hours · Prerequisites: Stack basics, Tree BFS, Recursion

When to use it — the signal

The input is n nodes and a list of pairs — "edges", "connections", "friends", "prerequisites", "flights", "roads" — or the question asks "can you reach", "how many groups", "fewest steps". Build an adjacency list, then DFS or BFS.

The idea in plain words

Think of a map: cities are nodes and roads are edges. A tree is a graph too, but in a general graph there is no root, a city can have any number of roads, and roads can form loops (A → B → C → A).

  • Undirected: a two-way road. If 0 connects to 1, then 1 connects to 0. (Friendships.)
  • Directed: a one-way street, drawn with an arrow. 0 → 1 does not mean 1 → 0. (Course prerequisites, Twitter follows.)
  • Weighted: every road has a number on it — kilometres, minutes, rupees. (Flight prices.)

Problems usually hand you an edge list like [[0,1],[0,2],[1,3]]. That is awkward to search: to find 1's roads you must read the whole list. So the first thing you do is build an adjacency list — for every node, the list of its neighbours (adjacent = directly connected). Now "who are 1's neighbours?" is one lookup.

Then you walk the graph. DFS (depth-first search) keeps going down one road until it hits a dead end, then backs up — it uses a stack (or recursion). BFS (breadth-first search) visits everything 1 road away, then 2 roads away, then 3 — it uses a queue, and that is why BFS finds the fewest steps.

Because roads can loop, you keep a visited set: a node you have already seen is never entered again. With 6 nodes and 6 edges, each is touched about once, so the walk is O(V + E) — V = number of nodes, E = number of edges.

Analogy

Exploring a city with no map. DFS is the stubborn tourist: take any street, keep walking until a dead end, then walk back to the last crossroads with an unexplored street. BFS is a drop of ink on a paper map: it spreads to every street one block away, then two blocks, then three. Both tourists carry a notebook of streets already walked — that notebook is visited.

Watch it work

1. From edge list to adjacency list. 6 nodes, edges [[0,1],[0,2],[1,3],[1,4],[2,4],[4,5]], undirected. Watch the map fill in: every edge is written twice, once in each direction. Press ▶ or use the arrow keys to step.

2. DFS and BFS side by side on the same map. Left copy: DFS with a stack (take the newest). Right copy: BFS with a queue (take the oldest). The small badge on a node is the order it was visited. Both start at node 0.

3. Why we need visited. A triangle 0 – 1 – 2 has a loop. First BFS without the visited check, then with it.

Why it works

"Every node is marked visited the first time we reach it and is never processed again, and every edge is looked at once from each end, so the traversal is O(V + E). BFS processes nodes in order of distance from the start, so the first time it reaches a node is along a path with the fewest edges."

The template to remember

// 1. build
List<List<Integer>> adj = ...;   // n empty lists, add both directions
// 2. walk (BFS; swap Queue for a Stack and you get DFS)
boolean[] seen = new boolean[n];
Queue<Integer> q = new ArrayDeque<>();
q.add(start); seen[start] = true;
while (!q.isEmpty()) {
    int u = q.poll();
    for (int v : adj.get(u))
        if (!seen[v]) { seen[v] = true; q.add(v); }
}
// 3. count groups: loop over all nodes, start a walk from each unseen one
Remember

Edge list → adjacency list → walk with a visited set. Stack = deep (DFS, reachability, groups). Queue = wide (BFS, fewest steps).

Common mistakes
  • Forgetting the second add for undirected edges — half the roads become one-way.
  • Marking visited when you poll in BFS instead of when you add — the same node enters the queue many times.
  • Starting one walk from node 0 only — a graph can have several separate groups; loop over every node.
  • Recursive DFS on 100,000 nodes in a line — stack overflow. Use an explicit stack.

Test yourself

You need the fewest number of moves from A to B in an unweighted graph. DFS or BFS?

BFS. It reaches nodes in order of distance, so the first time it sees B is via a shortest path. DFS may find a long path first.

An undirected graph has 5 nodes and 4 edges. How many entries does the adjacency list hold?

8 — every undirected edge is stored once in each direction.

Why does a tree traversal not need a visited set, but a graph traversal does?

A tree has no loops and you only walk from parent to child, so you can never come back. A graph can have cycles, and undirected edges lead straight back to where you came from.

What is the time complexity of BFS on an adjacency list, and why not O(V²)?

O(V + E): each node is polled once and each neighbour list is read once, so total work is the number of nodes plus the total length of all lists (2E).
