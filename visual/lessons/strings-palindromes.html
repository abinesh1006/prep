Strings and Palindromes

Four string tools interviewers love: grow palindromes from their middle, compare letter counts in a sliding window, skip re-checking with KMP, and compare whole windows with one number using a rolling hash.

Time to learn: about 3 hours · Prerequisites: Two pointers, Sliding window, Arrays and hashing

When to use it — the signal

"Longest palindromic substring", "count palindromic substrings" → expand around center. "Anagram", "permutation of p inside s" → frequency window. "Find a pattern in a text", "repeated substring", "shortest palindrome by adding letters" → KMP prefix function. "Find duplicate substrings of length L", "compare many substrings fast" → rolling hash (Rabin–Karp).

The idea in plain words

Palindrome = a word that reads the same forwards and backwards, like abba or racecar. Every palindrome has a middle: a single letter (racecar, odd length) or the gap between two letters (ab|ba, even length). A string of length 6 has 6 letters and 5 gaps, so only 11 possible middles. From each middle, step one letter left and one right; as long as the two letters match, it is still a palindrome. That is expand around center: O(n²) time, O(1) extra memory, and much simpler than any table.

Anagram = same letters, different order (abc, bca, cab). Two words are anagrams exactly when their letter counts match. To find every anagram of p (length 3) inside s, slide a window of length 3: add the new letter on the right, remove the old letter on the left, and compare 26 counts. Each slide costs O(26), not O(3 log 3) for sorting.

KMP (Knuth–Morris–Pratt) answers "where does pattern p appear in text t?" in O(n + m). Its secret is one array, lps ("longest proper prefix that is also a suffix"). lps[i] says: in p[0..i], how many letters at the end are the same as the letters at the start? For aabaaab, the full string ends with aab and starts with aab, so lps[6] = 3. When a match fails, you do not start over — you jump back to that already-matched prefix.

Rabin–Karp turns each window of text into one number (a hash = a fingerprint number). If the window's number differs from the pattern's number, the strings surely differ, so you skip them in O(1). Sliding the window one step only needs "remove the left digit, shift, add the right digit" — a rolling hash. If the numbers are equal, you check letter by letter, because two different strings can share a hash (a collision).

Analogy

Expand around center is like dropping a stone in a pond: the ripple grows outwards from the middle until the two sides stop matching. The anagram window is a bag of Scrabble tiles: you do not care about the order, only how many of each letter are in the bag. KMP is a reader who, after a mismatch, remembers "the last few letters I read are also how the word starts", so they never re-read. The rolling hash is a cashier who keeps a running total instead of re-adding the whole basket each time one item changes.

Watch it work

1. Longest palindromic substring — expand around every middle

String cabbad. We try all 11 middles. The answer, abba, comes from an even middle — the gap between the two bs.

2. Find all anagrams — a fixed window of letter counts

Find every start index in cbaebabacd where a rearrangement of abc begins. The window always holds exactly 3 letters.

3. KMP prefix function — building the lps array

Pattern aabaaab. len = how many letters at the start we have matched so far; i = the letter we are filling in. Watch the "fall back" at i = 2 and i = 5: instead of restarting from zero, len jumps to lps[len − 1].

4. Rabin–Karp — a rolling hash

Find 159 in 31415926. Each 3-digit window becomes one number. To slide, drop the left digit (subtract it × 100), shift (× 10) and add the new right digit.

Why it works

"Every palindrome is symmetric around its middle, and there are only 2n − 1 middles, so expanding from each one finds every palindrome in O(n²) with O(1) memory." For anagrams: "Two strings are anagrams exactly when their letter counts are equal, and sliding a fixed window changes only two counts." For KMP: "lps tells me the longest part of what I already matched that I can reuse, so the text pointer never moves backwards — O(n + m)."

The template to remember

// Expand around center: try 2n-1 middles
for (int i = 0; i < n; i++) {
    expand(i, i);       // odd
    expand(i, i + 1);   // even
}
// Anagram window: counts in, counts out
win[s[i]]++;  if (i >= m) win[s[i - m]]--;
if (Arrays.equals(need, win)) ans.add(i - m + 1);
// KMP: on mismatch, fall back with lps
while (len > 0 && c != p[len]) len = lps[len - 1];
if (c == p[len]) len++;
Remember

Palindrome → grow from 2n−1 middles. Anagram → compare counts in a sliding window. Pattern search → KMP's lps "never re-read". Many substrings → rolling hash, but verify on equal hashes.

Common mistakes
  • Forgetting the even middles: abba has no middle letter, so expand(i, i) alone misses it.
  • Computing the start index wrong after expand: it is i − (len − 1) / 2.
  • In KMP, moving i forward on a fall back — only len changes; i stays.
  • In Rabin–Karp, trusting equal hashes without checking the letters, or getting a negative number after subtraction (add MOD before %).
  • Sorting each window for anagrams — that is O(n · m log m) instead of O(26 · n).

  • Easy242. Valid Anagram — compare 26 counts.
    Show solution

    The idea

    Two words are anagrams when they use exactly the same letters the same number of times: "anagram" and "nagaram" both have three a's, one n, one g, one r, one m. So count the letters. Keep 26 counters (one per letter), add 1 for each letter of s, take 1 away for each letter of t. If every counter ends at 0, they match. Pattern: frequency count.

    Brute force first

    Sort both strings and compare them. That works but costs O(n log n) for the sort.

    Step by step

    1. If the lengths differ, they cannot be anagrams. Return false.
    2. Make an array count of 26 zeros. Index 0 is 'a', index 25 is 'z'.
    3. Walk both strings together. For position i, do count[s[i]]++ and count[t[i]]--.
    4. At the end, if any counter is not 0, some letter appears more in one word. Return false. Otherwise return true.

    Java

    class Solution {
    public boolean isAnagram(String s, String t) {
        if (s.length() != t.length()) return false;
        int[] count = new int[26];
        for (int i = 0; i < s.length(); i++) {
            count[s.charAt(i) - 'a']++; // s adds
            count[t.charAt(i) - 'a']--; // t removes
        }
        for (int c : count) {
            if (c != 0) return false;
        }
        return true;
    }
}

    Time O(n) · Space O(1) — one pass over the strings, and the array is always 26 long.

    Dry run

    s = "rat", t = "car". After the loop: r: +1, a: +1 −1 = 0, t: +1, c: −1. The counters for r, t and c are not 0, so the answer is false.

    Watch out

    s.charAt(i) - 'a' only works for lowercase a–z. For Unicode (the follow-up), use a HashMap<Character, Integer> instead of the array.

  • Medium5. Longest Palindromic Substring — animation 1.
    Show solution

    The idea

    Find the longest piece of the string that reads the same both ways. In "babad" that is "bab" (or "aba"). Every palindrome has a middle. So try each middle and grow outwards while the left and right letters are equal. A middle is either one letter ("aba") or the gap between two letters ("abba"). Pattern: expand around centre.

    Brute force first

    Check every substring (O(n²) of them) to see if it is a palindrome (O(n) each). That is O(n³), too slow for n = 1000.

    Step by step

    1. For each index c, try two centres: (c, c) for odd lengths and (c, c+1) for even lengths.
    2. Grow: while l >= 0, r < n and s[l] == s[r], move l left and r right.
    3. When the loop stops, the last good palindrome is s[l+1 .. r-1].
    4. If it is longer than the best so far, remember its ends.
    5. Return the best substring.

    Java

    class Solution {
    public String longestPalindrome(String s) {
        int bestL = 0, bestR = 0; // best = s[bestL..bestR]
        for (int c = 0; c < s.length(); c++) {
            // odd length: centre is one letter
            int[] odd = grow(s, c, c);
            // even length: centre is the gap c | c+1
            int[] even = grow(s, c, c + 1);
            if (odd[1] - odd[0] > bestR - bestL) {
                bestL = odd[0]; bestR = odd[1];
            }
            if (even[1] - even[0] > bestR - bestL) {
                bestL = even[0]; bestR = even[1];
            }
        }
        return s.substring(bestL, bestR + 1);
    }

    // expand while both ends match; return last good [l, r]
    private int[] grow(String s, int l, int r) {
        while (l >= 0 && r < s.length()
                && s.charAt(l) == s.charAt(r)) {
            l--;
            r++;
        }
        return new int[]{l + 1, r - 1};
    }
}

    Time O(n²) · Space O(1) — 2n centres, each grows at most n steps.

    Dry run

    s = "cbbd". Centre (1,1) "b" stays length 1. Centre (1,2): s[1] = s[2] = 'b', grow to (0,3): 'c' ≠ 'd', stop. Palindrome is s[1..2] = "bb", length 2, the answer.

    Watch out

    Forgetting the even centre (c, c+1) misses answers like "bb". Also return l + 1 and r - 1: the loop has already stepped one past the last match.

  • Medium647. Palindromic Substrings — same loop, count every grow step.
    Show solution

    The idea

    Count every substring that is a palindrome. "aaa" has six: a, a, a, aa, aa, aaa. Use the same expand-around-centre loop as problem 5, but instead of keeping the longest, add 1 for every step that still matches, because each successful step is a new palindrome. Pattern: expand around centre.

    Brute force first

    Test all O(n²) substrings with an O(n) check: O(n³).

    Step by step

    1. Set count = 0.
    2. For each index c, grow from centre (c, c) and from (c, c+1).
    3. Inside the grow loop, every time s[l] == s[r] holds, add 1 and step outwards.
    4. Return the total.

    Java

    class Solution {
    public int countSubstrings(String s) {
        int count = 0;
        for (int c = 0; c < s.length(); c++) {
            count += grow(s, c, c);     // odd centres
            count += grow(s, c, c + 1); // even centres
        }
        return count;
    }

    // every successful grow step is one palindrome
    private int grow(String s, int l, int r) {
        int found = 0;
        while (l >= 0 && r < s.length()
                && s.charAt(l) == s.charAt(r)) {
            found++;
            l--;
            r++;
        }
        return found;
    }
}

    Time O(n²) · Space O(1) — the same 2n centres, each growing at most n steps.

    Dry run

    s = "aaa". Odd centres give 1 + 2 + 1 = 4 (index 1 grows to "aaa"). Even centres give 1 ("aa" at 0–1) + 1 ("aa" at 1–2) + 0 = 2. Total 6.

    Watch out

    Each single letter is a palindrome, so the answer is always at least n. If you get less, the odd centre is missing.

  • Medium438. Find All Anagrams in a String — animation 2.
    Show solution

    The idea

    Find every place in s where a block of length p.length() is a reshuffle of p. Slide a window of that fixed size across s and keep 26 letter counts for the window. When a letter enters, add it; when one leaves, take it away. If the window's counts equal p's counts, record the start. Pattern: fixed-size sliding window.

    Brute force first

    Sort or count every window from scratch: O(n · k) where k is the length of p.

    Step by step

    1. If p is longer than s, return an empty list.
    2. Count p's letters into need.
    3. For each i in s, add s[i] to have. If i ≥ k, remove s[i-k], which just left the window.
    4. Once i ≥ k−1 the window is full: if need equals have, add the start i-k+1.

    Java

    class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> res = new ArrayList<>();
        int k = p.length();
        if (k > s.length()) return res;
        int[] need = new int[26], have = new int[26];
        for (char ch : p.toCharArray()) need[ch - 'a']++;
        for (int i = 0; i < s.length(); i++) {
            have[s.charAt(i) - 'a']++;          // letter enters
            if (i >= k) {
                have[s.charAt(i - k) - 'a']--;  // letter leaves
            }
            // window is s[i-k+1 .. i] once i >= k-1
            if (i >= k - 1 && Arrays.equals(need, have)) {
                res.add(i - k + 1);
            }
        }
        return res;
    }
}

    Time O(n · 26) = O(n) · Space O(1) — each step compares two arrays of 26.

    Dry run

    s = "abab", p = "ab", k = 2
i=1 window "ab"  match -> add 0
i=2 window "ba"  match -> add 1
i=3 window "ab"  match -> add 2      result [0, 1, 2]

    Watch out

    The start index is i - k + 1, not i - k. To avoid the 26-step compare, you can keep a "matches" counter instead, but the array compare is simpler and still O(n).

  • Medium567. Permutation in String — same window, return true at the first match.
    Show solution

    The idea

    Does s2 contain some reshuffle of s1 as one solid block? That is problem 438 asked as yes/no. Slide a window the size of s1 over s2 with 26 counts, and return true the first time the counts match. Pattern: fixed-size sliding window.

    Brute force first

    Generate every permutation of s1 and search for it: factorial time, hopeless.

    Step by step

    1. If s1 is longer than s2, return false.
    2. Count s1's letters into need.
    3. Slide over s2: add the new letter, and once the window is longer than k remove the letter k places back.
    4. When the window is full and need equals have, return true.
    5. If the loop ends, return false.

    Java

    class Solution {
    public boolean checkInclusion(String s1, String s2) {
        int k = s1.length();
        if (k > s2.length()) return false;
        int[] need = new int[26], have = new int[26];
        for (char ch : s1.toCharArray()) need[ch - 'a']++;
        for (int i = 0; i < s2.length(); i++) {
            have[s2.charAt(i) - 'a']++;
            if (i >= k) have[s2.charAt(i - k) - 'a']--;
            if (i >= k - 1 && Arrays.equals(need, have)) {
                return true; // first match is enough
            }
        }
        return false;
    }
}

    Time O(n) · Space O(1) — one pass and two arrays of 26.

    Dry run

    s1 = "ab", s2 = "eidbaooo". Windows: "ei", "id", "db", "ba". At "ba" the counts are a:1, b:1, the same as "ab", so the answer is true.

    Watch out

    Order inside the window does not matter, only counts. Do not compare strings.

  • Easy28. Find the Index of the First Occurrence — write KMP once by hand.
    Show solution

    The idea

    Find where needle first appears in haystack. KMP avoids starting over after a mismatch. First build lps: for each prefix of the needle, how long its longest "prefix that is also a suffix" is. On a mismatch you jump back to that length instead of to zero, because those letters already match. Pattern: KMP string matching.

    Brute force first

    Try each start in the haystack and compare letter by letter: O(n · m). That is accepted here, but interviewers ask for KMP.

    Step by step

    1. Build lps. Keep len, the current matched prefix length. For each i from 1: while there is a mismatch and len > 0, set len = lps[len-1]. If the letters match, add 1 to len. Store lps[i] = len.
    2. Scan the haystack with j = letters of needle matched so far.
    3. On a mismatch with j > 0, fall back: j = lps[j-1] (repeat while needed).
    4. On a match, add 1 to j. When j reaches m, the match starts at i - m + 1.
    5. If the scan ends without a full match, return −1.

    Java

    class Solution {
    public int strStr(String haystack, String needle) {
        int m = needle.length();
        if (m == 0) return 0;
        // lps[i] = length of the longest proper prefix of
        // needle[0..i] that is also a suffix of it
        int[] lps = new int[m];
        int len = 0;
        for (int i = 1; i < m; i++) {
            while (len > 0
                    && needle.charAt(i) != needle.charAt(len)) {
                len = lps[len - 1]; // fall back
            }
            if (needle.charAt(i) == needle.charAt(len)) len++;
            lps[i] = len;
        }
        int j = 0; // letters of needle matched so far
        for (int i = 0; i < haystack.length(); i++) {
            while (j > 0
                    && haystack.charAt(i) != needle.charAt(j)) {
                j = lps[j - 1]; // keep the matched prefix
            }
            if (haystack.charAt(i) == needle.charAt(j)) j++;
            if (j == m) return i - m + 1; // full match
        }
        return -1;
    }
}

    Time O(n + m) · Space O(m) — j only falls back as far as it has gone forward, so the total work is linear.

    Dry run

    needle = "aabaaac" gives lps = [0,1,0,1,2,2,0]. In "aabaaabaaac", after "aabaaa" fails on 'c' vs 'b', j falls back to lps[5] = 2 ("aa" is kept) instead of restarting. The full match ends at i = 10, so the start is 10 − 7 + 1 = 4.

    Watch out

    lps[0] is always 0 (a "proper" prefix cannot be the whole string), so the loop starts at i = 1. Use while, not if, for the fall back.

  • Hard214. Shortest Palindrome — lps of s + "#" + reverse(s).
    Show solution

    The idea

    You may only add letters to the front. So keep the longest palindrome that already starts at index 0, and put the rest of the string, reversed, in front of it. For "aacecaaa" the longest palindrome prefix is "aacecaa", so add the leftover "a" in front: "aaacecaaa". To find that prefix fast, build s + "#" + reverse(s) and take the KMP lps value at its last position. Pattern: KMP prefix function.

    Brute force first

    For each length from n down, check whether s[0..len) is a palindrome: O(n²).

    Step by step

    1. Let rev be s reversed, and t = s + "#" + rev.
    2. Build the lps array of t, the same as in KMP.
    3. keep = lps[last] is the longest prefix of s that equals a suffix of rev, which means it is a palindrome.
    4. Return rev.substring(0, n - keep) + s: the reversed leftover goes in front.

    Java

    class Solution {
    public String shortestPalindrome(String s) {
        String rev = new StringBuilder(s).reverse().toString();
        String t = s + "#" + rev; // '#' stops overlap
        int[] lps = new int[t.length()];
        int len = 0;
        for (int i = 1; i < t.length(); i++) {
            while (len > 0 && t.charAt(i) != t.charAt(len)) {
                len = lps[len - 1];
            }
            if (t.charAt(i) == t.charAt(len)) len++;
            lps[i] = len;
        }
        // longest palindrome that starts at index 0
        int keep = lps[t.length() - 1];
        // put the rest, reversed, in front
        return rev.substring(0, s.length() - keep) + s;
    }
}

    Time O(n) · Space O(n) — one lps pass over a string of length 2n + 1.

    Dry run

    s = "abcd", rev = "dcba", t = "abcd#dcba". The last lps value is 1 (only "a"). Add rev[0..3) = "dcb" in front: "dcbabcd".

    Watch out

    The '#' matters. Without it, for s = "aaa" the lps could run past the middle and come out longer than s. The empty string must return "".

  • Hard1044. Longest Duplicate Substring — binary search the length + rolling hash.
    Show solution

    The idea

    Find the longest substring that appears at least twice. If a repeat of length L exists, a repeat of length L−1 also exists (cut one letter off), so we can binary search the length. To test one length L fast, slide a rolling hash over every window of length L and look for a hash seen before. A rolling hash is a number for the window that you update in O(1) when it moves one step.

    Brute force first

    Compare all pairs of substrings: O(n³) or worse.

    Step by step

    1. Binary search L between 1 and n−1. For each middle value, run findDup(L).
    2. findDup: hash the first L letters as a base-31 number mod a big prime.
    3. Slide: remove the leaving letter (times BASE^(L−1)), multiply by BASE, add the new letter.
    4. If the hash was seen before, compare the actual text to rule out a false match (two different strings with the same hash). If it truly repeats, return this start.
    5. If findDup succeeds, keep the answer and try longer; otherwise try shorter.

    Java

    class Solution {
    private static final long MOD = 1_000_000_007L;
    private static final long BASE = 31;

    public String longestDupSubstring(String s) {
        int lo = 1, hi = s.length() - 1, bestStart = -1;
        int bestLen = 0;
        while (lo <= hi) {
            int mid = (lo + hi) / 2;
            int start = findDup(s, mid);
            if (start != -1) {      // length mid works
                bestStart = start;
                bestLen = mid;
                lo = mid + 1;       // try longer
            } else {
                hi = mid - 1;       // try shorter
            }
        }
        return bestStart == -1 ? ""
                : s.substring(bestStart, bestStart + bestLen);
    }

    // start of a repeated substring of length len, or -1
    private int findDup(String s, int len) {
        long hash = 0, power = 1; // power = BASE^(len-1)
        for (int i = 0; i < len; i++) {
            hash = (hash * BASE + s.charAt(i) - 'a' + 1) % MOD;
            if (i > 0) power = power * BASE % MOD;
        }
        Map<Long, List<Integer>> seen = new HashMap<>();
        seen.computeIfAbsent(hash, x -> new ArrayList<>())
            .add(0);
        for (int i = len; i < s.length(); i++) {
            // drop s[i-len], add s[i]
            long out = (s.charAt(i - len) - 'a' + 1) * power % MOD;
            hash = (hash - out + MOD) % MOD;
            hash = (hash * BASE + s.charAt(i) - 'a' + 1) % MOD;
            int start = i - len + 1;
            List<Integer> list = seen.get(hash);
            if (list != null) {
                // same hash: compare text to rule out a clash
                String cur = s.substring(start, start + len);
                for (int p : list) {
                    if (s.startsWith(cur, p)) return start;
                }
            }
            seen.computeIfAbsent(hash, x -> new ArrayList<>())
                .add(start);
        }
        return -1;
    }
}

    Time O(n log n) on average · Space O(n) — log n lengths, each a linear hash scan; text checks only run on hash hits.

    Dry run

    s = "banana". L = 2: "an" repeats, so try longer. L = 4: "bana", "anan", "nana" are all different, so try shorter. L = 3: "ana" appears at 1 and at 3, so it works. The answer is "ana".

    Watch out

    Keep every value in range: add MOD before taking % after a subtraction, or the hash goes negative. Without the text check, a hash clash can return a wrong answer.

Test yourself

How many middles does a string of length n have, and why both kinds?

2n − 1: n letters (odd-length palindromes) and n − 1 gaps (even-length palindromes like "abba").

What is lps for "abab"?

[0, 0, 1, 2]. "aba" ends with "a" = its start; "abab" ends with "ab" = its start.

Why does KMP never move the text pointer backwards?

After a mismatch, lps tells you how much of what you already matched is still a valid start, so you continue from there; the text characters already read are never needed again.

Two windows have the same rolling hash. Are they equal?

Not necessarily — different strings can collide. Always compare the letters (or use two different moduli to make collisions very unlikely).
