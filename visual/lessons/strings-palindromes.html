Strings and Palindromes

Four string tools interviewers love: grow palindromes from their middle, compare letter counts in a sliding window, skip re-checking with KMP, and compare whole windows with one number using a rolling hash.

Time to learn: about 3 hours · Prerequisites: Two pointers, Sliding window, Arrays and hashing

When to use it — the signal

"Longest palindromic substring", "count palindromic substrings" → expand around center. "Anagram", "permutation of p inside s" → frequency window. "Find a pattern in a text", "repeated substring", "shortest palindrome by adding letters" → KMP prefix function. "Find duplicate substrings of length L", "compare many substrings fast" → rolling hash (Rabin–Karp).

The idea in plain words

Palindrome = a word that reads the same forwards and backwards, like abba or racecar. Every palindrome has a middle: a single letter (racecar, odd length) or the gap between two letters (ab|ba, even length). A string of length 6 has 6 letters and 5 gaps, so only 11 possible middles. From each middle, step one letter left and one right; as long as the two letters match, it is still a palindrome. That is expand around center: O(n²) time, O(1) extra memory, and much simpler than any table.

Anagram = same letters, different order (abc, bca, cab). Two words are anagrams exactly when their letter counts match. To find every anagram of p (length 3) inside s, slide a window of length 3: add the new letter on the right, remove the old letter on the left, and compare 26 counts. Each slide costs O(26), not O(3 log 3) for sorting.

KMP (Knuth–Morris–Pratt) answers "where does pattern p appear in text t?" in O(n + m). Its secret is one array, lps ("longest proper prefix that is also a suffix"). lps[i] says: in p[0..i], how many letters at the end are the same as the letters at the start? For aabaaab, the full string ends with aab and starts with aab, so lps[6] = 3. When a match fails, you do not start over — you jump back to that already-matched prefix.

Rabin–Karp turns each window of text into one number (a hash = a fingerprint number). If the window's number differs from the pattern's number, the strings surely differ, so you skip them in O(1). Sliding the window one step only needs "remove the left digit, shift, add the right digit" — a rolling hash. If the numbers are equal, you check letter by letter, because two different strings can share a hash (a collision).

Analogy

Expand around center is like dropping a stone in a pond: the ripple grows outwards from the middle until the two sides stop matching. The anagram window is a bag of Scrabble tiles: you do not care about the order, only how many of each letter are in the bag. KMP is a reader who, after a mismatch, remembers "the last few letters I read are also how the word starts", so they never re-read. The rolling hash is a cashier who keeps a running total instead of re-adding the whole basket each time one item changes.

Watch it work

1. Longest palindromic substring — expand around every middle

String cabbad. We try all 11 middles. The answer, abba, comes from an even middle — the gap between the two bs.

2. Find all anagrams — a fixed window of letter counts

Find every start index in cbaebabacd where a rearrangement of abc begins. The window always holds exactly 3 letters.

3. KMP prefix function — building the lps array

Pattern aabaaab. len = how many letters at the start we have matched so far; i = the letter we are filling in. Watch the "fall back" at i = 2 and i = 5: instead of restarting from zero, len jumps to lps[len − 1].

4. Rabin–Karp — a rolling hash

Find 159 in 31415926. Each 3-digit window becomes one number. To slide, drop the left digit (subtract it × 100), shift (× 10) and add the new right digit.

Why it works

"Every palindrome is symmetric around its middle, and there are only 2n − 1 middles, so expanding from each one finds every palindrome in O(n²) with O(1) memory." For anagrams: "Two strings are anagrams exactly when their letter counts are equal, and sliding a fixed window changes only two counts." For KMP: "lps tells me the longest part of what I already matched that I can reuse, so the text pointer never moves backwards — O(n + m)."

The template to remember

// Expand around center: try 2n-1 middles
for (int i = 0; i < n; i++) {
    expand(i, i);       // odd
    expand(i, i + 1);   // even
}
// Anagram window: counts in, counts out
win[s[i]]++;  if (i >= m) win[s[i - m]]--;
if (Arrays.equals(need, win)) ans.add(i - m + 1);
// KMP: on mismatch, fall back with lps
while (len > 0 && c != p[len]) len = lps[len - 1];
if (c == p[len]) len++;
Remember

Palindrome → grow from 2n−1 middles. Anagram → compare counts in a sliding window. Pattern search → KMP's lps "never re-read". Many substrings → rolling hash, but verify on equal hashes.

Common mistakes
  • Forgetting the even middles: abba has no middle letter, so expand(i, i) alone misses it.
  • Computing the start index wrong after expand: it is i − (len − 1) / 2.
  • In KMP, moving i forward on a fall back — only len changes; i stays.
  • In Rabin–Karp, trusting equal hashes without checking the letters, or getting a negative number after subtraction (add MOD before %).
  • Sorting each window for anagrams — that is O(n · m log m) instead of O(26 · n).

Test yourself

How many middles does a string of length n have, and why both kinds?

2n − 1: n letters (odd-length palindromes) and n − 1 gaps (even-length palindromes like "abba").

What is lps for "abab"?

[0, 0, 1, 2]. "aba" ends with "a" = its start; "abab" ends with "ab" = its start.

Why does KMP never move the text pointer backwards?

After a mismatch, lps tells you how much of what you already matched is still a valid start, so you continue from there; the text characters already read are never needed again.

Two windows have the same rolling hash. Are they equal?

Not necessarily — different strings can collide. Always compare the letters (or use two different moduli to make collisions very unlikely).
