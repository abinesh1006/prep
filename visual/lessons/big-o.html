Big-O

A short label that says how fast the work grows when the input grows — so you can tell, before writing code, whether an idea is fast enough.

Time to learn: about 1.5 hours · Prerequisites: none (start here)

When to use it — the signal

Every problem. Look at the constraints line ("1 ≤ n ≤ 105") before anything else, and the interviewer's follow-up "can you do better?" or "what is the time and space complexity?" — both are Big-O questions.

The idea in plain words

Big-O does not measure seconds. It counts steps (one comparison, one addition, one array read) and asks one question: if the input gets 10 times bigger, how many times more steps?

  • O(1) — constant. Reading nums[5] takes 1 step whether the array has 10 or 10 million numbers.
  • O(log n) — halving. Each step throws away half the input. 1,000,000 numbers need only about 20 steps.
  • O(n) — one pass. Look at every number once. 10× more numbers → 10× more steps.
  • O(n log n) — sorting. A bit more than one pass.
  • O(n²) — every pair. A loop inside a loop. 10× more numbers → 100× more steps.

We drop constants and small terms: 3n + 7 steps is just O(n), because when n is a million the "×3" and the "+7" never decide whether you pass or fail.

Space complexity is the same idea for memory: how much extra memory (a copy, a map, a stack) you need as n grows.

Analogy

Finding a name in a phone book. Reading every page from the start is O(n). Opening the middle, deciding "earlier or later", and throwing away half each time is O(log n) — a 1,000-page book needs about 10 openings. Comparing every name with every other name to find two people with the same birthday is O(n²).

Why it works (the one sentence to say in an interview)

"Big-O describes how the number of steps grows with the input, ignoring constants: one pass is O(n), a loop inside a loop is O(n²), and anything that halves the input each step is O(log n). I check the constraints first — with n up to 105 an O(n²) idea is about 1010 steps, so I need O(n log n) or better."

The template to remember

// Read the code, count the shape
for (...)                 // one loop over n          -> O(n)
for (...) for (...)       // loop inside loop          -> O(n^2)
while (n > 1) n /= 2;    // halve each step           -> O(log n)
Arrays.sort(a);          // sort                      -> O(n log n)
map.get(k); a[i];        // hash lookup, index read   -> O(1)
// loops one after another: add, keep the biggest  (n + n = O(n))
// loops one inside another: multiply             (n * n = O(n^2))
Remember

Next to each other → add. Inside each other → multiply. Halving → log. 105 means "no n²"; 109 means "no n".

Common mistakes
  • Thinking two loops one after the other are O(n²). They are O(n + n) = O(n).
  • Forgetting hidden loops: list.contains(x), s.substring(), list.remove(0) and string + in a loop are each O(n).
  • Forgetting space: a recursion that goes n levels deep uses O(n) stack memory even with no arrays.
  • Saying "O(2n)" or "O(n + 5)". Drop constants: say O(n).
  • Using two different sizes as one: a grid of r rows and c columns is O(r·c), not O(n²).

Practice in this order

  • Easy217. Contains Duplicate — write the O(n²) pair check, then beat it with a set in O(n).
    Show solution

    The idea

    Given numbers, say whether any value appears twice. [1,2,3,1] → true because 1 shows up twice. The insight: instead of comparing every pair, remember what you have already seen in a hash set (a bag that answers "have I seen this?" in O(1)). Pattern: hashing to replace a nested loop.

    Brute force first

    Compare every pair i < j and return true if nums[i] == nums[j]. Two nested loops: O(n²) time, O(1) space. For n = 105 that is about 5×109 checks, far too slow.

    Step by step

    1. Make an empty HashSet.
    2. Walk the array one number at a time.
    3. set.add(x) returns false if x was already inside: that is a duplicate, return true.
    4. If the loop ends, no number repeated: return false.

    Java

    class Solution {
    public boolean containsDuplicate(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) {
            // add() is false when x was already there
            if (!seen.add(x)) return true;
        }
        return false;
    }
}

    Time O(n) · Space O(n) — each number is added once, and the set may hold all n.

    Dry run

    [1,2,3,1]: add 1 → {1}; add 2 → {1,2}; add 3 → {1,2,3}; add 1 fails → return true.

    Watch out

    Sorting first and checking neighbours also works in O(n log n) time with O(1) extra space; mention it if the interviewer asks for less memory. A single-element array has no duplicate.

  • Easy1480. Running Sum of 1d Array — turn an O(n²) "sum each prefix again" into one O(n) pass.
    Show solution

    The idea

    Return an array where position i holds nums[0] + ... + nums[i]. [1,2,3,4] → [1,3,6,10]. The insight: each answer is the previous answer plus one number, so never re-add from the start. Pattern: running total (prefix sum).

    Brute force first

    For each i, loop from 0 to i and add up. That is 1 + 2 + ... + n additions = O(n²) time.

    Step by step

    1. Start at index 1 (index 0 is already its own running sum).
    2. Set nums[i] += nums[i - 1]: the previous cell already holds the sum of everything before.
    3. Keep going to the end and return nums.

    Java

    class Solution {
    public int[] runningSum(int[] nums) {
        for (int i = 1; i < nums.length; i++) {
            // nums[i-1] already holds the sum so far
            nums[i] += nums[i - 1];
        }
        return nums;
    }
}

    Time O(n) · Space O(1) — one pass, and we reuse the input array for the answer.

    Dry run

    [1,2,3,4]: i=1 → 2+1=3; i=2 → 3+3=6; i=3 → 4+6=10 → [1,3,6,10].

    Watch out

    Start the loop at 1, not 0, or you read nums[-1]. If you must not change the input, copy it into a new array first (then space is O(n)).

  • Easy704. Binary Search — feel O(log n): count how many halvings for n = 104.
    Show solution

    The idea

    Find target in a sorted array and return its index, or -1. The insight: look at the middle; if it is too small the answer can only be on the right, so throw away the left half. Each step halves the range, so n = 104 needs only about 14 looks (214 = 16384). Pattern: binary search, O(log n).

    Brute force first

    Scan left to right until you find the target: O(n). It works but ignores that the array is sorted.

    Step by step

    1. Keep two ends: lo = 0, hi = n - 1. The answer, if it exists, is between them.
    2. While lo <= hi, take mid = lo + (hi - lo) / 2.
    3. If nums[mid] equals target, return mid.
    4. If it is smaller, the target is to the right: lo = mid + 1. Otherwise hi = mid - 1.
    5. If the range becomes empty, return -1.

    Java

    class Solution {
    public int search(int[] nums, int target) {
        int lo = 0, hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2; // no overflow
            if (nums[mid] == target) return mid;
            if (nums[mid] < target) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }
}

    Time O(log n) · Space O(1) — the search range halves every loop.

    Dry run

    nums = [-1,0,3,5,9,12], target = 9
lo=0 hi=5 mid=2 -> 3 < 9  -> lo=3
lo=3 hi=5 mid=4 -> 9 == 9 -> return 4

    Watch out

    Use lo <= hi (not <) or you skip the last single element. Write lo + (hi - lo) / 2 instead of (lo + hi) / 2 so huge indexes cannot overflow.

  • Easy69. Sqrt(x) — x up to 231: the constraint forces O(log n).
    Show solution

    The idea

    Return the whole-number square root of x, rounded down: sqrt(8) → 2. x can be about 2×109, so trying 1, 2, 3, ... could take ~46,000 steps per call and is the wrong shape; the constraint is a hint to binary search on the answer: find the largest m with m×m ≤ x.

    Brute force first

    Try m = 1, 2, 3, ... while m * m <= x. That is O(√x) steps; it passes, but the interviewer wants O(log x).

    Step by step

    1. Search range: lo = 0, hi = x.
    2. Take mid. Compute mid * mid as a long so it cannot overflow.
    3. If it is ≤ x, mid could be the answer: remember it and try bigger (lo = mid + 1).
    4. Otherwise mid is too big: hi = mid - 1.
    5. Return the last remembered mid.

    Java

    class Solution {
    public int mySqrt(int x) {
        int lo = 0, hi = x, ans = 0;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if ((long) mid * mid <= x) {
                ans = mid;      // fits, try bigger
                lo = mid + 1;
            } else {
                hi = mid - 1;   // too big
            }
        }
        return ans;
    }
}

    Time O(log x) · Space O(1) — about 31 halvings at most for a 32-bit x.

    Dry run

    x = 8
lo=0 hi=8 mid=4  16 > 8  -> hi=3
lo=0 hi=3 mid=1   1 <= 8 -> ans=1 lo=2
lo=2 hi=3 mid=2   4 <= 8 -> ans=2 lo=3
lo=3 hi=3 mid=3   9 > 8  -> hi=2  stop, return 2

    Watch out

    mid * mid in int overflows for big x and turns negative; cast to long. Remember x = 0 and x = 1.

  • Medium1. Two Sum — n ≤ 104: O(n²) passes, but say how a map makes it O(n).
    Show solution

    The idea

    Find the two indexes whose values add up to target. [2,7,11,15], target 9 → [0,1]. The insight: when you stand on x, the partner you need is target - x; a hash map from value to index tells you in O(1) if you already passed it. Pattern: hash map lookup of the complement.

    Brute force first

    Try every pair i < j: O(n²). With n ≤ 104 that is ~5×107 checks, which passes, but say how the map makes it O(n).

    Step by step

    1. Make an empty map: value → index.
    2. For each index i, compute need = target - nums[i].
    3. If need is in the map, return [map.get(need), i].
    4. Otherwise put nums[i] → i into the map and continue.

    Java

    class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            if (seen.containsKey(need)) {
                return new int[]{seen.get(need), i};
            }
            seen.put(nums[i], i); // store after checking
        }
        return new int[0]; // problem says never happens
    }
}

    Time O(n) · Space O(n) — one pass, each lookup O(1), the map can hold n values.

    Dry run

    [3,2,4], target 6: i=0 need 3, map empty, store 3→0. i=1 need 4, not there, store 2→1. i=2 need 2, found at 1 → return [1,2].

    Watch out

    Check the map before putting the current number in, otherwise [3,2,4], target 6 would pair index 0 with itself. Duplicates like [3,3] work because the first 3 is stored before the second is checked.

Test yourself

A loop over n, and after it (not inside) a second loop over n. What is the time?

O(n). n + n = 2n, and we drop the 2. Only nesting multiplies.

n ≤ 105. Is an O(n²) solution OK?

No. 1010 steps is about 100 seconds. Aim for O(n log n) or O(n).

How many times can you halve 1,000,000 before reaching 1?

About 20, because 220 ≈ 1,000,000. That is O(log n).

You build a HashMap holding every element. What is the extra space?

O(n) — the map grows with the input.
