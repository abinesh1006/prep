Binary Search Trees

A tree kept in order — everything on the left is smaller, everything on the right is bigger — so each step down throws away half of what is left, like binary search.

Time to learn: about 3 hours · Prerequisites: Tree traversals, Tree recursion, Binary search

When to use it — the signal

The problem says "BST" or "binary search tree", or asks for sorted order, "kth smallest", "successor / predecessor", "closest value", "values in range [lo, hi]", or "is this a valid BST". In Java code, "I need a sorted set / map with fast insert" means a TreeMap — a balanced BST.

The idea in plain words

The one rule: for every node, all values in its left subtree are smaller than it, and all values in its right subtree are bigger. Not just the direct children — the whole subtree.

  • Search for 7 starting at 8: 7 < 8, so it can only be on the left. Go left. Each step discards one whole side.
  • Insert 5: search for 5 as if it existed; where you fall off the tree (an empty spot) is exactly where 5 belongs.
  • In-order traversal (left, me, right) of a BST lists the values sorted. So "kth smallest" = the kth node of an in-order walk.
  • Validate: carry an allowed range (lo, hi) down. The root may be anything; its left child must be below the root; its left child's right child must be above the left child but still below the root.
  • Delete has three cases: a leaf (just remove it), one child (the child takes its place), two children (copy in the next bigger value — the successor, the smallest value in the right subtree — then delete that).

Cost: every operation walks one root-to-leaf path → O(h). For a balanced tree h ≈ log₂ n (1,000,000 nodes → about 20 steps). If you insert sorted data, the tree becomes a line and h = n — that is why Java's TreeMap uses a self-balancing red-black tree.

Analogy

A "guess my number" game with a friend who answers "smaller" or "bigger". Each answer tells you which half to keep. A BST is that game written down as a tree: every node is a guess, left is "smaller", right is "bigger". Or a library: books to the left of any shelf label come earlier in the alphabet, books to the right come later.

Why it works

"The BST rule holds for every subtree, so at each node the value I want can only be on one side — I discard the other side and walk one path: O(h). In-order visits left, me, right, which for a BST means smallest to biggest. Validation must carry a (lo, hi) range down, because the rule is about all ancestors, not just the parent."

The template to remember

// walk one path: O(h)
while (node != null) {
    if (x == node.val) return node;
    node = x < node.val ? node.left : node.right;
}
// validate: pass the allowed range down
boolean ok(node, lo, hi) = node == null
    || (lo < node.val && node.val < hi
        && ok(node.left, lo, node.val) && ok(node.right, node.val, hi));
Remember

Left < me < right, for whole subtrees. Search/insert/delete = one path, O(h). In-order = sorted. Validate with (lo, hi). Delete with two children = copy the successor.

Common mistakes
  • Validating by comparing a node only with its own children — misses cases like 6 under 3 under 5 above.
  • Using int bounds with Integer.MIN_VALUE / MAX_VALUE — a node holding exactly that value is wrongly rejected. Use long or Integer objects with null.
  • Forgetting to re-link: calling insert(node.left, x) without node.left = ... loses the new node.
  • Delete with two children: deleting the successor from the whole tree instead of from node.right.
  • Saying "BST operations are O(log n)" without "if balanced". A BST built from sorted input is a line: O(n).

Practice in this order

  • Easy700. Search in a Binary Search Tree — animation 1.
    Show solution

    The idea

    Find the node holding val in a BST (binary search tree: everything in a node's left subtree is smaller, everything in its right subtree is bigger) and return it, or null. Like binary search: at each node, one comparison tells you which half to throw away.

    Step by step

    1. Start at the root.
    2. If the node is null or holds val, stop and return it.
    3. If val is smaller, go left; otherwise go right.
    4. Repeat.

    Java

    class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        TreeNode cur = root;
        while (cur != null && cur.val != val) {
            // smaller lives on the left, bigger on the right
            cur = val < cur.val ? cur.left : cur.right;
        }
        return cur;          // the node, or null if missing
    }
}

    Time O(h) · Space O(1) — one step down per level; h is about log n for a balanced tree, n for a chain.

    Dry run

    [4,2,7,1,3], val 2: at 4, 2 < 4 → left; at 2, found → return subtree [2,1,3].

    Watch out

    Return the node itself (its whole subtree), not just true/false. When val is missing you fall off into null, which is the right answer.

  • Easy108. Convert Sorted Array to BST — the middle value is the root; recurse on both halves.
    Show solution

    The idea

    Turn a sorted array into a height-balanced BST (left and right heights differ by at most 1 everywhere). Pick the middle value as the root: everything left of it is smaller and goes into the left subtree, everything right of it goes right. Recurse on both halves (divide and conquer).

    Step by step

    1. build(lo, hi) works on nums[lo..hi]; empty range → null.
    2. mid = lo + (hi − lo) / 2; make a node with nums[mid].
    3. Its left child = build(lo, mid − 1); its right child = build(mid + 1, hi).
    4. Return the node; the answer is build(0, n − 1).

    Java

    class Solution {
    public TreeNode sortedArrayToBST(int[] nums) {
        return build(nums, 0, nums.length - 1);
    }

    // balanced BST from nums[lo..hi]
    private TreeNode build(int[] nums, int lo, int hi) {
        if (lo > hi) return null;
        int mid = lo + (hi - lo) / 2; // middle is the root
        TreeNode root = new TreeNode(nums[mid]);
        root.left = build(nums, lo, mid - 1); // smaller half
        root.right = build(nums, mid + 1, hi); // bigger half
        return root;
    }
}

    Time O(n) · Space O(log n) — each value becomes one node; recursion depth is log n because ranges halve.

    Dry run

    [-10,-3,0,5,9]: mid 0 → root 0. Left [-10,-3]: mid -10, right child -3. Right [5,9]: mid 5, right child 9. Tree [0,-10,5,null,-3,null,9].

    Watch out

    Use lo + (hi − lo) / 2 to avoid overflow on huge indices. Picking the left or right middle on even sizes are both accepted.

  • Medium701. Insert into a BST — animation 2.
    Show solution

    The idea

    Insert a new value into a BST and keep it a valid BST. Walk down as in a search: go left if the value is smaller, right if bigger, until you reach an empty spot; put the new node there. No existing node moves.

    Step by step

    1. If the current node is null, this is the gap: return a new node with val.
    2. If val is smaller, set root.left = insert(root.left, val).
    3. Otherwise set root.right = insert(root.right, val).
    4. Return root, so each parent keeps its (same) child link.

    Java

    class Solution {
    public TreeNode insertIntoBST(TreeNode root, int val) {
        if (root == null) return new TreeNode(val); // the gap
        if (val < root.val) {
            root.left = insertIntoBST(root.left, val);
        } else {
            root.right = insertIntoBST(root.right, val);
        }
        return root;         // hand my (same) node back up
    }
}

    Time O(h) · Space O(h) — one path down; recursion stack of height h (a loop makes it O(1)).

    Dry run

    [4,2,7,1,3], insert 5: 5 > 4 → right to 7; 5 < 7 → left, null → new node 5 becomes 7's left.

    Watch out

    Forgetting root.left = ... (just calling insert) loses the new node. An empty tree must return the new node as the root.

  • Medium98. Validate Binary Search Tree — animation 3; or check that in-order is strictly increasing.
    Show solution

    The idea

    Check the BST rule everywhere: not just "left child < me < right child", but every value in my left subtree is below me and every value in my right subtree is above me. Pass down an allowed range (lo, hi): going left lowers hi to my value, going right raises lo to my value.

    Brute force first

    Do an inorder traversal and check the list is strictly increasing; also O(n) and a fine alternative.

    Step by step

    1. Start with range (−∞, +∞), using long limits.
    2. Null node: valid.
    3. If the value is ≤ lo or ≥ hi, invalid.
    4. Check left with (lo, val) and right with (val, hi); both must be valid.

    Java

    class Solution {
    public boolean isValidBST(TreeNode root) {
        return valid(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }

    // every value in n's subtree must be in (lo, hi)
    private boolean valid(TreeNode n, long lo, long hi) {
        if (n == null) return true;
        if (n.val <= lo || n.val >= hi) return false;
        // left side: below me; right side: above me
        return valid(n.left, lo, n.val)
            && valid(n.right, n.val, hi);
    }
}

    Time O(n) · Space O(h) — each node checked once.

    Dry run

    [5,4,6,null,null,3,7]: 6 is in (5, ∞) fine; its left child 3 must be in (5, 6) → 3 ≤ 5 → false, even though 3 < 6 locally.

    Watch out

    Using Integer.MIN_VALUE/MAX_VALUE as limits fails for a node that holds exactly that value; use long limits (or null for "no limit"). Duplicates are not allowed, so use strict comparisons.

  • Medium230. Kth Smallest Element in a BST — animation 4.
    Show solution

    The idea

    In a BST, an inorder traversal (left, me, right) visits values in sorted order. So the k-th value it visits is the k-th smallest. Do the iterative inorder with a stack and stop as soon as you have counted k nodes.

    Brute force first

    Collect the whole inorder list, then return element k − 1: O(n) time and space.

    Step by step

    1. Slide left from the current node, pushing every node on the way.
    2. Pop: this is the next smallest value; decrease k.
    3. If k reached 0, return this value.
    4. Otherwise move to the popped node's right child and repeat.

    Java

    class Solution {
    public int kthSmallest(TreeNode root, int k) {
        Deque<TreeNode> stack = new ArrayDeque<>();
        TreeNode cur = root;
        while (true) {
            while (cur != null) {    // slide left
                stack.push(cur);
                cur = cur.left;
            }
            cur = stack.pop();       // next smallest value
            if (--k == 0) return cur.val;
            cur = cur.right;
        }
    }
}

    Time O(h + k) · Space O(h) — we only walk down to the start and then k steps.

    Dry run

    [3,1,4,null,2], k = 1: push 3, push 1 → pop 1, k = 0 → return 1.

    Watch out

    k is 1-based: the smallest value is k = 1. Decrease k before comparing with 0 (or compare with 1).

  • Medium450. Delete Node in a BST — animation 5.
    Show solution

    The idea

    Remove the node with value key and keep the BST valid. Find it like a search. A node with 0 or 1 child is easy: replace it by its child (or null). A node with 2 children: copy in its successor (the smallest value in its right subtree), then delete that successor from the right subtree; the successor has no left child, so that delete is the easy case.

    Step by step

    1. If root is null, the key is not there: return null.
    2. If key is smaller, delete in the left subtree; if bigger, in the right subtree.
    3. Found it: if there is no left child return the right one; if no right child return the left one.
    4. Two children: find the leftmost node of the right subtree, copy its value here, then delete that value from the right subtree.
    5. Return root.

    Java

    class Solution {
    public TreeNode deleteNode(TreeNode root, int key) {
        if (root == null) return null;         // not found
        if (key < root.val) {
            root.left = deleteNode(root.left, key);
        } else if (key > root.val) {
            root.right = deleteNode(root.right, key);
        } else {
            // found it. 0 or 1 child: lift the child up
            if (root.left == null) return root.right;
            if (root.right == null) return root.left;
            // 2 children: copy in the successor (smallest
            // on the right), then delete that successor
            TreeNode s = root.right;
            while (s.left != null) s = s.left;
            root.val = s.val;
            root.right = deleteNode(root.right, s.val);
        }
        return root;
    }
}

    Time O(h) · Space O(h) — one path down plus one walk to the successor.

    Dry run

    [5,3,6,2,4,null,7], delete 3: 3 has two children; successor = 4 (leftmost of [4]); copy 4 into the node, delete 4 from its right subtree. Tree [5,4,6,2,null,null,7].

    Watch out

    Always assign the result back (root.left = deleteNode(...)); that is how a removed child gets replaced. Deleting the root itself must also work.

  • Medium173. Binary Search Tree Iterator — the iterative in-order, paused between calls.
    Show solution

    The idea

    Build an iterator over a BST that returns values in sorted order, one per next() call, using only O(h) memory. It is the iterative inorder traversal "paused": the stack holds the left spine still waiting to be printed.

    Brute force first

    Do a full inorder into a list in the constructor and walk through it: easy, but O(n) memory.

    Step by step

    1. pushLeft(n): push n and every node down its left edge.
    2. Constructor: pushLeft(root).
    3. next(): pop the top (the smallest remaining), then pushLeft(its right child), then return its value.
    4. hasNext(): the stack is not empty.

    Java

    class BSTIterator {
    // the "left spine" still waiting to be printed
    private final Deque<TreeNode> stack = new ArrayDeque<>();

    public BSTIterator(TreeNode root) {
        pushLeft(root);
    }

    public int next() {
        TreeNode n = stack.pop();  // smallest not yet given
        pushLeft(n.right);         // its right side is next
        return n.val;
    }

    public boolean hasNext() {
        return !stack.isEmpty();
    }

    // push n and everything down its left edge
    private void pushLeft(TreeNode n) {
        while (n != null) {
            stack.push(n);
            n = n.left;
        }
    }
}

    Time O(1) on average per call · Space O(h) — every node is pushed and popped exactly once over all calls.

    Dry run

    [7,3,15,null,null,9,20]: stack [7,3]. next → 3. next → 7, push 15, 9 → stack [15,9]. next → 9. next → 15, push 20. next → 20. hasNext → false.

    Watch out

    Remember to pushLeft the popped node's right child; skipping it loses the whole right subtree.

Test yourself

You insert 1, 2, 3, 4, 5 in that order into an empty BST. What shape is it and what does search cost?

A line going right (every node only has a right child). Height 5 = n, so search is O(n). Balanced trees (TreeMap) avoid this.

What range does the right child of the left child of the root get, if the root is 10 and its left child is 5?

(5, 10): bigger than its parent 5, but still smaller than the root 10 because it is in the root's left subtree.

Why copy the successor instead of the predecessor? Would the predecessor work?

Either works. The successor (smallest on the right) and the predecessor (biggest on the left) both keep "left < me < right" true, and both have at most one child, so removing them is easy.

Kth smallest: what is the time if you stop as soon as k reaches 0?

O(h + k): sliding down to the smallest costs h, then each of the k pops is amortised O(1).
