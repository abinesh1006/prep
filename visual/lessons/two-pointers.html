Two Pointers

Two fingers on the same array, moving towards each other (or in the same direction), so you check pairs in one pass instead of trying every pair.

Time to learn: about 2 hours · Prerequisites: Arrays & hashing, Big-O

When to use it — the signal

The array is sorted (or you may sort it) and the question asks about a pair or triplet — "two numbers that add up to", "closest sum", "remove duplicates in place", "is it a palindrome".

The idea in plain words

Suppose you must find two numbers in a sorted list that add up to 9. The slow way is to try every pair: first with second, first with third, and so on. With 10,000 numbers that is about 50 million pairs.

The smart way: put your left finger on the smallest number and your right finger on the largest. Add them.

  • Sum too small? You need a bigger number. The only way to grow the sum is to move the left finger right.
  • Sum too big? You need a smaller number. Move the right finger left.
  • Sum exactly right? Done.

Every step throws away one number for good, so you finish in at most n steps.

Analogy

Two people stand at opposite ends of a line of kids sorted by height, looking for a pair whose heights add to exactly 2 metres. If the pair is too short, the person at the short end steps forward to a taller kid. If too tall, the person at the tall end steps forward to a shorter kid. They never need to go back.

Watch it work

Find two numbers that add up to target = 9 in [1, 2, 4, 5, 7, 11]. Press ▶ or use the arrow keys to step.

Why it is correct (the one sentence to say in an interview)

"When the sum is too small, the left number cannot pair with anything — even the largest remaining number is not enough — so discarding it loses no answer. The same logic in reverse discards the right number when the sum is too big."

Second flavour: same direction (read / write pointers)

Both fingers start at the left. The fast finger reads every number; the slow finger marks where the next "keeper" should be written. Classic use: remove duplicates from a sorted array in place.

The template to remember

// Opposite ends — sorted array, pair questions
int l = 0, r = n - 1;
while (l < r) {
    if (good(l, r)) return ...;
    else if (needBigger) l++;
    else r--;
}

Data structures used — and why

StructureWhat we need from itCostWhy not the alternative
sorted int[]O(1) access at both ends, and the sorted order tells which pointer to move.O(1) per step, O(n) total A HashMap also solves pair sums in O(n) but needs O(n) extra space; Two Sum II asks for O(1).
String125: charAt(l) and charAt(r) from both ends.O(1) per charAt Building a cleaned, reversed copy works but costs O(n) extra space.

Two pointers is the pattern that needs almost no structure: a sorted array and two indexes replace the hash map, which is why its space is O(1).

Remember

Sorted + pair → two pointers. Unsorted + pair → hash map. Too small → left moves. Too big → right moves.

Common mistakes
  • Using l <= r — the same element would be used twice.
  • Using two pointers on an unsorted array. Sort first (O(n log n)) or use a hash map.
  • In 3Sum, forgetting to skip duplicates after a match — you return the same triplet twice.

Practice in this order

  • Easy125. Valid Palindrome — pointers from both ends, skip non-letters.
    Show solution

    The idea

    Ignore everything that is not a letter or digit, ignore upper/lower case, then ask: does it read the same both ways? "A man, a plan, a canal: Panama" → true. The insight: put one pointer at each end and walk them inward, skipping junk characters, comparing as you go. Pattern: two pointers from both ends.

    Brute force first

    Build a cleaned lowercase string, reverse it, compare: O(n) time but O(n) extra space. Two pointers need O(1) space.

    Step by step

    1. l = 0, r = n - 1.
    2. Move l right while it points at a non letter/digit; move r left the same way.
    3. Compare the two characters in lowercase; if different, return false.
    4. Step both inward (l++, r--) and repeat while l < r.
    5. If they meet, it is a palindrome.

    Java

    class Solution {
    public boolean isPalindrome(String s) {
        int l = 0, r = s.length() - 1;
        while (l < r) {
            char a = s.charAt(l), b = s.charAt(r);
            if (!Character.isLetterOrDigit(a)) { l++; continue; }
            if (!Character.isLetterOrDigit(b)) { r--; continue; }
            if (Character.toLowerCase(a)
                    != Character.toLowerCase(b)) return false;
            l++;
            r--;
        }
        return true;
    }
}

    Time O(n) · Space O(1) — each pointer moves across the string at most once.

    Dry run

    "race a car" (indexes 0..9): r/r, a/a, c/c match. Then l=3 is e; r=6 is a space, skip to r=5 a. e ≠ a → false.

    Watch out

    Digits count too: "0P" is false. A string with no letters at all (" ") is a palindrome. Use Character.isLetterOrDigit, not only isLetter.

  • Medium167. Two Sum II — exactly the animation above.
    Show solution

    The idea

    The array is sorted; find two numbers that add to target and return their positions 1-based. [2,7,11,15], 9 → [1,2]. The insight: start with the smallest and largest. If the sum is too big, the only way to shrink it is to move the right pointer left; too small, move the left pointer right. Pattern: two pointers on a sorted array, O(1) space.

    Brute force first

    Every pair: O(n²). Or a hash map like Two Sum: O(n) time but O(n) space; the problem asks for constant extra space.

    Step by step

    1. l = 0, r = n - 1.
    2. Compute sum = numbers[l] + numbers[r].
    3. Equal to target: return [l + 1, r + 1].
    4. Too small: l++ (need a bigger number). Too big: r--.

    Java

    class Solution {
    public int[] twoSum(int[] numbers, int target) {
        int l = 0, r = numbers.length - 1;
        while (l < r) {
            int sum = numbers[l] + numbers[r];
            if (sum == target) return new int[]{l + 1, r + 1};
            if (sum < target) l++; // need bigger
            else r--;              // need smaller
        }
        return new int[0]; // problem says never happens
    }
}

    Time O(n) · Space O(1) — each step moves one pointer, so at most n steps.

    Dry run

    [2,3,4], 6: 2+4=6 → return [1,3]. [2,7,11,15], 9: 2+15=17 big r--; 2+11=13 r--; 2+7=9 → [1,2].

    Watch out

    Answer is 1-based: return l + 1, r + 1. Use l < r so you never use the same element twice.

  • Medium15. 3Sum — fix one number, two pointers on the rest.
    Show solution

    The idea

    Find every unique triple that sums to 0: [-1,0,1,2,-1,-4] → [[-1,-1,2],[-1,0,1]]. The insight: sort, then fix the first number nums[i] and solve Two Sum II on the rest with two pointers, looking for -nums[i]. Skip equal neighbours so no triple is reported twice.

    Brute force first

    Three nested loops plus a set to remove duplicate triples: O(n³). Too slow for n = 3000.

    Step by step

    1. Sort the array.
    2. For each i: if nums[i] equals nums[i - 1], skip it (same first number again). If nums[i] > 0, stop: nothing after can sum to 0.
    3. Set l = i + 1, r = n - 1; compute sum = nums[i] + nums[l] + nums[r].
    4. Sum < 0: l++. Sum > 0: r--. Sum = 0: record the triple, move both, and skip duplicates of nums[l].
    5. Return all recorded triples.

    Java

    class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> res = new ArrayList<>();
        int n = nums.length;
        for (int i = 0; i < n - 2; i++) {
            if (nums[i] > 0) break;
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            int l = i + 1, r = n - 1;
            while (l < r) {
                int sum = nums[i] + nums[l] + nums[r];
                if (sum < 0) l++;
                else if (sum > 0) r--;
                else {
                    res.add(List.of(nums[i], nums[l], nums[r]));
                    l++;
                    r--;
                    // skip repeats of the middle number
                    while (l < r && nums[l] == nums[l - 1]) l++;
                }
            }
        }
        return res;
    }
}

    Time O(n²) · Space O(1) extra (besides the output and the sort) — n choices of i, each a linear two-pointer scan.

    Dry run

    sorted: [-4,-1,-1,0,1,2]
i=0 (-4): l,r sums all < 0, no triple
i=1 (-1): -1+-1+2=0 add [-1,-1,2]; l=3 r=4: -1+0+1=0 add [-1,0,1]
i=2 (-1): same as nums[1], skip
i=3 (0):  0+1+2 > 0, r-- ... none

    Watch out

    Duplicates are the classic bug: skip equal nums[i] values, and after a hit skip equal nums[l] values. [0,0,0,0] must give one triple, not several.

  • Medium11. Container With Most Water — move the shorter wall.
    Show solution

    The idea

    Pick two lines; the water they hold is min(height) × distance. Find the largest. [1,8,6,2,5,4,8,3,7] → 49. The insight: start with the widest pair. The shorter wall limits the water, so moving the taller wall inward can never help; always move the shorter wall. Pattern: two pointers, greedy shrink.

    Brute force first

    Try every pair: O(n²). With n up to 105 that is too slow.

    Step by step

    1. l = 0, r = n - 1, best = 0.
    2. Area = min(h[l], h[r]) * (r - l); keep the max.
    3. If h[l] < h[r], move l++; otherwise r--.
    4. Repeat until the pointers meet.

    Java

    class Solution {
    public int maxArea(int[] height) {
        int l = 0, r = height.length - 1, best = 0;
        while (l < r) {
            int h = Math.min(height[l], height[r]);
            best = Math.max(best, h * (r - l));
            // the shorter wall can't do better; drop it
            if (height[l] < height[r]) l++;
            else r--;
        }
        return best;
    }
}

    Time O(n) · Space O(1) — one pointer moves each step.

    Dry run

    h=[1,8,6,2,5,4,8,3,7]
l=0 r=8: min(1,7)*8 = 8   1<7 -> l=1
l=1 r=8: min(8,7)*7 = 49  8>7 -> r=7
l=1 r=7: min(8,3)*6 = 18  r=6 ... best stays 49

    Watch out

    When the walls are equal, moving either one is fine. Do not confuse this with Trapping Rain Water: here only the two chosen walls matter, not the bars between them.

  • Hard42. Trapping Rain Water — move the side with the smaller max.
    Show solution

    The idea

    Bars of height h[i]; how much rain stays on top? [0,1,0,2,1,0,1,3,2,1,2,1] → 6. Water above bar i is min(tallest on left, tallest on right) - h[i]. The insight: with pointers at both ends, the side with the smaller max is the limiting side, so its water is already known. Settle that side and move it. Pattern: two pointers with running maxima.

    Brute force first

    For each bar, scan left and right for the tallest bars: O(n²). Precomputing leftMax[] and rightMax[] arrays gives O(n) time but O(n) space.

    Step by step

    1. l = 0, r = n - 1, leftMax = rightMax = 0.
    2. Update leftMax = max(leftMax, h[l]) and rightMax = max(rightMax, h[r]).
    3. If leftMax < rightMax: the left side is limiting; add leftMax - h[l] and l++.
    4. Otherwise add rightMax - h[r] and r--.
    5. Stop when the pointers meet.

    Java

    class Solution {
    public int trap(int[] h) {
        int l = 0, r = h.length - 1;
        int leftMax = 0, rightMax = 0, water = 0;
        while (l < r) {
            leftMax = Math.max(leftMax, h[l]);
            rightMax = Math.max(rightMax, h[r]);
            if (leftMax < rightMax) {
                water += leftMax - h[l]; // left limits
                l++;
            } else {
                water += rightMax - h[r]; // right limits
                r--;
            }
        }
        return water;
    }
}

    Time O(n) · Space O(1) — one pass, four variables.

    Dry run

    h=[4,2,0,3,2,5]
l=0 r=5: lM=4 rM=5, 4<5 add 0, l=1
l=1:     lM=4 add 4-2=2, l=2
l=2:     add 4-0=4, l=3
l=3:     add 4-3=1, l=4
l=4:     add 4-2=2, l=5 stop -> 9

    Watch out

    Update the max before adding water, so max - h is never negative. Arrays shorter than 3 hold no water.

Test yourself

The array is not sorted and you need the original indices. Two pointers or hash map?

Hash map. Sorting would scramble the indices, and the hash map solves it in O(n) anyway.

Why is two pointers O(n) and not O(n²)?

Each step moves one pointer inward by one, and they meet after at most n moves. No pair is checked twice.
